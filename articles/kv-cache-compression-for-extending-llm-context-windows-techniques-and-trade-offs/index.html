Before making a design choice, clarify:

  • The rapid adoption of large language models (LLMs) in interactive applications—code assistants, chatbots, and document‑analysis tools—has exposed a fundamental tension between model capability and hardware reality.
  • Modern transformer architectures store the key‑value (KV) pairs produced by each attention layer for every token that has been processed.
  • These KV caches enable the model to attend to all prior context without recomputing earlier layers, but they also consume a linear amount of memory with respect to the context length.

Stage 1 — KV Cache Fundamentals

  • The key‑value (KV) cache is the linchpin that lets transformer‑based language models (LLMs) reuse intermediate activations across decoding steps.
  • At its core, the cache stores the keys and values produced by each self‑attention layer for every token that has already been generated.
  • Subsequent tokens can then query this repository instead of recomputing the entire attention context, yielding a dramatic reduction in compute and memory overhead.
  • To understand how compression can be applied, we first need a rigorous view of the cache’s structure, lifecycle, and role in the decoding pipeline.

Stage 2 — 1. Quantization‑Based Compression

  • 1.1 Uniform & Per‑Channel Quantization The most straightforward memory reduction is to shrink the 16‑ or 32‑bit floating‑point tensors to 8‑bit (or even 4‑bit) integers.
  • Uniform quantization maps a floating‑point value x to an integer q via where scale and zero point are learned per tensor (or per channel) during a calibration pass on a representative corpus.
  • The key advantage is that the matrix‑multiply kernel can stay in the integer domain, leveraging SIMD instructions on modern CPUs/GPUs.
  • The downside is a bias in the dot‑product that grows with the length of the cache, especially when the distribution of keys and values is heavy‑tailed.

Stage 4 — 3. Chunk‑wise Pruning & Sparsification

  • Autoregressive generation exhibits a temporal decay in relevance: tokens far in the past contribute diminishingly to the current attention distribution.
  • Temporal Chunking – Split the cache into fixed‑size windows (e.g., 128 tokens).
  • Norm‑Based Scoring – Compute the ℓ₂ norm of each key vector within a chunk; low‑norm keys are deemed less informative.
  • Hard Threshold – Drop a configurable percentage (e.g., 30 %) of keys per chunk, storing a compact index map for reconstruction.
