Stage 1 — Architectural Overview & System Mechanics

  • The lock‑free Union‑Find component is positioned as a dedicated Set Service within the fraud‑detection micro‑service ecosystem.
  • It receives edge streams from the Transaction Ingestion Service , applies atomic path‑compressed unions, and exposes a lightweight REST API for find queries.
  • The service is built on Spring Boot, leverages Resilience4j for fault tolerance, and consumes Kafka events via Spring Kafka.
  • Event‑driven state changes are captured with Axon, enabling eventual consistency and auditability.

The **data flow** is illustrated below. The ingestion service streams raw transaction edges to Kafka. Each Set Service instance subscribes to a dedicated topic partition, ensuring that the union‑find array is partitioned by node hash. This partitioning eliminates cross‑instance contention and allows each instance to maintain a local, NUMA‑aware parent array.


### System Mechanics

* **Atomic Path Compression**: Each `find` operation performs a read‑modify‑write cycle on the parent pointer using `VarHandle.compareAndSet`. The algorithm compresses the path in a single pass, guaranteeing that subsequent finds traverse a flat tree. Because the operation is lock‑free, multiple threads can concurrently compress distinct subtrees without blocking.

* **NUMA‑Aware Allocation**: The parent array is allocated in a thread‑local memory region aligned with the NUMA node of the owning thread pool. This reduces remote memory access latency and aligns with the contention‑free design.

* **Resilience & Retry**: Resilience4j’s circuit breaker wraps the Kafka consumer and REST endpoint. If a downstream snapshot operation to PostgreSQL fails, the breaker trips, and the service retries with exponential back‑off, preventing cascading failures.

* **Event Sourcing with Axon**: Every union operation is published as a domain event (`EdgeAdded`). Axon’s event store persists these events, enabling replay for state recovery and audit trails. Snapshots are taken periodically to avoid replaying the entire event history.

### Trade‑offs

| Aspect | Lock‑Free Union‑Find | Lock‑Based (e.g., `synchronized`) |
|--------|---------------------|-----------------------------------|
| Throughput | 10× higher on multi‑core systems | Limited by global lock contention |
| Latency | Deterministic O(α(n)) per operation | Variable, can spike under load |
| Memory | Slight overhead for atomic fields | Minimal overhead |
| Complexity | Requires careful use of `VarHandle` and memory fences | Simpler to implement but less scalable |

The architectural design balances raw performance with operational resilience. By isolating the Union‑Find logic into a horizontally scalable service, the system can ingest millions of edges per second while still servicing low‑latency `find` queries, meeting the stringent demands of real‑time fraud detection.
