This walkthrough focuses on Why Structure Choice Beats Algorithm Cleverness.

Before making a design choice, clarify:

  • A senior engineer traced a 400ms latency spike on Airbnb's search service to a single line of code: a membership check against a Python list .
  • The service was calling if item in results inside a hot path, and with tens of thousands of items, each check was O(n) — scanning every element in the list.
  • Replacing the list with a set dropped the check to O(1) and cut latency by 400ms overnight.

Stage 3 — Deep Dive: How Hash Maps Handle Collisions

  • A hash map converts each key to a bucket index via a hash function.
  • When two keys hash to the same bucket — a collision — most implementations use separate chaining (a linked list per bucket) or open addressing (probe to the next empty slot).
  • Performance degrades as the load factor (entries ÷ buckets) rises; most implementations rehash at ~0.75, copying all entries into a larger array.

Stage 4 — Hidden Costs Beginners Miss

  • The Big-O table shows asymptotic behavior — but real performance includes constant factors, cache misses, and allocation overhead.

# Pre-size a dict to avoid rehash pauses
from sys import getsizeof
d = {}
d.update({i: i for i in range(10_000)})  # triggers multiple rehashes

# Better: pre-size if you know the approximate count
d = dict.fromkeys(range(10_000))         # allocates once

Stage 6 — Spot the Wrong Structure

  • The most common cause of sluggish code is not a bad algorithm — it is a mismatched data structure.
  • Here are four high-frequency selection mistakes and the fix for each.
  • Before-and-after gut check: if you find yourself scanning a list inside a hot loop just to test membership, that list should be a set.
  • If you are sorting a collection just to peek at the smallest element, that collection should be a heap.
