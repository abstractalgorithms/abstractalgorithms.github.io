Algorithmic Complexity & Asymptotic Analysis.

Asymptotic analysis classifies how runtime and memory scale as input size N grows: Big-O gives an upper bound, Big-Omega a lower bound, and Big-Theta a tight bound. Divide-and-conquer algorithms follow T(n) = aT(n/b) + f(n), solved by the Master Theorem across leaf-heavy, balanced (O(n log n)), and root-heavy regimes. When rare expensive operations occur—like doubling a dynamic array's capacity—amortized analysis (aggregate, accounting, or potential method Phi(D)) proves the average cost per operation remains O(1). When exact O(N) space is prohibitive, probabilistic structures like HyperLogLog trade a small bounded error (standard error ~ 1.04 / sqrt(m)) for logarithmic space.

Potential-Method Amortization

HyperLogLog estimates cardinality up to 10^9 in ~1.5 KB (m = 2048 6-bit registers) with ~2.3% standard error by tracking maximum leading-zero bit runs.

Memory Hierarchy & Hardware Sympathy.

Modern CPUs execute instructions in ~0.3 ns, but fetching a 64-byte cache line costs ~1 ns from L1 (32-64 KB), ~4 ns from L2 (256 KB-1 MB), ~15 ns from shared L3, and ~80-100 ns from DRAM—a 100x penalty per cache miss. Pointer-chasing structures (linked lists, naive binary trees) stall the out-of-order pipeline on dependent loads and TLB misses. Contiguous arrays and Struct-of-Arrays (SoA) layouts let the hardware prefetcher stream sequential cache lines ahead of execution. On multi-core CPUs, two threads updating independent fields on the same 64-byte cache line trigger MESI invalidation ping-ponging (false sharing), solved by padding hot per-thread state to 64-byte boundaries.

Mechanical Sympathy

CPU Cache Hierarchy, 64B Cache Lines & Hardware Prefetching

1.Spatial Locality: Contiguous arrays fetch 64 bytes per cache miss, letting the hardware prefetcher stream subsequent elements ahead of time.

2.Pointer Chasing Penalty: Linked lists and scattered heap objects cause dependent DRAM stalls (100 ns each) even when Big-O is identical.

3.False Sharing: Two cores mutating independent variables on the same 64B cache line trigger MESI invalidation ping-pong.

Contiguous arrays saturate L1/L2 prefetchers, whereas pointer-heavy structures stall on 100 ns DRAM fetches.

Arrays, Strings & Two-Pointer Techniques.

Arrays and strings dominate in-memory algorithms because contiguous indexing is O(1). Two-pointer patterns eliminate nested loops by maintaining a monotonic invariant: opposite-end pointers converge on sorted pairs in O(N), while Floyd's fast-and-slow pointers detect cycles and find midpoints in O(1) extra space. Sliding windows expand a right boundary and shrink a left boundary only when an invariant breaks—touching each element at most twice for O(N) total time. Prefix sums and difference arrays precompute cumulative state in O(N) to answer arbitrary range queries or range updates in O(1), while power-of-2 ring buffers replace modulo with bitwise index & (cap - 1).

O(N) Linear Scan Invariants

Sliding Window & Two-Pointer Invariant Maintenance

Because both L and R advance monotonically from 0 to N without backtracking, nested-looking shrink loops run in O(N) total time.

Amortized Sliding Window

Maintain incremental window state (counts, sum, distinct keys) so neither the left nor right pointer ever moves backward, bounding total work to 2N steps.

Power-of-Two Ring Buffers

Size circular buffers to 2^k slots so wrap-around indexing compiles to a single bitwise AND instead of integer division.

Order platform / Zero-allocation sliding-window rate limiter at 100k RPS

Zero-allocation sliding-window rate limiter at 100k RPS.

An API gateway tracked 60-second sliding request windows by appending timestamps to a per-key list and pruning expired entries, triggering severe GC pauses under 100k RPS.

Replaced timestamp lists with a fixed 64-slot circular ring buffer of 1-second buckets (epoch_sec & 63), resetting stale buckets lazily on write. Memory per key became fixed at 512 bytes with zero allocations and p99 check latency under 40 microseconds.

Lesson: Fixed-size ring buffers turn dynamic sliding-window pruning into O(1) bounded memory operations.

Linked Lists, Stacks & Monotonic Queues.

Stacks and queues enforce strict ordering invariants. Sentinel (dummy) head/tail nodes eliminate null-pointer edge cases when mutating linked lists, and intrusive lists (embedding next/prev pointers inside the payload struct, as in the Linux kernel) halve heap allocations. However, for general queues and deques, contiguous array-backed circular buffers vastly outperform linked lists due to cache locality. Algorithmically, monotonic stacks maintain elements in strictly increasing or decreasing order—popping dominated elements as new ones arrive—to solve Next Greater Element and Largest Rectangle in Histogram in O(N) time because every element is pushed and popped at most once. Monotonic deques extend this to O(N) sliding-window min/max.

Monotonic Deque Invariant

Maintaining a Monotonically Decreasing Deque for O(1) Window Max

Each index enters and leaves the deque at most once, yielding O(N) sliding-window extrema with the current maximum always at front.

Monotonic Stack Domination

Evict elements from the stack top that can never be the answer for future elements; each index enters and leaves the stack at most once, guaranteeing O(N) total runtime.

Array-Backed Circular Deque

Use a contiguous ring buffer for stacks, queues, and deques so push/pop operations stay inside L1 cache without per-node malloc/free overhead.

Computing 100-tick rolling max/min over 5M market ticks.

A quantitative backtester scanned a 100-tick window for every incoming price tick across 5M rows, spending 4.2 seconds per symbol in nested O(N * W) loops.

Lesson: Monotonic deques eliminate inner-loop rescans for sliding-window extrema in strict O(N) time.

Hash Tables, Collision Resolution & Bloom Filters.

Hash tables achieve O(1) expected lookups by mapping keys across M buckets at load factor alpha = N/M. Separate chaining handles high load factors gracefully and can treeify long buckets (Java HashMap converts chains > 8 to Red-Black trees) to defeat O(N) HashDoS attacks, but chases heap pointers on every collision. Open addressing stores entries inline in a contiguous array for high cache locality: Robin Hood hashing caps probe-distance variance by stealing slots from 'richer' keys, while SwissTable/Abseil probes 16 control bytes in parallel using SIMD. For pure membership checks, a Bloom filter uses k = (m/n) ln(2) hash functions over an m-bit array (~9.6 bits per key for 1% false positives) with zero false negatives.

Probabilistic & O(1) Lookup

Bloom Filter Pre-Check Shielding Hash Table & Disk Lookups

1.Zero False Negatives: If any of the k hashed bit positions is 0, the key is guaranteed absent, bypassing disk or DB queries.

2.Open Addressing & Robin Hood: Keeping entries in a flat array with bounded probe variance maximizes CPU cache hits up to ~85% load factor.

3.Load Factor Resize: Doubling capacity before probe chains explode preserves O(1) expected lookup and prevents hash-flooding DoS.

Bloom filters reject non-existent keys in O(k) bit checks in L1/L2 cache, while open-addressed hash tables keep probe sequences cache-local.

Zero per-entry pointer overhead.Performance degrades sharply above alpha ~0.7-0.85; requires tombstones or backward-shift delete. Resizing reallocates and rehashes the entire contiguous table.

Keyed Hashing Against HashDoS

Use per-process randomized seeds with SipHash or wyhash on untrusted external keys so attackers cannot craft colliding payloads.

Bloom Filter Negative-Lookup Shield

Maintain k optimal bit probes (~10 bits/key for <1% false positive rate) in RAM to reject missing keys before touching disk or remote stores.

Trees & Binary Search Trees (BST).

Trees model hierarchies from ASTs and DOMs to routing tables. In a Binary Search Tree, left < root < right ensures inorder traversal yields sorted keys in O(N), and searches run in O(h) where h is tree height. Unbalanced inserts of sorted keys degenerate h to N, turning O(log N) into O(N) and risking call-stack overflow in recursive DFS. Level-order BFS uses a FIFO queue for shortest unweighted paths, while Lowest Common Ancestor (LCA) queries can be preprocessed with binary lifting for O(log N) lookups. For string keys, compressed Radix (Patricia) tries collapse single-child chains into multi-character edges, delivering O(L) prefix matching independent of dictionary size.

Hierarchical BST Invariant

Binary Search Tree Order Property & Recursive Traversal Paths

1.DFS vs BFS Trade-off: Iterative/recursive DFS uses O(h) stack space for path/subtree invariants; BFS uses O(w) queue space for shortest unweighted levels.

2.In-Order Sorted Yield: In-order traversal (Left -> Node -> Right) visits BST keys in strictly non-decreasing sorted order.

3.Skew Degeneration: Inserting sorted keys without rebalancing degrades tree height h from O(log N) to O(N) linked-list depth.

BSTs partition search space by subtree bounds in O(h) steps, requiring balance invariants to prevent O(N) skew.

Radix Tree Path Compression

Merge chains of single-child trie nodes into compact edge substrings to slash pointer hops and memory footprint for URL routing and IP lookups.

Iterative DFS & Binary Lifting

Use explicit heap stacks for deep trees to prevent stack overflow, and precompute 2^k ancestor tables for O(log N) LCA queries.

Balanced Trees & Storage Engine Indexes.

Self-balancing trees bound height to O(log N): AVL trees enforce |h_L - h_R| <= 1 (max height 1.44 log2 N) for faster reads, while Red-Black trees allow 2x black-height skew (max 2 log2 N) to cap insert/delete rotations at 2-3—making them the default in std::map and Linux's CFS scheduler. On SSD/disk, pointer-per-node trees fail because each hop triggers a 4-16 KB page read. B+ Trees pack hundreds of keys per page (fan-out B ~ 200-500), keeping 100M rows within height 3-4 and linking leaf pages for fast range scans, at the cost of random in-place page rewrites (write amplification). LSM-Trees invert this trade-off: writes append to a WAL and an in-memory SkipList MemTable, flushing sequentially to immutable SSTables compacted in the background.

Disk & SSD Storage Indexes

B+Tree High Fan-Out (4KB-16KB Pages) vs Binary Tree Pointer Hops

1.Shallow 3-4 Level Height: A fan-out of 500 keys per 16KB page indexes 125 million rows in just 3-4 page hops.

2.Linked Leaf Siblings: All row payloads or pointers live in doubly-linked leaf pages, turning range scans into sequential I/O.

3.B+Tree vs LSM-Tree: B+Trees optimize point/range reads with in-place page updates; LSM-Trees batch sequential writes via MemTable + SSTables.

B+Trees align node size to 4KB-16KB OS/SSD pages so billions of keys fit in 3-4 hops with sequential leaf range scans.

Leveled vs. Size-Tiered Compaction

Leveled compaction (RocksDB default) caps space and read amplification for read-heavy workloads, while size-tiered compaction minimizes write amplification for append-heavy telemetry.

High-Fanout Page Alignment

Match B+ Tree node size to OS/SSD page multiples (4-16 KB) so each disk I/O fetches hundreds of keys in one read.

Heaps, Priority Queues, Top-K & Streaming Medians.

A binary heap packs a complete tree into a contiguous flat array where parent(i) = (i - 1) / 2 and children sit at 2i + 1 and 2i + 2, avoiding pointer overhead. Floyd's bottom-up heapify builds a heap in O(N) rather than O(N log N) because half the nodes are leaves needing zero sift-downs. For Top-K over N items, a bounded Min-Heap of size K runs in O(N log K) time and O(K) space—far cheaper than O(N log N) full sorting when K << N. Streaming medians pair a Max-Heap for the lower half with a Min-Heap for the upper half, rebalancing sizes to differ by at most 1 for O(1) median reads and O(log N) inserts. In production Dijkstra or timer wheels, d-ary heaps (e.g., 4-ary) halve tree depth and pack 4 children per 64-byte cache line, while indexed priority queues store a position map for O(log N) decrease-key updates.

Dual-Heap & Top-K Mechanics

Two-Heaps Streaming Median Partitioning & Bounded Min-Heap Top-K

1.Size Balance Invariant: Keep |len(MaxHeap) - len(MinHeap)| <= 1 by transferring roots whenever one half grows by 2.

2.Order Invariant: Every element in MaxHeap <= every element in MinHeap, isolating the median at the two heap tops.

3.d-ary Cache Packing: 4-ary heaps align 4 child keys inside one 64-byte cache line, halving tree depth for Dijkstra and timers.

Dual heaps maintain exact streaming medians in O(log N) per update, while flat d-ary arrays maximize cache-line density.

Tries, Prefix Trees & String Matching.

Standard tries branch by character so lookup time O(L) depends solely on key length L, not dictionary size N—ideal for autocomplete and longest-prefix IP/URL routing. Because naive 26-way or 256-way pointer arrays waste huge RAM on sparse nodes, compressed Radix (Patricia) tries merge single-child chains into multi-character edge slices. For substring search in text of length N and pattern of length M, brute-force backtracking degrades to O(N * M) on repetitive inputs. Knuth-Morris-Pratt (KMP) precomputes a Longest Prefix Suffix (LPS) failure table in O(M) so the text pointer never moves backward, guaranteeing strict O(N + M) worst-case time. Rabin-Karp computes a polynomial rolling hash in O(1) per slide to match multiple patterns simultaneously (or detect plagiarism/chunk boundaries via content-defined rolling hashes), verifying hash hits to avoid collisions.

Prefix & Automaton Indexing

Compressed Radix Trie Edge Merging & KMP Failure-Link Jumps

1.Path Compression: Merging single-child edges reduces trie depth from character count to branch points, slashing pointer chases.

2.Zero Text Backtracking: KMP LPS links reuse already-matched prefix characters so the text cursor advances monotonically in O(N + M).

3.Rolling Hash Window: Rabin-Karp updates hash(s[i+1..i+M]) from hash(s[i..i+M-1]) in O(1) arithmetic ops.

Compressed tries eliminate dictionary-size scaling for prefixes, while KMP and Rabin-Karp prevent O(N * M) substring backtracking.

Graph Traversals, Topological Sort & Shortest Paths.

Graphs capture dependencies, networks, and state transitions. Unweighted shortest paths use BFS in O(V + E), while 0-1 edge weights use a Deque (0-weight pushed to front, 1-weight to back) to stay O(V + E) without heap overhead. Directed Acyclic Graph (DAG) scheduling relies on Kahn's in-degree queue algorithm or 3-color DFS (unvisited/visiting/visited) to detect cycles and produce topological order in O(V + E). For non-negative weighted edges, Dijkstra's algorithm with a binary/d-ary heap runs in O((V + E) log V)—never use Dijkstra when negative weights exist, because once a node is popped its distance is assumed final. Bellman-Ford relaxes all E edges V - 1 times in O(V * E) to handle negative weights and detect negative cycles on the V-th pass, while Floyd-Warshall computes all-pairs shortest paths in O(V^3) for dense small graphs.

Shortest-Path Decision Tree

Selecting Graph Shortest-Path Algorithms by Edge Weight Constraints

1.DAG Shortest Path: If the graph is acyclic, relax edges in topological order in strict O(V + E)—even with negative weights.

2.Stale Heap Entries: In lazy Dijkstra, immediately `continue` if `popped_dist > dist[u]` to avoid redundant edge relaxations.

3.Kahn's Cycle Proof: Any node never reaching in-degree 0 belongs to or depends on a directed cycle.

Matching edge-weight properties to the right traversal avoids paying O(V * E) where O(V + E) or O(E log V) suffices.

Kahn's In-Degree Cycle Gate

Enqueue nodes with in_degree == 0; if total popped nodes < V after the queue empties, a dependency cycle exists.

When edge weights are strictly 0 or 1, push 0-cost relaxations to deque.push_front and 1-cost to push_back for O(V + E) shortest paths.

Disjoint Set Union (Union-Find), MSTs & Network Flow.

Disjoint Set Union (DSU / Union-Find) maintains dynamic connected components across edge additions. Combining Path Compression during find() with Union by Rank/Size flattens trees so both find and union run in O(alpha(N)) amortized time—where the inverse Ackermann function alpha(N) <= 4 for any N <= 10^80. Kruskal's algorithm sorts all edges in O(E log E) and uses DSU to greedily add non-cyclic edges for a Minimum Spanning Tree (ideal for sparse graphs), whereas Prim's algorithm grows a single tree from a start vertex using a priority queue in O(E log V) (better for dense graphs). For capacity-constrained routing, bipartite matching, and resource allocation, Edmonds-Karp (BFS augmenting paths, O(V * E^2)) and Dinic's algorithm (level graph + blocking flows, O(E * sqrt(V)) on unit networks) compute Max-Flow, which by the Max-Flow Min-Cut Theorem equals the minimum bottleneck capacity separating source and sink.

Dynamic Programming, Memoization, Greedy & Sliding Window.

Dynamic Programming (DP) solves problems exhibiting overlapping subproblems and optimal substructure by caching state transitions instead of recomputing exponential recursion trees. Top-down memoization writes natural recursion with a cache and computes only reachable states, while bottom-up tabulation iterates in topological state order—enabling rolling-array space compression (turning O(N * W) 2D knapsack tables into O(W) 1D arrays by iterating capacity backward) and eliminating recursion stack limits. When a problem satisfies the greedy-choice property (proved via an exchange argument—such as interval scheduling sorted by earliest end time), a single O(N log N) pass beats O(N^2) DP. Bitmask DP encodes small subset states (N <= 20) as integers for TSP/assignment problems, while monotonic-deque DP optimizations collapse O(N * K) transition windows down to O(N).

DP State & Space Compression

From Exponential Recursion to 1D Rolling-Array Tabulation

Identifying minimal DP state transitions and rolling 2D dependencies into 1D arrays unlocks both polynomial time and L1-cache speed.

Rolling-Row Space Compression

When dp[i][j] depends only on row i - 1, overwrite a single 1D array in reverse inner-loop order to cut memory from O(N * W) to O(W).

Greedy Exchange Argument

Before writing DP, test if sorting by a local key (e.g., earliest finish time) lets any optimal solution swap into the greedy choice without worsening cost.

The decision framework

01

What is the true hardware bottleneck: CPU instructions, DRAM cache misses, or disk IOPS?

An O(N) sequential array scan in L1/L2 cache often beats an O(log N) pointer-chasing structure on real silicon.

02

Is the workload read-heavy, range-scan-heavy, or random-write-heavy?

B+ Trees favor predictable reads and range scans; LSM-Trees convert random writes into sequential appends.

03

What worst-case input can break amortized or expected O(1) bounds?

Guard against HashDoS collisions, dynamic resize latency spikes, and unbalanced tree degeneration.

04

Can a bounded probabilistic error replace O(N) exact memory?

Bloom filters and HyperLogLog cut RAM by 100x-1000x when <1% false-positive or cardinality error is acceptable.

05

Do concurrent threads share cache lines or contend on allocations?

Align per-thread state to 64-byte cache lines and prefer flat buffers or arena/slab allocators over millions of small heap nodes.
