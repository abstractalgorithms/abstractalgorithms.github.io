Vector Embeddings, Mathematical Spaces & Similarity.

Embedding models project text, images, or code into dense floating-point vectors in R^D (commonly D = 768 to 3072). Choosing between Cosine similarity, Euclidean (L2) distance, and Inner Product depends on whether vector magnitude carries signal. When vectors are L2-normalized to unit length (||v|| = 1), Euclidean squared distance reduces to 2 - 2(a · b), making Cosine, L2, and Dot Product rank-equivalent while letting CPUs compute similarity as raw AVX-512 or NEON SIMD dot products. In high dimensions, random vector distances concentrate around their mean (curse of dimensionality), so models trained with contrastive or Matryoshka losses are required to preserve meaningful angular separation.

Approximate Nearest Neighbors (ANN) & Vector Indexing.

Exact K-Nearest Neighbors (KNN) scans every vector in O(N * D) time, saturating DRAM bandwidth long before compute. Approximate Nearest Neighbor (ANN) indexes eliminate exhaustive scans. HNSW builds a multi-layer proximity graph where upper sparse layers act as express highways and lower dense layers refine the local neighborhood in O(log N) hops, tuned via M (edges per node), efConstruction, and efSearch. Inverted File (IVF) indexes partition the space into k Voronoi cells via k-means and scan only the nearest nprobe cells. To fit billion-scale corpora in RAM, Product Quantization (PQ) splits a D-dimensional vector into M sub-vectors and encodes each to an 8-bit centroid ID—compressing a 1536-d FP32 vector (6,144 bytes) down to 96 bytes (64x compression) at the cost of slight quantization error.

HNSW Multi-Layer Graph

Hierarchical Navigable Small World (HNSW) Greedy Routing

1.Upper Layers (Sparse): Exponentially fewer nodes with long-range edges jump across the vector space in O(log N) hops.

2.Layer 0 (Dense): Contains all N vectors; beam search with efSearch width explores local neighbors for >98% recall.

3.Memory vs Disk: HNSW keeps graph edges in RAM (~1.5x vector size); IVF-PQ or DiskANN trades recall/latency for 10x lower RAM.

HNSW routes from sparse upper-layer skip-links down to a dense Layer-0 neighborhood search in logarithmic hops.

Hybrid Search: Dense Semantic Vectors & Sparse BM25.

Dense bi-encoder embeddings compress entire passages into a single fixed-width vector, which blurs rare tokens, exact SKUs, stack traces, and invoice IDs. Sparse lexical algorithms like BM25 score exact term matches using saturated term frequency (k1) and document-length normalization (b) weighted by Inverse Document Frequency (IDF), while neural sparse models like SPLADE expand documents into learned vocabulary weights. Because BM25 scores are unbounded positive floats and cosine scores lie in [-1, 1], summing raw scores directly is unstable. Reciprocal Rank Fusion (RRF) merges ranked lists purely by position: RRF(d) = sum(1 / (k + rank_i(d))) with k = 60, ensuring documents ranked highly by both retrievers rise deterministically.

Hybrid Retrieval & Fusion

Parallel Dense + BM25 Retrieval Merged via Reciprocal Rank Fusion

RRF fuses incompatible cosine and BM25 score distributions by rank position before a cross-encoder reranks the top candidates.

Reciprocal Rank Fusion (RRF)

Fuse dense and sparse rankings using 1 / (60 + rank) so neither retriever's raw score scale dominates without fragile min-max calibration.

SPLADE Learned Sparse Expansion

Use a masked-language-model head to project passages into high-dimensional sparse vectors that capture synonyms (e.g. 'car' -> 'automobile') while remaining compatible with inverted indexes.

Retrieval-Augmented Generation (RAG) Architecture.

Naive RAG—embed a raw user query, fetch top-k chunks, and stuff them into a prompt—fails on ambiguous phrasing, multi-hop questions, and strict ACL filtering. Short user questions occupy a different region of embedding space than long declarative answers; HyDE bridges this gap by generating a hypothetical answer first and embedding that passage. Multi-query expansion and sub-query decomposition split compound requests into parallel retrievals. Equally critical is enforcing tenant and document permissions via metadata pre-filtering inside the index rather than post-filtering, which can return zero results when an authorized subset is small.

Production RAG Pipeline

Semantic Cache, Hybrid Retriever, Reranker & Grounded LLM

1.Query Translation: Rewrites conversational queries into standalone search terms and enforces tenant RBAC metadata filters before retrieval.

2.Semantic Cache: Short-circuits repeated or paraphrased questions in <20ms without invoking the generator LLM.

3.Grounded Generation: Injects top-k reranked chunks with strict citation instructions and evaluates faithfulness via RAGAS.

Production RAG pairs pre-retrieval RBAC filtering and semantic caching with two-stage reranking to minimize hallucinations and latency.

Chunking Strategies, Context Compression & Reranking.

Bi-encoder embeddings encode queries and documents independently in O(1) vector lookups, losing fine-grained token-to-token interactions. Cross-encoders concatenate (query, chunk) and run full self-attention across both, producing dramatically more accurate relevance scores at O((L_q + L_d)^2) compute cost—making them ideal as a second-stage filter over the top 50–100 hybrid hits. Chunking faces a core tension: small chunks (128–256 tokens) yield sharp embeddings, while LLMs need surrounding context (1024+ tokens) to reason accurately. Parent-child indexing resolves this by indexing small child chunks while returning their parent section to the generator, and placing the highest-ranked chunks at the start and end of the prompt mitigates the 'Lost in the Middle' attention decay.

  • Fixed-character chunking splits tables, code blocks, and sentences mid-thought; use structure-aware or recursive splitters.

Deep Learning Foundations & GPU Tensor Hardware.

Deep learning workloads are governed by GPU hardware physics. Tensors are N-dimensional views over contiguous 1D memory buffers indexed via shape and stride metadata; non-contiguous transposes must be materialized before coalesced GPU memory reads. Training builds a dynamic or static computation graph for reverse-mode automatic differentiation (autograd), storing intermediate activations in VRAM unless activation checkpointing recomputes them on the fly. On modern GPUs, Tensor Cores execute warp-level Matrix Multiply-Accumulate (MMA) in FP16, BF16, or FP8 at hundreds of teraflops. By the Roofline model, arithmetic intensity (FLOPs per byte moved from HBM) determines whether an operation is compute-bound (LLM prompt prefill, large GEMMs) or memory-bandwidth-bound (token-by-token LLM decode, elementwise activations).

GPU Memory & Tensor Cores

Arithmetic Intensity Across HBM, Shared SRAM & Tensor Cores

1.Memory-Bound Ops: Elementwise ops (ReLU, LayerNorm) stall waiting on HBM bandwidth; kernel fusion merges them into one SRAM pass.

2.Compute-Bound GEMM: Large matrix multiplications saturate Tensor Cores via BF16/FP8 mixed precision and 128x128 SRAM tiling.

3.Activation Checkpointing: Trades ~30% extra compute to discard intermediate activations and recompute during backward pass.

Modern deep learning speedups come from keeping data in on-chip SRAM via fused kernels so Tensor Cores never stall on HBM.

Prefill vs. Decode Roofline Split

Prefill processes all prompt tokens in parallel as large matrix-matrix multiplications (compute-bound), whereas autoregressive decode processes 1 token per sequence per step (HBM bandwidth-bound).

BF16 & FP8 Precision Trade-offs

BF16 preserves FP32's 8-bit exponent range to prevent training gradient underflow, while FP8 cuts weight and KV-cache HBM traffic in half during inference.

Transformer Architecture & Attention Physics.

Scaled Dot-Product Attention computes Attention(Q, K, V) = softmax((Q * K^T) / sqrt(d_k)) * V, where scaling by sqrt(d_k) keeps dot-product variance near 1 so softmax gradients do not vanish. Materializing the N x N attention matrix in HBM scales quadratically in memory and bandwidth; FlashAttention tiles Q, K, and V blocks into fast on-chip GPU SRAM and computes softmax incrementally via online rescaling, keeping memory O(N). During autoregressive generation, caching past K and V tensors avoids recomputing the prefix, but KV-cache size (2 * layers * kv_heads * d_head * bytes_per_param * seq_len) quickly dominates VRAM. Grouped-Query Attention (GQA) shares K/V heads across groups of Q heads to shrink KV-cache traffic, RoPE encodes relative token positions via 2D rotations, and PagedAttention allocates KV-cache in fixed-size non-contiguous blocks to eliminate fragmentation.

LLM Inference Engine

Prefill vs Decode, PagedAttention & KV-Cache Memory Management

1.Quadratic Attention & FlashAttention: FlashAttention tiles Q, K, V in SRAM to compute exact softmax without materializing the O(N^2) attention matrix in HBM.

2.KV-Cache Bottleneck: Autoregressive decoding is memory-bandwidth bound; GQA and PagedAttention slash KV-cache VRAM fragmentation.

3.Continuous Batching: Iteration-level scheduling packs new requests into idle slots alongside running decodes for 4x-10x throughput.

FlashAttention eliminates O(N^2) HBM traffic during prefill, while GQA and PagedAttention break the KV-cache memory wall during decode.

FlashAttention Online Softmax Tiling

Fuse QK^T, masking, softmax, and V multiplication inside GPU SRAM tiles so the quadratic N x N score matrix is never written to slow HBM.

PagedAttention Virtual KV Blocks

Manage KV-cache like OS virtual memory pages so sequences grow dynamically without reserving contiguous max-context VRAM buffers.

LLM Inference Optimization, Quantization & Continuous Batching.

Serving LLMs at scale is a scheduling and memory-bandwidth problem. Static batching forces short requests to wait until the longest sequence in the batch finishes generating EOS, wasting up to 65% of GPU cycles. Continuous (iteration-level) batching schedules at token-step granularity: as soon as one request emits EOS, a waiting request enters the batch on the very next forward pass. To prevent long prompt prefills from stalling active decode steps (ITL spikes), engines like vLLM and Sarathi-Serve use chunked prefill, slicing 8K-token prompts into 512-token chunks interleaved with decode tokens. On the weight side, FP8 and INT4 AWQ/GPTQ quantization cut HBM reads by 2x-4x for memory-bound decode, while speculative decoding uses a small draft model (or Medusa/EAGLE heads) to propose gamma=4..6 tokens that the target model verifies in one parallel forward pass without altering the output distribution.

Serving Engine Loop

Continuous Batching, Chunked Prefill & Speculative Verification

1.Iteration Scheduling: Evicts finished sequences after every token step and immediately slots queued requests.

2.INT4 AWQ / FP8: Cuts weight HBM traffic 2x-4x so decode throughput scales with batch size.

3.Lossless Draft-Verify: Rejection sampling accepts matching draft tokens in 1 pass, yielding 1.8x-2.5x speedup.

High-goodput LLM serving requires token-granularity scheduling, bounded prefill chunks, and quantized HBM footprints.

Continuous Batching & Chunked Prefill

Iteration-level scheduling frees KV-cache slots immediately on EOS, while chunked prefill caps prompt compute per step so Time-to-First-Token (TTFT) does not stall Inter-Token Latency (ITL).

Speculative Decoding & Disaggregated Serving

Drafting K tokens cheaply and verifying them in a single target pass converts memory-bound decode into compute-bound parallel verification; disaggregated pools separate prefill GPUs from decode GPUs.

Each 12K-token prefill monopolized the GPU for ~850 ms, stalling all in-flight decode streams. Enabling chunked prefill (max 512 prefill tokens per iteration) and moving weights to FP8 cut p99 ITL to 42 ms while sustaining 2.1x higher request throughput.

Lesson: Never mix unchunked long prefills with latency-sensitive decode steps; bound prefill chunk size or disaggregate prefill and decode pools.

AI & Machine Learning Systems / Stage 09L6 · SCALE & TRADE-OFFS

Fine-Tuning, LoRA/QLoRA & Alignment (SFT, DPO, RLHF).

Full-parameter fine-tuning of a 70B model in FP16 with AdamW requires ~1.12 TB of VRAM (16 bytes per parameter across weights, gradients, FP32 master weights, and m/v optimizer moments). Low-Rank Adaptation (LoRA) freezes the base weights W and injects trainable rank-r decompositions deltaW = (alpha / r) * B * A into attention and MLP projections, shrinking trainable parameters by >99% (often <0.5% of W). QLoRA pushes this further by storing frozen W in 4-bit NormalFloat (NF4) with double quantization and paged CPU-offloaded optimizer states, letting a 70B adapter train on a single 48-80 GB GPU. In production, multi-tenant LoRA serving (S-LoRA / Punica) keeps one shared base model in HBM and batches heterogeneous customer adapters in one kernel. For behavior shaping, teams run Supervised Fine-Tuning (SFT) for format and domain style, followed by Direct Preference Optimization (DPO) or PPO/GRPO to suppress refusals, verbosity, and policy violations.

Adaptation & Alignment

QLoRA Adapter Training & Preference Alignment Pipeline

1.16x Optimizer Cut: Gradients and AdamW moments exist only for low-rank A and B matrices.

2.DPO Stability: Directly optimizes log-ratio between chosen and rejected completions without a reward model.

3.Adapter Hot-Swap: Serve hundreds of domain adapters over one pinned base model in HBM.

Pair RAG for dynamic knowledge with QLoRA + SFT/DPO to lock in structured behavior and distill large teachers into fast small models.

RAG vs. Fine-Tuning Boundary

Use RAG for mutable facts, citations, and tenant ACLs; use LoRA fine-tuning for output schema adherence, specialized syntax, tone, or latency reduction via distilling a 70B teacher into an 8B student.

Multi-Tenant LoRA Serving (S-LoRA)

Instead of deploying N separate model replicas, hold one quantized base model in VRAM and execute Segmented Gather Matrix-Vector Multiplication (SGMV) across per-tenant LoRA adapters.

Distilling a 70B SQL agent into a fine-tuned 8B LoRA model.

A SaaS analytics copilot spent $42K/month running 70B prompts with 18 few-shot examples to emit valid dialect-specific SQL at 1.4s TTFT.

AI & Machine Learning Systems / Stage 10L7 · PRINCIPAL ARCHITECTURE

Agentic Workflows, Tool Calling, LangGraph & MCP.

Production agents fail when treated as unbounded 'while not done' ReAct loops. Reliable systems model agent execution as a deterministic directed state graph (e.g., LangGraph) with typed state transitions, hard step/token budgets, and cycle detection. Every external action uses the Model Context Protocol (MCP) or strict JSON-schema tool contracts with idempotency keys so retries after network timeouts never double-charge or duplicate tickets. For high-blast-radius mutations (refunds, production deploys, SQL writes), the state graph persists a durable checkpoint to Postgres/Redis and emits an interrupt for Human-in-the-Loop (HITL) approval before resuming. In multi-agent topologies, a Supervisor node routes scoped sub-tasks to specialized worker agents with isolated context windows so tool outputs from one domain do not pollute the global prompt.

Durable Agent Runtime

Bounded Agent State Machine with MCP Tools & HITL Gate

1.MCP Contracts: Typed JSON schemas and scoped credentials decouple tools from model prompts.

2.Idempotent Writes: Every mutating call carries a deterministic request_id to make retries safe.

3.Step & Cost Caps: Hard max_steps and token budgets trigger graceful fallback before runaway loops.

Reliable agents replace open-ended loops with checkpointed state graphs, typed MCP tools, and explicit HITL approval gates.

Bounded State Graphs & Durable Checkpointing

AI & Machine Learning Systems / Stage 11L5 · PRODUCTION PATTERNS

LLM Evaluation Harnesses, Semantic Caching & Prompt Security.

Because LLM outputs are non-deterministic, vibe-checking five prompts before shipping guarantees silent regressions. Production teams run CI/CD evaluation harnesses (e.g., RAGAS) over golden datasets to track Context Recall, Context Precision, Faithfulness (claim-by-claim NLI against retrieved chunks), and Answer Relevance. When using LLM-as-a-Judge, mitigate position bias (swapping A/B order), verbosity bias, and self-preference using calibrated rubrics. On the serving path, semantic caching embeds incoming queries and checks a Redis/Qdrant cache; only high-similarity hits (cosine >= 0.94) scoped by tenant_id, ACL group, and prompt template version may short-circuit generation. Finally, defense-in-depth against direct and indirect prompt injection separates trusted system instructions from untrusted retrieved text, validates structured outputs against strict schemas, and blocks PII or secret exfiltration before responses stream to clients.

Quality, Cost & Safety

Guardrailed Serving with Semantic Cache & CI Eval Gate

1.RAGAS Triad: Tracks Context Recall, Context Precision, and Faithfulness on every prompt or chunker PR.

2.ACL-Safe Cache: Partitions cache index by tenant and permission hash before vector similarity lookup.

3.Instruction Isolation: Treats retrieved chunks as untrusted data and enforces output schema + URL allowlists.

Production reliability pairs offline CI eval gates with runtime input/output guardrails and tenant-isolated semantic caching.

Decomposed RAG Evals (Retrieval vs. Generation)

Measure retrieval (Context Recall/Precision) separately from generation (Faithfulness/Groundedness) so you know immediately whether a failure is an indexing bug or an LLM hallucination.

Tenant-Scoped Semantic Caching

Never cache solely by raw query embedding: partition cache keys by tenant_id, ACL role, and model version, and require cosine >= 0.94 to avoid serving wrong-intent answers.

AI & Machine Learning Systems / Stage 12L5 · PRODUCTION PATTERNS

Classical ML Systems, Feature Stores & Pipeline Orchestration.

Most production ranking, fraud, and recommendation systems still rely on tabular gradient-boosted trees (XGBoost/LightGBM) or two-tower neural rankers backed by disciplined feature engineering. The #1 failure mode is training-serving skew: computing a feature differently in offline Python/Spark notebooks than in the online Java/Go microservice, or leaking future labels via naive SQL joins. A Feature Store (Feast, Tecton) solves both by compiling one declarative feature definition into an offline columnar store (Parquet/BigQuery with AS-OF point-in-time joins) for training and a low-latency online KV store (Redis/DynamoDB at <10 ms p99) for inference. Orchestrators (Airflow, Dagster, Kubeflow) version datasets, feature snapshots, and model artifacts together, while deployment gates use shadow traffic, canary percentages, and Population Stability Index (PSI) / concept-drift monitors to catch silent accuracy decay.

Feature & MLOps Spine

Dual-Store Feature Platform with Point-in-Time Parity

1.AS-OF Time Travel: Reconstructs exact feature values as of prediction timestamp with zero future leakage.

2.Sub-10ms Online KV: Materializes latest sliding-window aggregates into Redis/DynamoDB for real-time rankers.

3.Shadow Rollout: Scores live traffic asynchronously and compares PSI/calibration before shifting user traffic.

Durable ML systems unify offline training and online serving around one versioned feature definition and continuous drift telemetry.

Point-in-Time (AS-OF) Joins

Training datasets must join each historical label event with only the feature values that existed strictly before the event timestamp, preventing future data leakage.

Offline-Online Parity & Drift Monitoring

Share transformation code across batch backfills and streaming Flink/Kafka jobs, and monitor input feature shift (data drift) separately from label-relationship shift (concept drift).

GPU VRAM Exhaustion & KV-Cache Preemption Storm

A burst of 80 concurrent users submits 16K-token document-comparison prompts. KV-cache blocks fill 100% of HBM, forcing vLLM to preempt and recompute running sequences repeatedly while TTFT spikes past 15 seconds.

Enforce strict max_input_tokens and max_output_tokens admission caps, enable chunked prefill so long prompts do not starve decode tokens, and shed excess load at the API queue with HTTP 429 + Retry-After.

The decision framework

01

Is a probabilistic model actually required, or will deterministic rules/SQL suffice?

Exact lookups, financial math, and strict state transitions should never rely on stochastic token generation.

02

Which retrieval failure mode dominates: semantic mismatch or exact-token miss?

Pair dense ANN with BM25 + RRF whenever queries contain IDs, SKUs, code symbols, or rare domain terms.

03

What is the RAM and recall budget for the vector index at 12-month scale?

Size M, quantization (int8/PQ), and oversampling ratios explicitly rather than defaulting to uncompressed FP32 HNSW.

04

Is inference gated by compute (prefill) or HBM bandwidth (decode)?

Optimize prefill with prefix caching and context pruning; optimize decode with FP8 quantization, GQA, and continuous batching.

05

How are hallucinations, prompt injections, and client disconnects bounded?

Enforce structured output schemas, grounding evals in CI, input/output guardrails, and immediate SSE cancellation.
