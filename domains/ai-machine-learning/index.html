Vector Embeddings, Mathematical Spaces & Similarity.

Embedding models project text, images, or code into dense floating-point vectors in R^D (commonly D = 768 to 3072). Choosing between Cosine similarity, Euclidean (L2) distance, and Inner Product depends on whether vector magnitude carries signal. When vectors are L2-normalized to unit length (||v|| = 1), Euclidean squared distance reduces to 2 - 2(a · b), making Cosine, L2, and Dot Product rank-equivalent while letting CPUs compute similarity as raw AVX-512 or NEON SIMD dot products. In high dimensions, random vector distances concentrate around their mean (curse of dimensionality), so models trained with contrastive or Matryoshka losses are required to preserve meaningful angular separation.

Unit Normalization at Ingest

Normalize embeddings to unit L2 norm once during ingestion so query-time cosine similarity executes as a pure SIMD dot product without square-root or division instructions.

Matryoshka Representation Learning (MRL)

Models trained with MRL pack coarse semantics into early dimensions, allowing a 3072-d vector to be truncated to 512-d or 256-d for fast first-stage retrieval before full-dimension rescoring.

Approximate Nearest Neighbors (ANN) & Vector Indexing.

Exact K-Nearest Neighbors (KNN) scans every vector in O(N * D) time, saturating DRAM bandwidth long before compute. Approximate Nearest Neighbor (ANN) indexes eliminate exhaustive scans. HNSW builds a multi-layer proximity graph where upper sparse layers act as express highways and lower dense layers refine the local neighborhood in O(log N) hops, tuned via M (edges per node), efConstruction, and efSearch. Inverted File (IVF) indexes partition the space into k Voronoi cells via k-means and scan only the nearest nprobe cells. To fit billion-scale corpora in RAM, Product Quantization (PQ) splits a D-dimensional vector into M sub-vectors and encodes each to an 8-bit centroid ID—compressing a 1536-d FP32 vector (6,144 bytes) down to 96 bytes (64x compression) at the cost of slight quantization error.

ChoiceWhat it buysWhat it costs
HNSW Graph IndexHigh recall (97-99%) at sub-10ms p99 latency without centroid training. Supports incremental inserts and deletes with strong query-time QPS.High RAM overhead (raw vectors plus graph adjacency lists). Slow index build times and expensive in-memory tombstones on heavy deletes.
IVF-PQ (Inverted File + Product Quantization)10x-64x smaller memory footprint via sub-vector centroid codebooks. Predictable linear scan over nprobe cells with high cache locality.Requires periodic k-means/codebook retraining as data distribution drifts. Lower recall unless paired with a second-stage disk/RAM rescore of top candidates.

Two-Stage Oversampling and Rescoring

Retrieve top 4*K candidates using compressed int8 or PQ codes in RAM, then fetch full-precision FP32/FP16 vectors from NVMe or RAM to compute exact distances for the final top K.

Segment-Based Immutable Indexing

Buffer live vector writes in a WAL and small mutable segment while merging immutable HNSW segments asynchronously in the background so compaction never stalls query threads.

Order platform / Fitting 50M 1536-d vectors into a 64 GB RAM node

Fitting 50M 1536-d vectors into a 64 GB RAM node.

Storing 50M 1536-d FP32 vectors in an unquantized HNSW graph required ~360 GB of RAM, forcing an expensive 6-node memory-optimized cluster.

Switched to Scalar Quantization (int8) with HNSW oversampling (4x) and exact FP16 rescoring from NVMe. RAM dropped by 74% to ~52 GB on a single node while keeping recall@10 at 98.1% and p99 latency at 11ms.

Lesson: Quantize in-memory index vectors and oversample + rescore exact vectors from fast storage.

Hybrid Search: Dense Semantic Vectors & Sparse BM25.

Dense bi-encoder embeddings compress entire passages into a single fixed-width vector, which blurs rare tokens, exact SKUs, stack traces, and invoice IDs. Sparse lexical algorithms like BM25 score exact term matches using saturated term frequency (k1) and document-length normalization (b) weighted by Inverse Document Frequency (IDF), while neural sparse models like SPLADE expand documents into learned vocabulary weights. Because BM25 scores are unbounded positive floats and cosine scores lie in [-1, 1], summing raw scores directly is unstable. Reciprocal Rank Fusion (RRF) merges ranked lists purely by position: RRF(d) = sum(1 / (k + rank_i(d))) with k = 60, ensuring documents ranked highly by both retrievers rise deterministically.

Reciprocal Rank Fusion (RRF)

Fuse dense and sparse rankings using 1 / (60 + rank) so neither retriever's raw score scale dominates without fragile min-max calibration.

SPLADE Learned Sparse Expansion

Use a masked-language-model head to project passages into high-dimensional sparse vectors that capture synonyms (e.g. 'car' -> 'automobile') while remaining compatible with inverted indexes.

Order platform / Sub-20ms hybrid semantic search at 10M document scale

Sub-20ms hybrid semantic search at 10M document scale.

An enterprise document platform using pure dense embeddings failed when finance teams searched exact invoice IDs like 'INV-90210' or error codes like 'ERR_QUOTA_429', returning topically similar but wrong memos.

Deployed parallel Qdrant HNSW dense retrieval and BM25 inverted-index search, merging top-100 candidates from each leg via RRF (k = 60). Exact identifier recall hit 99.4% and overall NDCG@10 improved by 42% at 18ms p95 latency.

Lesson: Pair dense embeddings with sparse lexical retrieval via RRF whenever queries include exact identifiers or domain jargon.
Pause & reason: where would you draw the boundary?▼
  • Which query classes in your workload require exact token matching (IDs, error codes, proper nouns) vs. semantic paraphrasing?
  • Should dense and sparse legs carry equal weight in RRF, or do domain benchmarks justify weighted rank fusion?
  • How do you tokenize compound technical identifiers (camelCase, snake_case, hyphenated SKUs) in your BM25 analyzer?
  • What is the tail-latency impact of running dense and sparse queries in parallel and waiting for the slower leg?

Retrieval-Augmented Generation (RAG) Architecture.

Naive RAG—embed a raw user query, fetch top-k chunks, and stuff them into a prompt—fails on ambiguous phrasing, multi-hop questions, and strict ACL filtering. Short user questions occupy a different region of embedding space than long declarative answers; HyDE bridges this gap by generating a hypothetical answer first and embedding that passage. Multi-query expansion and sub-query decomposition split compound requests into parallel retrievals. Equally critical is enforcing tenant and document permissions via metadata pre-filtering inside the index rather than post-filtering, which can return zero results when an authorized subset is small.

Chunking Strategies, Context Compression & Reranking.

Bi-encoder embeddings encode queries and documents independently in O(1) vector lookups, losing fine-grained token-to-token interactions. Cross-encoders concatenate (query, chunk) and run full self-attention across both, producing dramatically more accurate relevance scores at O((L_q + L_d)^2) compute cost—making them ideal as a second-stage filter over the top 50–100 hybrid hits. Chunking faces a core tension: small chunks (128–256 tokens) yield sharp embeddings, while LLMs need surrounding context (1024+ tokens) to reason accurately. Parent-child indexing resolves this by indexing small child chunks while returning their parent section to the generator, and placing the highest-ranked chunks at the start and end of the prompt mitigates the 'Lost in the Middle' attention decay.

Parent-Child Retrieval

Embed 150-token child windows for high retrieval precision, then map hits back to their 1,000-token parent block for coherent LLM synthesis.

Edge-Weighted Context Ordering

Place the top-1 and top-2 reranked passages at the beginning and end of the prompt context to counter U-shaped transformer attention decay.

Order platform / Eliminating missed clauses in 100-page legal contract QA

Eliminating missed clauses in 100-page legal contract QA.

A legal assistant injected top-30 500-token chunks into the prompt, yet the LLM repeatedly missed exception clauses placed in chunks 12 through 22.

Switched to clause-aware parent-child indexing (200-token child chunks linked to full section parents) and added a BGE-reranker-v2 cross-encoder to prune top-50 hits down to the top 5 ordered at prompt edges. Hallucinated or missed exceptions dropped by 68% and prefill latency fell 45%.

Lesson: Rerank aggressively to a small, high-signal context rather than relying on raw context-window size.
  • Cross-encoder latency scales linearly with candidate count K; cap reranking to top 30-50 chunks or run on dedicated GPU batching.
  • Fixed-character chunking splits tables, code blocks, and sentences mid-thought; use structure-aware or recursive splitters.
  • Stuffing 30+ chunks into long-context windows inflates TTFT (Time to First Token) quadratically during prefill and degrades accuracy.
Pause & reason: where would you draw the boundary?▼

  • How do you deduplicate overlapping parent blocks when multiple child chunks match the same section?
  • Have you evaluated whether placing critical context at the prompt edges changes answer accuracy?

Deep Learning Foundations & GPU Tensor Hardware.

Deep learning workloads are governed by GPU hardware physics. Tensors are N-dimensional views over contiguous 1D memory buffers indexed via shape and stride metadata; non-contiguous transposes must be materialized before coalesced GPU memory reads. Training builds a dynamic or static computation graph for reverse-mode automatic differentiation (autograd), storing intermediate activations in VRAM unless activation checkpointing recomputes them on the fly. On modern GPUs, Tensor Cores execute warp-level Matrix Multiply-Accumulate (MMA) in FP16, BF16, or FP8 at hundreds of teraflops. By the Roofline model, arithmetic intensity (FLOPs per byte moved from HBM) determines whether an operation is compute-bound (LLM prompt prefill, large GEMMs) or memory-bandwidth-bound (token-by-token LLM decode, elementwise activations).

Prefill vs. Decode Roofline Split

Prefill processes all prompt tokens in parallel as large matrix-matrix multiplications (compute-bound), whereas autoregressive decode processes 1 token per sequence per step (HBM bandwidth-bound).

BF16 & FP8 Precision Trade-offs

BF16 preserves FP32's 8-bit exponent range to prevent training gradient underflow, while FP8 cuts weight and KV-cache HBM traffic in half during inference.

Order platform / Breaking the HBM bandwidth wall in 70B decode

Breaking the HBM bandwidth wall in 70B decode.

A 70B FP16 model on 2x H100 GPUs showed only 8% Tensor Core compute utilization during decode despite 100% HBM bandwidth saturation.

Each decode step streamed ~140 GB of weights from HBM for a single token per request. Quantizing weights to FP8 (halving HBM bytes per token) and enabling continuous batching raised arithmetic intensity across concurrent sequences, boosting decode tokens/sec by 2.4x.

Lesson: Autoregressive LLM decode is gated by HBM memory bandwidth; increase batching or quantize weights to raise arithmetic intensity.

  • How much VRAM must be reserved for activation memory vs. model weights vs. KV-cache?
  • Does FP8 or INT4 AWQ quantization introduce unacceptable perplexity or tool-calling regression on your eval set?

Transformer Architecture & Attention Physics.

Scaled Dot-Product Attention computes Attention(Q, K, V) = softmax((Q K^T) / sqrt(d_k)) V, where scaling by sqrt(d_k) keeps dot-product variance near 1 so softmax gradients do not vanish. Materializing the N x N attention matrix in HBM scales quadratically in memory and bandwidth; FlashAttention tiles Q, K, and V blocks into fast on-chip GPU SRAM and computes softmax incrementally via online rescaling, keeping memory O(N). During autoregressive generation, caching past K and V tensors avoids recomputing the prefix, but KV-cache size (2 layers kv_heads d_head bytes_per_param * seq_len) quickly dominates VRAM. Grouped-Query Attention (GQA) shares K/V heads across groups of Q heads to shrink KV-cache traffic, RoPE encodes relative token positions via 2D rotations, and PagedAttention allocates KV-cache in fixed-size non-contiguous blocks to eliminate fragmentation.

FlashAttention Online Softmax Tiling

Fuse QK^T, masking, softmax, and V multiplication inside GPU SRAM tiles so the quadratic N x N score matrix is never written to slow HBM.

PagedAttention Virtual KV Blocks

Manage KV-cache like OS virtual memory pages so sequences grow dynamically without reserving contiguous max-context VRAM buffers.

Order platform / Eliminating 60% VRAM waste with PagedAttention and continuous batching

Eliminating 60% VRAM waste with PagedAttention and continuous batching.

A customer-support AI cluster on 8x A100 GPUs suffered OOM crashes during morning traffic spikes and dropped 14% of active sessions due to static max-length KV-cache pre-allocation.

Migrated serving to vLLM using PagedAttention and iteration-level continuous batching. KV-cache internal fragmentation dropped from ~60% to under 4%, quadrupling concurrent request capacity and cutting monthly GPU spend by 58%.

Lesson: KV-cache memory management—not raw FLOPs—determines concurrent LLM serving capacity.

  • What happens to tail latency when a long-prompt prefill shares the same GPU batch as active decode requests (chunked prefill vs. disaggregated prefill/decode)?
  • How does your streaming gateway detect client SSE disconnects and abort GPU decode iterations immediately?

The decision framework

01

Is a probabilistic model actually required, or will deterministic rules/SQL suffice?

Exact lookups, financial math, and strict state transitions should never rely on stochastic token generation.

02

Which retrieval failure mode dominates: semantic mismatch or exact-token miss?

Pair dense ANN with BM25 + RRF whenever queries contain IDs, SKUs, code symbols, or rare domain terms.

03

What is the RAM and recall budget for the vector index at 12-month scale?

Size M, quantization (int8/PQ), and oversampling ratios explicitly rather than defaulting to uncompressed FP32 HNSW.

04

Is inference gated by compute (prefill) or HBM bandwidth (decode)?

Optimize prefill with prefix caching and context pruning; optimize decode with FP8 quantization, GQA, and continuous batching.

05

How are hallucinations, prompt injections, and client disconnects bounded?

Enforce structured output schemas, grounding evals in CI, input/output guardrails, and immediate SSE cancellation.
