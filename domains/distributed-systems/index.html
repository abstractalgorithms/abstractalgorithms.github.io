TCP/IP & Linux Socket Networking Internals

TCP delivers an in-order, guaranteed byte stream across unreliable packet-switched IP networks. The Linux kernel manages this via send/receive socket buffers (SO_SNDBUF/SO_RCVBUF), sliding-window flow control to protect receivers from saturation, and congestion algorithms (CUBIC/BBR) to regulate transmission across shared bottlenecks.

Reverse Proxy Patterns & Edge Load Balancing

A reverse proxy acts as an intermediary gateway positioned between external clients and private backend services. It terminates client TLS handshakes, multiplexes requests across persistent upstream connection pools, distributes traffic via balancing algorithms (Round Robin, Least Connections, P2C), and guards internal services against direct internet exposure.

Step 1.3
~5m readintermediate

In-Memory Caching & Event Loop Architecture

Caching stores high-frequency read data in fast RAM instead of slow disk/network databases. Redis achieves sub-millisecond QPS by operating a single-threaded event loop paired with OS epoll I/O multiplexing, completely eliminating thread locking contention.

Explore Concept Journey→
Step 1.4
~6m readintermediate

CDN Architecture & Geo-Distributed Edge Caching

A Content Delivery Network (CDN) is a globally distributed network of Points of Presence (PoPs) that terminates client TCP/TLS connections physically close to users via BGP Anycast routing. By serving cached static assets and API responses from the network edge, CDNs reduce origin server load by 80-95% and drop round-trip times from hundreds of milliseconds to under 15ms.

Quorum Consistency & Raft Consensus

Distributed databases replicate data across N nodes for fault tolerance. Quorum math (Read Nodes + Write Nodes > Total Nodes) guarantees that any read operation overlaps with at least one node containing the latest write.
