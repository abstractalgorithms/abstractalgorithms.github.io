  • 12

    Apache Kafka

    5 chapters · L4→L7

    Treating Apache Kafka like a traditional in-memory message queue—with random key distribution, small unbatched sends, or unbounded consumer processing delays—triggers partition ordering bugs, broker CPU saturation, and stop-the-world consumer group rebalance storms. Mastering Kafka requires thinking in immutable append-only commit logs, OS page-cache zero-copy (`sendfile`), ISR quorum durability (`acks=all` + `min.insync.replicas=2`), and cooperative incremental rebalancing.

    ↗
  • 13

    Kubernetes

    5 chapters · L4→L71 concept

    Treating Kubernetes like a magic self-healing platform—while misconfiguring liveness probes, omitting `preStop` connection draining, setting `minAvailable: 100%` on PodDisruptionBudgets, or ignoring Linux CFS CPU throttling—causes rolling deployments to drop live traffic and freeze cluster upgrades. Production Kubernetes mastery means understanding the reconciliation loop (`API Server -> etcd -> Scheduler -> Kubelet`), decoupling readiness from liveness, right-sizing CPU/memory cgroups, and coordinating graceful pod termination.

    ↗
  • 14

    Large Language Models (LLM) Systems & Inference

    5 chapters · L4→L7

    Serving Large Language Models in production fails when treated like stateless CPU microservices: autoregressive decoding is strictly GPU HBM memory-bandwidth bound, unpaged KV caches waste 60–80% of VRAM via fragmentation, and static request batching stalls fast users behind 2,000-token generations. Engineering high-throughput LLM gateways requires separating compute-bound Prefill from memory-bound Decode, paging KV-cache blocks (PagedAttention), caching shared system prefixes via radix trees, and enforcing deterministic schema + prompt-injection guardrails.

    ↗
  • 15

    NoSQL Databases & Distributed Storage Engines

    5 chapters · L4→L72 concepts

    Adopting Cassandra, DynamoDB, or MongoDB while modeling tables like normalized SQL schemas creates hot-partition throttling, tombstone read timeouts, and brittle application-side joins. Engineering high-scale NoSQL systems requires query-driven partition-key modeling, bounded time-bucketed partitions, LSM-Tree compaction discipline, and tunable quorum consistency (`R + W > N`).
