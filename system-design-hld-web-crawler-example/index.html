Stage 2 — Presenting the Web Crawler HLD in a System Design Interview

  • Start every web crawler answer by drawing the core loop on the whiteboard: Frontier → Fetcher → Content Store → Link Extractor → Frontier.
  • This loop is the entire system.
  • Every other component — Bloom Filter, SimHash Engine, Robots.txt cache, DNS cache — is a correctness or performance guard on one of the loop's stages.

Stage 3 — What Building a Web Crawler Teaches About Adversarial Distributed Systems

  • A web crawler is a distributed system that must cooperate with millions of external systems — the web's servers — over which it has zero control.
  • This forces architectural decisions that most internal distributed systems never encounter: adversarial environments, unpredictable response times, resource-constrained counterparties, and legal constraints from robots.…
  • Every design choice in a web crawler is a negotiation between the crawler's appetite for throughput and the web's need for stability.
  • The politeness constraint is not merely an ethical guideline — it is a self-preservation mechanism.
