Little's Law: The Secret Formula for System Performance

Scenario context

Little's Law ($L = \lambda W$) connects three metrics every system designer measures: $L$ = concurrent requests in flight, $\lambda$ = throughput (RPS), $W$ = average response time. If latency spikes, your concurrency requirement explodes with it.

This walkthrough focuses on **The Coffee Shop Queue Formula**.

Before making a design choice, clarify:

- You count: $L$ (Length of queue): How many people are inside the shop right now — ordering + waiting.
- $\\lambda$ (Arrival rate): Customers entering per minute (e.g., 2/min).
- $W$ (Wait time): How long a customer stays, entry to exit (e.g., 5 min).

Stage 5 — Deep Dive: Sizing for Real Systems with Little's Law

  • Sizing a Thread Pool Use P99 latency (99th percentile), not average.
  • Tail latencies dominate under load.
  • Example — 500 RPS, P99 = 800ms, safety\ factor = 1.5: L=500×0.8×1.5=600 threads Sizing a Database Connection Pool The same law applies.
  • A PostgreSQL server with 100 max connections is not "100 requests per second" — it's 100 concurrent transactions in flight.
