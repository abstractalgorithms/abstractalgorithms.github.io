Monotonic Stack Pattern: Efficiently Solving Range Queries and Next Greater Element Problems

TLDR: A Monotonic Stack is a specialized data structure that maintains its elements in a strictly increasing or decreasing order. By processing elements and popping those that violate the monotonic property, it solves range query and next-greater-element problems in amortized $O(N)$ time instead of the naive $O(N^2)$ brute-force search.

The Intuition behind Monotonic Stacks

To understand the core mechanics of a monotonic stack, imagine a line of people waiting to buy tickets at a theater. Each person in line can see the screen unless someone taller stands in front of them. If a very tall person enters the line, they block the view of everyone shorter standing behind them.

In computer science, this visual blocking behavior represents the Next Greater Element problem. For any element in an array, we want to find the first element to its right (or left) that is larger than it.

The brute-force solution is to use nested loops: for each element, scan the rest of the array until you find a larger value. This approach runs in $O(N^2)$ time. A Monotonic Stack solves this by storing indices or values in a sorted (monotonic) order, allowing us to find the next greater or smaller element in a single pass.

Monotonic Decreasing Stack: Elements are ordered from largest to smallest.
[ 10, 8, 5, 2 ]  <-- Top of Stack is 2

If 7 arrives:
1. Pop 2 (7 > 2)
2. Pop 5 (7 > 5)
3. Push 7 (7 < 8)
Resulting Stack: [ 10, 8, 7 ]

Mechanics: Maintaining the Monotonic Property

A monotonic stack is simply a standard stack with an insertion invariant:

  • Monotonic Increasing Stack: Elements are sorted from bottom to top in increasing order. When inserting a new element $X$, we must pop all elements larger than $X$ from the top of the stack before pushing $X$.
  • Monotonic Decreasing Stack: Elements are sorted from bottom to top in decreasing order. When inserting $X$, we must pop all elements smaller than $X$ before pushing $X$.

Each pop event represents a resolution. When we pop an element $Y$ because of a new arriving element $X$, it means $X$ is the "next greater/smaller" element for $Y$. This structural property is what allows us to resolve queries for all elements in a single linear scan.

Problem 1: Next Greater Element

Problem Statement

Given an array of integers, return a new array where the $i$-th element is the first element to the right of the input array that is strictly greater than the input element. If no greater element exists, return -1.

Java Implementation

package com.abstractalgorithms.dsa.stack;

import java.util.Arrays;
import java.util.Stack;

public class NextGreaterElementSolver {

    public int[] solveNextGreaterElement(int[] nums) {
        if (nums == null) {
            return new int[0];
        }

        int n = nums.length;
        int[] result = new int[n];
        Arrays.fill(result, -1);

        // Stack stores indices of elements
        Stack<Integer> indexStack = new Stack<>();

        for (int i = 0; i < n; i++) {
            // Maintain monotonic decreasing property
            // If current element is larger, we found the next greater element for the index at top of stack
            while (!indexStack.isEmpty() && nums[i] > nums[indexStack.peek()]) {
                int resolvedIndex = indexStack.pop();
                result[resolvedIndex] = nums[i];
            }
            indexStack.push(i);
        }

        return result;
    }
}

Dry-Run Walkthrough

Let us dry-run the input array [2, 1, 2, 4, 3]:

  1. $i = 0$ (Value: 2): Stack is empty. Push index 0. Stack: [0] (value 2).
  2. $i = 1$ (Value: 1): nums[1] (1) < nums[0] (2). Push index 1. Stack: [0, 1] (values 2, 1).
  3. $i = 2$ (Value: 2): nums[2] (2) > nums[1] (1). Pop index 1. Set result[1] = 2.
    Next check: nums[2] (2) > nums[0] (2) is false. Push index 2. Stack: [0, 2] (values 2, 2).
  4. $i = 3$ (Value: 4): nums[3] (4) > nums[2] (2). Pop index 2. Set result[2] = 4.
    Next check: nums[3] (4) > nums[0] (2). Pop index 0. Set result[0] = 4.
    Stack is empty. Push index 3. Stack: [3] (value 4).
  5. $i = 4$ (Value: 3): nums[4] (3) < nums[3] (4). Push index 4. Stack: [3, 4] (values 4, 3).
  6. End of Loop: Remaining indices in stack default to -1. Final Result: [4, 2, 4, -1, -1].

Problem 2: Daily Temperatures

Problem Statement

Given an array of integers temperatures representing the daily temperatures, return an array answer such that answer[i] is the number of days you have to wait after the $i$-th day to get a warmer temperature. If there is no future day for which this is possible, keep answer[i] == 0 instead.

Java Implementation

package com.abstractalgorithms.dsa.stack;

import java.util.Stack;

public class DailyTemperaturesSolver {

    public int[] dailyTemperatures(int[] temperatures) {
        if (temperatures == null || temperatures.length == 0) {
            return new int[0];
        }

        int n = temperatures.length;
        int[] answer = new int[n];

        // Stack stores indices of temperatures
        Stack<Integer> stack = new Stack<>();

        for (int i = 0; i < n; i++) {
            int currentTemp = temperatures[i];

            // If current temperature is warmer than the temperature at the index on top of stack
            while (!stack.isEmpty() && currentTemp > temperatures[stack.peek()]) {
                int prevIndex = stack.pop();
                answer[prevIndex] = i - prevIndex; // Calculate wait days
            }
            stack.push(i);
        }

        return answer;
    }
}

Algorithmic Execution Flow

Each step in this algorithm is a constant-time check unless we pop elements. For an input [73, 74, 75, 71, 69, 72, 76, 73]:

  • Index 0 (73): Push 0. Stack: [0]
  • Index 1 (74): 74 > 73. Pop 0. answer[0] = 1 - 0 = 1. Push 1. Stack: [1]
  • Index 2 (75): 75 > 74. Pop 1. answer[1] = 2 - 1 = 1. Push 2. Stack: [2]
  • Index 3 (71): Push 3. Stack: [2, 3]
  • Index 4 (69): Push 4. Stack: [2, 3, 4]
  • Index 5 (72):
    • 72 > 69. Pop 4. answer[4] = 5 - 4 = 1.
    • 72 > 71. Pop 3. answer[3] = 5 - 3 = 2.
    • Push 5. Stack: [2, 5]
  • Index 6 (76):
    • Pop 5. answer[5] = 6 - 5 = 1.
    • Pop 2. answer[2] = 6 - 2 = 4.
    • Push 6. Stack: [6]
  • Index 7 (73): Push 7. Stack: [6, 7].
  • Final Result: [1, 1, 4, 2, 1, 1, 0, 0].

Problem 3: Largest Rectangle in Histogram

Problem Statement

Given an array of integers heights representing the histogram's bar height where the width of each bar is 1, find the area of the largest rectangle in the histogram.

Java Implementation

package com.abstractalgorithms.dsa.stack;

import java.util.Stack;

public class LargestRectangleHistogram {

    public int largestRectangleArea(int[] heights) {
        if (heights == null || heights.length == 0) {
            return 0;
        }

        int n = heights.length;
        int maxArea = 0;

        // Stack stores indices of heights to maintain monotonic increasing order
        Stack<Integer> stack = new Stack<>();

        for (int i = 0; i <= n; i++) {
            // Use a virtual bar of height 0 at index 'n' to flush the stack at the end
            int currentHeight = (i == n) ? 0 : heights[i];

            // If current height is smaller, we can no longer expand the rectangle at the top's height
            while (!stack.isEmpty() && currentHeight < heights[stack.peek()]) {
                int height = heights[stack.pop()];

                // Determine the width of the rectangle
                int width = stack.isEmpty() ? i : i - stack.peek() - 1;

                maxArea = Math.max(maxArea, height * width);
            }
            stack.push(i);
        }

        return maxArea;
    }
}

Explaining the Width Calculation

Why is the width calculated as i - stack.peek() - 1? When we pop an index, the rectangle's height is determined by heights[poppedIndex]. The boundaries of this rectangle are:

  • Right Boundary: The current index i (since the current height is strictly smaller, we cannot extend the rectangle to the right).
  • Left Boundary: The index on top of the stack after the pop operation (since the stack is monotonic increasing, the new top index is the first bar to the left that is strictly smaller than our height).
  • If the stack is empty, it means there are no smaller bars to the left; the rectangle can expand all the way to the beginning of the histogram (width = i).

🧠 Deep Dive: Amortized Complexity Analysis

At first glance, a monotonic stack implementation might look like an $O(N^2)$ algorithm because it contains a nested while loop inside a for loop. However, let us perform a rigorous Amortized Analysis using the Accounting Method.

Let each element in the array represent a coin:

  1. Push Operation: When we iterate to index i, we push it onto the stack. This operation costs $O(1)$.
  2. Pop Operation: During the execution of the while loop, we pop elements from the stack. Each pop costs $O(1)$.

The key observation is: any given element can be pushed onto the stack exactly once, and popped from the stack at most once.

If we have $N$ elements:

  • Total push operations across the entire execution = $N$.
  • Total pop operations across the entire execution $\le N$.

Therefore, the total number of operations performed by the nested loops is at most $2N$. The average (amortized) cost per element is:

$$\frac{\text{Total Cost}}{N} = \frac{O(2N)}{N} = O(1)$$

Thus, the overall time complexity is strictly $O(N)$ linear time, which is a significant optimization over the $O(N^2)$ brute-force approach.

Space Complexity

The space complexity is determined by the size of the stack. In the worst-case scenario (e.g., an input array sorted in strictly decreasing order for a monotonic increasing stack), the stack will grow to store all elements, resulting in a space complexity of $O(N)$.

⚖️ Trade-offs: Stack vs. Two Pointers

While the Monotonic Stack is highly efficient, you must balance it against alternative approaches:

  • Two Pointers: If you only need to compare adjacent elements or maintain a fixed-size range, a two-pointer sliding window is simpler and uses $O(1)$ auxiliary space. However, it cannot solve global "next greater" lookups where the target is arbitrarily far away.
  • Segment Trees / Fenwick Trees: Capable of handling dynamic array updates and range queries simultaneously. However, they run in $O(\log N)$ time and are significantly harder to implement.

🧭 Decision Guide: When to Use a Monotonic Stack

Use this matrix to identify if a problem should be solved with a Monotonic Stack:

  • Use a Monotonic Stack if:
    • You need to find the "first element larger than X" or "first element smaller than X" to the left or right of a index.
    • The array size is large (e.g., $N > 10^5$), requiring a linear time solution.
    • The array elements are static during the queries.
  • Do NOT use a Monotonic Stack if:
    • The array elements are modified dynamically between queries (use a Segment Tree instead).
    • You only need to query min/max values over fixed ranges (use a Sparse Table or Segment Tree).
