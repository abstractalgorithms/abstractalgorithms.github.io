Transactional Outbox vs. Change Data Capture: Choosing the Right Event Pipeline

TLDR: 🎯 Pick transactional outbox for guaranteed atomicity and minimal latency, or CDC for a lightweight, log‑driven approach when you can tolerate small gaps.

⚠️ Problem: “Lost Events” in Microservices

You’ve built a service that updates a user profile and must publish an UserUpdated event. If you write the event to the broker after the DB commit, a crash in between can leave the database updated but no event sent—breaking downstream consumers. You need a pattern that keeps the DB write and event publication transactionally consistent.

🔄 Solution: Transactional Outbox

With an outbox, the service writes both the domain record and a new row in an outbox table inside the same transaction. A separate “outbox worker” polls this table, serializes the payload, and pushes it to Kafka (or another broker). Because the DB commit guarantees both rows exist, the worker will never see a partially written state.

-- Inside a single transaction
INSERT INTO users (id, name) VALUES (:id, :name);
INSERT INTO outbox (id, aggregate_id, payload, created_at)
VALUES (uuid_generate_v4(), :id, jsonb_build_object('type','UserUpdated','id',:id), now());

The worker:

# pseudo‑worker
for event in outbox_table.fetch_unprocessed():
    broker.publish(event.payload)
    mark_as_sent(event.id)

⚡️ Trade‑offs

AspectOutboxCDC
AtomicityGuaranteed (same transaction)Not guaranteed (log may be written before commit)
LatencySlightly higher (extra DB write + worker loop)Lower (log is written immediately)
ComplexityRequires an outbox table + workerRequires log reader (Debezium, custom)
Fault ToleranceWorker can replay on restartLog gaps can cause missed events if not handled
InfrastructureOne DB + brokerOne DB + log reader + broker

📈 When to Use Which

  • Transactional Outbox: When exactly‑once delivery and strong consistency are non‑negotiable (e.g., financial transactions).
  • CDC: When you can tolerate occasional retries or gaps, or you already have a log‑driven architecture in place (e.g., micro‑services that read from a shared event store).

🧩 Architecture Kit Diagram

🎯 Bottom Line

Choose the outbox when you can’t afford a single lost event; lean on CDC when you need minimal latency and can handle eventual consistency. The right choice hinges on your service’s tolerance for gaps versus the cost of extra infrastructure.
