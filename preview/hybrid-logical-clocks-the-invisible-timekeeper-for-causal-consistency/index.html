Hybrid Logical Clocks: The Invisible Timekeeper for Causal Consistency

Stage 1 — The HLC Coordinate & Tuple Invariant

In a multi-region distributed key-value store, transactions execute on asynchronous nodes across the globe. When a client performs a write in Region 1 and subsequently reads from Region 2, the system must guarantee that the second operation observes the first—satisfying causal consistency.

Relying purely on physical time (NTP) is flawed: clocks drift by dozens of milliseconds, causing newer writes to be stamped with older physical timestamps and silently overwritten. Conversely, standard Vector Clocks grow with the number of participating nodes ($O(N)$), incurring unacceptable network bandwidth overhead as clusters scale.

The Hybrid Logical Clock Solution

A Hybrid Logical Clock solves this dilemma by coupling physical wall-clock time with an in-memory logical counter. Every timestamp is represented as a 128-bit coordinate:

$$\text{HLC} = \langle l, c \rangle$$

  • $l$ (Physical component): The highest physical millisecond epoch observed so far by the node or received from peers.
  • $c$ (Logical counter): A monotonically increasing integer used to tie-break events that occur within the same physical millisecond.

The core mathematical invariant of HLC guarantees:

  1. If event $e$ causally happens before $f$ ($e \to f$), then $\text{HLC}(e) < \text{HLC}(f)$.
  2. The physical component $l$ tracks physical time $pt$ within bounded drift: $|l.e - pt.e| \le \epsilon$.

Stage 2 — Local Event Tick & Message Receive Rules

An HLC node maintains state $\langle l, c \rangle$. Physical wall-clock time on node $j$ is denoted $pt_j$.

1. Local Event or Write Execution

When a client submits a local mutation, the node updates its clock using the following state transition:

$$\begin{aligned} l' &= \max(l, pt_j) \\ c' &= \begin{cases} c + 1 & \text{if } l' = l \\ 0 & \text{otherwise} \end{cases} \end{aligned}$$

If physical time has moved forward past our last recorded timestamp, we advance $l$ to the new physical time and reset the counter $c$ to $0$. If physical time has not advanced, we simply increment the logical counter $c$.

2. Remote Message or Replication Payload Reception

When receiving an incoming message containing remote timestamp $\langle l_m, c_m \rangle$, the node integrates the causal evidence:

$$\begin{aligned} l' &= \max(l, pt_j, l_m) \\ c' &= \begin{cases} c + 1 & \text{if } l' = l = l_m \\ c_m + 1 & \text{if } l' = l_m \\ c + 1 & \text{if } l' = l \\ 0 & \text{otherwise} \end{cases} \end{aligned}$$

Production Implementation (Go)

package hlc

import (
    "sync"
    "time"
)

// HLC represents a 128-bit Hybrid Logical Clock timestamp.
type HLC struct {
    Physical int64 // Unix epoch in milliseconds
    Counter  int64 // Monotonic tie-breaker counter
}

// Compare returns -1 if h < other, 1 if h > other, and 0 if equal.
func (h HLC) Compare(other HLC) int {
    if h.Physical != other.Physical {
        if h.Physical < other.Physical {
            return -1
        }
        return 1
    }
    if h.Counter < other.Counter {
        return -1
    } else if h.Counter > other.Counter {
        return 1
    }
    return 0
}

// Clock manages thread-safe monotonic HLC coordinate generation.
type Clock struct {
    mu       sync.Mutex
    latest   HLC
    maxDrift int64 // maximum allowed physical clock skew in ms (epsilon)
}

func NewClock(maxDriftMs int64) *Clock {
    now := time.Now().UnixMilli()
    return &Clock{
        latest:   HLC{Physical: now, Counter: 0},
        maxDrift: maxDriftMs,
    }
}

// Tick advances the clock for a local write event.
func (c *Clock) Tick() HLC {
    c.mu.Lock()
    defer c.mu.Unlock()

    now := time.Now().UnixMilli()
    if now > c.latest.Physical {
        c.latest.Physical = now
        c.latest.Counter = 0
    } else {
        c.latest.Counter++
    }
    return c.latest
}

// Update incorporates causal evidence from a received replication payload.
func (c *Clock) Update(remote HLC) HLC {
    c.mu.Lock()
    defer c.mu.Unlock()

    now := time.Now().UnixMilli()
    maxPhysical := now
    if c.latest.Physical > maxPhysical {
        maxPhysical = c.latest.Physical
    }
    if remote.Physical > maxPhysical {
        maxPhysical = remote.Physical
    }

    if maxPhysical == c.latest.Physical && maxPhysical == remote.Physical {
        maxCounter := c.latest.Counter
        if remote.Counter > maxCounter {
            maxCounter = remote.Counter
        }
        c.latest.Counter = maxCounter + 1
    } else if maxPhysical == c.latest.Physical {
        c.latest.Counter++
    } else if maxPhysical == remote.Physical {
        c.latest.Counter = remote.Counter + 1
    } else {
        c.latest.Counter = 0
    }

    c.latest.Physical = maxPhysical
    return c.latest
}

Stage 3 — Causal Merging & CRDT Integration

In a multi-master distributed KV store, writes can occur concurrently on multiple regional replicas. When an entity is updated across regions, the storage layer combines HLC timestamps with Conflict-Free Replicated Data Types (CRDTs) to guarantee eventual convergence.

Resolving Concurrent Writes (LWW-Register)

For Last-Write-Wins (LWW) registers, concurrent mutations are ordered deterministically by comparing their HLC timestamps:

  1. Higher Physical Time: If write $W_1$ has physical component $1729600000$ and $W_2$ has $1729600050$, $W_2$ wins.
  2. Equal Physical Time, Higher Counter: If both writes occurred within the same physical millisecond, the write with the higher logical counter $c$ wins.
  3. Identical Timestamp: If both physical time and logical counters match (two concurrent writes on distinct nodes during the same tick), the tie is broken deterministically by node identifier: $\text{NodeID}_A > \text{NodeID}_B$.

Causality Preservation Proof

Suppose transaction $T_1$ writes key $K$ on Node 1, and the client receives confirmation with timestamp $H_1$. The client then sends a request to Node 2 to update key $Y$. The client includes $H_1$ in the payload. Node 2 executes Update(H_1). By the HLC update rule, Node 2's new timestamp $H_2$ is guaranteed to satisfy:

$$H_2 > H_1$$

When a reader subsequently queries Node 2 and Node 1, any causal dependency $T_1 \to T_2$ is preserved because $H_1 < H_2$. The reader will never observe $T_2$ without being able to order it after $T_1$.
