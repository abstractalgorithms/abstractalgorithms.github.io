How It Works: The Internals of Database B+ Tree Indexes

Scenario context

Database indexes utilize B+ Trees to minimize slow disk I/O operations. By organizing data into balanced, wide node pages and linking leaf nodes sequentially, databases resolve queries in logarithmic time and support fast range scans.

Stage 4 — Deep Dive: Disk I/O Blocks and Node Fan-out

  • Understanding why B+ Trees outperform other trees (like Red-Black trees or AVL trees) on disk requires analyzing how hardware reads data.
  • The Internals of Page Allocations and Row Offsets Operating systems and storage controllers read and write data in fixed-size blocks (typically 4 KB).
  • Databases group these blocks into pages (e.g., 16 KB pages in MySQL InnoDB).
  • When the database reads a single byte from a row, the storage controller must transfer the entire 16 KB page block from disk to the RAM buffer pool.
