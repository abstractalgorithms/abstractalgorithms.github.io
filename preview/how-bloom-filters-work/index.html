How Bloom Filters Work: The Probabilistic Set

Scenario context

Imagine a nightclub with a strict guestlist. The bouncer has a system with ten switches (0 or 1). When Alice registers, her name is hashed by three different functions: switch 2, 5, and 8 are turned ON. When Bob registers, switch 1, 5, and 9 are turned ON.

At the door: "Is Charlie here?"

  • Hash Charlie → switches 2, 7, 4.
  • Switch 7 is OFF. Definitely not registered. (No false negative.)

Stage 1 — Bit Arrays, Hash Functions, and the Two Operations

  • A Bloom filter has just two parts and two operations — that's the whole structure.
  • The two parts: - A bit array of size m , initialized to all zeros.
    • k independent hash functions , each of which maps any element to one position in the array.
  • The two operations: Insert(x): Run x through all k hash functions.

Stage 3 — False Positives Are Guaranteed; False Negatives Are Not

  • Why can you never have a false negative?
  • When you insert an element, you set specific bits.
  • When you query the same element, you check the exact same bits.
  • Those bits can only be 1 (we set them).

Database Indexing: B-Trees vs LSM-Trees

↗

Database indexes turn linear O(N) table scans into logarithmic O(log N) lookups. B-Trees optimize point & range reads; LSM-Trees turn random writes into sequential disk writes.
