The Event Sourcing Pattern: Rebuilding State from Scratch in Distributed Systems

How to design systems that treat state as a derivative of immutable events—not the source of truth

Event sourcing inverts the traditional data model: instead of persisting the current state of an entity, you store an append-only log of every state-changing event. The state itself is rebuilt on demand by replaying those events. This shift unlocks temporal queries, audit trails, and deterministic replays without sacrificing performance or consistency.

Core mental model

ConceptTraditional CRUDEvent Sourced
Source of truthCurrent row in a tableImmutable event log
State derivationDirect readFold over events
MutationsOverwrite existing rowAppend new event
Temporal queriesRequires history tables or CDCNative replay
Audit trailSeparate log tableBuilt into the event stream

Event stream anatomy

An event is a past-tense fact: OrderPlaced, PaymentAuthorized, ShipmentDispatched. Each event carries a timestamp, a unique identifier, and the minimal payload needed to describe what happened. Events are never updated or deleted; corrections are published as new compensating events.

State reconstruction pipeline

  1. Load all events for an aggregate root (e.g., Order-123) from the event store.
  2. Instantiate an empty aggregate instance.
  3. Apply each event in chronological order by invoking the corresponding apply method on the aggregate.
  4. Return the fully hydrated state.

This pipeline is idempotent and deterministic: replaying the same events always yields the same state.

Java domain model

public interface Event {
    UUID eventId();
    Instant occurredOn();
}

public record OrderPlaced(UUID eventId, Instant occurredOn,
                          UUID orderId, List<OrderLine> lines) implements Event {}

public record OrderLine(UUID productId, int quantity, BigDecimal unitPrice) {}

public abstract class AggregateRoot {
    private final List<Event> uncommittedEvents = new ArrayList<>();

    protected void raise(Event event) {
        uncommittedEvents.add(event);
        apply(event);
    }

    protected abstract void apply(Event event);

    public List<Event> uncommittedEvents() {
        return List.copyOf(uncommittedEvents);
    }

    public void clearUncommittedEvents() {
        uncommittedEvents.clear();
    }
}

public class Order extends AggregateRoot {
    private UUID id;
    private OrderStatus status;
    private List<OrderLine> lines = new ArrayList<>();
    private BigDecimal total = BigDecimal.ZERO;

    public Order(UUID id) {
        this.id = id;
    }

    public void place(List<OrderLine> lines) {
        if (status != null) throw new IllegalStateException("Order already exists");
        raise(new OrderPlaced(UUID.randomUUID(), Instant.now(), id, lines));
    }

    @Override
    protected void apply(Event event) {
        if (event instanceof OrderPlaced placed) {
            status = OrderStatus.PLACED;
            lines.addAll(placed.lines());
            total = placed.lines().stream()
                    .map(line -> line.unitPrice().multiply(BigDecimal.valueOf(line.quantity())))
                    .reduce(BigDecimal.ZERO, BigDecimal::add);
        }
    }
}

public enum OrderStatus {
    PLACED, PAID, SHIPPED, CANCELLED
}

Event store contract

public interface EventStore {
    void append(UUID aggregateId, List<Event> events);
    List<Event> load(UUID aggregateId);
    List<Event> load(UUID aggregateId, Instant since);
}

A simple in-memory implementation:

@Service
public class InMemoryEventStore implements EventStore {
    private final Map<UUID, List<Event>> store = new ConcurrentHashMap<>();

    @Override
    public void append(UUID aggregateId, List<Event> events) {
        store.compute(aggregateId, (id, existing) -> {
            var list = existing != null ? new ArrayList<>(existing) : new ArrayList<>();
            list.addAll(events);
            return list;
        });
    }

    @Override
    public List<Event> load(UUID aggregateId) {
        return List.copyOf(store.getOrDefault(aggregateId, List.of()));
    }

    @Override
    public List<Event> load(UUID aggregateId, Instant since) {
        return load(aggregateId).stream()
                .filter(e -> !e.occurredOn().isBefore(since))
                .toList();
    }
}

Spring REST endpoint

@RestController
@RequestMapping("/orders")
public class OrderController {
    private final EventStore eventStore;

    public OrderController(EventStore eventStore) {
        this.eventStore = eventStore;
    }

    @PostMapping
    public ResponseEntity<UUID> placeOrder(@RequestBody PlaceOrderRequest request) {
        var order = new Order(UUID.randomUUID());
        order.place(request.lines());
        eventStore.append(order.id(), order.uncommittedEvents());
        order.clearUncommittedEvents();
        return ResponseEntity.ok(order.id());
    }

    @GetMapping("/{id}")
    public ResponseEntity<OrderView> getOrder(@PathVariable UUID id) {
        var events = eventStore.load(id);
        var order = new Order(id);
        events.forEach(order::apply);
        var view = new OrderView(order.id(), order.status(), order.lines(), order.total());
        return ResponseEntity.ok(view);
    }
}

public record PlaceOrderRequest(List<OrderLine> lines) {}
public record OrderView(UUID id, OrderStatus status, List<OrderLine> lines, BigDecimal total) {}

Event replay for temporal queries

To answer “What was the order total on 2024-03-15?”:

  1. Load all events for the order up to the query timestamp.
  2. Replay them into a fresh aggregate.
  3. Read the total field.

No additional history tables are required; the event log is the history.

Trade-offs

AdvantageDrawback
Full audit trail out of the boxEvent schema evolution challenges
Time-travel debuggingIncreased storage footprint
Deterministic state reconstructionEventual consistency model
Easy integration with CQRSLearning curve for developers

When to reach for event sourcing

  • Regulated domains (finance, healthcare) where auditability is non-negotiable.
  • Systems that need point-in-time recovery or “as-of” queries.
  • Collaborative editing, multiplayer games, or any scenario where you must reconcile concurrent edits.
  • Microservices that communicate via event streams and need to rebuild local state after a restart.

Event sourcing is not a silver bullet; it shines brightest when the cost of storing every event is outweighed by the value of perfect auditability and temporal flexibility.
