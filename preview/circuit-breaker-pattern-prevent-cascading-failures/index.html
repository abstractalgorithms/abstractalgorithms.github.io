Circuit Breaker Pattern: Prevent Cascading Failures in Service Calls

Scenario context

Circuit breakers protect callers from repeatedly hitting a failing dependency. They turn slow failure into fast failure, giving the rest of the system room to recover.

stateDiagram-v2
  [*] --> Closed
  Closed --> Open : failure rate exceeds threshold
  Open --> HalfOpen : wait interval elapses
  HalfOpen --> Closed : all probe calls succeed
  HalfOpen --> Open : any probe call fails
  note right of Closed
    Normal traffic flows
    Records outcomes in window
  end note
  note right of Open
    Fail fast or fallback
    No calls to dependency
  end note
  note right of HalfOpen
    Limited probe calls
    Test dependency recovery
  end note

Observable outcome: 📊 State Machine: CLOSED → OPEN → HALF OPEN This state diagram formalizes the three-state circuit breaker lifecycle as a finite state machine with precisely defined transition triggers.

resilience4j:
  circuitbreaker:
    instances:
      fraudService:
        slidingWindowType: COUNT_BASED
        slidingWindowSize: 50
        minimumNumberOfCalls: 20
        failureRateThreshold: 50
        slowCallRateThreshold: 60
        slowCallDurationThreshold: 500ms
        waitDurationInOpenState: 30s
        permittedNumberOfCallsInHalfOpenState: 5
        automaticTransitionFromOpenToHalfOpenEnabled: true

Circuit Breakers & Resilience Patterns

↗

Circuit Breakers monitor remote service call failure rates. If downstream failures exceed a threshold (e.g. 50%), the breaker trips to OPEN, instantly returning fallback responses instead of stalling threads.
