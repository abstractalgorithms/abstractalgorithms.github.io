System Design HLD Example: Ride-Sharing (Uber/Lyft)

Scenario context

A ride-sharing platform is a high-velocity geospatial matching engine. Drivers stream GPS coordinates every 5 seconds into a Redis Geospatial Index. When a rider requests a trip, the Matching Service executes a GEORADIUS query to find the closest available drivers. A distributed Trip State Machine ensures transactional consistency (no double-matching), while WebSockets provide the real-time "car on map…

This walkthrough focuses on 1. Use Cases & Requirements.

Before making a design choice, clarify:

  • Imagine it’s New Year's Eve in New York City.
  • At 12:05 AM, one million people open their ride-sharing apps simultaneously.
  • In the background, 50,000 drivers are moving through the city, sending GPS updates every few seconds.

Stage 3 — 4. Detailed Design: Location Ingestion & Geohashing

  • A traditional relational database with a B-tree index cannot execute two-dimensional range queries efficiently under heavy load.
  • To solve this, the Location Service leverages Geohashing .
  • The Mechanics of Geohashing Geohashing partitions the Earth's surface into a hierarchical grid of cells.
  • Each grid cell is represented by a unique base-32 string.

Database Indexing: B-Trees vs LSM-Trees

↗

Database indexes turn linear O(N) table scans into logarithmic O(log N) lookups. B-Trees optimize point & range reads; LSM-Trees turn random writes into sequential disk writes.

Stage 4 — 5. Detailed Design: Matching Engine & Distributed Locking

  • A core correctness invariant is that a driver must never be matched to two riders at the same time .
  • Double-booking is a catastrophic user experience failure.
  • Candidate Discovery: The Matching Service queries GEORADIUS to find available drivers within a 2km radius.
  • Lock Acquisition: For each candidate, the service attempts to acquire an atomic distributed lock in Redis: 3.

Stage 5 — 6. Detailed Design: WebSocket Gateway Fleet & Real-Time Updates

  • Pings from active drivers must be streamed live to the matched rider's map display to provide the expected real-time tracking experience.
  • Gateway Scalability At a scale of 1 million concurrent riders, maintaining WebSocket connection states on a single instance is impossible.
  • We scale this horizontally: Stateless Gateways: A fleet of WebSocket gateway nodes holds open TCP connections with client apps.
  • Redis Pub/Sub Backplane: When the Location Service receives a driver update, it publishes the coordinate packet to Redis Pub/Sub on channel trip:ws:${riderId} .
