Python's Tricky Default Arguments

TLDR: Python's default arguments are evaluated once when the function is defined, not on each call. If a default argument is a mutable object (like a list or dictionary 📝), all subsequent calls that don't override that argument will share the same mutable object, leading to surprising side effects and difficult-to-debug bugs 🐛.

Have you ever encountered a Python function where a default list or dictionary parameter seemed to retain changes from previous calls, even though you expected it to be fresh each time? This common "gotcha" can lead to subtle bugs where function calls unexpectedly modify shared state. Understanding this behavior is crucial for writing robust and predictable Python code, especially when dealing with data structures.

🧐 The Unexpected Behavior

Consider a function designed to add an item to a list, with an empty list as its default:

def add_to_list(item, my_list=[]):
    my_list.append(item)
    return my_list

print(add_to_list(1))
print(add_to_list(2))
print(add_to_list(3, ['a', 'b']))
print(add_to_list(4))

What would you expect the output of the last line to be? Many new Pythonistas expect [4], but the actual output reveals the shared state:

[1]
[1, 2]
['a', 'b', 3]
[1, 2, 4] # Wait, what?!

💡 Why It Happens

The core issue is that default arguments are evaluated only once when the function object is created (i.e., when the def statement is executed). For immutable types (numbers, strings, tuples, None), this isn't a problem because operations on them create new objects. However, for mutable types like lists, dictionaries, or sets, the same object instance is reused across all calls where the default is not explicitly overridden. Each time add_to_list() is called without providing my_list, it refers to the same list object created at function definition time.

🛠️ The Fix: Using None

The standard and recommended solution is to use None as the default value, and then check inside the function body to initialize a new mutable object if None was passed. This ensures a fresh mutable object is created for each call that relies on the default.

def add_to_list_fixed(item, my_list=None):
    if my_list is None:
        my_list = [] # A new list is created only if no list was provided
    my_list.append(item)
    return my_list

print(add_to_list_fixed(1))
print(add_to_list_fixed(2))
print(add_to_list_fixed(3, ['a', 'b']))
print(add_to_list_fixed(4))

Now, the output is as expected:

[1]
[2]
['a', 'b', 3]
[4]

⚖️ The Takeaway

Always be wary of using mutable objects (lists, dictionaries, sets, custom class instances) as default arguments in Python. The None idiom is your reliable pattern for ensuring that default mutable arguments behave as independent instances for each function call, preventing unexpected shared state and making your code more predictable and robust.
