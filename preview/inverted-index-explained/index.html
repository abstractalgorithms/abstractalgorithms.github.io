Stage 2 — Terms, Documents, and Posting Lists: The Three Building Blocks

  • Before seeing how an inverted index is built, it helps to understand what it stores.
  • Three concepts are central to every inverted index: - Term — a single searchable token: a stemmed, lowercased word after stop-word removal (e.g., "running" → "run" ).
    • Document — any unit of content that can be retrieved: a webpage, a product description, a log line, a database row.
    • Posting List — the sorted list of document IDs that contain a given term, optionally extended with term position and frequency.

Stage 3 — How an Inverted Index Is Built

  • Given three documents: Step 1 — Tokenize: Split into tokens.
  • Apply stemming ("fruits" → "fruit") and stop word removal ("is", "are", "and" removed).
  • Step 2 — Build posting lists: Each posting list entry also stores the position of the word in the document (for phrase queries) and the frequency (for TF-IDF ranking).
  • Step 3 — Sort posting lists by document ID.

Stage 4 — Executing a Query: AND, OR, and Phrase

  • AND Query: "Apple AND Banana" Intersect the two posting lists: Since both lists are sorted, a simple two-pointer merge achieves O(m + n) intersection — no nested loops.
  • OR Query: "Apple OR Banana" Union: [1, 2, 3] — all documents containing either word.
  • Phrase Query: "Apple Banana" (adjacent) Use position data: find documents in both lists where apple's position + 1 = banana's position.

Stage 5 — Deep Dive: Skip Pointers and Scoring

  • When posting lists are large (millions of documents), pointer-by-pointer traversal is slow.
  • Skip pointers index every $\sqrt{n}$ entries in the list, allowing jumps: If apple[i]=3 and banana[j]=22 , the skip pointer can jump directly to the first entry ≥ 22 in the apple list without touching 7, 11, 15.

Stage 6 — From Raw Document to Search Results

  • The indexing and querying pipelines are entirely separated — a query never re-reads raw documents.
  • The pipeline has two distinct halves: indexing (write time, left side) and querying (read time, right side).
  • At indexing time: raw text enters the analyzer pipeline.
  • The tokenizer splits on whitespace and punctuation.
