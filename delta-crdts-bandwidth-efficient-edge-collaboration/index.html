This walkthrough focuses on The Gotcha.

Before making a design choice, clarify:

  • Edge devices (smartphones, IoT sensors, remote terminals) often have intermittent connectivity and limited uplink bandwidth.
  • When a CRDT (Conflict‑Free Replicated Data Type) is used naively, every update pushes the entire data structure to peers.
  • In a 10‑kB counter that grows to 1 MB after a week of edits, this becomes a nightmare: high latency, battery drain, and data caps.

Concepts in play: consistency-replication, jvm-internals-and-garbage-collection

Stage 1 — The Solution – Delta CRDTs

  • Delta CRDTs store only the change (delta) that occurred, not the whole state.
  • Each operation produces a small delta object that is merged into the local state and propagated to peers.
  • When a peer receives a delta, it merges it into its state and can optionally send back a compressed acknowledgment.
  • Because deltas are usually a few bytes, bandwidth usage drops dramatically, and the time to apply changes remains low.

type Delta = { id: string; inc: number };
type GCounter = Map<string, number>;

function deltaInc(counter: GCounter, nodeId: string, n: number): Delta {
  const current = counter.get(nodeId) ?? 0;
  counter.set(nodeId, current + n);
  return { id: nodeId, inc: n }; // delta to send
}

function mergeDelta(counter: GCounter, delta: Delta): void {
  const current = counter.get(delta.id) ?? 0;
  counter.set(delta.id, current + delta.inc); // idempotent merge
}

Observable outcome: The full state can be reconstructed by summing all values in the map.
