TLDR: Trees are hierarchical data structures used everywhere — file systems, HTML DOM, databases, and search algorithms. Understanding Binary Trees, BSTs, and Heaps gives you efficient $O(\log N)$ search, insertion, and deletion — and helps you ace a large class of interview problems.

Both collections solve the core problem from this post: they handle the self-balancing and heap-property maintenance for you, so you get the correctness guarantees without implementing rotations or heapify logic manually.

import java.util.*;

public class TreeAndHeapDemo {
    public static void main(String[] args) {

        // ── TreeMap: Red-Black tree BST ────────────────────────────────────────
        // Insert in sorted order — TreeMap stays balanced (O(log n) per op)
        TreeMap<Integer, String> bst = new TreeMap<>();
        for (int v : new int[]{5, 3, 7, 1, 4, 6, 8}) {
            bst.put(v, "node-" + v);
        }

        // In-order traversal via entrySet() → always sorted ascending
        System.out.println("In-order: " + bst.keySet());
        // → [1, 3, 4, 5, 6, 7, 8]   — BST ordering property guaranteed

        // O(log n) floor and ceiling queries
        System.out.println("Floor of 5:   " + bst.floorKey(5));    // → 5
        System.out.println("Ceiling of 5: " + bst.ceilingKey(5));  // → 5
        System.out.println("Floor of 2:   " + bst.floorKey(2));    // → 1
        System.out.println("Ceiling of 2: " + bst.ceilingKey(2));  // → 3

        // Range query: keys between 3 and 6 inclusive — O(log n + k)
        NavigableMap<Integer, String> range = bst.subMap(3, true, 6, true);
        System.out.println("Range [3,6]: " + range.keySet()); // → [3, 4, 5, 6]

        // ── PriorityQueue: min-heap (array-backed) ─────────────────────────────
        PriorityQueue<Integer> minHeap = new PriorityQueue<>();
        int[] values = {10, 4, 7, 1, 8};
        for (int v : values) minHeap.offer(v);   // O(log n) each

        System.out.println("\nMin peek (O(1)): " + minHeap.peek());   // → 1

        // Extract all in sorted order — equivalent to heap sort
        System.out.print("Extract order: ");
        while (!minHeap.isEmpty()) {
            System.out.print(minHeap.poll() + " "); // O(log n) each
        }
        // → 1 4 7 8 10

        // Max-heap via reversed comparator
        PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder());
        for (int v : values) maxHeap.offer(v);
        System.out.println("\nMax peek (O(1)): " + maxHeap.peek());   // → 10

        // Top-3 elements from a stream using a bounded min-heap
        int k = 3;
        PriorityQueue<Integer> topK = new PriorityQueue<>(k); // min-heap of size k
        int[] stream = {5, 12, 3, 8, 19, 1, 7};
        for (int n : stream) {
            topK.offer(n);
            if (topK.size() > k) topK.poll(); // evict smallest
        }
        System.out.println("Top-" + k + " elements: " + topK);
        // → [8, 12, 19]  — largest 3 values retained
    }
}

TreeMap automatically rebalances via Red-Black rotations on every insert and delete — the O(log n) guarantee holds regardless of insertion order, unlike a plain BST. For a max-heap, pass Collections.reverseOrder() to the PriorityQueue constructor.
