Stage 3 — Key Mechanics: Caching, Fan-out, and Hot Users

  • Caching the feed Each user's feed is stored in Redis as a sorted set, where the tweet ID is the member and the tweet's creation timestamp is the score.
  • This structure makes inserting a new tweet O(log N) and retrieving the most recent top-N tweets equally fast — both well within the sub-10 ms latency budget of a production feed service.
  • The score-based ordering also enables cursor-based pagination naturally: slide the score window backward in time to fetch the next page without offset scanning.
  • Fan-out strategies Hot user problem: A celebrity with 50 M followers cannot push-fan-out on write without overloading the system.
