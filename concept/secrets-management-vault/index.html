01
STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What is Centralized Secrets Management (Vault).

Centralized secrets management separates who a workload is from what credentials it holds. HashiCorp Vault stores only AES-256-GCM ciphertext in its Integrated Storage (Raft); the root key sits in RAM behind a seal barrier unlocked by Cloud KMS Auto-Unseal or Shamir's Secret Sharing.

Workloads authenticate via platform identity (Kubernetes ServiceAccount JWT, AWS IAM, OIDC) and receive dynamic secrets (ephemeral 15m–1h Postgres roles or STS tokens) or use the Transit engine for encryption-as-a-service.

Dynamic Lease Flow

Kubernetes Workload Identity -> Dynamic 1h Postgres Role

Dynamic leases shrink credential blast radius from years to minutes without touching disk or env vars.

02
STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why Static `.env` & Env Vars Leak (and Audit Backpressure).

Hardcoded Git keys, base64-encoded Kubernetes Secrets, and container environment variables (/proc/<pid>/environ, crash dumps, accidental env logs) turn one container compromise into permanent lateral movement. Vault fixes this via tmpfs memory-backed mounts and MLOCK (no swap)—while enforcing dual audit sinks (e.g., syslog + file) because Vault halts all requests if its sole audit device fills disk.

Reload Connection Pools on Lease Rotation

When Vault Agent rotates /vault/secrets/db.env in tmpfs, the app must reload or re-open DB connections (e.g., via SIGHUP or inotify) before the old lease expires.

Revoke Dynamic Leases on `SIGTERM`

High-churn crash-looping pods can exhaust Postgres max_roles unless TTLs stay short (15m–1h) and leases revoke on shutdown.

STAGE 03 · WHERE IT IS USEDL5 · APPLIED DESIGN

Where Vault fits (and where ConfigMaps or PKCE belong).

Use Vault for dynamic DB/IAM/PKI credentials and regulated PII encryption; skip it for non-sensitive config or untrusted client apps.

ChoiceWhat it buysWhat it costs
Good Candidate: Dynamic DB/STS/PKI & PCI/HIPAA Audit LogsPer-pod ephemeral credentials, immutable audit trails, and centralized Transit key rotation.Operating a 3–5 node HA Raft cluster requires KMS auto-unseal, snapshots, and upgrade discipline.
Avoid: Public Config Flags (Feature Toggles, Log Levels)Keep non-sensitive settings in Kubernetes ConfigMaps or a config service.Routing public config through Vault adds unnecessary seal/quorum dependency.
Avoid: Browser / Mobile Client SecretsNever ship secrets to untrusted user devices—use OAuth2 PKCE and backend proxies.Any secret embedded in client binaries or JS is extractable.
04
STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

How Least-Privilege HCL Policies & Transit Encryption are managed.

Scope HCL policies strictly to secret/data/prod/<service>/* bound to exact Kubernetes namespace + ServiceAccount claims (never * wildcards), enable Cloud KMS Auto-Unseal, and revoke the initial root token after bootstrap.

# Least-privilege Vault HCL policy scoped to orders-api only
path "secret/data/prod/orders-api/*" {
  capabilities = ["read"]
}
path "database/creds/orders-readonly" {
  capabilities = ["read"]
}
path "transit/encrypt/pii-orders" {
  capabilities = ["update"]
}

STAGE 05 · ALTERNATIVESL6 · SCALE & TRADE-OFFS

Alternatives: Self-Hosted HA Vault vs. Cloud Secrets Manager vs. Static K8s Secrets.

Trade multi-cloud dynamic credential power against managed simplicity.

ChoiceWhat it buysWhat it costs
HashiCorp Vault (3–5 Node Raft + KMS Auto-Unseal)Dynamic DB roles, SSH/PKI, and Transit encryption-as-a-service across AWS, GCP, and on-prem.Team owns Raft quorum upgrades, snapshots, and dual audit-sink reliability.
Cloud-Native Secrets Manager (AWS / GCP)Zero control-plane operations; integrates natively with IAM roles.Vendor lock-in and fewer dynamic protocol engines (SSH/PKI/Transit) out of the box.
Static Env Vars / Unencrypted K8s SecretsZero setup for tiny local prototypes.Exposed in `/proc`, core dumps, and etcd unless KMS-encrypted; manual rotation only.

STAGE 06 · PRODUCTION ARCHITECTUREL7 · STAFF / PRINCIPAL

Production example: 3-AZ Raft Vault Cluster + CSI tmpfs Injection.

A 5-node Vault Raft cluster spans 3 AZs with Cloud KMS Auto-Unseal and dual audit sinks (syslog + local rotated file). Pods stay Vault-agnostic via the Secrets Store CSI Driver mounting dynamic credentials into RAM-backed /vault/secrets tmpfs.

3-AZ HA Raft Vault

5-Node Integrated Storage (Raft) Vault + Cloud KMS Auto-Unseal

1.1. KMS Auto-Unseal: Survives node reboots without manual Shamir key entry during scale-out.

2.2. Dual Audit Sinks: Syslog + local file ensures one full disk never halts Vault authentication.

3.3. tmpfs Mount: Secrets never touch worker node disks or container environment variables.

HA Raft + KMS Auto-Unseal + tmpfs injection eliminates both secret leakage and cluster seal outages.
