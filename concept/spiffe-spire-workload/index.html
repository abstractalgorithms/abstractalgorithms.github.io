SPIFFE & SPIRE
Cryptographic Workload Identity.

SPIFFE defines a universal URI-based workload identity standard, while SPIRE attests running processes via kernel and cloud metadata to issue short-lived X.509/JWT SVIDs over a local Unix Domain Socket.

The idea to keep with you

If a pod needs an API key or Vault token to fetch its TLS certificate, how does it authenticate to get that first, eliminate secret-zero and static API keys by letting a local SPIRE Agent attest processes and rotate 1-hour X.509 SVIDs automatically in memory.

TL;DR30-second simplified summary
▾

SPIFFE defines URI-based workload identities encoded in X.509 or JWT SVIDs, while SPIRE implements two-tier Node and Workload Attestation (cloud IID + kernel SO_PEERCRED/cgroup) to stream 1-hour SVIDs over a Unix Domain Socket. Workloads rotate certs at 50% TTL and enforce exact SAN URI authorization.
