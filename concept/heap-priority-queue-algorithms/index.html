Heaps & Priority Queues

Maintain dynamic min/max order with O(log n) inserts and O(1) peek for top-K, scheduling, and graph algorithms.

Orientation & Intuition

A binary heap stores elements in a complete tree where each parent is smaller (min-heap) or larger (max-heap) than its children, enabling efficient priority queue operations.

Key takeaway Use a heap when you need repeated access to the current best element—top-K, Dijkstra, or task scheduling—not when you need full sorted order.

Core Architecture & Trade-offs

Many interview and production problems reduce to “always know the next best item” without sorting the entire collection on every step.

Key Architecture Invariants

  • Heapify builds a heap in O(n)
  • Push/pop are O(log n)
  • Priority queue API maps cleanly to min/max heaps

When to Use

  • Top-K frequent elements
  • Dijkstra shortest path
  • Merge K sorted lists
  • Job schedulers and timers

When NOT to Use

  • Need fully sorted output of all elements upfront
  • Tiny fixed-size arrays where sort is simpler

Deep Dive & Production Considerations

Heap mechanics

Heaps are typically stored in arrays with index arithmetic for parent/child navigation. Priority queues power Dijkstra, Huffman coding, and OS schedulers.
