THE BIG IDEA / Key takeaway · CONCEPT GUIDE

Choosing the right traversal order (row-major for cache hits, multi-source BFS for shortest grid distances, 2D prefix sums for O(1) submatrix queries) cuts latency by 10x–60x.

Explanation anchor
01 / The idea

Foundational mechanics & core principles

2D grids underpin image convolutions, pathfinding, dynamic programming tables, and dense linear algebra. Even when two algorithms share O(R · C) time complexity, striding against memory layout (column-major in C/Java/NumPy) or running repeated single-source BFS turns a 2 ms pass into a 120 ms cache-miss bottleneck.

  • Row-major traversal (for r: for c:) streams contiguous 64-byte cache lines with hardware prefetching, running 20x–60x faster than column-major traversal on large C/Java/NumPy arrays.
  • Multi-source BFS enqueues all starting cells at dist = 0 before popping, computing shortest distances from any source in a single O(R · C) pass instead of O(K · R · C).
  • 0-1 BFS (using a deque) solves grids with {0, 1} edge weights in O(R · C) time—faster than Dijkstra's O(R · C log(R · C)).
  • Diagonal traversals exploit constant r + c (anti-diagonals) and r - c (main diagonals) invariants; spiral traversals shrink four boundary pointers (top, bottom, left, right).
  • 2D Prefix Sums (P[r+1][c+1] = grid[r][c] + P[r][c+1] + P[r+1][c] - P[r][c]) answer any submatrix sum query in O(1) after O(R · C) preprocessing.

Good candidates

  • Grid shortest-path, flood-fill, and connected-component problems (4-directional or 8-directional BFS/DFS).
  • Multi-origin propagation (nearest exit, fire spread, distance to nearest 0) using simultaneous multi-source BFS.
  • Repeated rectangular region queries (sumRegion(r1, c1, r2, c2)) via 2D prefix sums or dense image/DP sweeps.

Think twice

  • Ultra-sparse graphs (e.g., 10,000 nodes with 20,000 edges) where an O(V²) adjacency matrix wastes 99% of memory and iteration time compared to an adjacency list.
  • Unbounded continuous coordinate spaces where quadtrees, R-trees, or spatial hashing avoid materializing huge empty grids.
  • Recursive DFS on grids larger than ~10,000 cells in languages without tail-call optimization (Python/Java), where stack overflow is guaranteed.

02 / Concrete walkthrough

Architectural mechanics & implementation

ScenarioA Python/C++ service transposes and convolves 4096×4096 float64 satellite tiles (128 MB each, exceeding L3 cache).

The idea

Matrix traversal is the art of choosing a visitation schedule over a 2D coordinate space (r, c) that matches both the algorithm's dependency order and the CPU's memory layout.

In row-major languages (C, C++, Java, Python/NumPy, Rust), element (r, c) sits immediately adjacent to (r, c + 1). A linear row sweep loads 8 int64 values per 64-byte cache line (~0.4 ns/element), whereas jumping down columns triggers L1/L2/L3 cache misses (~12–25 ns/element). Beyond hardware locality, specialized schedules—multi-source BFS, 0-1 BFS, diagonal (r ± c) sweeps, spiral boundary peeling, and 2D prefix sums—collapse multi-pass work into single O(R · C) passes.

Concrete walkthrough

Walk through Multi-Source BFS to compute each cell's distance to the nearest gate (0) around walls (-1) in an R × C grid:

  1. Seed Phase: Scan the grid once in row-major order. Push every gate (r, c) with grid[r][c] == 0 into a deque (already marked at distance 0).
  2. Wavefront Expansion: Pop (r, c) from the front of the deque. For each of the 4 neighbors (nr, nc) via dirs = [(0,1),(1,0),(0,-1),(-1,0)], verify bounds 0 <= nr < R and 0 <= nc < C.
  3. Mark-on-Push Invariant: If grid[nr][nc] == INF (unvisited open room), immediately set grid[nr][nc] = grid[r][c] + 1 before pushing (nr, nc) to the back of the deque.
  4. Termination: Because all distance-d cells are processed before any distance-d+1 cell, the first time any cell is reached is guaranteed optimal in O(R · C) time and O(R · C) worst-case queue space.

Seeding all sources at t=0 and marking distances on push guarantees O(R·C) time without duplicate queue entries.

Cache locality, tiling & diagonal invariants

Three structural tricks separate naive grid loops from systems-grade implementations:

  • Loop Tiling (Blocking): For operations that read both rows and columns (matrix transpose, Floyd-Warshall, C = A × B), process B × B sub-blocks (e.g., B = 32 or 64 fitting inside 32 KB L1D cache) so both source and destination lines stay resident.
  • Diagonal Keys: Cells on the same top-left-to-bottom-right diagonal share r - c = const; cells on the same anti-diagonal share r + c = const. Grouping or indexing by r ± c turns diagonal scans into O(1) bucket lookups.
  • In-Place State Encoding: When values are bounded (e.g., 0 or 1 in Game of Life), pack next_state into bit 1 (val |= next << 1) during the pass and right-shift (val >>= 1) in a cleanup pass for O(1) extra space.

Failure modes

  1. Queue Blowup from Mark-on-Pop: In a diamond-shaped open grid, marking visited on pop lets each cell be pushed by up to 2–4 neighbors, causing O(2^(R+C)) queue growth. Mitigation: Mark visited at enqueue time.
  2. Python RecursionError / JVM StackOverflowError: Recursive DFS on a 1000×1000 grid hits depth 10^6. Mitigation: Always convert grid DFS to an explicit iterative stack.
  3. O(N) Queue Pop Overhead: Using ArrayList.remove(0) or Python list.pop(0) degrades BFS from O(R · C) to O((R · C)^2). Mitigation: Use collections.deque or java.util.ArrayDeque.
  4. Integer Overflow in 2D Prefix Sums: Summing int32 pixels across a 4096×4096 grid overflows signed 32-bit integers. Mitigation: Store prefix arrays in int64 / long.

0-1 BFS & A* heuristics on grids

When grid edges have non-uniform costs, avoid defaulting blindly to Dijkstra:

  • 0-1 BFS: If every step costs 0 (e.g., matching arrow direction) or 1 (changing direction), push 0-cost neighbors to the front of a deque and 1-cost neighbors to the back. This preserves sorted frontier order in O(R · C) without a log(R · C) heap.
  • A with Manhattan/Chebyshev Heuristic*: For single-source single-target routing on large open maps, adding admissible h(r, c) = |r - tr| + |c - tc| (4-dir) or max(|r - tr|, |c - tc|) (8-dir) prunes > 80% of off-target wavefront cells.

Practical checklist

  • Verify (r, c) bounds (0 <= r < R, 0 <= c < C) before indexing.
  • Iterate row-major (r outer, c inner) or use cache-tiled blocks for large matrices.
  • Use iterative deque / ArrayDeque for BFS/DFS on grids larger than 32×32.
  • Mark cells visited (or update distance) on push, never on pop.
  • Use int64/long for 2D prefix sums and test edge cases: 1×1, 1×N, N×1, and all-walls grids.
03 / Engineering trade-offs

Weighing architectural decisions

Iterative Queue/Stack vs. Recursive DFS

Advantage: Iterative BFS/DFS with an explicit `deque`/`ArrayDeque` never overflows the call stack on 1000×1000 grids.

Drawback: Requires slightly more boilerplate to manage explicit state frames.

In-Place Marking vs. Separate `visited` Matrix

Advantage: Mutating the grid (e.g., `grid[r][c] = -1` or bitmasking) saves `O(R · C)` auxiliary memory.

Drawback: Destroys input data for concurrent readers unless restored or bit-masked carefully.

2D Prefix Sum Preprocessing vs. Direct Scan

Advantage: Reduces each rectangular sum query from `O(R · C)` to `O(1)`.

Drawback: Static only: each cell update forces `O(R · C)` rebuild unless upgraded to a 2D Fenwick Tree (`O(log R · log C)`).

04 / Failure modes & resilience

Explain where it breaks · Known failure modes

Call-Stack Overflow in Recursive DFS

A snake-like path on a 500×500 grid reaches recursion depth 250,000, crashing Python (`RecursionError` at 1,000) or Java (`StackOverflowError`).

What helps: Use an explicit iterative stack/deque for DFS or BFS on any grid larger than 32×32.

Late Visited Marking (BFS Memory Explosion)

Marking `visited[nr][nc] = true` when *popping* from the BFS queue instead of when *pushing* causes the same cell to be enqueued multiple times, blowing up memory exponentially.

What helps: Always mark cells as visited immediately before `queue.append((nr, nc))`.

Column-Major Cache Thrashing

Iterating `for c in cols: for r in rows:` on a 4096×4096 `int64` matrix jumps 32 KB per step, causing a cache miss on almost every read.

What helps: Traverse row-major (`for r: for c:`) or use cache-oblivious/tiled 32×32 blocks for transposes and DP.

Boundary Off-by-One in Spiral / Diagonal Sweeps

Shrinking `top/bottom/left/right` bounds without re-checking `top <= bottom && left <= right` double-visits the center row/column of odd-dimension matrices.

What helps: Guard the reverse bottom/left loops with explicit `if top <= bottom` and `if left <= right` checks.

05 / Practical checklist

Avoid these mistakes

  • Mutating or checking `grid[r][c]` before validating `0 <= r < R and 0 <= c < C`.
  • Using `list.pop(0)` in Python for BFS (`O(N)` shift) instead of `collections.deque.popleft()` (`O(1)`).
  • Confusing `grid[row][col]` indexing with Cartesian `(x, y)` coordinates.
  • Using standard BFS on a weighted grid instead of 0-1 BFS (deque) or Dijkstra (min-heap).
  • Ignoring integer overflow in 2D prefix sums on large `int32` matrices (use `int64`/`long`).
