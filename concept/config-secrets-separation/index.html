01
STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What is Configuration vs. Secrets Separation.

Modern production security splits the Twelve-Factor environment into two distinct planes:

  • Configuration Plane: Non-sensitive behavior tuning (LOG_LEVEL, DB_HOST, HIKARI_MAX_POOL, STRIPE_TIMEOUT_MS, feature flags) that is safe to commit to Git and review in PRs.
  • Secrets Plane: Cryptographic material, DB passwords, and API keys (STRIPE_SK, JWT_PRIVATE_KEY) that grant identity or billing authority.

Base64 is encoding, not encryption: never commit Kubernetes Secret YAML or .env files to Git. Instead, use Workload Identity (IRSA / GCP WI / SPIFFE) to eliminate static secrets altogether, and Vault / External Secrets Operator (ESO) for any remaining credentials.

Two-Plane Injection

Git ConfigMap + KMS/Vault Dynamic Secret -> Pod tmpfs Mount

1.Zero Static Cloud Keys: Pods exchange short-lived OIDC/SPIFFE tokens for IAM roles—no AWS_ACCESS_KEY_ID needed.

2.Dynamic DB Leases: Vault mints per-pod PostgreSQL users with 1-hour TTL and automatic revocation.

3.In-Memory tmpfs: Mounting secrets as tmpfs files avoids leaking credentials in /proc/environ or crash dumps.

Separating Git-tracked config from runtime KMS/Vault injection eliminates credential sprawl.

02
STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why we need Runtime Secret Injection & Dynamic Rotation.

Mixing secrets into Git or static .env files causes irreversible leaks—even deleting a committed key in a follow-up commit leaves it in Git history forever.

Watch three operational failure modes:

  1. Startup-Only Secret Reads: Apps that read a secret file once in main() fail with 401 or 28P01 when rotated in-place; support file-watch reload or dual-key grace periods.
  2. CI/CD Exfiltration: Printing env in GitHub Actions or passing $TOKEN as a CLI flag exposes secrets in logs and ps aux.
  3. Unencrypted etcd: Kubernetes Secret objects are base64-encoded in etcd unless KMS envelope encryption is enabled.
Zero-Downtime Rotation

Dual-Key Grace Period & Dynamic Workload Identity Exchange

Overlapping lease grace periods let connection pools drain old credentials without dropping in-flight queries.

Pre-Commit & CI Secret Scanning

Run gitleaks or trufflehog on every PR to block AKIA... prefixes and BEGIN PRIVATE KEY headers before merge.

Admission Control Guard

Use Kyverno/OPA to reject pods using static env secrets where ESO or Workload Identity is mandated.

Where Different Secret Delivery Mechanisms fit.

Eliminate static secrets with Workload Identity first; use Vault/ESO for third-party API keys and dynamic DB leases.

ChoiceWhat it buysWhat it costs
Workload Identity (IRSA / GCP WI / SPIFFE)Zero static secrets to store or rotate; short-lived 15-60m OIDC/X.509 tokens.Only covers cloud/mesh identities, not external third-party SaaS API keys.

04
STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

How ExternalSecret Sync & File-Watched Reloading work.

Keep ConfigMaps in Git for non-sensitive settings, sync secrets via ExternalSecret, and reload rotated credentials without pod restarts.

# Separation: ConfigMap in Git + ExternalSecret pulling from AWS Secrets Manager
apiVersion: v1
kind: ConfigMap
metadata: { name: invoice-worker-config }
data:
  DB_HOST: "orders-rw.internal"
  HIKARI_MAX_POOL: "12"
  STRIPE_TIMEOUT_MS: "2000"
---
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata: { name: invoice-worker-secrets }
spec:
  refreshInterval: 15m
  secretStoreRef: { name: aws-secretsmanager, kind: ClusterSecretStore }
  target: { name: invoice-worker-runtime-secret }
  data:
    - secretKey: STRIPE_API_KEY
      remoteRef: { key: prod/invoice/stripe, property: api_key }
