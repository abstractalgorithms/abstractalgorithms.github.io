01
STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What is Property-Based Testing.

Traditional unit tests assert single points: assert sort([3, 1, 2]) == [1, 2, 3]. Property-based testing (pioneered by Haskell's QuickCheck and realized in Python's Hypothesis, Java's jqwik, and TypeScript's fast-check) asserts universal invariants across generated strategies.

Its killer feature is shrinking: when a 40-element random list fails an invariant, Hypothesis bisects and simplifies it down to the minimal counterexample (e.g., [0, -1]) and saves the seed in .hypothesis/examples for deterministic replay.

Generate-Fail-Shrink Loop

Property-Based Testing Generation & Shrinking Lifecycle

Shrinking turns chaotic 40-element random failures into crisp 2-line minimal bug reports.

02
STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why we need Property-Based Testing (Unknown Unknowns).

Example-based tests only check edge cases the author remembered to write, leaving parsers, financial ledgers, and state machines exposed to empty strings, Unicode surrogates, DST timezone gaps, NaN propagation, and rare interleavings. Five algebraic invariants catch these without duplicating implementation logic: Round-trip (decode(encode(x)) == x), Conservation (sum(splits) == total), Idempotence (f(f(x)) == f(x)), Oracle Equivalence (fast impl == simple brute-force), and Stateful Model Equivalence.

Constructive Strategies Over `.filter()`

Chaining .filter(lambda x: x > 100 and is_prime(x)) causes Unsatisfiable discard failures—build valid inputs constructively instead.

Never Put Live DB/Network I/O Inside `@given`

Running 200 examples against a live database turns a 200 ms suite into 30+ seconds; test pure domain logic and in-memory fakes.

03
STAGE 03 · WHERE IT IS USEDL5 · APPLIED DESIGN

Where Property-Based Testing shines (and where to skip).

Target parsers, financial allocators, and stateful caches; skip UI layout and live SaaS integrations.

ChoiceWhat it buysWhat it costs
Good Candidate: Codecs, Ledgers & Stateful State MachinesUncovers Unicode, overflow, and multi-step `insert -> evict -> delete` bugs automatically.Requires formulating non-tautological invariants rather than hardcoded outputs.
Avoid: UI Styling & Live SaaS End-to-End FlowsUse deterministic Playwright/contract tests for browser rendering and third-party APIs.Generating 500 random permutations over network I/O is slow and brittle.
Avoid: C/C++ Binary Memory FuzzingUse coverage-guided fuzzers (AFL++ / libFuzzer) for raw byte-level memory corruption.Black-box property generators lack coverage-guided branch feedback.
04
STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

How Hypothesis Strategies, Shrinking & Profiles are managed.

Register dev (max_examples=50) and ci (max_examples=250, derandomize=True) profiles, persist .hypothesis/examples in CI cache, and use integer minor units (cents) rather than floats for financial invariants.

from hypothesis import given, settings, strategies as st

@settings(max_examples=200)
@given(total=st.integers(min_value=1, max_value=10_000_00),
       weights=st.lists(st.integers(min_value=1, max_value=100), min_size=1, max_size=20))
def test_split_conserves_cents(total: int, weights: list[int]):
    shares = allocate_proportionally(total, weights)
    assert len(shares) == len(weights)
    assert sum(shares) == total  # Conservation invariant
    assert all(s >= 0 for s in shares)

STAGE 05 · ALTERNATIVESL6 · SCALE & TRADE-OFFS

Alternatives: Property-Based Testing vs. Example Tests vs. Coverage Fuzzers.

Combine all three at the appropriate layer of the testing pyramid.

ChoiceWhat it buysWhat it costs
Property-Based Testing (Hypothesis / jqwik / fast-check)Explores combinatorial edge cases and shrinks failures to minimal reproducers.Slightly slower than 3-case unit tests; needs invariant thinking.
Example-Based Unit TestsFast, explicit documentation of known business scenarios and regression cases.Blind to edge cases the author did not anticipate.
Coverage-Guided Fuzzing (AFL++ / Jazzer)Maximizes branch coverage on binary/network parsers.Requires long continuous fuzzing harnesses outside normal PR checks.

STAGE 06 · PRODUCTION ARCHITECTUREL7 · STAFF / PRINCIPAL

Production example: Stateful RuleBasedStateMachine Against Reference Model.

To verify a production LRU cache or billing ledger, a RuleBasedStateMachine runs randomized sequences of put, get, evict, and delete against both the real implementation and a trivial Python dict oracle—catching subtle eviction-order bugs in milliseconds.
