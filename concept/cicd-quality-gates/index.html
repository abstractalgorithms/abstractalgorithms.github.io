01
STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What are CI/CD Quality Gates.

CI/CD quality gates are automated, non-negotiable verification checkpoints placed along the path from git push to 100% production traffic. Instead of relying on manual QA sign-offs, gates encode engineering, security, and reliability standards into executable checks.

The core design principle is tiered latency matching (the Testing Trophy): fast deterministic checks (gitleaks, semgrep SAST, buf breaking, unit tests) fail bad PRs in <3 minutes; Pact contract tests, Testcontainers, Trivy CVE scans, and Cosign signing run in the merge queue (5–10m); and Canary SLO gates verify live p99 and 5xx in production.

Tiered Gate Funnel

PR Fast Gate (<3m) -> Merge Queue (5-10m) -> Policy Gate -> Canary SLO

1.Fast-Fail Feedback: Developers get deterministic unit/SAST feedback in <3 minutes without waiting on 30-minute E2E suites.

2.Policy-as-Code: OPA/Conftest and Kyverno block public S3 buckets, missing resource limits, and :latest tags.

3.SLSA Provenance: Keyless Cosign signatures bind the built digest to its exact CI workflow and commit SHA.

Tiered quality gates match check latency to pipeline stage so velocity and safety reinforce each other.

02
STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why we need Tiered Gates (and how flaky/slow gates fail).

Badly designed CI gates hurt both reliability and velocity:

  1. Flaky Test Erosion: A 5% flaky integration test trains developers to hit 'Re-run' blindly, masking real regressions.
  2. Slow-Gate Queue Jamming: Putting a 35-minute E2E suite as a blocking PR check creates a 10-PR backlog and forces teams to bundle risky giant diffs.
  3. Canary Blind Spots: Checking only HTTP 5xx in a canary gate misses silent latency regressions (p99 doubling) or business conversion drops.
Flake Quarantine Loop

CI Test Health & Quarantine State Machine

Auto-quarantining flaky tests preserves developer trust in blocking gates while tracking repair SLAs.

Track DORA Metrics

Target Change Failure Rate (CFR) < 5% and Stage 1 PR feedback < 5 minutes; feed escaped incidents back into new contract/canary checks.

Zero Unaudited Bypasses

Never allow silent --no-verify or admin merge overrides without an audited reason and post-merge tracking.

STAGE 03 · WHERE IT IS USEDL5 · APPLIED DESIGN

Where Quality Gates apply across the SDLC.

Place each check at the earliest stage where it can run fast and deterministically.

ChoiceWhat it buysWhat it costs
Pre-Commit / PR Fast Gate (1–3 min)Catches secrets (gitleaks), SAST (semgrep), Protobuf breaking changes (buf), and unit logic immediately.Cannot catch real Postgres/Kafka integration bugs or multi-service contract drift.
Merge Queue / Artifact Gate (5–10 min)Runs Testcontainers, Pact consumer contracts, Trivy CVE scans, and Cosign signing on serialized merges.Requires merge-queue batching/speculative checks under high commit volume.
Admission & Canary Runtime GatesKyverno blocks unsigned/:latest pods; Argo AnalysisTemplate aborts bad canaries on real golden signals.Requires Prometheus/SLO instrumentation and rollback automation.
04
STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

How GitHub Actions Gates & OPA/Conftest Policies are written.

Run fast PR checks in parallel, enforce policy-as-code on Terraform/Kubernetes manifests, and sign every promoted digest.

# Fast-to-slow GitHub Actions PR quality gate workflow
name: pr-quality-gates
on: [pull_request]
jobs:
  fast-static-and-unit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Secret & SAST Scan
        run: |
          gitleaks detect --no-git --redact
          semgrep --config p/owasp-top-ten --error
      - name: Policy-as-Code (Conftest / OPA)
        run: conftest test deploy/k8s/*.yaml -p policy/
      - name: Unit Tests & Diff Coverage
        run: pytest --cov=app --cov-fail-under=80

STAGE 05 · ALTERNATIVESL6 · SCALE & TRADE-OFFS

Alternatives: Blocking E2E Suites vs. Contract Testing + Canary Gates.

Replace brittle, slow end-to-end staging suites with fast consumer-driven contracts and production canary analysis.

ChoiceWhat it buysWhat it costs
Shared-Staging Blocking E2E SuiteTests full multi-service flows end-to-end.35+ minute runtime, environment flakiness, and merge-queue gridlock.
Pact Contract Tests + TestcontainersVerifies API schemas and real DB/Kafka behavior in <5 minutes per service independently.Requires teams to publish and version Pact contracts in a broker.
Canary SLO Analysis + Feature FlagsCatches real-world load, memory, and latency regressions safely on 1-5% traffic.Must have automated rollback and sufficient traffic sample size.

STAGE 06 · PRODUCTION ARCHITECTUREL7 · STAFF / PRINCIPAL

Production example: Merge Queue -> Signed OCI + Kyverno -> Canary SLO.

In a high-velocity platform, PRs clear fast static/unit gates in <3m, enter a speculative Merge Queue for Pact + Testcontainers + Trivy + Cosign signing, and deploy via Argo Rollouts gated by Kyverno admission and Prometheus golden signals.

Commit-to-Prod Pipeline

PR -> Merge Queue -> Cosign Attestation -> Kyverno -> Canary

Every stage enforces a clear contract without slowing down developer iteration.
