STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What is Spark Structured Streaming & Watermarking.

Spark Structured Streaming models unbounded streams as continuously appended tables. Event-time watermarks bound how long in-memory or RocksDB state is retained for late-arriving records, enabling fault-tolerant stateful aggregations and Kafka-to-Lakehouse pipelines.

Core Pillars:

  • Micro-Batch vs Continuous: Micro-batch gives exactly-once end-to-end guarantees and full stateful SQL; Continuous mode targets ~1ms latency for stateless map/filter.
  • Watermark Formula: Watermark = max(event_time_seen) - delayThreshold. Windows older than the watermark are finalized and evicted.
  • Stateful Timeout: mapGroupsWithState supports EventTimeTimeout (driven by watermark) and ProcessingTimeTimeout (driven by wall clock).
  • State Store Backends: HDFSBackedStateStoreProvider keeps state on JVM heap (fast, OOM risk); RocksDBStateStoreProvider spills state to local NVMe + changelog.
State & Checkpointing

Micro-Batch Offset WAL & RocksDB State Store

Write-ahead offset logs in the checkpoint directory paired with RocksDB state snapshots guarantee fault-tolerant exactly-once stateful streaming.

STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why we need Spark Structured Streaming & Watermarking (and what fails without it).

Mobile clients and IoT devices routinely deliver events minutes or hours late. Without watermarks, stateful streaming jobs accumulate infinite state until executors crash; with overly aggressive watermarks, valid late events are silently dropped.

Common Pitfalls:

  • Using update mode when writing to Parquet/Iceberg append-only sinks without proper merge/upsert.
  • Forgetting checkpointLocation on writeStream, losing Kafka offset tracking across restarts.

Production Failure Mode

Unbounded state OOM when withWatermark is omitted on a streaming aggregation or dropDuplicates.

Production Failure Mode

Watermark stalling when one Kafka partition receives no traffic (max event time advances only as fast as the slowest partition).

Where Spark Structured Streaming & Watermarking is used (and where to avoid it).

Spark Structured Streaming & Watermarking delivers the highest leverage at well-defined architectural boundaries. Use it for real-time sessionization, windowed metrics, and deduplication over Kafka event streams.
