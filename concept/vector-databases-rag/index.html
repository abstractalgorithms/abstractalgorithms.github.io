Vector Databases, HNSW Indexing & RAG Pipelines

Perform high-dimensional approximate nearest neighbor (ANN) similarity search for AI LLM context retrieval.

Orientation & Intuition

Vector databases index high-dimensional vector embeddings (e.g. 1536-dim vectors) produced by AI models, enabling sub-millisecond semantic search via Hierarchical Navigable Small World (HNSW) graph indexing.

Key takeaway Use HNSW graph indexing with Cosine Similarity or Dot Product metrics for fast RAG knowledge retrieval.

Core Architecture & Trade-offs

Traditional B-Trees and relational indexes cannot search unstructured high-dimensional embeddings. Vector databases bridge LLM context windows with enterprise data.

Key Architecture Invariants

  • Embeddings map text or media into dense numerical vectors in high-dimensional vector space.
  • HNSW constructs multi-layer navigable small world graphs to achieve logarithmic O(log N) search latency.
  • RAG combines vector similarity retrieval with generative LLM prompt context.

When to Use

  • Retrieval-Augmented Generation (RAG) for LLM chatbots.
  • Semantic document and code search.
  • Multimodal image/text similarity recommendations.

When NOT to Use

  • Exact string lookups or traditional SQL primary key relational queries.

Deep Dive & Production Considerations

📖 HNSW Graph Indexing & Retrieval-Augmented Generation (RAG)

Relational B-Trees cannot efficiently query high-dimensional embeddings (e.g. 1536-dimensional vectors from OpenAI or Cohere) because the Curse of Dimensionality forces table scans. Vector databases (Pinecone, Milvus, Qdrant, pgvector) rely on Approximate Nearest Neighbor (ANN) indexing—most prominently Hierarchical Navigable Small World (HNSW) graphs.

🕸️ How HNSW Multilayer Graphs Work

HNSW extends probabilistic skip-lists into multidimensional graph spaces:

  1. Top Layers (Sparse Highway):
    • Only a fraction of vectors are promoted to upper layers ($l > 0$).
    • Traversal begins at the top entry point, executing rapid, long-distance hops across clusters to quickly home in on the query region.
  2. Bottom Layer (Layer 0 - Dense Network):
    • Contains 100% of the vector population connected by local Delaunay-approximated edges.
    • Executes greedy beam search to return the true Top-$K$ nearest neighbors based on Cosine Similarity or Dot Product.

⚖️ Vector Indexing Strategies: HNSW vs IVF-PQ

Index TypeSearch LatencyRAM ConsumptionRecall AccuracyBest Workload
HNSWUltra-fast (< 5ms)High (must hold vectors + graph pointers in RAM)> 98% recallReal-time chat assistants, latency-critical RAG
IVF-PQMedium (10–25ms)Low (compresses vectors into 8-bit quantization codes)~85–92% recallBillions of embeddings, cost-constrained search

🔍 Single-Stage Hybrid Search & Pre-Filtering

In enterprise RAG, vector distance alone is insufficient—queries must be constrained by metadata (e.g. tenant_id = 'acme' and created_at >= 2024-01-01).

  • Anti-pattern (Post-filtering): Finding Top-100 nearest vectors and then filtering by tenant often yields 0 valid results.
  • Production Pattern (Filtered HNSW): Graph traversal evaluates metadata constraints at each node evaluation hop, guaranteeing valid Top-$K$ retrieval.
