The idea to keep with you

Hexagonal Architecture (Ports & Adapters) isolates core domain logic inside an explicit boundary where all external I/O—HTTP, SQL, queues, third-party APIs—plugs in through interfaces owned by the domain.

01
STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What is Hexagonal Architecture.

In traditional layered architectures (Controller -> Service -> Repository -> DB), business rules inevitably leak ORM annotations (@Entity, @Transactional) and HTTP status codes. Hexagonal Architecture (Alistair Cockburn) draws a strict boundary around the application core:

  • Driving (Primary) Ports: Interfaces exposed by the core (PlaceOrderUseCase), called by Driving Adapters (REST controller, gRPC handler, Kafka listener).
  • Driven (Secondary) Ports: Interfaces defined by the core for what it needs (OrderRepository, PaymentGateway), implemented by Driven Adapters (Postgres, Stripe, in-memory fakes).
  • The Dependency Rule: Source-code imports point strictly inward (adapters -> application -> domain).
Inward Dependency Rule

Driving Adapters -> Domain Core (Ports) <- Driven Adapters

1.Zero Framework Leaks: The domain package never imports Spring, FastAPI, Hibernate, or AWS SDKs.

2.Multi-Channel Reuse: REST, Kafka, and CLI adapters invoke the exact same PlaceOrderUseCase port.

3.Millisecond Tests: Swap Postgres/Stripe adapters for in-memory fakes to test invariants in <5 ms.

Adapters depend on domain-owned ports—never the reverse—so infrastructure remains a replaceable plugin.

02
STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why Decoupling Domain Invariants from Frameworks Pays Off.

Web frameworks and ORMs churn every few years, while core billing, ledger, and risk-scoring invariants endure for decades. Hexagonal Architecture lets you swap Stripe for Adyen, or wrap a messy legacy ERP behind an Anti-Corruption Layer (ACL) without polluting domain models.

Enforce Boundaries in CI

Use ArchUnit (Java), import-linter (Python), or depguard (Go) in CI to fail any PR where domain imports infra or adapters.

Contract Tests Prevent Fake Drift

Run a shared contract test suite against both the in-memory fake (on every save) and the real Postgres adapter (in CI) so fakes never diverge from real SQL behavior.

STAGE 03 · WHERE IT IS USEDL5 · APPLIED DESIGN

Where Hexagonal Architecture Shines (and Where It's Boilerplate).

Apply Hexagonal ports where domain invariants and multiple I/O channels exist; skip the ceremony for thin CRUD or SQL-centric ETL.

ChoiceWhat it buysWhat it costs
Good Candidate: Billing, Ledger & Order State MachinesComplex invariants stay framework-free and testable across REST, gRPC, and Kafka consumers.Requires mapping between `OrderEntity <-> Order <-> OrderResponseDto`.
Good Candidate: Pragmatic CQRS SplitUse full Hexagonal ports for commands/writes with invariants, while letting read queries hit optimized SQL views directly.Read models bypass domain entities, requiring discipline not to sneak mutations into read paths.
Avoid: Thin CRUD or Analytical ETL PipelinesDirect SQL/dbt or simple layered handlers avoid pointless pass-through interfaces.Wrapping 1-to-1 table CRUD in 4 layers of ports and DTOs creates pure boilerplate.
04
STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

Domain Ports, Pure Domain Models & Unit-of-Work Boundaries.

Keep domain entities as plain dataclasses/POJOs/structs, and keep transaction boundaries explicit via a UnitOfWork port so hiding persistence behind a Repository never accidentally splits an atomic write across two transactions.

from typing import Protocol
from dataclasses import dataclass

@dataclass(frozen=True)
class Order:
    order_id: str
    total_cents: int

class OrderRepositoryPort(Protocol):  # Driven Port owned by domain
    def save(self, order: Order) -> None: ...

class PaymentGatewayPort(Protocol):   # Driven Port owned by domain
    def charge(self, order_id: str, cents: int) -> str: ...

class PlaceOrderUseCase:              # Pure domain service (zero framework imports)
    def __init__(self, repo: OrderRepositoryPort, payments: PaymentGatewayPort):
        self._repo = repo
        self._payments = payments

    def execute(self, order_id: str, cents: int) -> str:
        if cents <= 0:
            raise ValueError("Order total must be positive")
        tx_id = self._payments.charge(order_id, cents)
        self._repo.save(Order(order_id=order_id, total_cents=cents))
        return tx_id

Alternatives: Hexagonal vs. Classic 3-Layer vs. Vertical Slices.

Compare architectural styles by coupling, test speed, and ceremony.
