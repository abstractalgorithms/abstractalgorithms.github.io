The idea & core mechanics.

Adding a single non-redundant authentication service in the critical path of a 99.99% API immediately caps your system at the weakest link. Understanding Active-Passive vs. Active-Active failover and series/parallel availability math is essential for hitting three-9s (8.77h/yr) or four-9s (52.6m/yr) SLO error budgets.

ChoiceWhat it buysWhat it costs
Good candidateActive-Passive (hot/warm standby) when only one writer/leader can safely hold state or licensing restricts dual-active nodes.
Good candidateActive-Active when stateless services or multi-region databases can serve traffic simultaneously across zones/regions.
Think twiceAssuming two 99.9% components in sequence give 99.9% availability—in series they drop to 99.8% (doubling downtime).

Principle 1

99.9% (Three 9s) allows 8h 45m 57s downtime/year (~43.8m/month); 99.99% (Four 9s) allows 52m 36s/year (~4.38m/month); 99.999% (Five 9s) allows 5m 15s/year.

Principle 2

Active-Passive failover uses heartbeats; if the active node stops responding, the standby promotes (RTO depends on hot vs. cold standby; async replication risks RPO > 0).

Principle 3

Active-Active spreads live traffic across multiple instances via DNS/load balancers—higher utilization and instant blast-radius isolation, but requires conflict resolution for shared writes.

Reference Implementations (Python & Java)

# Series vs. Parallel availability calculator (Python)
import math

def availability_series(availabilities: list[float]) -> float:
    return math.prod(availabilities)

def availability_parallel(availabilities: list[float]) -> float:
    return 1.0 - math.prod(1.0 - a for a in availabilities)

// Series vs. Parallel availability calculator (Java)
public static double availabilitySeries(double... availabilities) {
    return Arrays.stream(availabilities).reduce(1.0, (a, b) -> a * b);
}
public static double availabilityParallel(double... availabilities) {
    double unavail = Arrays.stream(availabilities).map(a -> 1.0 - a).reduce(1.0, (a, b) -> a * b);
    return 1.0 - unavail;
}
