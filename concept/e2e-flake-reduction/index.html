What is E2E Test Flakiness.

Why this matters: The mechanism: understand how E2E Test Flakiness works from first principles.

An E2E test is flaky when it passes and fails intermittently on the exact same commit without code changes. Flakiness stems from non-determinism across three boundaries: async UI hydration/network timing, shared mutable test state, and environment variance between fast laptops and 2-vCPU CI containers.

Eliminating flakes means replacing arbitrary waitForTimeout(2000) sleeps with event-driven synchronization (expect(locator).toBeVisible(), waitForResponse) and strict per-test isolation.

Global coordination serializes throughput under load, while unbounded retries amplify transient stalls into full outages.

Request & State Flow

How to Ban Sleeps, Pin Clocks & Stub Third-Party APIs

// Deterministic Playwright test: API seed, explicit response sync, web-first assertion
test('archives invoice deterministically', async ({ page, request }, testInfo) => {
  const inv = await request.post('/api/test/invoices', {
    data: { idempotencyKey: `inv-${testInfo.workerIndex}-${Date.now()}` }
  }).then(r => r.json());

  await page.goto(`/invoices/${inv.id}`);
  const archiveBtn = page.getByRole('button', { name: 'Archive Invoice' });
  await expect(archiveBtn).toBeEnabled();

  await Promise.all([
    page.waitForResponse(r => r.url().endsWith('/archive') && r.status() === 200),
    archiveBtn.click(),
  ]);
  await expect(page.getByText('Status: Archived')).toBeVisible();
});
