STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What is the Bellman-Ford Algorithm.

Why this matters: The mechanism: understand how the Bellman-Ford Algorithm works from first principles.

Bellman-Ford replaces Dijkstra's greedy vertex selection with dynamic programming over path length. Define dk[v]d_k[v]dk​[v] as the shortest path from source sss to vvv using at most kkk edges.

Starting from dist[s] = 0 and dist[v] = INF, each pass iterates over every edge (u,v,w)∈E(u, v, w) \in E(u,v,w)∈E and relaxes dist[v] = min(dist[v], dist[u] + w). Because any simple path in a VVV-vertex graph has at most V−1V - 1V−1 edges, V−1V - 1V−1 passes finalize all shortest paths when no negative cycles exist. A VVV-th pass that still relaxes any edge proves a reachable negative-weight cycle.

STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why we need Bellman-Ford (and where Dijkstra & naive implementations fail).

Why this matters: The problem: see what breaks without Bellman-Ford under real concurrency or scale.

Dijkstra's greedy invariant—once a node is popped from the min-heap, its distance is final—breaks immediately if a later negative edge offers a shorter detour.

Watch out for three classic Bellman-Ford bugs:

  1. Relaxing INF Nodes: Checking dist[u] + w < dist[v] when dist[u] == INF and w < 0 falsely marks unreachable nodes as INF - 3!
  2. Missed Disconnected Arbitrage: To detect any negative cycle in a currency graph (not just reachable from node 0), initialize all dist[v] = 0.
  3. Multi-Hop Cascade in K-Stops: In Cheapest Flights Within K Stops, you must snapshot prev = dist.copy() each round so one pass doesn't chain multiple hops.
Edge Relaxation Walkthrough

Negative Edge Correction: C->B (-3) Improves A->B (4 -> 2)

Unlike Dijkstra, Bellman-Ford revisits B when C->B (-3) lowers B's cost from 4 to 2.

Naive Solution
Use a single unpartitioned path with unbounded retries and synchronous global coordination.
Why It Fails
Global coordination serializes throughput under load, while unbounded retries amplify transient stalls into full outages.
Alternatives
Compare synchronous strict-consistency paths against bounded asynchronous replication, local caching, or partitioned ownership.
Engineering Decision

Trade-Offs
Gains predictable p99 latency and fault isolation in exchange for explicit bounding, observability, and slightly higher implementation complexity.

# Bellman-Ford with early exit, INF guard, and negative-cycle detection (Python)
from typing import List, Tuple, Optional

def bellman_ford(n: int, edges: List[Tuple[int, int, int]], src: int) -> Optional[List[float]]:
    INF = float("inf")
    dist = [INF] * n
    dist[src] = 0

    for i in range(n):
        changed = False
        for u, v, w in edges:
            if dist[u] != INF and dist[u] + w < dist[v]:
                if i == n - 1:
                    return None # V-th pass relaxed an edge -> negative cycle!
                dist[v] = dist[u] + w
                changed = True
        if not changed:
            break
    return dist

In sparse all-pairs graphs with negative weights, Johnson's Algorithm runs Bellman-Ford once from a virtual source to compute node potentials h(v)h(v)h(v), reweights all edges to non-negative w′(u,v)=w(u,v)+h(u)−h(v)≥0w'(u,v) = w(u,v) + h(u) - h(v) \ge 0w′(u,v)=w(u,v)+h(u)−h(v)≥0, and then runs fast Dijkstra from every vertex.

Johnson's Hybrid Pipeline

Virtual Source -> Bellman-Ford Potentials -> Non-Negative Dijkstra

1.Cycle Guard First: The single Bellman-Ford pass aborts immediately if any negative cycle exists.

2.Non-Negative Guarantee: Triangle inequality ensures every reweighted edge w' >= 0 for Dijkstra.

3.Original Cost Recovery: True distance d(u, v) = d'(u, v) - h(u) + h(v) in O(1).

Johnson's algorithm combines Bellman-Ford's negative-weight safety with Dijkstra's speed.
