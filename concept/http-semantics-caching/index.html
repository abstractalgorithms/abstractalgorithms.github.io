What is RFC 9111 HTTP Caching.

Why this matters: The mechanism: understand how RFC 9111 HTTP Caching works from first principles.

Every uncached origin request pays full TLS, application compute, and cross-region RTT (50–250 ms). HTTP caching (RFC 9111) lets browsers (private caches) and CDNs/proxies (shared caches) store and reuse responses governed by Cache-Control:

  • no-store: Never write to disk or cache (mandatory for PII/auth).
  • no-cache: May store, but must revalidate with origin (If-None-Match: "etag") before every reuse.
  • public, max-age=31536000, immutable: Serve for 1 year with zero revalidation (for content-hashed bundles).
  • s-maxage=60, stale-while-revalidate=120: Shared CDN caches for 60s, then serves stale for 120s while refreshing asynchronously.
Multi-Tier HTTP Cache

Browser Cache -> CDN Edge (s-maxage + SWR) -> Origin (304 ETag)

1.99.4% Static Offload: Content-hashed JS/CSS (app.9f3a.js) use max-age=31536000, immutable.

2.304 Bandwidth Savings: ETag validation skips sending the response body when content hasn't changed.

3.Zero PII Leaks: Authenticated endpoints default to Cache-Control: private, no-store.

Explicit Cache-Control directives separate 1-year immutable bundles, SWR-cached public APIs, and uncached private endpoints.
