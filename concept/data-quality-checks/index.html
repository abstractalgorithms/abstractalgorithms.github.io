STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What are Data Quality Checks (5 Dimensions & 3 Layers).

Data quality checks are automated assertions and statistical monitors placed at pipeline boundaries to verify datasets are fit for purpose across five dimensions: completeness (null rates), uniqueness (duplicate keys), validity (regex/enum/range), timeliness (freshness lag), and consistency (referential & accounting invariants).

A mature architecture separates structural contracts (Avro/Protobuf at ingestion), semantic invariants (net_amount == gross - discount), and statistical observability (row-count z-scores, PSI/KS distribution drift).

02
STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why Check-After-Publish Fails (and How Write-Audit-Publish Fixes It).

Silent data corruption—a timezone shift, duplicate Kafka offset, or SDK enum change—trains broken ML models and skews ARR reports long before infra alerts fire. Running tests after overwriting production tables creates a race condition where BI tools already consumed bad data. Write-Audit-Publish (WAP) stages writes in an isolated Iceberg branch, runs audits, and atomically fast-forwards main only on pass.

Write-Audit-Publish (WAP)

Hourly Iceberg WAP Gate Preventing Corrupt Data From Reaching BI

Staging data on an isolated Iceberg branch eliminates the check-after-publish race condition.

Write-Audit-Publish on Daily Billing Mart

Duplicate Stripe webhooks inflated ARR by 8%. Implementing Iceberg WAP + dbt tests (unique on invoice_id, net_amount == gross - discount) kept failed runs on the staging branch and cut billing discrepancies to zero.

ML Feature Drift Detection in Fraud Scoring

An SDK changed device_os_version from 17.2 to iOS 17.2, defaulting the encoder to UNKNOWN and spiking false declines by 3.4%. Soda Core PSI (>0.2) and set-membership checks caught the schema-valid semantic drift in 15 minutes.

STAGE 03 · WHERE IT IS USEDL5 · APPLIED DESIGN

Where to Place Quality Gates (and Cost/Latency Guardrails).

Scope checks to incremental partitions or Iceberg snapshot diffs (SELECT * FROM table.changes) to keep audit latency under 30 seconds and avoid full-table warehouse scan bills.

ChoiceWhat it buysWhat it costs
Ingestion Boundary (Schema Registry + DLQ)Blocks malformed JSON/Avro payloads before they ever pollute Bronze storage.Validates single-record syntax only—cannot catch cross-row duplicates or volume drops.
Transformation Boundary (WAP in dbt / Spark / Iceberg)Verifies primary keys, accounting identities, and partition freshness before `main` swap.Requires severity tiering (`ERROR` halts vs `WARN` alerts) so minor nulls don't freeze dashboards.
Avoid: Unpartitioned Hourly Full-Table ScansPartition-scoped checks + HyperLogLog sketches are 10–100x cheaper.Running `COUNT(DISTINCT user_id)` over 5 years of history hourly explodes Snowflake/BigQuery spend.

STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

How to manage Quarantine, Severity Tiers & Quality SLIs.

  1. Row Quarantine vs. Batch Halt: For non-critical dimensions, tag bad rows with _dq_error_reason and route to a quarantine table; for financial ledgers, halt the batch.
  2. Monitor the DLQ: Track Bad Record Rate (quarantined_rows / total_rows), Time-to-Detect (TTD), and Freshness SLO—alert if >0.1% is quarantined so the DLQ never becomes a silent black hole.
  3. Seasonal Baselines: Calibrate statistical volume/drift alerts against 28-day seasonal windows.
-- Partition-scoped Write-Audit-Publish (WAP) invariant check in dbt / Iceberg SQL
SELECT invoice_id, gross_cents, discount_cents, net_cents
FROM {{ ref('stg_billing_invoices') }}
WHERE _ingested_date = CURRENT_DATE
  AND (net_cents != gross_cents - discount_cents OR net_cents < 0);
-- Non-empty result triggers ERROR severity, blocking fast-forward to Iceberg main.
