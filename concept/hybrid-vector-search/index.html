STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What is Hybrid Vector Search.

Why this matters: The mechanism: understand how Hybrid Vector Search works from first principles.

Pure dense vector search embeds queries into 768–1536D vectors (indexed in HNSW graphs for ~10 ms ANN lookup) and excels at paraphrases—but routinely misses exact tokens like ERR_CONNECTION_RESET or SKU-4920B. Conversely, BM25 nails exact rare tokens via inverted indexes but misses synonyms.

Hybrid search runs both retrievers in parallel and merges their ranked lists using Reciprocal Rank Fusion (RRF): RRF(d) = sum(1 / (k + rank_i(d))) (typically k = 60), requiring zero brittle score normalization between unbounded BM25 scores and [0, 1] cosine similarities.

Two-Stage Retrieval

Parallel BM25 + HNSW -> RRF Fusion (k=60) -> Cross-Encoder Top-50

1.Scale-Free RRF: Fuses ranks rather than raw scores, avoiding arbitrary BM25 vs. cosine scaling.

2.Single-Stage Filtering: Evaluates tenant/stock bitsets *inside* HNSW traversal so selective filters never return 0 results.

3.Scalar Quantization: int8 quantization cuts HNSW RAM by 4x with minimal recall loss when oversampling top-K.

Parallel lexical + dense retrieval fused with RRF captures both exact identifiers and semantic intent.

Two classic traps ruin hybrid search: (1) Post-filtering runs HNSW top-20 first and then applies WHERE in_stock = true—returning 0 results if the top-20 were out of stock; and (2) Naive score addition (bm25 + cosine) lets unbounded BM25 scores (0..40+) drown out cosine (0..1).

STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

Reciprocal Rank Fusion (RRF) & Single-Stage Filtered Retrieval.

Why this matters: Operational control: configure bounds, failure handling, and safe production defaults.

Think of Reciprocal Rank Fusion (RRF) & Single-Stage Filtered Retrieval as the intuition layer for Hybrid Vector Search (BM25 + HNSW + RRF): Operational control: configure bounds, failure handling, and safe production defaults.

Implement RRF with k = 60 so documents appearing near the top of both BM25 and HNSW lists receive a strong boost without tuning per-corpus alpha weights.

from collections import defaultdict

def reciprocal_rank_fusion(
    bm25_ids: list[str],
    vector_ids: list[str],
    k: int = 60,
    top_n: int = 20,
) -> list[tuple[str, float]]:
    scores: dict[str, float] = defaultdict(float)
    for rank, doc_id in enumerate(bm25_ids, start=1):
        scores[doc_id] += 1.0 / (k + rank)
    for rank, doc_id in enumerate(vector_ids, start=1):
        scores[doc_id] += 1.0 / (k + rank)
    return sorted(scores.items(), key=lambda x: x[1], reverse=True)[:top_n]
