STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What is Container Image Scanning.

Why this matters: The mechanism: understand how Container Image Scanning works from first principles.

An OCI container image is a JSON manifest pointing to a config blob and an ordered stack of compressed tar layers. Container image scanners (Trivy, Syft + Grype) unpack those layers virtually to inventory OS packages (apk, dpkg, rpm), language lockfiles (uv.lock, package-lock.json, go.sum), and hardcoded secrets.

Crucially, distro-specific feeds (Alpine secdb, Debian Security Tracker, Red Hat OVAL) are far more accurate than raw NVD CPE matching because Linux maintainers backport security patches without bumping upstream version numbers. Generating a CycloneDX / SPDX SBOM once at build time lets you re-evaluate zero-days in milliseconds without re-pulling gigabytes.

OCI Layer & SBOM Graph

Multi-Stage Distroless Image -> SBOM + VEX -> Kyverno Admission

1.Distro Backport Feeds: Alpine secdb and Debian OVAL prevent false positives on patched packages like openssl 3.0.11-deb12u2.

2.Build-Once SBOM: Querying stored CycloneDX SBOMs finds Log4j/OpenSSL zero-days across 500 services in seconds.

3.VEX Noise Filtering: Vulnerability Exploitability eXchange (VEX) suppresses CVEs in unused/unreachable code paths.

Minimal distroless bases + distro-aware SBOMs + VEX cut CVE noise while blocking real reachable risks.

STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why Naive Scanning & Dockerfiles Leak Secrets and Miss CVEs.

Why this matters: The problem: see what breaks without Why Naive Scanning & Dockerfiles Leak Secrets and Miss CVEs under real concurrency or scale.

Three classic container mistakes bypass naive security checks:

  1. Layer Deletion Myth: Copying .env or SSH keys in Dockerfile layer 3 and running RUN rm .env in layer 4 still leaves the secret readable inside layer 3's tarball via docker save or skopeo copy! Use multi-stage builds + BuildKit --mount=type=secret.
  2. Digestless Deployment: Scanning :latest or :v1.2 in CI and deploying by mutable tag lets a stale or compromised image slip past admission.
  3. Alert Fatigue from Raw NVD: Blocking builds on unpatched LOW/MEDIUM or unexploitable base-image CVEs trains teams to disable scanners.
Build-to-Runtime Loop

CI Trivy SBOM + Cosign -> Kyverno Gate -> Tetragon eBPF Correlation

Pairing build-time SBOMs with runtime eBPF library-load telemetry prioritizes CVEs that are actually loaded in memory.

Engineering Decision Framework
Problem
How to implement Container Image Scanning & SBOMs without hitting unbounded tail latency, state divergence, or operational fragility.
Naive Solution
Use a single unpartitioned path with unbounded retries and synchronous global coordination.
Why It Fails
Global coordination serializes throughput under load, while unbounded retries amplify transient stalls into full outages.
Alternatives
Compare synchronous strict-consistency paths against bounded asynchronous replication, local caching, or partitioned ownership.
Engineering Decision
If credentials or tokens are verified at the edge, pair build-time SBOM generation (Syft/Trivy) with VEX-filtered admission gates (Kyverno/Cosign) so you block reachable critical CVEs without drowning engineers in unexploitable base-image noise.
Trade-Offs
Gains predictable p99 latency and fault isolation in exchange for explicit bounding, observability, and slightly higher implementation complexity.

Use BuildKit secret mounts so credentials never enter any layer, export a CycloneDX SBOM, and fail CI on secrets or fixable critical CVEs.

  • Explicit capacity budgets
  • Isolated failure domains

# Multi-stage Dockerfile with BuildKit secret mount & minimal distroless/chainguard runtime
FROM python:3.12-slim AS builder
WORKDIR /app
RUN --mount=type=secret,id=pip_conf,target=/etc/pip.conf \
    pip install --no-cache-dir --prefix=/install -r requirements.txt

FROM cgr.io/chainguard/python:latest
COPY --from=builder /install /usr/local
COPY src/ /app/src/
ENTRYPOINT ["python", "/app/src/main.py"]

# CI gate: generate CycloneDX SBOM, fail on leaked secrets or fixable CRITICAL/HIGH CVEs
trivy image --format cyclonedx --output sbom.cdx.json "$IMAGE_DIGEST"
trivy image --severity CRITICAL,HIGH --ignore-unfixed --scanners vuln,secret --exit-code 1 "$IMAGE_DIGEST"
