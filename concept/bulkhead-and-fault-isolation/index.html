Bulkhead & Fault Isolation

Partition thread pools, connections, and queues so one slow dependency cannot exhaust all capacity.

Orientation & Intuition

The bulkhead pattern limits resources per dependency or tenant—like ship compartments—so failures stay localized.

Key takeaway Give each risky dependency its own budget; shared pools convert partial outages into total outages.

Core Architecture & Trade-offs

Without bulkheads, one flaky partner API can stall every checkout thread.

Key Architecture Invariants

  • Separate executors per dependency
  • Queue limits shed load early
  • Pairs with circuit breakers

When to Use

  • Multi-tenant SaaS
  • Services with heterogeneous dependency SLAs
  • Mixed critical/non-critical traffic

When NOT to Use

  • Tiny services with one dependency
  • When total pool size is smaller than minimum per-bulkhead floor

Deep Dive & Production Considerations
