What are Linked List Patterns.

Why this matters: The mechanism: understand how Linked List Patterns works from first principles.

A linked list stores elements in heap-allocated nodes connected by pointers (next, and prev for doubly linked lists) rather than contiguous memory.

Three foundational patterns eliminate most pointer bugs and unlock O(1)O(1)O(1) structural updates:

  • Sentinel Dummy Head/Tail: eliminates if (head == null) special cases during head insertion/deletion.
  • Fast & Slow Pointers (Floyd's Tortoise & Hare): finds midpoints and detects cycles in O(N)O(N)O(N) time, O(1)O(1)O(1) space.
  • HashMap + Doubly Linked List: powers O(1)O(1)O(1) get/put/evict in LRU caches.
O(1) LRU Hybrid

HashMap Index + Doubly Linked List Recency Chain

1.1. O(1) Lookup: HashMap jumps directly to the heap node without traversing the list.

2.2. O(1) Promotion: Unlink node via prev/next and insert right after Dummy Head.

3.3. O(1) Eviction: When full, unlink tail.prev and delete its key from the HashMap.

Combining a HashMap with sentinel-bounded doubly linked nodes turns O(N) list search into O(1) end-to-end LRU operations.

STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why pointer splicing still matters despite CPU cache locality.

Why this matters: The problem: see what breaks without Why pointer splicing still matters despite CPU cache locality under real concurrency or scale.

Contiguous arrays (std::vector, ArrayList) win 95% of general workloads because sequential elements fit in 64-byte CPU cache lines. However, arrays require O(N)O(N)O(N) element shifting on middle removal and periodic O(N)O(N)O(N) reallocation pauses.

Wherever you already hold a node reference and need O(1)O(1)O(1) middle removal/promotion without reallocation—such as OS kernel intrusive lists (struct list_head), timer wheels, or LRU/LFU eviction queues—linked-list patterns are indispensable.

In-Place Reversal

3-Pointer Reversal Invariant (Capture Next Before Mutating)

Always capture nxt = curr.next before overwriting curr.next = prev; otherwise the rest of the list is lost.

Naive Solution
Use a single unpartitioned path with unbounded retries and synchronous global coordination.
Why It Fails
Global coordination serializes throughput under load, while unbounded retries amplify transient stalls into full outages.
Alternatives
Compare synchronous strict-consistency paths against bounded asynchronous replication, local caching, or partitioned ownership.
Engineering Decision
If disk I/O or compaction stalls threaten tail latency, use sentinel dummy heads, fast/slow pointers, and HashMap+Doubly-Linked-List hybrids (LRU) to eliminate edge-case bugs and achieve O(1) structural mutations.
Trade-Offs
Gains predictable p99 latency and fault isolation in exchange for explicit bounding, observability, and slightly higher implementation complexity.

Component Topology

Sentinel-guarded LRU & in-place splicing

class Node:
    __slots__ = ("key", "val", "prev", "next")
    def __init__(self, key=0, val=0):
        self.key, self.val = key, val
        self.prev = self.next = None

class LRUCache:
    def __init__(self, capacity: int):
        self.cap = capacity
        self.map = {}
        self.head, self.tail = Node(), Node()
        self.head.next, self.tail.prev = self.tail, self.head

    def _remove(self, node: Node) -> None:
        node.prev.next, node.next.prev = node.next, node.prev

    def _insert_front(self, node: Node) -> None:
        node.next, node.prev = self.head.next, self.head
        self.head.next.prev = node
        self.head.next = node

    def get(self, key: int) -> int:
        if key not in self.map:
            return -1
        node = self.map[key]
        self._remove(node)
        self._insert_front(node)
        return node.val

Intrusive Lists & Lock-Free ABA Mitigation.

Why this matters: Production architecture: see how the components compose end to end under real load.

Think of Intrusive Lists & Lock-Free ABA Mitigation as the intuition layer for Linked List Patterns: Production architecture: see how the components compose end to end under real load.

In systems programming (Linux struct list_head), embedding link pointers inside the payload struct avoids double heap allocations. In lock-free CAS linked lists, tagged pointers (64-bit pointer + 64-bit monotonic version) or epoch-based reclamation prevent the ABA problem where a freed-and-reused node tricks CAS into corrupting the list.

Intrusive Lists & Lock-Free ABA Mitigation

Intrusive List Advantage

One allocation per object instead of separate node wrapper + payload allocations, cutting allocator fragmentation.

ABA Prevention

Pair pointer CAS with a monotonic version counter (cmpxchg16b) or hazard pointers before reclaiming unlinked nodes.
