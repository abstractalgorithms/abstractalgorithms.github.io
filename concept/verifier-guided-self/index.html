Stage 1 · Foundationfoundation

The Model Collapse Trap in Unverified Self-Training.

Why this matters: Understand why training models recursively on unverified synthetic outputs degrades tail diversity and accuracy.

Think of The Model Collapse Trap in Unverified Self-Training as the intuition layer for Verifier-Guided Self-Play & Synthetic Data Pipelines: Understand why training models recursively on unverified synthetic outputs degrades tail diversity and accuracy.

When a generator trains on its own raw samples, low-probability valid reasoning paths are clipped out first, followed by progressive variance shrinkage (mode collapse). Bounding generation diversity with a continuous KL-divergence floor D_KL(P_gen || P_ref) >= 0.72 and filtering through an external oracle (compiler, proof kernel, or unit test) prevents self-reinforcing errors.

Failure Mode

Unverified Self-Training vs Verifier-Grounded Self-Play

1.External Ground Truth: Compilers and formal proof checkers cannot be fooled by plausible-sounding prose.

2.Entropy Floor: Monitoring KL divergence and lexical diversity catches collapse before training runs waste GPU-hours.

Caption: External deterministic verifiers and entropy floors prevent recursive self-training from collapsing.

Stage 2 · Foundationfoundation

Hierarchical Curriculum Mutator & L1–L5 Difficulty Ladder.

Why this matters: Dynamically steer synthetic prompt generation toward the model's learning frontier using pass@k telemetry.

Static prompt sets quickly saturate (100% pass@k on easy tasks, 0% on impossible ones). A hierarchical DAG of 1B+ persona-domain seeds mutates constraints across levels L1 (Elementary) to L5 (Research), shifting sampling weights toward tasks where 0.15 <= pass@k <= 0.65.

def curriculum_weight(pass_at_k: float, min_kl: float, current_kl: float) -> float:
    if current_kl < min_kl:
        return 0.0  # Reject collapsed distribution
    # Peak sampling weight at ~40% pass rate (frontier difficulty)
    return max(0.05, 1.0 - abs(pass_at_k - 0.40) * 2.0)
Curriculum Engine

Adaptive L1–L5 Frontier Sampling with KL Floor

1.Goldilocks Zone: Tasks with ~40% pass@k yield maximum gradient signal per GPU-hour.

2.Mode-Collapse Guard: Prompts failing the KL entropy floor are rejected before hitting the H100 fleet.

Caption: Adaptive curriculum mutation concentrates compute on frontier difficulty while enforcing an entropy floor.

Stage 3 · Intermediateintermediate

Deterministic Verifier Sandboxing via Firecracker MicroVMs.

Why this matters: Execute untrusted model-generated code and formal proofs at 2,500+ rollouts/sec without host compromise.

Think of Deterministic Verifier Sandboxing via Firecracker MicroVMs as the intuition layer for Verifier-Guided Self-Play & Synthetic Data Pipelines: Execute untrusted model-generated code and formal proofs at 2,500+ rollouts/sec without host compromise.

Model-generated Python, C++, Rust, or shell traces can contain fork bombs, infinite loops, or accidental network probes. Standard Docker containers share the host kernel; instead, ephemeral Firecracker microVMs restore from pre-warmed memory snapshots via userfaultfd in <125 ms, enforcing strict seccomp-bpf, cgroups v2, and zero-egress virtual TAP interfaces for Lean4, Pytest, GCC, and Z3.

Isolated Execution

Sub-125ms Firecracker MicroVM Verifier Farm

1.Hardware Isolation: KVM microVM boundary prevents kernel exploits from escaping untrusted code sandboxes.

2.Deterministic Timeouts: Hard CPU/RAM cgroups caps kill runaway loops cleanly without stalling sibling workers.

Caption: Pre-warmed Firecracker microVMs provide kernel-isolated deterministic verification in under 125ms.

Stage 4 · Intermediateintermediate

Dual-Stage Decontamination: MinHash LSH + 13-Gram Bloom Filter.

Why this matters: Eliminate near-duplicate synthetic traces and guarantee zero leakage against held-out evaluation benchmarks.

Think of Dual-Stage Decontamination: MinHash LSH + 13-Gram Bloom Filter as the intuition layer for Verifier-Guided Self-Play & Synthetic Data Pipelines: Eliminate near-duplicate synthetic traces and guarantee zero leakage against held-out evaluation benchmarks.

Generating 250M rollouts/day inevitably produces paraphrases and occasional memorized benchmark questions (MMLU, HumanEval, SWE-bench, MATH). Stage 1 uses 128-permutation MinHash LSH (32 bands x 4 rows) to drop traces with Jaccard similarity J >= 0.80; Stage 2 streams rolling Rabin-Karp 13-grams through a Bloom filter pre-loaded with all eval test sets in <= 4 ms per 1K tokens.

Data Hygiene

MinHash LSH Deduplication + 13-Gram Eval Decontamination

1.Zero False Negatives: Bloom filter guarantees no exact 13-gram benchmark match slips into training.

2.Sub-Linear Dedup: LSH buckets avoid O(N^2) pairwise comparisons across 100M+ daily traces.

Caption: MinHash LSH and 13-gram Bloom filters remove near-duplicates and benchmark leakage in milliseconds.

Stage 5 · Intermediateintermediate

Process Reward Model (PRM) Step Scoring & Early Pruning.

Why this matters: Filter out lucky guesses with flawed intermediate reasoning and save H100 compute via early trajectory pruning.

An outcome-only verifier can accidentally reward a trace that guessed the right final answer via broken intermediate logic. A Process Reward Model (PRM) scores every reasoning step t with r_t in [0.0, 1.0] (p95 <= 35 ms/step), rejecting traces where min_t(r_t) < 0.78 and aborting dead-end rollouts early during beam/tree search.

def accept_trajectory(step_scores: list[float], min_threshold: float = 0.78) -> bool:
    if not step_scores:
        return False
    return min(step_scores) >= min_threshold
Step-Level Filtering

PRM Trajectory Scoring & Early Pruning

1.No Lucky Flukes: Requiring min(r_t) >= 0.78 ensures every intermediate step is sound, not just the final answer.

2.Compute Savings: Early-stopping low-PRM branches frees H100 KV-cache slots for promising paths.

Caption: Step-level PRM scoring rejects flawed reasoning chains even when the final answer happens to pass.

Stage 6 · Advancedadvanced

Immutable Data Lineage & ACID Rollbacks with Apache Iceberg.

Why this matters: Enable instant snapshot rollbacks if a bad generator checkpoint or contaminated batch slips into storage.

Think of Immutable Data Lineage & ACID Rollbacks with Apache Iceberg as the intuition layer for Verifier-Guided Self-Play & Synthetic Data Pipelines: Enable instant snapshot rollbacks if a bad generator checkpoint or contaminated batch slips into storage.

At 140 TB/day persisted Parquet data, discovering that yesterday's batch had a subtle verifier bug or benchmark leak cannot be fixed by manual file deletion. Storing golden traces in Apache Iceberg with immutable snapshot IDs (iceberg_commit_id) and streaming metrics to ClickHouse allows instant time-travel rollbacks and lineage audits per batch_id.

Lineage & Recovery

Apache Iceberg Snapshots + ClickHouse Telemetry

1.Zero-Copy Rollback: Revert a poisoned 10M-trace batch in seconds by rolling back the Iceberg catalog pointer.

2.Full Provenance: Every trace links back to generator checkpoint, seed persona, and verifier receipt.

Caption: ACID table snapshots in Apache Iceberg make dataset poisoning recoverable in seconds.

Stage 7 · Advancedadvanced

Reward Hacking & Verifier Overfitting Mitigations.

Why this matters: Prevent generators from exploiting quirks in unit tests or PRM scoring models.

Think of Reward Hacking & Verifier Overfitting Mitigations as the intuition layer for Verifier-Guided Self-Play & Synthetic Data Pipelines: Prevent generators from exploiting quirks in unit tests or PRM scoring models.

Generators in self-play can learn to game weak verifiers (e.g., hardcoding test outputs or exploiting PRM verbosity bias). Mitigate reward hacking via hidden held-out test suites inside the Firecracker sandbox, periodic PRM recalibration against human/formal gold labels, and length-normalized reward penalties.

Alignment Hardening

Defending Against Verifier & PRM Reward Hacking

1.Goodhart's Law: When a PRM becomes the sole optimization target, models exploit its blind spots.

2.Blind Sandboxes: Keeping adversarial property-based tests hidden from the prompt stops trivial memorization.

Caption: Hidden property-based tests and periodic PRM recalibration prevent generators from gaming verifiers.
