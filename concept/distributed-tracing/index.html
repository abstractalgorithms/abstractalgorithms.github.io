STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What is Distributed Tracing (Traces, Spans & W3C Trace Context).

Distributed tracing models a request's journey across microservices, queues, and databases as a DAG of timed operations called spans. Every request gets a 128-bit trace_id at ingress; each hop creates a 64-bit span_id with parent_span_id, timestamps, and attributes (http.status_code, db.system).

Context crosses process boundaries via W3C Trace Context (traceparent: 00-<trace_id>-<span_id>-<flags>), and spans export asynchronously via OTLP (gRPC 4317 / HTTP 4318) to an OpenTelemetry Collector.

STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why Local Logs Fail Across Microservices (and How Tail Sampling Captures p99).

When one API call triggers 15 RPCs and Kafka messages, local logs are fragmented across hosts. Head-based sampling (1% at ingress) discards 99% of rare 500 errors before we know they failed; two-tier tail-based sampling routes all spans by trace_id to a Tier-2 collector that buffers for decision_wait (10–15s) and retains 100% of errors and slow traces.

End-to-End Trace & Tail Sampling

W3C traceparent Across Sync gRPC, Async Kafka & Two-Tier OTel Collectors

Hashing by trace_id in Tier-1 ensures all spans for a trace land on the same Tier-2 collector for accurate tail sampling.

Pinpointing an N+1 gRPC Fan-Out in Checkout

Checkout p99 jumped from 180 ms to 1.4s at <30% CPU. A tail-sampled trace in Jaeger exposed 42 sequential PricingService.GetDiscount spans (30 ms each) inside a loop; batching cut p99 to 165 ms.

Prometheus Exemplars + JSON Log Correlation

Injecting trace_id/span_id into structlog/slog JSON logs and attaching Exemplar trace_ids to Prometheus histogram buckets gives one-click jumps from p99 alert -> slow trace -> exact error log.

STAGE 03 · WHERE IT IS USEDL5 · APPLIED DESIGN

Where Distributed Tracing Belongs (and Where Metrics / Flame Graphs Win).

Tracing answers where in the call graph a request slowed down or failed; it complements—never replaces—aggregate metrics and CPU profilers.

ChoiceWhat it buysWhat it costs
Use Tracing: Multi-Hop Latency, N+1 RPCs & Cross-Service ErrorsVisualizes causal waterfalls across HTTP, gRPC, SQL, and Kafka consumers.~1.5 KB/span telemetry volume requires head or tail sampling at high QPS.
Use Metrics: Real-Time Alerting, Burn Rates & CapacityFixed cost per time-series; low cardinality (`service.name`, `http.route`).Cannot show which specific `order_id` triggered an N+1 loop.
Use eBPF / Flame Graphs: In-Process CPU HotspotsPinpoints exact functions (`serde_json`, `regexp`) at <2% overhead.Tracing spans shouldn't wrap tight per-item loops.
04
STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

How to Propagate Async Context, Scrub PII & Protect App Threads.

  1. Never Block Request Threads: Always use an asynchronous BatchSpanProcessor with bounded queues and drop-on-full semantics.
  2. Wrap Thread Pools & Queues: Use Context.taskWrapping / Kafka interceptors so background goroutines/futures don't orphan traces.
  3. Scrub PII at Collector: Strip ?token= query strings and SQL literals using OTel redaction/attributes processors.
  4. Sync Clocks: Keep NTP/Chrony skew < 5 ms so child spans never appear to start before parent spans.
# Propagating W3C traceparent across Kafka headers with OpenTelemetry (Python)
from opentelemetry import propagate, trace

tracer = trace.get_tracer(__name__)

def produce_event(producer, topic: str, payload: bytes) -> None:
    with tracer.start_as_current_span("kafka.produce", kind=trace.SpanKind.PRODUCER):
        headers = {}
        propagate.inject(headers)  # Injects 'traceparent' & 'tracestate'
        producer.send(topic, value=payload, headers=[(k, v.encode()) for k, v in headers.items()])

STAGE 05 · ALTERNATIVESL6 · SCALE & TRADE-OFFS

Alternatives: Head vs. Tail vs. Adaptive Sampling.

Choose your sampling strategy to balance collector RAM against error visibility.

ChoiceWhat it buysWhat it costs
Head-Based Sampling (`TraceIDRatioBased(0.02)`)Stateless O(1) decision at ingress; zero collector buffering RAM.Discards 98% of rare 500 errors and p99 latency spikes before they occur.
Two-Tier Tail-Based SamplingRetains 100% of `ERROR` and `>1000ms` traces plus a 1% healthy baseline.Needs stateful Tier-2 RAM, `loadbalancingexporter` by `traceID`, and `memory_limiter`.
Adaptive Per-Endpoint SamplingSamples `/health` at 0.01% and `/v1/refund` at 50% automatically.Requires dynamic control-plane config push to ingress/collectors.
06
STAGE 06 · PRODUCTION ARCHITECTUREL7 · STAFF / PRINCIPAL

Production Architecture: Two-Tier OTel Collector Topology.

Never place a round-robin load balancer in front of tail-sampling collectors—it splits a trace's spans across pods and breaks tail policies. Use a stateless Tier-1 loadbalancingexporter hashing on traceID into Tier-2 collectors protected by memory_limiter and num_traces caps.
