STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What are Load, Soak, and Spike Tests.

Performance testing validates non-functional SLOs under three distinct traffic profiles:

  • Load Test: ramps smoothly (e.g., 500 to 5,000 RPS over 15 min) to map the knee of the throughput-vs-p99 latency curve.
  • Soak (Endurance) Test: holds 70%–85% of peak load for 8–72 hours to catch slow memory leaks (2–5 MB/hr), connection-pool leaks, or disk/WAL bloat.
  • Spike Test: jumps arrival rate 5x–20x in under 30 seconds to test HPA autoscaling lag, circuit breakers, and load shedding.
Workload Modeling

Open-Model Arrival Rate vs. Closed-Loop Coordinated Omission

Open-model generators decouple request arrival from server latency, exposing queueing explosions that closed VU loops hide.

02
STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why 1-RPS functional tests miss Coordinated Omission and leaks.

Functional tests pass at 1 RPS while production outages happen when HikariCP pools saturate, GC pauses compound, or flash-sale traffic arrives faster than Kubernetes HPA can boot pods.

Two measurement traps invalidate naive benchmarks: Coordinated Omission (closed-loop virtual users pause sending while waiting on a slow response, hiding 5-second GC stalls from p99) and Load Generator Bottlenecks (the test runner exhausts its own ephemeral TIME_WAIT ports before the server saturates).

Track Intended vs. Actual Send Time

Use open constant-arrival-rate executors (k6, Vegeta) or HdrHistogram correction so queued requests count toward tail latency.

Monitor the Generator Itself

Watch generator CPU, NIC drops, and ip_local_port_range so you never mistake client port exhaustion for server capacity.

Where Performance Suites belong (and where they do not).

Run targeted load/soak/spike tests before major infra shifts or predictable traffic cliffs.

ChoiceWhat it buysWhat it costs

STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

Configuring Open-Workload Ramp, Spike & Abort Thresholds in k6.

Use ramping-arrival-rate with preAllocatedVUs and maxVUs caps plus strict thresholds that abort if error rates spike.

import http from 'k6/http';
import { check } from 'k6';

export const options = {
  scenarios: {
    open_spike: {
      executor: 'ramping-arrival-rate',
      startRate: 200, timeUnit: '1s',
      preAllocatedVUs: 100, maxVUs: 2000,
      stages: [
        { target: 500, duration: '5m' },   // Steady load
        { target: 4000, duration: '30s' }, // 8x traffic cliff
        { target: 500, duration: '5m' },   // Recovery check
      ],
    },
  },
  thresholds: {
    http_req_duration: ['p(99)<350'],
    http_req_failed: [{ threshold: 'rate<0.01', abortOnFail: true }],
  },
};

export default function () {
  const res = http.get('https://staging.example.com/api/v1/catalog');
  check(res, { 'status 200': (r) => r.status === 200 });
}

STAGE 05 · ALTERNATIVESL6 · SCALE & TRADE-OFFS

Alternatives: Open vs. Closed Workload & Short vs. Multi-Hour Soak.

Select the workload model and duration that match the failure mode you are hunting.

ChoiceWhat it buysWhat it costs
Open-Workload Model (Fixed RPS)Reveals true queueing explosions and tail latency when the server slows.Can rapidly overwhelm fragile staging environments without `maxVUs` caps.
Closed-Workload Model (Fixed VUs)Models bounded internal worker pools or finite concurrent browser tabs.Suffers Coordinated Omission for public internet traffic.
Multi-Hour Soak (8–72h) vs. 15-Min LoadCatches slow heap leaks, unclosed HikariCP connections, and WAL/log-disk fill.Delays CI/CD and burns cloud staging budget; run nightly/pre-release.
06
STAGE 06 · PRODUCTION ARCHITECTUREL7 · STAFF / PRINCIPAL

Distributed Load Mesh + SLO Telemetry Gate.

Production performance harnesses distribute open-model runners across multiple nodes (with tuned net.ipv4.ip_local_port_range) and correlate client HdrHistogram percentiles against server-side Prometheus/OTel metrics (GC pause, pool wait, HPA pod-boot lag).

Test Progression

Capacity Knee -> Endurance Soak -> Spike Recovery Gate

Passing all three profiles verifies steady-state capacity, leak-free endurance, and graceful burst recovery.
