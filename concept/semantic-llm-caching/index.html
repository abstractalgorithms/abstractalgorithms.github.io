A foundational engineering concept

Semantic Caching
for LLMs.

Semantic LLM caching intercepts natural-language prompts, embeds them into dense vectors (e.g., 1536-dim via text-embedding-3-small), and performs an Approximate Nearest Neighbor (ANN) lookup in a vector store like Redis or Qdrant. When cosine similarity clears a strict threshold (typically 0.93–0.96), the system returns a cached completion in 20–45 ms instead of paying 1.5–6 seconds and 0.01–0.01–0.01–0.05 per frontier model inference.

THE BIG IDEA / Key takeaway · CONCEPT GUIDE

Pair an L1 exact-hash cache with an L2 vector ANN cache gated by tenant metadata filters and high cosine thresholds to cut LLM latency by 90%+ without leaking cross-user context.

Explanation anchor
01 / The idea

Foundational mechanics & core principles

Production LLM applications fail economically and interactively when every paraphrased question ('How do I reset MFA?' vs 'Where can I reconfigure two-factor auth?') triggers a full autoregressive decode. Frontier models cost 2.50–2.50–2.50–15.00 per million output tokens and exhibit 1.5–8.0 second end-to-end latencies. In high-volume support, RAG, and coding assistants where 25–45% of traffic is semantically redundant, semantic caching eliminates redundant GPU compute, absorbs traffic spikes without hitting provider RPM/TPM rate limits, and stabilizes p95 response times.

  • Two-tier lookup beats vector-only: check an L1 SHA-256 exact-match hash (after whitespace/case normalization) in <2 ms before paying ~15–25 ms for an embedding API call and HNSW vector search.
  • Cosine similarity is blind to negation and swapped entities: 'enable TLS 1.3' and 'disable TLS 1.3' often score >0.94 in bi-encoder embeddings, requiring keyword/entity checks or a fast cross-encoder reranker.
  • Metadata pre-filtering is mandatory for security: tenant_id, RBAC role, model_version, and prompt_template_hash must be filtered inside the vector index before scoring neighbors.
  • Cache only the final grounded response alongside its citation IDs and TTL—if underlying RAG documents update, invalidate linked cache keys via document-ID reverse indexes.
  • Embedding model upgrades invalidate the entire vector space: always namespace cache keys by embedding_model_id (e.g., te3s_v1) to prevent silent similarity drift.

Good candidates

  • High-frequency, read-heavy Q&A, documentation search, or customer support bots where users phrase identical intents in dozens of ways.
  • Deterministic or low-temperature (T <= 0.2) workloads where a verified canonical answer remains valid across multiple users.
  • Cost-constrained pipelines calling expensive reasoning or long-context models (e.g., 32k+ input tokens) with repetitive system prompts.

Think twice

  • Personalized, stateful, or real-time queries ('What is my current account balance?' or 'Summarize emails from the last 10 minutes') where answers depend on mutable user state.
  • Creative writing, brainstorming, or high-temperature (T >= 0.7) generation where users explicitly expect novel, non-repetitive outputs.
  • Code refactoring or data-extraction prompts with subtle negation, numeric, or entity differences ('delete rows > 100' vs 'delete rows < 100') unless guarded by a verifier.
Deep Dive & Production Considerations
02 / Concrete walkthrough

Architectural mechanics & implementation

ScenarioA B2B support portal handles 180k daily queries across 4,000 tenant organizations using GPT-4o over a 12k-token product manual, averaging 3.4 s latency and $2,400/day in token spend.

Caching meaning in vector space instead of exact bytes

Traditional HTTP and Redis caches rely on exact key equality: change a single comma or synonym and SHA256(prompt) misses. Semantic LLM caching replaces exact byte matching with geometric proximity in an embedding space. Incoming prompts are mapped to unit-normalized vectors (e.g., 1536 floats), and an Approximate Nearest Neighbor (ANN) index such as HNSW locates the closest previously answered prompt. If the cosine similarity exceeds a calibrated threshold (commonly 0.93–0.96) and all security/context filters match, the gateway short-circuits LLM inference and streams the cached completion back to the client.

Tracing a request through an L1/L2 semantic gateway

  1. Normalize & L1 Check (1–2 ms): The gateway strips extra whitespace, extracts tenant_id, model, and locale, and computes SHA256(normalized_prompt + scope_key). An exact hit in Redis returns immediately.
  2. Embed Intent (10–25 ms): On L1 miss, the gateway embeds only the canonical user query (not the static system prompt) using text-embedding-3-small or a local ONNX bge-small model.
  3. Filtered HNSW Search (5–15 ms): The gateway queries Qdrant/Redis HNSW with filter: {tenant_id == 'acme', prompt_ver == 'v4'} for top_k = 3 by cosine similarity.
  4. Guardrail Gate (1–40 ms): If score >= 0.94, a lightweight verifier confirms matching entities, numbers, and polarity (e.g., >= vs <).
  5. Hit or Async Write-Back: On pass, return cached tokens with X-Cache: SEMANTIC-HIT. On miss, invoke the upstream LLM, stream the response to the user, and asynchronously upsert the (vector, response, source_doc_ids, ttl) record.

L1 exact hashing eliminates embedding overhead on identical repeats; L2 HNSW catches paraphrases while pre-filtering prevents cross-tenant leaks.

Why 0.85 fails and how to tune similarity gates

General-purpose bi-encoders compress syntax and semantics into a single vector, which means structurally similar sentences with opposite meanings ('HTTP 502 on /checkout' vs 'HTTP 504 on /checkout') routinely score 0.91–0.94. Instead of guessing a magic cutoff, collect 500–1,000 production query pairs, label true paraphrases vs near-miss collisions, and plot precision-recall curves per intent category. High-risk categories (billing, IAM policies, SQL generation) typically require >= 0.96 plus regex entity matching, whereas general FAQ queries tolerate 0.92–0.94.

Where semantic caches break in production

  1. Negation & Operator Inversion: 'Show users who did pay' vs 'Show users who did not pay' can collide in cosine space. Mitigate with a cross-encoder or AST/keyword diff on operators and negation words.
  2. Multi-Turn Context Blindness: Caching only the last user turn ('How much does it cost?') without the prior turn ('Enterprise plan' vs 'Starter plan') returns the wrong product's price. Always embed a standalone rewritten query (via query-condensation) or include conversation state in the scope key.
  3. Cache Poisoning via Low-Quality Outputs: If a transient tool timeout causes the LLM to reply 'I cannot access that right now', caching that response locks in the outage for every similar query until TTL expires.

Keeping cached completions fresh without full flushes

Time-based TTL alone is too blunt for knowledge-backed systems: a 24-hour TTL serves stale pricing for a day, while a 5-minute TTL destroys hit rates. Attach source_doc_ids and prompt_template_hash as indexed metadata on every cached entry. When your ingestion pipeline updates doc_482 in the knowledge base, run a metadata delete (DELETE WHERE 'doc_482' IN source_doc_ids) to evict only affected answers. Combine this with an LRU/LFU eviction policy and embedding_model_id collection versioning so schema or model rollouts never require downtime.

Production readiness checklist

  • L1 before L2: Serve exact normalized SHA-256 matches from Redis in <2 ms before calling any embedding model.
  • Mandatory scope filters: Pre-filter by tenant_id, role, locale, model_id, and prompt_version inside the vector query.
  • Condense multi-turn queries: Rewrite follow-up questions into self-contained queries before embedding.
  • Guard against false positives: Add an entity/number/negation verifier or cross-encoder for scores between 0.92 and 0.97.
  • Never cache errors or low-confidence answers: Gate cache writes on HTTP 200, non-empty tool results, and minimum token length.
  • Track precision, not just hit rate: Continuously sample 1–2% of semantic hits for shadow LLM evaluation to detect threshold drift.
03 / Engineering trade-offs

Weighing architectural decisions

Similarity threshold strictness (0.90 vs 0.96)

Advantage: Lower thresholds (0.88–0.91) boost hit rates by 15–25 percentage points and maximize token savings.

Drawback: False-positive cache hits return off-topic or dangerously inverted answers on edge-case phrasing.

Local ONNX embedder vs hosted embedding API

Advantage: In-process ONNX models (e.g., BGE-small-en-v1.5) embed in 5–12 ms with zero external network hops or per-token fees.

Drawback: Consumes app-tier CPU/RAM and locks you into managing model weights and tokenizer parity.

Cross-encoder verification on L2 hits

Advantage: A lightweight cross-encoder (e.g., ms-marco-MiniLM-L-6-v2) catches negation and entity mismatches that bi-encoders miss.

Drawback: Adds 20–60 ms of CPU/GPU inference latency to every candidate hit and increases serving complexity.

04 / Failure modes & resilience

Explain where it breaks · Known failure modes

False-Positive Semantic Collision

Two prompts share high lexical overlap but opposite intent (e.g., 'Allow port 443 in AWS SG' vs 'Block port 443 in AWS SG'), scoring 0.95 cosine similarity and serving destructive instructions.

What helps: Run a fast entity/negation diff check (comparing extracted numbers, flags, and negation tokens) or a cross-encoder gate before accepting any L2 hit below 0.98.

Cross-Tenant Context Leakage

A shared vector index returns Tenant A's cached summary (containing proprietary names or pricing) to Tenant B because their prompt phrasing was identical.

What helps: Enforce mandatory pre-filtering on tenant_id and permission_scope in the vector query (never post-filter top-K results) and segregate sensitive endpoints to exact-match or no-cache.

Stale RAG Answer Persistence

A policy or pricing document is updated in the knowledge base, but the semantic cache continues serving yesterday's outdated LLM completion until TTL expiry.

What helps: Store source_doc_ids[] in each cache entry's metadata and trigger targeted cache eviction whenever a source document is re-indexed.

Embedding Dimension / Model Mismatch

A deployment switches from OpenAI ada-002 to text-embedding-3-small without flushing or namespacing the index, causing silent zero-hits or corrupted distance comparisons.

What helps: Include embedding_model and dimension count in the Redis/Qdrant collection name and reject queries with mismatched vector metadata.

05 / Practical checklist

Avoid these mistakes

  • Hashing or embedding the entire 10k-token system prompt + conversation history instead of isolating the normalized user intent and context fingerprint.
  • Using post-filtering on vector search results (fetch top-5, then filter by tenant_id), which yields zero hits when all top-5 belong to other tenants.
  • Setting a uniform 0.85 cosine threshold across all domains without measuring precision/recall on a golden evaluation set of near-miss pairs.
  • Forgetting to exclude streaming/non-deterministic tool-calling turns that depend on live timestamps or external API side effects.
  • Caching unvalidated or hallucinated LLM outputs (e.g., low-confidence or error-fallback responses) and amplifying a single bad generation across thousands of users.
