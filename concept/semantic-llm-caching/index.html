Semantic Caching
for LLMs.

Semantic LLM caching intercepts natural-language prompts, embeds them into dense vectors (e.g., 1536-dim via text-embedding-3-small), and performs an Approximate Nearest Neighbor (ANN) lookup in a vector store like Redis or Qdrant. When cosine similarity clears a strict threshold (typically 0.93–0.96), the system returns a cached completion in 20–45 ms instead of paying 1.5–6 seconds and $0.01–$0.05 per frontier model inference.

STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What is Semantic LLM Caching.

Why this matters: The mechanism: understand how Semantic LLM Caching works from first principles.

Traditional HTTP/Redis caches require exact byte equality—changing a comma misses SHA256(prompt). Semantic LLM caching intercepts natural-language intents ("How do I reset MFA?" vs. "Where can I reconfigure 2FA?") using a two-tier lookup:

  1. L1 Exact Hash (<2 ms): Check SHA256(normalized_prompt + tenant_id + model_id).
  2. L2 Vector ANN (15–40 ms): Embed the prompt and run a pre-filtered HNSW lookup in Redis Stack or Qdrant; if cosine similarity clears a calibrated threshold (typically 0.93–0.96) and passes a negation/entity guard, return the cached completion.
L1 Exact + L2 Vector Cache

Two-Tier Semantic LLM Cache with Tenant Pre-Filtering

1.1. L1 Before L2: Exact normalized SHA-256 hits in <2 ms without paying embedding latency or cost.

2.2. Pre-Filtered HNSW: Filter tenant_id, role, model_id, and prompt_version inside the vector query—never post-filter.

3.3. Negation Guard: Verify numbers, flags, and negation tokens ('allow' vs 'block') before serving L2 hits.

L1+L2 caching absorbs 25–45% of redundant support/RAG LLM traffic at 20–45 ms p95.

Naive Solution
Use a single unpartitioned path with unbounded retries and synchronous global coordination.
Why It Fails
Global coordination serializes throughput under load, while unbounded retries amplify transient stalls into full outages.
Alternatives
Compare synchronous strict-consistency paths against bounded asynchronous replication, local caching, or partitioned ownership.

Trade-Offs
Gains predictable p99 latency and fault isolation in exchange for explicit bounding, observability, and slightly higher implementation complexity.

STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

How L1/L2 Lookup, Negation Checks & Doc Invalidation are implemented.

Why this matters: Operational control: configure bounds, failure handling, and safe production defaults.

Think of How L1/L2 Lookup, Negation Checks & Doc Invalidation are implemented as the intuition layer for Semantic Caching for LLMs: Operational control: configure bounds, failure handling, and safe production defaults.

Isolate the normalized user intent (do not embed a 10k-token system prompt), run L1 SHA-256 first, execute pre-filtered L2 ANN, and gate L2 hits < 0.98 with a negation/operator diff or lightweight cross-encoder (ms-marco-MiniLM-L-6-v2).

import hashlib, re

NEGATIONS = {"not", "no", "never", "disable", "block", "deny", "without"}

def safe_semantic_hit(query: str, cached_query: str, score: float, threshold: float = 0.94) -> bool:
    if score < threshold:
        return False
    if score >= 0.985:
        return True
    # Guard against bi-encoder negation / numeric collisions ('allow 443' vs 'block 443')
    q_tokens = set(re.findall(r"[a-z0-9_<>!=]+", query.lower()))
    c_tokens = set(re.findall(r"[a-z0-9_<>!=]+", cached_query.lower()))
    if (q_tokens & NEGATIONS) != (c_tokens & NEGATIONS):
        return False
    return re.findall(r"\d+", query) == re.findall(r"\d+", cached_query)
