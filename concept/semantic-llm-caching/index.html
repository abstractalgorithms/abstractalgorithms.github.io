Semantic Caching
for LLMs.

Semantic LLM caching intercepts natural-language prompts, embeds them into dense vectors (e.g., 1536-dim via text-embedding-3-small), and performs an Approximate Nearest Neighbor (ANN) lookup in a vector store like Redis or Qdrant. When cosine similarity clears a strict threshold (typically 0.93–0.96), the system returns a cached completion in 20–45 ms instead of paying 1.5–6 seconds and $0.01–$0.05 per frontier model inference.

01
STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What is Semantic LLM Caching.

Traditional HTTP/Redis caches require exact byte equality—changing a comma misses SHA256(prompt). Semantic LLM caching intercepts natural-language intents ("How do I reset MFA?" vs. "Where can I reconfigure 2FA?") using a two-tier lookup:

  1. L1 Exact Hash (<2 ms): Check SHA256(normalized_prompt + tenant_id + model_id).
  2. L2 Vector ANN (15–40 ms): Embed the prompt and run a pre-filtered HNSW lookup in Redis Stack or Qdrant; if cosine similarity clears a calibrated threshold (typically 0.93–0.96) and passes a negation/entity guard, return the cached completion.
L1 Exact + L2 Vector Cache

Two-Tier Semantic LLM Cache with Tenant Pre-Filtering

1.1. L1 Before L2: Exact normalized SHA-256 hits in <2 ms without paying embedding latency or cost.

2.2. Pre-Filtered HNSW: Filter tenant_id, role, model_id, and prompt_version inside the vector query—never post-filter.

3.3. Negation Guard: Verify numbers, flags, and negation tokens ('allow' vs 'block') before serving L2 hits.

L1+L2 caching absorbs 25–45% of redundant support/RAG LLM traffic at 20–45 ms p95.

02
STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why Naive Cosine Thresholds Fail (Negation & Cross-Tenant Leaks).

General-purpose bi-encoders compress syntax and semantics into one vector—so opposite intents score >0.94 cosine similarity: 'Allow port 443 in AWS SG' vs. 'Block port 443 in AWS SG', or 'delete rows > 100' vs. 'delete rows < 100'. Worse, post-filtering a shared vector index risks cross-tenant leaks or zero-hit starvation, and switching embedding models without namespacing corrupts distance comparisons.

Invalidate via `source_doc_ids[]` Reverse Index

Time-based TTLs are too blunt for RAG: store source_doc_ids in cache metadata so re-indexing a pricing doc evicts linked cache entries immediately.

Namespace Keys by `embedding_model_id`

Upgrading from ada-002 to text-embedding-3-small invalidates vector geometry—include model ID and dimensions in the collection name.

STAGE 03 · WHERE IT IS USEDL5 · APPLIED DESIGN

Where Semantic Caching shines (and where to bypass it).

Cache deterministic, read-heavy Q&A and documentation bots; bypass caching for personalized stateful queries, high-temperature creative tasks, or tool-calling mutations.

ChoiceWhat it buysWhat it costs
Good Candidate: Low-Temperature Support & Docs Q&A ($T \le 0.2$)25–45% cache hit rate slashes GPU spend, stabilizes p95 latency, and shields provider RPM/TPM limits.Requires golden-set precision/recall calibration on near-miss pairs.
Avoid: Personalized / Real-Time Stateful QueriesBypass cache for `'What is my account balance?'` or `'Summarize my last 10m emails'`.Serving stale or cross-user state is a correctness and security failure.
Avoid: High-Temperature Creative & Subtle Code DiffsUsers expect novel creative outputs, and subtle operator inversions (`>` vs `<`) risk false-positive collisions.Unless guarded by a cross-encoder or AST verifier, code-diff caching is unsafe.
04
STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

How L1/L2 Lookup, Negation Checks & Doc Invalidation are implemented.

Isolate the normalized user intent (do not embed a 10k-token system prompt), run L1 SHA-256 first, execute pre-filtered L2 ANN, and gate L2 hits < 0.98 with a negation/operator diff or lightweight cross-encoder (ms-marco-MiniLM-L-6-v2).

import hashlib, re

NEGATIONS = {"not", "no", "never", "disable", "block", "deny", "without"}

def safe_semantic_hit(query: str, cached_query: str, score: float, threshold: float = 0.94) -> bool:
    if score < threshold:
        return False
    if score >= 0.985:
        return True
    # Guard against bi-encoder negation / numeric collisions ('allow 443' vs 'block 443')
    q_tokens = set(re.findall(r"[a-z0-9_<>!=]+", query.lower()))
    c_tokens = set(re.findall(r"[a-z0-9_<>!=]+", cached_query.lower()))
    if (q_tokens & NEGATIONS) != (c_tokens & NEGATIONS):
        return False
    return re.findall(r"\d+", query) == re.findall(r"\d+", cached_query)

STAGE 05 · ALTERNATIVESL6 · SCALE & TRADE-OFFS

Alternatives: Redis Stack vs. Qdrant vs. Provider Prompt Caching.

Choose the caching layer based on whether you are caching shared system prefixes or full end-user completions.

ChoiceWhat it buysWhat it costs
Redis Stack (RediSearch HNSW)Unified L1 exact-hash + L2 pre-filtered vector search in 5–15 ms.RAM-bound for very large vector collections.
Qdrant / Milvus + In-Process ONNX EmbedderDisk-backed HNSW scales to tens of millions of entries; local ONNX (`BGE-small`) embeds in 5–12 ms with zero API fees.App tier must manage ONNX weights and tokenizer parity.
LLM Provider Prompt CachingZero false-positive semantic risk—caches exact long system/document prefixes in KV memory.Still runs full autoregressive decode for output tokens (1–5s latency).

STAGE 06 · PRODUCTION ARCHITECTUREL7 · STAFF / PRINCIPAL

Production example: Negation-Guarded Gateway + RAG Doc Reverse Index.

An AI support gateway checks L1 Redis SHA-256, embeds with local ONNX BGE-small-en-v1.5, queries Redis HNSW pre-filtered by (tenant_id, model_id, prompt_hash), verifies hits with a negation/cross-encoder gate, and registers doc_id -> cache_keys so RAG updates evict stale answers instantly.

L1 Exact -> Pre-Filtered L2 HNSW -> Negation/Cross-Encoder Gate
