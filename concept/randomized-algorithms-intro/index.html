STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What are Randomized Algorithms (Las Vegas vs. Monte Carlo).

Deterministic algorithms must handle every input, allowing pathological or adversarial data to trigger worst-case O(n2)O(n^2)O(n2) behavior. Randomized algorithms shift uncertainty from the input to internal coin flips.

Las Vegas algorithms (randomized QuickSort, Skip Lists) always return the exact answer; only runtime is probabilistic. Monte Carlo algorithms (Miller-Rabin primality, Bloom filters, HyperLogLog, Count-Min Sketch) run in fixed time/space and bound error probability exponentially via independent trials or hash bits.

Randomization Classes

Las Vegas (Exact Output) vs. Monte Carlo (Bounded Error)

Injecting OS-seeded randomness defeats worst-case inputs without complex deterministic balancing.

STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why we need Randomization (P2C, Jitter & Sublinear Sketches).

Randomization solves three massive distributed-systems problems in O(1)O(1)O(1) coordination: (1) Power-of-Two-Choices (P2C) probes 2 random backends and picks the less loaded one, cutting max queue depth from O(ln⁡n/ln⁡ln⁡n)O(\ln n / \ln\ln n)O(lnn/lnlnn) to O(ln⁡ln⁡n/ln⁡2)O(\ln\ln n / \ln 2)O(lnlnn/ln2); (2) Full Jitter breaks retry thundering herds and Raft election ties; (3) HyperLogLog counts 1 billion distinct users in 1.5 KB instead of 32 GB.

Avoid Modulo Bias (`rand() % N`)

When 232 mod N≠02^{32} \bmod N \neq 0232modN=0, rand() % N over-weights lower indices—use Lemire's fast range reduction or ThreadLocalRandom.nextInt(n).

Keyed Hashes (SipHash-2-4) Beat Hash-Flooding DoS

Unkeyed hashes like plain MurmurHash let attackers craft colliding keys; use per-process secret-keyed SipHash for untrusted hash tables.

STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

How PRNG Seeding, P2C & Full Jitter are implemented safely.

Never use global Math.random() or java.util.Random (CAS contention) on hot paths, never seed containers with time(NULL) (correlated boot jitter), and always log the seed in randomized simulations.

import random

def p2c_select(backends: list[tuple[str, int]], rng: random.Random) -> str:
    """Power-of-Two-Choices: O(1) probe cuts max queue depth exponentially."""
    if len(backends) == 1:
        return backends[0][0]
    i, j = rng.sample(range(len(backends)), 2)
    name_a, load_a = backends[i]
    name_b, load_b = backends[j]
    return name_a if load_a <= load_b else name_b

def full_jitter_delay(attempt: int, base_s: float = 0.05, cap_s: float = 5.0, rng: random.Random = None) -> float:
    r = rng or random.SystemRandom()
    return r.uniform(0.0, min(cap_s, base_s * (2 ** attempt)))

Production example: Envoy P2C Load Balancing Across 100 Pods.

At 100,000 RPS across 100 backend pods, Envoy avoids tracking all 100 queues globally and avoids pure random's O(ln⁡n/ln⁡ln⁡n)O(\ln n / \ln\ln n)O(lnn/lnlnn) skew by drawing 2 random healthy endpoints per request via thread-local PRNGs and picking the one with fewer active requests.
