Hybrid RAG: RRF Reranking
& Document-Level ACL Filtering.

Hybrid RAG combines dense HNSW vector search with sparse BM25 lexical search via Reciprocal Rank Fusion (RRF), enforces document-level ACLs via pre-filtered Roaring Bitmaps, and reranks Top-50 -> Top-5 with a Cross-Encoder.

The idea to keep with you

When batching and tail latency compete for accelerator cycles, always enforce ACL permissions as a pre-filter inside the retrieval index—never post-filter after Top-K or you risk empty results and unauthorized data leaks.

TL;DR30-second simplified summary
▾

Pure vector search excels at semantic paraphrases but fails on exact product SKUs, error codes (ERR_504_GATEWAY), and acronyms; pure BM25 catches exact keywords but misses synonyms. Hybrid RAG runs both in parallel and merges rankings with Reciprocal Rank Fusion (RRF): score(d) = sum(1 / (k + rank_i(d))).

In enterprise deployments, security is non-negotiable: if User A asks about Q4 layoffs and only 5 of 10M documents are accessible to User A, post-filtering Top-50 global results often yields 0 authorized chunks! Instead, pre-filtering with a Roaring Bitmap of the user's AD/Okta group IDs inside Qdrant/Milvus/Elasticsearch guarantees 100% authorized Top-K recall.

Architectural Mechanics

1.Dense vs. Sparse: HNSW captures synonyms and intent; BM25 preserves exact SKUs, error codes, and proper nouns.

2.Scale-Invariant Fusion: RRF sums 1 / (60 + rank) across engines without calibrating cosine vs. BM25 scores.

3.Cross-Encoder Stage: BGE-Reranker scores the Top-50 fused chunks jointly against the query for Top-5 precision.

Parallel ACL-masked HNSW and BM25 searches feed Reciprocal Rank Fusion before Cross-Encoder reranking.

Naive Solution
Use a single unpartitioned path with unbounded retries and synchronous global coordination.

Think of Reciprocal Rank Fusion (RRF) Merger as the intuition layer for Hybrid RAG: RRF Reranking & Document-Level ACL Filtering: Fuse dense and sparse rankings deterministically with RRF (k=60) and fail closed on empty ACL sets.

def reciprocal_rank_fusion(dense_ids: list[str], sparse_ids: list[str], k: int = 60, top_n: int = 50) -> list[tuple[str, float]]:
    if k <= 0 or top_n <= 0:
        raise ValueError('k and top_n must be positive')
    scores: dict[str, float] = {}
    for rank, doc_id in enumerate(dense_ids, start=1):
        scores[doc_id] = scores.get(doc_id, 0.0) + 1.0 / (k + rank)
    for rank, doc_id in enumerate(sparse_ids, start=1):
        scores[doc_id] = scores.get(doc_id, 0.0) + 1.0 / (k + rank)
    return sorted(scores.items(), key=lambda x: x[1], reverse=True)[:top_n]
STAGE 03 · SAFE IMPLEMENTATION

Reciprocal Rank Fusion (RRF) Merger

1.Fail-Closed ACL: Raise PermissionError immediately if user_principals is empty instead of running an unfiltered query.

2.Smoothing Constant k=60: Prevents rank-1 outliers from dominating while rewarding chunks appearing in both lists.

3.Deterministic Ties: Sort ties stably by document ID so identical queries yield reproducible citations.

RRF deterministically merges dense and sparse ranks while failing closed whenever principal groups are missing.
