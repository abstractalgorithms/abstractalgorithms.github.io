TCP/IP & Linux Socket Networking Internals

Master reliable byte streams, OS socket buffers, 3-way handshakes, sliding window flow control, and BBR vs CUBIC congestion mechanics under high load.

✓ When to Use

  • ✓High-throughput APIs and microservice RPCs (gRPC, REST, GraphQL) requiring ordered, lossless byte-stream transport.
  • ✓Database replication streams, transaction write-ahead logs (WAL), and distributed consensus protocols (Raft, Paxos).
  • ✓Persistent stateful connections like WebSockets and server-sent events (SSE) needing continuous bi-directional messaging without packet loss.

✕ When NOT to Use

  • ✕Real-time interactive media (VoIP, video conferencing, multiplayer gaming) where retransmitting lost packets introduces intolerable jitter; use UDP.
  • ✕Multiplexed independent streams over lossy wireless networks suffering from TCP Head-of-Line (HoL) blocking; adopt QUIC (HTTP/3 over UDP).
  • ✕Local inter-process communication on the same Linux host; use Unix Domain Sockets (AF_UNIX) to eliminate IP stack framing and checksum overhead.

Context & Constraints — Human Reviewed

Why It Matters

Every microservice RPC, distributed cache lookup, and database replication stream operates over TCP sockets. Un-tuned socket buffers introduce bufferbloat, un-pooled connections exhaust ephemeral ports in TIME_WAIT, and un-tuned accept queues silently drop connection requests during traffic spikes, spiking p99 latencies from 5ms to 1,000ms+.

Core Architecture & Rules

  • →Three-Way Handshake (SYN -> SYN-ACK -> ACK): Synchronizes initial sequence numbers (ISN) and negotiates Maximum Segment Size (MSS) and Window Scaling options before application bytes flow.
  • →Flow Control via Sliding Window (rwnd): The receiver advertises its available kernel receive buffer space in every ACK header, preventing the sender from overflowing receiver memory.
  • →Congestion Control (CUBIC vs BBR): Congestion window (cwnd) bounds unacknowledged in-flight packets. CUBIC cuts window size upon packet loss; Google's BBR models bottleneck bandwidth and round-trip propagation time to prevent router bufferbloat.
  • →Nagle's Algorithm vs Delayed ACK: Nagle buffers small outbound packets until an ACK arrives; paired with receiver's 40ms Delayed ACK, this creates pathological 40ms micro-latency spikes unless TCP_NODELAY is enabled.
  • →Connection Teardown & TIME_WAIT State: The socket endpoint that initiates active close remains in TIME_WAIT for 2×MSL (typically 60s) to drain duplicate packets; un-pooled client traffic will exhaust the 60,000 ephemeral port range.

Failure Modes & Mitigations

  • ⚖SYN Flood & Half-Open Connection Backlog:An attacker or sudden surge sends floods of SYN packets without completing the 3-way handshake, exhausting the OS SYN queue (tcp_max_syn_backlog) and dropping legitimate connections.

    Mitigation: Enable Linux SYN cookies (sysctl net.ipv4.tcp_syncookies = 1) to encode connection state in the initial sequence number without allocating kernel memory until ACK returns.

  • ⚖Silent Connection Drops via Cloud NAT / Middlebox Timeouts:Cloud NAT gateways and firewalls silently purge idle TCP connection state tracking entries after 300-350 seconds without sending TCP RST to either host.

    Mitigation: Configure OS-level or application-level keepalives (SO_KEEPALIVE) with tcp_keepalive_time = 60 and tcp_keepalive_intvl = 10 to keep NAT mapping alive.

  • ⚖Accept Queue Overflow (somaxconn Saturation):When application worker threads or event loops stall under CPU saturation, the listen backlog fills up; the kernel silently drops or RSTs completed 3-way handshakes.

    Mitigation: Increase net.core.somaxconn and pass higher backlog limits in listen(fd, backlog); alert on netstat -s ListenOverflows and ListenDrops metrics.

Example Usages

Eliminating 40ms RPC Latencies in Microservice Meshes

Scenario: A payments microservice using gRPC over HTTP/2 suffered random 40ms p99 spikes on small request payloads due to Nagle's algorithm waiting for Delayed ACKs.

Outcome: Setting socket option TCP_NODELAY = 1 disabled Nagle's buffering, dropping p99 latency from 42ms to 1.8ms across the cluster.

Resolving Ephemeral Port Exhaustion at API Edge Reverse Proxies

Scenario: An Envoy API gateway routing 50,000 req/s to backend upstreams began throwing EADDRNOTAVAIL connection errors during traffic spikes.

Outcome: Replaced per-request TCP handshakes with HTTP/2 persistent connection pooling and enabled Linux net.ipv4.tcp_tw_reuse = 1, dropping active TIME_WAIT sockets from 58,000 to under 400.
