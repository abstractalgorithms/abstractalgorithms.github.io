What are CNN, RNN, and Transformer Inductive Biases.

Why this matters: The mechanism: understand how CNN, RNN, and Transformer Inductive Biases works from first principles.

Each neural architecture encodes a structural assumption (inductive bias) about its input:

  • CNN (Convolutional Neural Network): Applies shared local spatial kernels (3x3 conv) across 2D/3D grids, giving translation equivariance and low parameter count.
  • RNN / LSTM: Updates a fixed-size hidden state sequentially ht=f(ht−1,xt)h_t = f(h_{t-1}, x_t)ht​=f(ht−1​,xt​)—giving O(1)O(1)O(1) per-token inference memory, but preventing parallel training across time and suffering vanishing gradients.
Inductive Bias & Compute

CNN (Local Kernel) vs. RNN (Sequential h_t) vs. Transformer (Global QKV)

1.Training Parallelism: Transformers process all N sequence tokens in parallel matmuls, saturating GPU Tensor Cores.

2.Path Length: Any two tokens in a Transformer interact in O(1) layers vs. O(N) steps in an RNN.

3.Inference Bottleneck: Autoregressive Transformer decoding is memory-bandwidth bound by the growing KV Cache.

Transformers trade RNN's O(1) state for massive training parallelism and global context routing.

STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why Transformers replaced RNNs (and their O(N^2) / KV-cache bottlenecks).

Why this matters: The problem: see what breaks without Why Transformers replaced RNNs under real concurrency or scale.

RNNs/LSTMs stall modern GPU clusters because step ttt cannot compute until t−1t-1t−1 finishes, and long-range gradients decay over hundreds of steps. Transformers solve both—every token attends directly to every prior token in parallel.

However, Transformers introduce two scaling bottlenecks: O(N2)O(N^2)O(N2) attention matrix memory during long-context prefill (solved via FlashAttention IO-aware tiling) and linearly growing KV-Cache VRAM during autoregressive decoding (solved via GQA and PagedAttention).

Autoregressive LLM Serving

Parallel Prefill (Compute-Bound) vs. Sequential Decode (KV-Cache Bound)

Prefill is compute-bound (parallel QKV); decode is memory-bandwidth-bound reading the KV cache.

How Scaled Dot-Product Attention & Causal Masking work in code

# Causal Scaled Dot-Product Self-Attention (PyTorch)
import math, torch
import torch.nn.functional as F

def causal_self_attention(q: torch.Tensor, k: torch.Tensor, v: torch.Tensor) -> torch.Tensor:
    # q, k, v: (batch, heads, seq_len, head_dim)
    d_k = q.size(-1)
    scores = torch.matmul(q, k.transpose(-2, -1)) / math.sqrt(d_k)
    seq_len = q.size(-2)
    causal_mask = torch.triu(torch.ones(seq_len, seq_len, device=q.device, dtype=torch.bool), diagonal=1)
    scores = scores.masked_fill(causal_mask, float("-inf"))
    attn_weights = F.softmax(scores, dim=-1)
    return torch.matmul(attn_weights, v)

Production example: FlashAttention + GQA + PagedAttention Serving.

Why this matters: Production architecture: see how the components compose end to end under real load.

Think of Production example: FlashAttention + GQA + PagedAttention Serving as the intuition layer for CNN, RNN & Transformer Architectures: Production architecture: see how the components compose end to end under real load.

Modern LLM serving stacks (vLLM, TensorRT-LLM) combine Grouped-Query Attention (GQA) (sharing K/V heads across Q heads to shrink KV cache 4–8x), FlashAttention for prefill, and PagedAttention to allocate non-contiguous KV memory blocks without fragmentation.

vLLM Serving Memory

Logical Sequence -> PagedAttention Block Table -> Physical HBM Blocks

1.Zero Fragmentation: PagedAttention eliminates contiguous max_seq_len pre-allocation, boosting batch size 2-4x.

2.Prefix Caching: Common system prompts share physical KV blocks across concurrent requests.

3.Continuous Batching: Iteration-level scheduling inserts new requests as soon as any sequence emits EOS.

GQA + PagedAttention + continuous batching turn Transformer inference into high-throughput GPU serving.
