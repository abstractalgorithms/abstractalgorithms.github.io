THE BIG IDEA / Key takeaway · CONCEPT GUIDE

Replace, don't repair: baking artifacts once into versioned images eliminates configuration drift, snowflakes, and partial-upgrade outages.

Explanation anchor
01 / The idea

Foundational mechanics & core principles

Mutable fleets accumulate undocumented hotfixes, stale libraries, and divergent kernel states over months of SSH sessions and Ansible runs. Immutable infrastructure moves mutation to build time so production nodes are disposable, byte-identical replicas of a tested artifact.

  • Build-time mutation only: tools like Packer, Docker BuildKit, or Nix bake OS packages, binaries, and systemd units into a sealed artifact.
  • Read-only runtime filesystems: distributions like Bottlerocket and Talos Linux mount / as read-only SquashFS protected by dm-verity, blocking runtime tampering.
  • Instance metadata and env injection: immutable images stay environment-agnostic by reading secrets and config at boot via IMDSv2, Vault, or Kubernetes ConfigMaps.
  • Atomic traffic cutover: Blue/Green or Canary rollouts drain ALB/Envoy connections from old instances only after new instances pass /healthz.
  • Digest pinning over mutable tags: deploying sha256:9f86d08... instead of :latest guarantees that a scale-out event at 03:00 boots the exact same bits.

Good candidates

  • Auto-scaling cloud fleets (AWS ASG, GCP MIG, Kubernetes) where nodes are frequently created and destroyed under load.
  • Regulated or security-sensitive environments requiring reproducible SBOMs, cryptographic image signing (Cosign/AMI), and 24-hour CVE rebuild SLAs.
  • Multi-region deployments where identical runtime behavior across US-East, EU-Central, and AP-South is mandatory.

Think twice

  • Stateful single-node databases (PostgreSQL primary, bare-metal Ceph OSDs) where destroying the host risks petabyte-scale data movement.
  • Bare-metal or legacy on-prem hardware without PXE/iPXE automated provisioning or API-driven hypervisors.
  • Early-stage local prototyping where 10-minute Packer AMI bake cycles slow down tight edit-compile-debug loops.

02 / Concrete walkthrough

Architectural mechanics & implementation

ScenarioA fintech API running 80 EC2 c6i.xlarge instances needs an OpenSSL security patch across three AWS regions without downtime.

The idea

Traditional server management treats machines like pets: you provision an OS once, then run Chef, Puppet, or Ansible repeatedly over months to mutate packages, sysctl flags, and binaries in place. Every failed run, manual hotfix, or skipped reboot leaves behind subtle state differences—configuration drift.

Immutable infrastructure treats compute instances like cattle by splitting the lifecycle into two strict phases. In the build phase, a pipeline starts from a clean base, installs dependencies, compiles or copies the application, runs security scans, and seals the result into a read-only artifact (an AWS AMI, GCP Image, or OCI container digest). In the runtime phase, instances boot from that artifact, fetch only environment-specific configuration (via IMDS, Vault, or Kubernetes Secrets), and never accept in-place mutations. When a CVE drops or code changes, you build a new artifact, spin up fresh instances, verify health, shift traffic, and terminate the old fleet.

Concrete walkthrough

Consider releasing checkout-api v2.14.0 on AWS EC2:

  1. Bake & Sign: GitHub Actions triggers packer build from ubuntu-24.04-minimal. Packer installs the compiled Go binary, configures systemd, applies CIS Level 1 sysctl hardening, removes openssh-server, and outputs ami-08f3c1e2a94b7d112.
  2. Provision: Terraform updates aws_launch_template.checkout with the new AMI ID and runs aws autoscaling start-instance-refresh with InstanceWarmup=120 and MinHealthyPercentage=90.
  3. Verify & Drain: New instances boot, read DB_HOST and TLS certs from AWS Secrets Manager, and pass GET /healthz on port 8080. Once the ALB marks a new target healthy, it shifts traffic and sends SIGTERM to an old instance, waiting 30 seconds (deregistration_delay) for in-flight HTTP/2 requests to finish before terminating it.
  4. Rollback: If p99 latency spikes from 40 ms to 300 ms, Terraform or the ASG reverts the Launch Template to ami-04d2a991c...—no reverse-Ansible playbooks required.

Immutable lifecycle: all mutations happen upstream of the artifact store; production nodes are replaced atomically after passing readiness probes.

Separating artifact from configuration

An image is only reusable across dev, staging, and prod if environment-specific state is decoupled from the baked bits. Follow the Twelve-Factor config boundary:

  • Baked into the image: OS kernel, libc/musl, runtime (JVM/Go/Python), application binary, static assets, default systemd or entrypoint scripts, and CA trust store.
  • Injected at boot: Database endpoints, feature flag keys, TLS leaf certificates, and region identifiers via AWS IMDSv2, GCP Metadata Server, Vault Agent, or Kubernetes CSI Secrets Store.

If you bake a staging config file into the image, you break artifact promotion: the bits you tested in staging are no longer the bits you run in production.

Failure modes

  • Slow EBS snapshot hydration: AWS lazily loads EBS blocks from S3 on first read, causing 10x latency spikes on freshly booted instances. Fix by enabling AWS EBS Fast Snapshot Restore (FSR) or warming critical binaries in /healthz.
  • Broken PreStop / draining: Terminating a pod or EC2 instance immediately on SIGTERM drops active keep-alive connections, producing HTTP 502s at the ALB. Fix with a 15–30s preStop sleep so kube-proxy/ALB endpoint removal propagates before the process exits.
  • Secret rotation deadlocks: If secrets are only read once at boot, rotating a database password requires replacing the entire fleet. Use dynamic secret leases (Vault Agent or AWS Secrets Manager rotation + SIGHUP reload).

Read-only root filesystems and runtime hardening

True immutability extends into the running OS. In Kubernetes, set securityContext.readOnlyRootFilesystem: true and allowPrivilegeEscalation: false, mounting emptyDir only for /tmp or /var/run with strict sizeLimit bounds. At the host OS layer, purpose-built Linux distributions like AWS Bottlerocket and Talos Linux eliminate shells, ssh, and package managers entirely, verifying every block read from the root partition against a cryptographic Merkle tree (dm-verity). If an attacker exploits an RCE vulnerability, they cannot drop a persistent binary or modify /etc/passwd.

Practical checklist

  • Disable SSH (sshd) and remove package managers (apt, yum, apk) in production images.
  • Pin every base image and deployment artifact by immutable sha256 digest or signed AMI ID, never :latest.
  • Enforce readOnlyRootFilesystem: true on all stateless containers and isolate scratch space to bounded emptyDir mounts.
  • Configure graceful connection draining (deregistration_delay >= 30s and terminationGracePeriodSeconds >= 45s) on all load-balanced targets.
  • Automate nightly base-image rebuilds with Trivy/Grype CVE gating and retention policies for old snapshots.
03 / Engineering trade-offs

Weighing architectural decisions

Deployment Latency

Advantage: Rollbacks take seconds by shifting load balancer targets back to the previous ASG or ReplicaSet.

Drawback: Small config or one-line script fixes require a full image build (3–15 minutes) instead of a 5-second `scp`.

Debugging & Forensics

Advantage: Eliminates 'works on node-04' mysteries because every instance is derived from the exact same immutable hash.

Drawback: No SSH or package tools (`tcpdump`, `strace`) in production forces teams to invest in eBPF sidecars, ephemeral debug containers, and centralized logs.

Storage & Registry Cost

Advantage: Predictable artifact retention with clear lineage between Git commit SHA and running AMI/container digest.

Drawback: Daily base-image rebuilds across dozens of microservices generate terabytes of EBS snapshots and ECR layers requiring lifecycle pruning.

04 / Failure modes & resilience

Explain where it breaks · Known failure modes

Boot-Time Cloud-Init Drift

Teams leave `apt-get update && apt-get install` inside `user_data` scripts; an upstream PyPI or Ubuntu mirror outage breaks auto-scaling at peak traffic.

What helps: Bake 100% of OS and application dependencies into the Packer/Docker image and restrict `user_data` to fast local wiring (env vars, hostname).

Mutable Tag Hijacking (`:latest`)

A scale-out event pulls `:prod` after a bad push, creating a split-brain fleet running two different binary versions under the same tag.

What helps: Enforce immutable image tags and SHA-256 digests in Kubernetes admission controllers (Kyverno/OPA Gatekeeper) and Terraform.

Slow Image Pulls During Traffic Spikes

Bloated 4 GB container images cause `ImagePullBackOff` or 5-minute cold starts when HPA scales from 10 to 100 pods.

What helps: Use multi-stage distroless builds (<100 MB), pre-warm EBS snapshots (AWS Fast Snapshot Restore), or enable eStargz lazy-pulling.

Stateful Data Loss on Instance Termination

An engineer stores local upload caches or SQLite files on instance ephemeral NVMe; an ASG replacement silently wipes customer data.

What helps: Externalize all state to RDS, S3, or detached EBS/PVCs with `Retain` reclaim policies and mount root filesystems read-only.

05 / Practical checklist

Avoid these mistakes

  • Leaving SSH port 22 open 'just in case', which inevitably tempts engineers to apply undocumented hotfixes during incidents.
  • Hardcoding environment-specific secrets or database URLs inside the baked image instead of injecting them at runtime.
  • Forgetting to configure graceful connection draining (`deregistration_delay` / `preStop` sleep), causing 502 errors during instance replacement.
  • Skipping automated smoke tests against the newly baked AMI before promoting its ID to production Terraform state.
  • Never garbage-collecting old AMIs and container layers, leading to silent AWS snapshot quota exhaustion.
