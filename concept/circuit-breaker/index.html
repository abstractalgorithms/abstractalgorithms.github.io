STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What is a Circuit Breaker.

Why this matters: The mechanism: understand how a Circuit Breaker works from first principles.

A circuit breaker wraps remote RPC/HTTP calls in a three-state finite state machine:

  • CLOSED: Normal traffic passes through while recording success/failure/slow-call outcomes in a sliding window.
  • OPEN: When failure rate (e.g., >= 50%) or slow-call ratio (> 2,000 ms) crosses threshold, calls fail immediately in microseconds (CallNotPermittedException / 503) without touching the network.
Resilience FSM

Circuit Breaker CLOSED -> OPEN -> HALF-OPEN State Machine

Failing fast in OPEN state protects caller thread pools and gives the degraded downstream service room to recover.

STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why we need Circuit Breakers (and common misconfigurations).

Why this matters: The problem: see what breaks without Circuit Breakers under real concurrency or scale.

When a Fraud Scoring gRPC service's p99 jumps from 45 ms to 6,000 ms, 200 Tomcat worker threads at 100 RPS saturate in 2 seconds—crashing /healthz too. A circuit breaker stops calling Fraud Scoring and serves a safe fallback.

Avoid three classic breaker bugs:

  1. Counting 4xx as Failures: Counting 400 Bad Request or 404 Not Found lets one buggy client trip the breaker for every tenant—ignore business/client errors.
  2. Half-Open Thundering Herd: Without permittedNumberOfCallsInHalfOpenState (e.g., 5) and jitter on the open timer, 100 pods probe simultaneously and re-crash the recovering service.
  3. Wrong Decorator Order: Retrying outside a circuit breaker wastes retries; retrying inside lets a single logical call burn 3x attempts before recording 1 failure.
Fast-Fail Protection

Fraud gRPC Stall -> Breaker Trips OPEN -> Order API Stays Healthy

Tripping OPEN drops thread hold time from 500ms-6s down to 0ms, keeping the caller's worker pool healthy.

Engineering Decision Framework
Problem
How to implement Circuit Breaker Pattern without hitting unbounded tail latency, state divergence, or operational fragility.
Naive Solution
Use a single unpartitioned path with unbounded retries and synchronous global coordination.
Why It Fails
Global coordination serializes throughput under load, while unbounded retries amplify transient stalls into full outages.
Alternatives
Compare synchronous strict-consistency paths against bounded asynchronous replication, local caching, or partitioned ownership.
Engineering Decision
When traffic spikes expose hidden coupling, pair tight client timeouts with a circuit breaker so a degraded dependency triggers deterministic fallbacks instead of a cascading thread-pool collapse.
Trade-Offs
Gains predictable p99 latency and fault isolation in exchange for explicit bounding, observability, and slightly higher implementation complexity.

Lifecycle & Failure Recovery

How Circuit Breakers, Sliding Windows, and Fallbacks are implemented

# Circuit Breaker with CLOSED / OPEN / HALF-OPEN & jittered cooldown (Python)
import random, time

class CircuitBreaker:
    def __init__(self, fail_threshold: int = 5, cooldown_s: float = 15.0, half_open_probes: int = 3):
        self.state = "CLOSED"
        self.failures = 0
        self.fail_threshold = fail_threshold
        self.cooldown_s = cooldown_s
        self.half_open_probes = half_open_probes
        self.probes_ok = 0
        self.opened_at = 0.0

    def allow_request(self) -> bool:
        if self.state == "OPEN":
            if time.monotonic() - self.opened_at >= self.cooldown_s:
                self.state = "HALF_OPEN"
                self.probes_ok = 0
                return True
            return False
        return True

    def record_success(self):
        if self.state == "HALF_OPEN":
            self.probes_ok += 1
            if self.probes_ok >= self.half_open_probes:
                self.state, self.failures = "CLOSED", 0
        else:
            self.failures = 0

    def record_failure(self): # call only on 5xx / timeout, NEVER on 4xx
        self.failures += 1
        if self.state == "HALF_OPEN" or self.failures >= self.fail_threshold:
            self.state = "OPEN"
            self.opened_at = time.monotonic() + random.uniform(0.0, 2.0) # jittered reset

Decorator Stack

Retry (Outer) -> Circuit Breaker -> TimeLimiter -> Bulkhead -> Downstream

1.Correct Nesting: Placing Retry outside CircuitBreaker prevents retrying against an already-OPEN breaker.

2.Slow-Call Tracking: Tripping on slow_call_rate (>2,000ms) catches gray failures that return 200 OK too late.

3.Alert on Sustained OPEN: Page on-call only if state stays OPEN > 2 minutes while fallback serves degraded UX.
