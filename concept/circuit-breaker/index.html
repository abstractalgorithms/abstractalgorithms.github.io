01
STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What is a Circuit Breaker.

A circuit breaker wraps remote RPC/HTTP calls in a three-state finite state machine:

  • CLOSED: Normal traffic passes through while recording success/failure/slow-call outcomes in a sliding window.
  • OPEN: When failure rate (e.g., >= 50%) or slow-call ratio (> 2,000 ms) crosses threshold, calls fail immediately in microseconds (CallNotPermittedException / 503) without touching the network.
  • HALF-OPEN: After waitDurationInOpenState (e.g., 30s + jitter), a small probe budget (5 requests) tests recovery before closing or re-opening.
Resilience FSM

Circuit Breaker CLOSED -> OPEN -> HALF-OPEN State Machine

Failing fast in OPEN state protects caller thread pools and gives the degraded downstream service room to recover.

02
STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why we need Circuit Breakers (and common misconfigurations).

When a Fraud Scoring gRPC service's p99 jumps from 45 ms to 6,000 ms, 200 Tomcat worker threads at 100 RPS saturate in 2 seconds—crashing /healthz too. A circuit breaker stops calling Fraud Scoring and serves a safe fallback.

Avoid three classic breaker bugs:

  1. Counting 4xx as Failures: Counting 400 Bad Request or 404 Not Found lets one buggy client trip the breaker for every tenant—ignore business/client errors.
  2. Half-Open Thundering Herd: Without permittedNumberOfCallsInHalfOpenState (e.g., 5) and jitter on the open timer, 100 pods probe simultaneously and re-crash the recovering service.
  3. Wrong Decorator Order: Retrying outside a circuit breaker wastes retries; retrying inside lets a single logical call burn 3x attempts before recording 1 failure.
Fast-Fail Protection

Fraud gRPC Stall -> Breaker Trips OPEN -> Order API Stays Healthy

Tripping OPEN drops thread hold time from 500ms-6s down to 0ms, keeping the caller's worker pool healthy.

Count-Based vs. Time-Based Windows

Count-based ring buffers (last 100 calls) adapt naturally to low-RPS endpoints; time-based buckets react faster at high RPS.

Prometheus Telemetry

Emit resilience4j_circuitbreaker_state and call outcome counters (failed, successful, not_permitted) to alert on sustained OPEN states.

03
STAGE 03 · WHERE IT IS USEDL5 · APPLIED DESIGN

Where Circuit Breakers belong (and where they don't).

Use circuit breakers on non-critical or fallback-capable remote dependencies (recommendations, fraud scoring, third-party webhooks). Avoid tripping a breaker on your own primary database unless you have a meaningful degraded read-only fallback.

ChoiceWhat it buysWhat it costs
Per-Dependency RPC / HTTP ClientsIsolates each downstream (Fraud, Pricing, Shipping) with independent sliding windows.Per-pod breakers can have uneven views at low RPS unless paired with Envoy outlier detection.
Envoy Outlier Detection (Mesh L7)Ejects individual unhealthy backend pods from the load-balancer pool based on consecutive 5xx.Pod-level ejection, not full-service fallback—still pair with app fallbacks when all pods fail.
Avoid: Single Global Breaker Across Multi-Tenant EndpointsPartition breakers by dependency or tenant tier.One broken endpoint or tenant would cut off healthy traffic sharing the same breaker.
04
STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

How Circuit Breakers, Sliding Windows, and Fallbacks are implemented.

Configure minimumNumberOfCalls (e.g., 20) so low traffic never trips on 1 error, exclude 4xx exceptions, and add jitter to waitDurationInOpenState.

# Circuit Breaker with CLOSED / OPEN / HALF-OPEN & jittered cooldown (Python)
import random, time

class CircuitBreaker:
    def __init__(self, fail_threshold: int = 5, cooldown_s: float = 15.0, half_open_probes: int = 3):
        self.state = "CLOSED"
        self.failures = 0
        self.fail_threshold = fail_threshold
        self.cooldown_s = cooldown_s
        self.half_open_probes = half_open_probes
        self.probes_ok = 0
        self.opened_at = 0.0

    def allow_request(self) -> bool:
        if self.state == "OPEN":
            if time.monotonic() - self.opened_at >= self.cooldown_s:
                self.state = "HALF_OPEN"
                self.probes_ok = 0
                return True
            return False
        return True

    def record_success(self):
        if self.state == "HALF_OPEN":
            self.probes_ok += 1
            if self.probes_ok >= self.half_open_probes:
                self.state, self.failures = "CLOSED", 0
        else:
            self.failures = 0

    def record_failure(self): # call only on 5xx / timeout, NEVER on 4xx
        self.failures += 1
        if self.state == "HALF_OPEN" or self.failures >= self.fail_threshold:
            self.state = "OPEN"
            self.opened_at = time.monotonic() + random.uniform(0.0, 2.0) # jittered reset

Alternatives: Circuit Breaker vs. Bulkhead vs. Adaptive Concurrency.

Compare the three core resilience primitives and how they compose.

ChoiceWhat it buysWhat it costs
Circuit BreakerDrops wait time to 0 ms when a dependency is failing; enables deterministic fallbacks.Reactive—first N calls still hit timeout before tripping; needs careful 4xx exclusion.
Bulkhead (Semaphore / Thread Pool)Proactively caps max concurrent exposure per dependency at all times.Still waits up to client timeout on each admitted call while dependency is slow.
Adaptive Concurrency (AIMD / Little's Law)Dynamically shrinks concurrency limit as RTT rises—no static threshold tuning.Complex to debug when combined with aggressive autoscaling.

STAGE 06 · PRODUCTION ARCHITECTUREL7 · STAFF / PRINCIPAL

Production example: Timeout -> Circuit Breaker -> Bulkhead -> Fallback.

Production Resilience4j/Envoy stacks compose decorators cleanly: Rate Limiter -> Retry (with jitter, idempotent only) -> Circuit Breaker -> TimeLimiter -> Bulkhead, ensuring retries stop immediately once the breaker trips OPEN.

Decorator Stack

Retry (Outer) -> Circuit Breaker -> TimeLimiter -> Bulkhead -> Downstream

1.Correct Nesting: Placing Retry outside CircuitBreaker prevents retrying against an already-OPEN breaker.

2.Slow-Call Tracking: Tripping on slow_call_rate (>2,000ms) catches gray failures that return 200 OK too late.

3.Alert on Sustained OPEN: Page on-call only if state stays OPEN > 2 minutes while fallback serves degraded UX.

Proper decorator ordering stops retry storms and converts 6-second hangs into 0 ms fallbacks.
