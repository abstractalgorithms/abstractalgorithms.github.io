01
STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What is GPU Inference Batching.

Serving a neural network at batch size 1 leaves modern GPUs (A100/H100) 80–90% idle because streaming weights from HBM into SRAM dominates compute time.

Batching amortizes one HBM weight read across BBB inputs, raising arithmetic intensity (FLOPs/byte) toward the GPU's roofline and multiplying throughput 5–20x per GPU.

Continuous Batching

Iteration-Level LLM Batching (Zero Head-of-Line Blocking)

Unlike static request-level batching, continuous batching ejects finished sequences on every token step.

02
STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why Static Batching causes Head-of-Line Blocking & Decode Stutter.

Two failure modes wreck tail latency in naive GPU servers:

  • Head-of-Line (HoL) Blocking: in static request-level batches, one 4,096-token generation stalls 15 already-finished 64-token requests, spiking p99 10x.
  • Prefill-Decode Interference: a 16k-token prompt prefill hogs GPU SMs for 400 ms, causing visible streaming stutter (ITL > 200 ms) for all active decode users.

Chunked Prefill

Split long 16k prefills into 512-token chunks interleaved with decode steps to keep inter-token latency smooth.

Length Bucketing / Ragged Tensors

Avoid wasting FLOPs on zero-padding by bucketing sequence lengths or using packed/ragged attention kernels.

STAGE 03 · WHERE IT IS USEDL5 · APPLIED DESIGN

Where GPU Batching applies (and where batch=1 wins).

Batching pays off when concurrent requests overlap within a 2–15 ms window.

ChoiceWhat it buysWhat it costs
Good Candidate: High-Concurrency Encoders & LLMs (>20 RPS)5–20x GPU throughput gain with sub-10 ms queue windows or continuous iteration batching.Requires PagedAttention KV-cache block management for LLMs.

04
STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

Dynamic Batching (Triton) & Continuous Batching (vLLM).

Set tight max_queue_delay_microseconds (2–10 ms) for encoders in Triton, and enable enable_chunked_prefill + max_num_batched_tokens in vLLM for LLMs.

# NVIDIA Triton config.pbtxt for fixed-shape embedding/vision encoders
dynamic_batching {
  preferred_batch_size: [ 8, 16, 32 ]
  max_queue_delay_microseconds: 5000  # 5 ms ceiling on queue wait
}

# vLLM continuous batching with chunked prefill to protect decode ITL
vllm serve meta-llama/Llama-3.1-8B-Instruct \
  --enable-chunked-prefill --max-num-batched-tokens 2048 --max-num-seqs 128

STAGE 05 · ALTERNATIVESL6 · SCALE & TRADE-OFFS

Alternatives: Dynamic Request Batching vs. Continuous Batching vs. Disaggregated P/D.

Match the batching scheduler to model architecture and TTFT/ITL SLOs.

ChoiceWhat it buysWhat it costs
Dynamic Request Batching (Triton)Simple to configure for fixed-compute encoders, embeddings, and vision models.Causes severe HoL blocking on variable-length autoregressive LLMs.
Continuous Batching + PagedAttention (vLLM / TensorRT-LLM)Zero HoL blocking; high KV-cache memory utilization via 16-token pages.Complex block-table scheduler; long prefills still contend with decodes unless chunked.
Disaggregated Prefill / Decode PoolsEliminates prefill-decode interference completely by isolating compute-bound prefill from bandwidth-bound decode.Requires fast RDMA/NVLink KV-cache transfer between prefill and decode GPUs.
06
STAGE 06 · PRODUCTION ARCHITECTUREL7 · STAFF / PRINCIPAL

KV-Cache Aware Router + Continuous Batching Pool.

At scale, an L7 inference router uses prefix-cache-aware consistent routing to steer repeated system-prompt prefixes to the same vLLM replica (maximizing RadixAttention/APC KV-cache hits) while shedding load when GPU KV-cache utilization exceeds 90%.

Inference Serving Tier

Prefix-Aware Router -> Continuous Batching Engine -> Paged KV HBM

1.1. Prefix Affinity: Routing identical system prompts to the same replica reuses cached KV blocks.

2.2. KV Backpressure: Reject or queue at the gateway when KV-cache occupancy > 90% to avoid preemption thrashing.

3.3. Smooth ITL: Chunked prefill bounds inter-token latency even when 16k-token prompts arrive.

Prefix routing + chunked continuous batching maximizes GPU arithmetic intensity without sacrificing streaming smoothness.
