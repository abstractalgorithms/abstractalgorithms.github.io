STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What are the Four Core Algorithm Patterns.

Most brute-force sequence and optimization algorithms fail at scale because they re-examine identical ranges (O(n^2)) or recompute identical subproblems (O(2^n)). These four patterns eliminate redundant work by exploiting structural invariants:

  • Two Pointers: On sorted or partitioned data, left and right move monotonically, pruning O(n^2) pairs to O(n) in O(1) space.
  • Fast & Slow Pointers (Floyd's): Advancing slow by +1 and fast by +2 detects cycles and midpoints in O(n) time and O(1) space.
  • Sliding Window: Expands right to include state and shrinks left only when a monotonic invariant breaks (O(n) amortized).
  • Dynamic Programming (DP): Caches overlapping subproblems (dp[i] or dp[i][j]) via memoization or bottom-up tabulation.
Window Invariant

Sliding Window Expand / Shrink State Machine

Each pointer crosses each element at most once, bounding total work to 2n operations = O(n) amortized time.

STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why we need Structural Invariants at Production Scale.

Production bottlenecks—from API gateway rate limiters and stream deduplication to config diff engines and knapsack schedulers—rely on these patterns to keep tail latency O(n) and memory bounded.

API Gateway Sliding-Window Rate Limiter

Scanning a full timestamp log on every request degraded to O(n) under 50k RPS bursts. A Sliding Window deque (evicting < now - 60s from left while pushing now at right) reduced per-request amortized work to O(1) (<0.3 ms p99).

Memory-Bounded Diff Engine (1D Rolling DP)

Computing Levenshtein edit distance on 20,000-line configs with a 2D dp[m][n] matrix allocated 1.6 GB RAM and OOMKilled. Compressing DP state to two 1D rolling rows (O(min(m, n)) space) cut RAM to 160 KB.

Where each Pattern Applies (and When to Switch).

Matching the wrong pattern—such as using a shrinkable Sliding Window on an array with negative weights—silently breaks correctness.

ChoiceWhat it buysWhat it costs
Two Pointers / Sliding WindowO(n) time, O(1)–O(k) space for sorted pair sums, partitions, and non-negative contiguous subarrays.Negative numbers break shrink monotonicity; switch to Prefix Sum + HashMap (`O(n)` space).
Fast & Slow PointersDetects cycles and finds cycle entry (`a = (k-1)L + c`) in O(1) space without a HashSet.Requires functional graph/next-pointer determinism; must guard `fast != null && fast.next != null`.
Dynamic ProgrammingSolves min/max cost and counting problems when greedy local choices fail.Can require `O(n * W)` time; avoid when greedy (Dijkstra, Huffman) is provably optimal.

STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

How to implement Sliding Window & 1D Compressed DP Safely.

In 0/1 Knapsack (dp[i][w] = max(dp[i-1][w], val[i] + dp[i-1][w - wt[i]])), row i depends only on row i-1 at smaller weights. Iterating w backward (W down to wt[i]) in a 1D array preserves dp[i-1][w - wt[i]] intact; iterating forward silently turns 0/1 Knapsack into Unbounded Knapsack. Always convert deep top-down DP (n > 10^4) to bottom-up tabulation to avoid stack overflow.

# 1. Minimum Window Substring (Sliding Window, O(|s| + |t|))
from collections import Counter

def min_window(s: str, t: str) -> str:
    need = Counter(t)
    have, required, formed = {}, len(need), 0
    left, best = 0, (float('inf'), 0, 0)
    for right, ch in enumerate(s):
        have[ch] = have.get(ch, 0) + 1
        if ch in need and have[ch] == need[ch]:
            formed += 1
        while formed == required:
            if right - left + 1 < best[0]:
                best = (right - left + 1, left, right)
            out = s[left]
            have[out] -= 1
            if out in need and have[out] < need[out]:
                formed -= 1
            left += 1
    return '' if best[0] == float('inf') else s[best[1]:best[2] + 1]

# 2. 0/1 Knapsack with O(W) 1D rolling array (backward capacity loop)
def knapsack_01(weights: list[int], values: list[int], W: int) -> int:
    dp = [0] * (W + 1)
    for wt, val in zip(weights, values):
        for w in range(W, wt - 1, -1):
            dp[w] = max(dp[w], val + dp[w - wt])
    return dp[W]

STAGE 05 · ALTERNATIVESL6 · SCALE & TRADE-OFFS

Alternatives & Complexity Trade-Offs.

Compare pattern alternatives when choosing between time, auxiliary memory, and recursion depth.

ChoiceWhat it buysWhat it costs
Top-Down Memoization vs. Bottom-Up TabulationTop-down computes only reachable states and is quick to prototype.Crashes with `RecursionError` above ~10^4 depth; bottom-up enables 1D `O(W)` compression.
Sorting + Two Pointers vs. Hash Map (2-Sum)Two Pointers uses O(1) extra space and avoids hash-collision worst cases.Costs `O(n log n)` to sort and alters original indices unless paired with index tuples.
Sliding Window vs. Prefix Sum + Hash MapSliding Window runs in O(1) space for non-negative subarray sums.Fails on negative weights; Prefix Sum + HashMap handles negatives in O(n) time and O(n) space.

STAGE 06 · PRODUCTION ARCHITECTUREL7 · STAFF / PRINCIPAL

Production Pattern Selection & Composition.

Real-world systems frequently compose patterns: Longest Increasing Subsequence (LIS) pairs DP state (tails[len]) with binary search to drop O(n^2) to O(n log n), while Sliding Window Maximum pairs a Sliding Window with a monotonic decreasing deque (O(n)) to track rolling p100 latency spikes without O(n log k) heap overhead.
