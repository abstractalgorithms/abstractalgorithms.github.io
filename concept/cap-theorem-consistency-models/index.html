STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What are CAP and PACELC.

Eric Brewer's CAP Theorem (Gilbert & Lynch, 2002) proves that when a network partition (P) splits a distributed store, it must choose between:

  • Consistency (C — Linearizability): Every read returns the most recent completed write in real-time order (or an error).
  • Availability (A): Every non-failing node returns a non-error response, even if stale.

PACELC (Daniel Abadi, 2012) adds the missing half: if P (partition), choose A or C; else (E) (normal operation), choose L (latency) or C (consistency).

PC/EC vs. PA/EL Partition

3-Region Cluster Under Network Partition (N1/N2 vs. Isolated N3)

1.PC/EC (etcd, Spanner): Majority (N1+N2) commits $80; isolated N3 rejects writes/reads to preserve linearizability.

2.PA/EL (Dynamo, Cassandra): Isolated N3 still accepts writes locally, risking divergent values reconciled later via CRDTs/LWW.

3.Normal-Op Latency Tax: Even without a partition, PC/EC pays cross-node RTT on writes while PA/EL responds locally.

During a partition, PC/EC fences the minority side while PA/EL stays available on both sides and reconciles later.

STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why we need Consistency Models (and how naive assumptions fail).

Treating 'CP vs AP' as a binary switch leads to three expensive production failures:

  1. Quorum Without Linearizability: Setting W+R>NW + R > NW+R>N (e.g., N=3,W=2,R=2N=3, W=2, R=2N=3,W=2,R=2) ensures overlap in Dynamo-style stores, but without leader/read-repair coordination, concurrent writes + partial propagation can still violate linearizability.
  2. Clock-Skew LWW Overwrites: Using Last-Write-Wins (LWW) with wall clocks when NTP drifts 150 ms lets older writes silently overwrite newer writes.
  3. Asymmetric / Gray Partitions: N1 can reach N2, N2 can reach N3, but N1 cannot reach N3—breaking naive health checks.
Consistency Spectrum

Stale Read Risk on Async Replica vs. Linearizable Quorum Read

Reading from async replicas violates read-your-own-writes; linearizable reads require quorum ReadIndex or valid leader leases.

Consistency Hierarchy

Linearizability (strongest, real-time) > Sequential > Causal (preserves happens-before) > Eventual (converges if writes stop).

TrueTime & HLC

Google Spanner uses GPS/atomic TrueTime [-7ms, +7ms] for external consistency; CockroachDB uses Hybrid Logical Clocks (HLC).

Where Different PACELC Classes belong in one system.

Production architectures rarely pick one PACELC class globally—they place each domain on the store whose guarantees match its invariants.

ChoiceWhat it buysWhat it costs
PC/EC (PostgreSQL, etcd, Spanner, CockroachDB)Linearizable/serializable guarantees for billing, inventory, identity, and leader election.10-85 ms write RTT across zones/regions; minority partition rejects writes.
PA/EL (Cassandra, DynamoDB default, Redis)Sub-5 ms local writes and high availability for carts, sessions, feeds, and telemetry.Eventual consistency requires CRDTs, idempotency, or read-repair to resolve conflicts.
PC/EL (Tunable DynamoDB / MongoDB)Fast local reads when healthy (EL), strict quorum/majority writes when configured.Default eventual reads can return stale values right after a write unless ConsistentRead=true.
04
STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

How Quorums, Session Consistency, and Conflict Resolution are managed.

Bridge consistency and latency in application code:

  1. Read-Your-Own-Writes: Pin a user's reads to the primary (or pass a monotonic LSN/commit token) for a few seconds after their write.
  2. Never Use Wall-Clock LWW for Critical State: Use CRDTs (OR-Set, PN-Counter) or HLC/version vectors instead of raw timestamps.
  3. Leader Leases / ReadIndex: In Raft stores, serve linearizable reads via ReadIndex without writing a log entry.
# LSN-pinned Read-Your-Own-Writes router (Python)
def route_read(user_id: str, session_min_lsn: int, primary_db, replica_db):
    # Check if async replica has caught up to user's last write LSN
    if replica_db.current_replay_lsn() >= session_min_lsn:
        return replica_db.query_user(user_id)
    # Fall back to primary only for the brief replication lag window
    return primary_db.query_user(user_id)

STAGE 06 · PRODUCTION ARCHITECTUREL7 · STAFF / PRINCIPAL

Production example: Hybrid PC/EC Core + PA/EL Edge Store.

A global e-commerce platform keeps inventory, payments, and auth on a PC/EC store (Spanner / CockroachDB) while serving product catalog, session carts (CRDTs), and user feeds from a PA/EL store (DynamoDB Global Tables / Redis).

Polyglot Consistency

Edge Gateway -> PA/EL Carts & Catalog vs. PC/EC Payments & Inventory

1.Zero Over-Selling: Inventory decrement and payment capture execute in PC/EC ACID transactions.

2.Always-On Carts: Shopping carts use PA/EL add-wins CRDT sets so users can add items even during a region split.

3.Causal Session Tokens: Write responses return an LSN/token so immediate follow-up reads see own writes.

Splitting PC/EC correctness from PA/EL availability gives both zero double-spends and 99.999% shopping uptime.
