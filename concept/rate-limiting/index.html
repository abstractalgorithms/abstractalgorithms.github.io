The idea to keep with you

Rate limiting enforces caps on request or resource consumption per caller, tenant, or endpoint over time to protect downstream capacity, ensure fair multi-tenant sharing, and blunt abuse.

TL;DR30-second simplified summary
▾

Core Mechanics: Rate limiting decouples incoming demand from system capacity by enforcing an admission budget keyed by tenant_id, api_key, or ip:route before expensive auth or database work runs.

Visual & Structural Flow: Depicts Two-Tier Local Token Bucket + Redis Lua Global Rate Limiter (API Client -> Gateway L1 Bucket -> Redis Lua (L2) -> Origin Service); Local Token-Lease Batching + Async Redis Sync (Client (500k RPS) -> Edge Gateway -> Regional Redis).

Trade-Offs & Production: Choose the algorithm based on memory per key, burst tolerance, and exactness. To eliminate cross-region RTT and Redis hot-key contention at 500,000 RPS, regional Envoy gateways enforce local in-memory Token Buckets and asynchronously batch-sync quota leases.

Failure Modes & Application: Explore distributed rate limiter architectures, token bucket designs, and retry-storm prevention.

01
STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What is Rate Limiting.

Rate limiting decouples incoming demand from system capacity by enforcing an admission budget keyed by tenant_id, api_key, or ip:route before expensive auth or database work runs.

Token Bucket allows controlled bursts up to capacity BBB while capping sustained rate at RRR tokens/sec in O(1)O(1)O(1) memory. Leaky Bucket smooths bursts into a constant egress rate. Sliding Window Counter eliminates the 2x boundary-burst spike of Fixed Windows in O(1)O(1)O(1) space.

Hybrid Edge + Global Quota

Two-Tier Local Token Bucket + Redis Lua Global Rate Limiter

1.1. Edge Rejection: Reject 429s at the outermost L7 proxy before JWT verification or DB queries.

2.2. Atomic Lua: Single Redis EVALSHA script reads/refills/decrements tokens and sets PEXPIRE TTL atomically.

3.3. Fail-Open Fallback: If Redis is unreachable, fall back to the gateway's local in-memory Token Bucket.

Hybrid local + Redis Lua rate limiting protects origin pools in <1 ms without a single point of failure.

02
STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why we need Rate Limiting (Race Conditions & Boundary Stampedes).

Without rate limiting, a single buggy retry loop or scraper saturates DB pools and causes 503 outages for all tenants. Implementing it naively introduces two classic bugs: (1) separate Redis GET then INCR commands create read-modify-write race conditions that over-admit concurrent bursts; (2) Fixed Window Counters allow 2x quota (1,000 req at 12:00:59 + 1,000 req at 12:01:01).

Weighted Cost Budgets

Charge cost = 1 for GET /items/{id} and cost = 25 for POST /search/export against the same tenant bucket so heavy routes cannot starve cheap ones.

IETF RateLimit Headers + `429`

Always return 429 Too Many Requests (never 500/503) with Retry-After, RateLimit-Limit, RateLimit-Remaining, and RateLimit-Reset.

03
STAGE 03 · WHERE IT IS USEDL5 · APPLIED DESIGN

Where Rate Limiting applies (and where Healthchecks Must Bypass).

Apply rate limits to public APIs, login/OTP endpoints, and expensive LLM/export routes; exempt internal healthchecks and metrics scrapes.

ChoiceWhat it buysWhat it costs
Good Candidate: Public APIs, Login/OTP & Multi-Tenant QuotasPrevents brute-force attacks, scraping, and noisy-neighbor DB pool exhaustion.Requires keying authenticated routes on `tenant_id`/`api_key_hash` rather than shared carrier NAT IPs.
Avoid: `/healthz`, Readiness & Prometheus Scrape PathsKeep probe endpoints unthrottled so Kubernetes never triggers false-positive pod restarts under load.Throttling `/healthz` turns a traffic spike into a cascading pod-eviction outage.
Avoid: Pure Downstream Slowness BottlenecksUse adaptive concurrency limits (Vegas/Gradient2) or backpressure when downstream latency degrades regardless of RPS.Static RPS limits cannot adapt when DB queries slow from 5 ms to 500 ms.
04
STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

How Atomic Token Buckets & Redis Lua are implemented.

Use Redis TIME inside Lua scripts (avoiding gateway wall-clock skew), attach PEXPIRE TTLs to every key so one-off IPs never leak RAM, and deploy new limits in shadow/dry-run mode (enforce: false) before blocking traffic.

-- Atomic Redis Token Bucket (KEYS[1]=key, ARGV[1]=cap, ARGV[2]=rate_per_sec, ARGV[3]=cost)
local t = redis.call('TIME')
local now = tonumber(t[1]) + tonumber(t[2]) / 1000000
local data = redis.call('HMGET', KEYS[1], 'tokens', 'ts')
local tokens = tonumber(data[1]) or tonumber(ARGV[1])
local last = tonumber(data[2]) or now

tokens = math.min(tonumber(ARGV[1]), tokens + math.max(0, now - last) * tonumber(ARGV[2]))
local allowed = 0
if tokens >= tonumber(ARGV[3]) then
  tokens = tokens - tonumber(ARGV[3])
  allowed = 1
end
redis.call('HMSET', KEYS[1], 'tokens', tokens, 'ts', now)
redis.call('PEXPIRE', KEYS[1], math.ceil((tonumber(ARGV[1]) / tonumber(ARGV[2])) * 1000) + 1000)
return {allowed, math.floor(tokens)}

STAGE 05 · ALTERNATIVESL6 · SCALE & TRADE-OFFS

Alternatives: Token Bucket vs. Sliding Window Log vs. Sliding Window Counter.

Choose the algorithm based on memory per key, burst tolerance, and exactness.

ChoiceWhat it buysWhat it costs
Token Bucket (Redis Hash / Local)$O(1)$ memory (2 numbers), allows controlled bursts up to $B$, zero boundary spikes.Requires atomic Lua script for distributed accuracy.
Sliding Window Counter$O(1)$ memory and smooths 2x fixed-window boundary spikes via weighted overlap.Approximate interpolation across the previous window.
Sliding Window Log (Redis `ZSET`)100% exact to the millisecond with zero boundary approximation.Stores $O(N)$ timestamps per key—explodes RAM for high-rate tenants.

STAGE 06 · PRODUCTION ARCHITECTUREL7 · STAFF / PRINCIPAL

Production example: Multi-Region Gateway with Token-Lease Batching.

To eliminate cross-region RTT and Redis hot-key contention at 500,000 RPS, regional Envoy gateways enforce local in-memory Token Buckets and asynchronously batch-sync quota leases (INCRBY 50) with a regional Redis/Valkey shard every 50–100 ms.

Hot-Key Mitigation

Local Token-Lease Batching + Async Redis Sync

Batching 50-token leases cuts Redis QPS by 50x and keeps normal API checks at sub-millisecond local latency.
