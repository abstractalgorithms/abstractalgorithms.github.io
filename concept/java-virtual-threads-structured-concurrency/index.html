STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What are Java Virtual Threads.

Traditional platform threads map 1:1 to OS kernel threads (~1 MB stack each), capping Spring/Tomcat servers at ~200–500 concurrent requests. Java 21+ Virtual Threads (Project Loom) are cheap JVM-managed continuations (~few KB) multiplexed onto a small ForkJoinPool of carrier OS threads.

When a virtual thread hits blocking I/O (Socket, LockSupport), the JVM unmounts its stack chunk onto the heap and frees the carrier OS thread to run another virtual thread—scaling imperative blocking code to 100,000+ concurrent tasks.

JVM Scheduler

Virtual Thread Mount / Unmount & Carrier Pinning State Machine

Replacing synchronized around I/O with ReentrantLock (or upgrading to Java 24+ JEP 491) prevents carrier-thread pinning.

02
STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why Virtual Threads Replace Reactive Chains Without Losing Scale.

Reactive frameworks (WebFlux/Netty) scale to 100k connections, but fragment stack traces, break try/catch and ThreadLocal, and steepen onboarding. Virtual threads restore readable imperative code and clean stack traces while keeping the same non-blocking OS efficiency.

Never Pool Virtual Threads

Virtual threads are cheap, disposable tasks—never wrap them in a fixed Executors.newFixedThreadPool. Use Executors.newVirtualThreadPerTaskExecutor() and bound downstream resources with a Semaphore.

Avoid `ThreadLocal` Bloat

Caching large buffers (e.g., 64 KB SimpleDateFormat or Jackson buffers) in ThreadLocal across 100,000 virtual threads explodes heap! Prefer immutable ScopedValue.

03
STAGE 03 · WHERE IT IS USEDL5 · APPLIED DESIGN

Where Virtual Threads Shine (and Where Platform Pools Still Rule).

Virtual threads are built for high-concurrency I/O wait; CPU-bound math still needs a core-sized pool.

ChoiceWhat it buysWhat it costs
Good Candidate: I/O-Bound Fan-Out & MicroservicesREST/gRPC fan-out, JDBC queries, and Redis calls scale to 50k+ concurrent tasks with imperative code.50k virtual threads will crush a 20-connection PostgreSQL pool unless gated by a `Semaphore`.
Good Candidate: Structured Concurrency (`StructuredTaskScope`)Ties child task lifetimes to a lexical `try`-with-resources block, canceling sibling RPCs immediately if one fails (`ShutdownOnFailure`).Requires JDK 21+ preview/standard APIs and disciplined cancellation handling.
Avoid: CPU-Bound Heavy ComputeUse a bounded `ForkJoinPool` sized to CPU cores for image encoding or matrix math.Spawning 10,000 CPU-bound virtual threads adds scheduling overhead without extra CPU cores.

STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

Virtual Thread Per-Task Executor, Semaphores & ReentrantLock.

Spawn one virtual thread per task via Executors.newVirtualThreadPerTaskExecutor(), replace synchronized around I/O with ReentrantLock on JDK 21–23, and use a Semaphore to cap concurrent downstream DB/API calls.

// Safe Java 21+ Virtual Thread fan-out with downstream Semaphore backpressure
private static final Semaphore DB_GATE = new Semaphore(32);
private static final ReentrantLock CACHE_LOCK = new ReentrantLock();

public Profile fetchProfile(String userId) throws Exception {
    try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
        Future<User> user = executor.submit(() -> {
            DB_GATE.acquire();
            try { return queryUser(userId); } finally { DB_GATE.release(); }
        });
        Future<List<Order>> orders = executor.submit(() -> fetchOrdersRpc(userId));
        return new Profile(user.get(), orders.get());
    }
}

STAGE 05 · ALTERNATIVESL6 · SCALE & TRADE-OFFS

Alternatives: Virtual Threads vs. Reactive (WebFlux) vs. Go Goroutines.

Compare JVM Project Loom against reactive pipelines and Go's M:N runtime.

ChoiceWhat it buysWhat it costs
Java 21+ Virtual ThreadsImperative stack traces, standard `try/catch`, and seamless Spring Boot 3.2+ integration (`spring.threads.virtual.enabled=true`).JDK 21–23 carrier pinning on `synchronized` + I/O (resolved in JDK 24 JEP 491) and `ThreadLocal` memory hazards.
Reactive (Spring WebFlux / Reactor)Fine-grained backpressure operators (`flatMap` concurrency, `bufferTimeout`) and zero pinning.Steep learning curve, viral `Mono`/`Flux` signatures, and fragmented async stack traces.
Go GoroutinesBuilt-in `select` and channels from day one with 2 KB initial stacks and no `synchronized` pinning.Different language ecosystem.

STAGE 06 · PRODUCTION ARCHITECTUREL7 · STAFF / PRINCIPAL

Production Migration: Bounded Downstream Pools & Pinning Telemetry.

When migrating a Spring Boot service to virtual threads, enable -Djdk.tracePinnedThreads=short (or JFR jdk.VirtualThreadPinned events) in staging to catch legacy JDBC drivers or libraries holding synchronized monitors over sockets.

Backpressure & Pinning Guard

Virtual Threads Protected by Downstream Semaphore

Virtual threads eliminate OS thread limits, so you must explicitly bound downstream DB/API concurrency with Semaphores.
