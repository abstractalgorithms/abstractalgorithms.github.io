STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What is Low-Rank Adaptation (LoRA).

LoRA freezes the pretrained weight matrix W0∈Rd×kW_0 \in \mathbb{R}^{d \times k}W0​∈Rd×k and injects a trainable low-rank decomposition ΔW=αrBA\Delta W = \frac{\alpha}{r} B AΔW=rα​BA, where A∈Rr×kA \in \mathbb{R}^{r \times k}A∈Rr×k, B∈Rd×rB \in \mathbb{R}^{d \times r}B∈Rd×r, and r≪min⁡(d,k)r \ll \min(d, k)r≪min(d,k) (typically r=8r = 8r=8 to $64$).

Because only AAA and BBB (<1% of total parameters) receive gradients and AdamW optimizer states, QLoRA (4-bit NF4 frozen base weights + paged optimizers) fits a 70B model into ~48 GB VRAM instead of >1 TB.

LoRA Forward & Adapter Merge

Frozen Base Weights (W0) + Low-Rank Trainable Branch (B x A)

1.1. All Linear Layers: Targeting q/k/v/o_proj plus MLP gate/up/down_proj consistently beats attention-only LoRA.

2.2. Zero-Latency Merge: At serving time, W' = W0 + (alpha/r)BA merges offline so inference adds zero extra FLOPs.

3.3. Multi-Tenant Adapters: Keep W0 shared in VRAM and hot-swap tiny 50 MB LoRA adapters per tenant.

LoRA slashes optimizer VRAM by 3–10x during training and merges cleanly into W0 for zero-overhead serving.

STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why full fine-tuning is prohibitive—and where LoRA fails.

Full fine-tuning of a 70B model requires >1 TB of GPU memory for FP16 weights, gradients, and 8-byte AdamW momentum/variance states, while risking catastrophic forgetting.

Even with LoRA, two failure modes dominate production runs: chat template / EOS token mismatch (omitting <|eot_id|> causes endless rambling) and overfitting after 8–10 epochs on narrow datasets.

1–3 Epochs + Replay Mix

Train for 1–3 epochs and mix in 10–20% general instruction replay data to preserve general reasoning and refusal behavior.

Completion-Only Loss Masking

Use DataCollatorForCompletionOnlyLM so loss is computed only on assistant tokens, not system/user prompt boilerplate.

STAGE 03 · WHERE IT IS USEDL5 · APPLIED DESIGN

When to Fine-Tune vs. When to Use RAG.

Fine-tuning teaches form, style, DSL syntax, and distilled reasoning; RAG supplies fresh, mutable facts.

ChoiceWhat it buysWhat it costs
Good Candidate: Schema / DSL & DistillationDistilling frontier traces into an 8B–14B model cuts serving latency and cost by 5–15x.Requires 500+ clean, diverse, verified training examples.
Avoid: Mutable Facts & Product CatalogsUse RAG + vector retrieval when knowledge changes daily; fine-tuning still hallucinates facts.Re-training adapters for every policy or inventory update is slow and brittle.

Configuring QLoRA with PEFT & Target Linear Modules.

from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training

model = prepare_model_for_kbit_training(base_4bit_model)
lora_cfg = LoraConfig(
    r=16,
    lora_alpha=32,
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM",
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj", "gate_proj", "up_proj", "down_proj"],
)
model = get_peft_model(model, lora_cfg)
model.print_trainable_parameters()  # Typically ~0.5% - 1.2% of total weights
