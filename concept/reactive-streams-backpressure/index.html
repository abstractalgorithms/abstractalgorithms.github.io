The idea to keep with you

STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What is Reactive Streams Backpressure.

Reactive Streams standardizes four interfaces (Publisher, Subscriber, Subscription, Processor) for dynamic push-pull flow control. Instead of a fast producer pushing blindly until an unbounded queue OOMs, or a naive pull paying 1 RTT per item, the downstream Subscriber signals cumulative credit via Subscription.request(n) (e.g., limitRate(64)), and the Publisher emits at most nnn items via onNext.

Dynamic Push-Pull Protocol

Reactive Streams `request(n)` Demand & 75% Replenishment

Low-tide/high-tide replenishment keeps the pipeline saturated without buffering unbounded memory.

02
STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why we need Backpressure (Unbounded OOM & Event-Loop Starvation).

A 10x speed mismatch between a 100k msg/s socket and a 10k writes/s database silently fills unbounded LinkedBlockingQueues or onBackpressureBuffer() operators until the JVM hits OutOfMemoryError. Conversely, running blocking JDBC I/O inside map() stalls the shared Netty event-loop thread, halting request(n) signals across all connections.

Never Call `request(Long.MAX_VALUE)`

Requesting Long.MAX_VALUE disables backpressure completely and reverts to unbounded push.

Watch `flatMap` Concurrency on Heavy Payloads

Reactor's default flatMap concurrency of 256 on 10 MB payloads buffers 2.5 GB in flight—cap maxConcurrency explicitly.

03
STAGE 03 · WHERE IT IS USEDL5 · APPLIED DESIGN

Where Reactive Backpressure fits (and where Drop/Conflate wins).

Propagate demand end-to-end for durable queues and DB sinks; apply DROP or LATEST conflation for hot non-slowable sources.

ChoiceWhat it buysWhat it costs
Good Candidate: Streaming Ingress -> Slower I/O SinksConnects Kafka/HTTP2/RSocket to Postgres or ML inference with bounded heap and Netty `autoRead=false` socket throttling.Steeper debugging stack traces; requires non-blocking drivers end-to-end.
Hot Non-Slowable Sources (UDP / Market Ticks / UI Events)Use `onBackpressureLatest()` or `onBackpressureDrop()` so stale ticks are discarded rather than crashing memory.Explicitly drops intermediate updates by design.
Avoid: Simple Request-Response CRUDHTTP timeouts + Java 21 Virtual Threads with bounded Semaphores are simpler to read and debug.Reactive operators add complexity for zero benefit on 1-item endpoints.
04
STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

How Bounded `limitRate`, Overflow Strategies & BlockHound are managed.

Specify explicit maxSize and BufferOverflowStrategy on onBackpressureBuffer, offload blocking work to Schedulers.boundedElastic(), and run BlockHound in CI to catch accidental blocking calls on Netty threads.

// Project Reactor bounded backpressure + isolated blocking sink
Flux<Event> stream = hotSource
    .onBackpressureBuffer(1024, dropped -> metrics.increment("dropped"), BufferOverflowStrategy.DROP_OLDEST)
    .limitRate(64) // Request 64, replenish at 75% (48)
    .flatMap(ev -> Mono.fromCallable(() -> blockingRepo.save(ev))
                       .subscribeOn(Schedulers.boundedElastic()),
             16); // Cap in-flight concurrency to 16

STAGE 05 · ALTERNATIVESL6 · SCALE & TRADE-OFFS

Alternatives: Reactive Streams vs. Java Virtual Threads + Semaphore vs. gRPC Flow Control.

Choose the flow-control mechanism that matches your runtime and protocol boundaries.

ChoiceWhat it buysWhat it costs
Reactive Streams (Project Reactor / RSocket)Minimal thread count and explicit message-level `REQUEST_N` credit across services.Requires reactive mental model and BlockHound discipline.
Java 21+ Virtual Threads + Bounded `Semaphore`/`BlockingQueue`Imperative stack traces with cheap blocking on bounded queues.Still needs explicit bounded queues/semaphores—unbounded queues OOM just the same.
TCP / gRPC HTTP/2 `WINDOW_UPDATE`Built-in byte-level flow control across network hops.Byte-level windows do not provide per-message logical backpressure across multiplexed streams.
06
STAGE 06 · PRODUCTION ARCHITECTUREL7 · STAFF / PRINCIPAL

Production example: End-to-End Credit Propagation to TCP Socket.

An RSocket/WebFlux ingestion gateway wires downstream limitRate(64) demand all the way to Netty's channel.config().setAutoRead(false). When PostgreSQL slows down, Netty stops reading bytes from the OS TCP receive buffer, pushing backpressure cleanly onto upstream producers.
