STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What is a Fenwick Tree.

Why this matters: The mechanism: understand how a Fenwick Tree works from first principles.

Every positive integer i has a unique binary decomposition, partitioning [1, i] into disjoint power-of-two blocks. For example, 13 (1101₂) splits [1, 13] into [1, 8], [9, 12], and [13, 13]. A Fenwick Tree (Binary Indexed Tree) stores each block's sum at its right endpoint: tree[i] holds the sum of [i - (i & -i) + 1, i].

Because i & -i isolates the lowest set bit in one CPU cycle (BLSI on x86-64), stripping it (i -= i & -i) walks disjoint prefix blocks in a query, while adding it (i += i & -i) climbs enclosing blocks in an update.

Implicit Bitwise Hierarchy

Fenwick Tree Responsibility Ranges (1-Indexed i & -i)

1.Query prefixSum(7): 0111 -> 0110 -> 0100 -> 0: sums tree[7] + tree[6] + tree[4] in 3 additions.

2.Update add(5, +2): 0101 -> 0110 -> 1000: updates tree[5], tree[6], and tree[8] upward.

3.Zero Pointers: All nodes live in a single contiguous int64[N+1] array fitting in L1/L2 cache.

A flat 1-indexed array acts as an implicit binary tree where i & -i encodes each node's exact range length.

Why Naive Prefix Arrays and Mutable Arrays Fail Together.

Why this matters: The problem: see what breaks without Why Naive Prefix Arrays and Mutable Arrays Fail Together under real concurrency or scale.

A static prefix-sum array answers range queries in O(1) but takes O(N) to rebuild on every point update.

Conversely, a plain mutable array updates in O(1) but scans O(N) per sum.

STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

1-Based Indexing, O(N) Build, and Binary Lifting.

Why this matters: Operational control: configure bounds, failure handling, and safe production defaults.

Think of 1-Based Indexing, O(N) Build, and Binary Lifting as the intuition layer for Fenwick Trees (Binary Indexed Trees): Operational control: configure bounds, failure handling, and safe production defaults.

Always enforce 1-based indexing (i >= 1) at the API boundary—passing i = 0 into while (i <= n) i += i & -i causes an infinite loop since 0 & -0 == 0.

class FenwickTree:
    def __init__(self, arr: list[int]):
        self.n = len(arr)
        self.tree = [0] * (self.n + 1)
        for i, val in enumerate(arr, start=1):
            self.tree[i] += val
            parent = i + (i & -i)
            if parent <= self.n:
                self.tree[parent] += self.tree[i]

    def add(self, idx0: int, delta: int) -> None:
        i = idx0 + 1  # strict 1-based guard
        while i <= self.n:
            self.tree[i] += delta
            i += i & -i

    def prefix_sum(self, idx0: int) -> int:
        i, acc = idx0 + 1, 0
        while i > 0:
            acc += self.tree[i]
            i -= i & -i
        return acc

    def range_sum(self, l0: int, r0: int) -> int:
        return self.prefix_sum(r0) - (self.prefix_sum(l0 - 1) if l0 > 0 else 0)
