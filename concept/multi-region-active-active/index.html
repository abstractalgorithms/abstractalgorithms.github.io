01
STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What is Multi-Region Active-Active.

Multi-region active-active routes live read and write traffic to the nearest healthy geographic region simultaneously via Anycast BGP or latency-based DNS.

Because light in fiber takes ~75–85 ms round-trip between us-east-1 and eu-west-1, every active-active database must choose a write model: synchronous consensus (Spanner/CockroachDB), async multi-master (DynamoDB Global Tables with LWW/CRDTs), or geo-partitioning (homing each tenant/user to a primary region).

Global Consensus vs Geo-Homing

3-Region Active-Active Consensus & Local Read Routing

1.1. Geo-Partitioning: EU user rows live on EU-homed Raft leaders so 95%+ of reads/writes stay local (<20ms).

2.2. N+1 Headroom: Cap each region at <=45% steady-state utilization so one surviving region can absorb 100% failover.

3.3. Conflict Safety: Async multi-master requires HLC timestamps or CRDTs to avoid NTP clock-skew clobbering.

Geo-partitioning combines consensus safety with local-region latency by pinning each tenant's leader near its users.

02
STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why single-region architectures fail—and how failover cascades happen.

Single-region apps fail catastrophically during regional control-plane outages and penalize distant users with 150–250 ms RTT.

Yet active-active introduces two severe failure modes: Surviving-Region Overload Cascade (Region A dies, Anycast shifts 100% of traffic to Region B, exhausting DB pools before autoscaling reacts) and Silent Write Clobbering (NTP clock drift causes Last-Writer-Wins to let an older edit overwrite a newer one).

Async Conflict Hazard

LWW Clock-Skew Clobbering vs. Hybrid Logical Clocks (HLC)

Wall-clock LWW silently drops updates under NTP drift; use HLC, CRDTs, or home-region write routing.

STAGE 03 · WHERE IT IS USEDL5 · APPLIED DESIGN

Where Active-Active is justified (and where Multi-AZ suffices).

Active-active doubles baseline infra cost; adopt it only when SLAs or global RTT demand it.

ChoiceWhat it buysWhat it costs
Good Candidate: 99.999% SLAs & Global User BasesSurvives full cloud-region outages in seconds and delivers <50 ms local reads globally.2x baseline compute/DB spend (<=45% utilization rule) and cross-region egress fees.
Avoid: Single-Geo Traffic or Hot Global CountersSingle-region Multi-AZ delivers 99.99% at a fraction of the cost; hot inventory counters need single-leader serialization.Cross-region locking on a single hot flash-sale SKU caps throughput at ~10 QPS.

STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

Geo-Partitioned Table Design & Adaptive Load Shedding.

Partition tables by region_code (CockroachDB REGIONAL BY ROW) so Raft leaders stay local, and enforce priority-based load shedding on failover.

-- CockroachDB REGIONAL BY ROW: pin each user's Raft leaseholder to their home region
CREATE TABLE user_profiles (
    region crdb_internal_region NOT NULL,
    user_id UUID NOT NULL DEFAULT gen_random_uuid(),
    email STRING NOT NULL,
    PRIMARY KEY (region, user_id)
) LOCALITY REGIONAL BY ROW;

Alternatives: Sync Consensus vs. Async Multi-Master vs. Active-Passive DR.

Navigate the PACELC trade-off between consistency, latency, and failover speed.

ChoiceWhat it buysWhat it costs
Synchronous Consensus (Spanner / CockroachDB)Linearizable writes; zero lost commits or split-brain.70–150 ms cross-region write RTT unless geo-partitioned; stalls if quorum partitions.
Async Multi-Master (DynamoDB Global Tables + CRDTs)Local <15 ms write latency in every region.Eventual consistency; requires CRDTs or HLC to avoid silent LWW data loss.

06
STAGE 06 · PRODUCTION ARCHITECTUREL7 · STAFF / PRINCIPAL

N+1 Headroom + Priority Load Shedding.

To survive sudden regional evacuation without cascading collapse, production active-active clusters cap steady-state regional CPU/DB utilization at <=45%, pre-warm connection pools, and configure edge gateways to shed low-priority analytics/batch traffic while protecting checkout and auth.

Regular Failover Chaos Drills

Drain one region via DNS/Anycast monthly during business hours to verify N+1 capacity and connection-pool limits.

Home-Region Write Routing

Even in async active-active, route writes for a specific tenant_id to its designated home region when linearizability is needed.
