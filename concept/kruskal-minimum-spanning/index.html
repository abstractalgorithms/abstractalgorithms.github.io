STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What is Kruskal's Algorithm.

Why this matters: The mechanism: understand how Kruskal's Algorithm works from first principles.

A Minimum Spanning Tree (MST) connects all V vertices of a weighted undirected graph using V - 1 edges with minimum total weight. By the Greedy Cut Property, the lightest edge crossing any vertex partition is guaranteed to belong to an MST.

Kruskal's algorithm sorts all E edges by ascending weight (O(E log E)), then scans them once using Disjoint Set Union (DSU) with path compression and union by rank/size (O(E · α(V)), where α(V) <= 4): if find(u) != find(v), union them and add the edge; otherwise skip it to avoid a cycle.

Union-Find Forest

Kruskal Sorted Edge Scan + Path-Compressed DSU Components

1.Early Exit: Stop as soon as edges_added == V - 1 without scanning heavier remaining edges.

2.Dual Heuristics: Pair path compression in find() with union by size/rank to guarantee inverse-Ackermann time.

3.Forest Check: If edges_added < V - 1 after scanning all edges, the input graph is disconnected.

Sorting edges once and merging with DSU avoids adjacency-list pointer chasing and excels on sparse edge lists.

Engineering Decision Framework
Problem
How to implement Kruskal's Minimum Spanning Tree without hitting unbounded tail latency, state divergence, or operational fragility.
Naive Solution
Use a single unpartitioned path with unbounded retries and synchronous global coordination.
Why It Fails
Global coordination serializes throughput under load, while unbounded retries amplify transient stalls into full outages.
Alternatives
Compare synchronous strict-consistency paths against bounded asynchronous replication, local caching, or partitioned ownership.
Engineering Decision
If disk I/O or compaction stalls threaten tail latency, sort edges in O(E log E) and merge components with Disjoint Set Union (path compression + union by rank)—ideal for sparse graphs, pre-sorted edges, and clustering.
Trade-Offs
Gains predictable p99 latency and fault isolation in exchange for explicit bounding, observability, and slightly higher implementation complexity.

64-Bit Weight Accumulation

Individual edge weights may fit in int32, but summing V - 1 edges overflows 32-bit integers—always accumulate total_weight in int64.

Iterative Path Halving

In constrained-stack environments or pre-compression trees, iterative path halving (while p[x] != x: p[x] = p[p[x]]; x = p[x]) avoids recursion overhead.

Request & State Flow

Kruskal's MST with Iterative Path-Halving DSU & Forest Guard

def kruskal_mst(n: int, edges: list[tuple[int, int, int]]) -> tuple[int, list[tuple[int, int, int]]]:
    parent = list(range(n))
    size = [1] * n

    def find(x: int) -> int:
        while parent[x] != x:
            parent[x] = parent[parent[x]]  # Iterative path halving
            x = parent[x]
        return x

    mst = []
    total_weight = 0  # Python int avoids 64-bit overflow; use int64 in Go/Java/C++
    for w, u, v in sorted(edges):
        ru, rv = find(u), find(v)
        if ru != rv:
            if size[ru] < size[rv]:
                ru, rv = rv, ru
            parent[rv] = ru
            size[ru] += size[rv]
            total_weight += w
            mst.append((w, u, v))
            if len(mst) == n - 1:
                break
    if n > 0 and len(mst) != n - 1:
        raise ValueError("Graph is disconnected; only a spanning forest exists")
    return total_weight, mst
