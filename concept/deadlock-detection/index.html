What is a Deadlock (Coffman's Four Conditions).

Why this matters: The mechanism: understand how a Deadlock (Coffman's Four Conditions) works from first principles.

A deadlock occurs when two or more concurrent executions are permanently blocked waiting for resources held by one another. Coffman's four conditions must all hold simultaneously: (1) Mutual Exclusion, (2) Hold and Wait, (3) No Preemption, and (4) Circular Wait (T1 -> T2 -> T1).

Systems either prevent deadlocks by breaking Circular Wait via canonical lock ordering (min(idA, idB) before max(idA, idB)), or detect & recover by modeling dependencies in a directed Wait-For Graph (WFG) and aborting a victim (SQLSTATE 40P01 in Postgres, Error 1213 in MySQL).

# Canonical lock ordering + jittered 40P01 deadlock retry (Python / PostgreSQL)
import random, time

def transfer_ordered(conn, from_id: int, to_id: int, cents: int) -> None:
    first, second = sorted((from_id, to_id))
    for attempt in range(4):
        try:
            with conn.cursor() as cur:
                cur.execute("SET LOCAL lock_timeout = '2s'")
                cur.execute("SELECT id FROM accounts WHERE id IN (%s, %s) ORDER BY id FOR UPDATE", (first, second))
                cur.execute("UPDATE accounts SET balance = balance - %s WHERE id = %s", (cents, from_id))
                cur.execute("UPDATE accounts SET balance = balance + %s WHERE id = %s", (cents, to_id))
            conn.commit()
            return
        except Exception as err:
            conn.rollback()
            if getattr(err, 'sqlstate', None) != '40P01' or attempt == 3:
                raise
            time.sleep(0.02 * (2 ** attempt) + random.uniform(0, 0.025))
