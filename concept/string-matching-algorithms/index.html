String Matching
Algorithms.

String matching algorithms locate exact or multi-pattern substrings in linear or sublinear time without naive O(N*M) backtracking, using prefix tables (KMP), bad-character jumps (Boyer-Moore), rolling hashes (Rabin-Karp), or failure-link tries (Aho-Corasick).

THE BIG IDEA / Key takeaway · CONCEPT GUIDE

Match the algorithm to the cardinality and alphabet: KMP guarantees O(N + M) worst-case for single patterns, Boyer-Moore/Two-Way powers fast single-pattern scans like grep/std::search, Rabin-Karp handles 2D/plagiarism hashing, and Aho-Corasick matches 10,000+ keywords simultaneously in a single O(N + Z) pass.

Explanation anchor
01 / The idea

Foundational mechanics & core principles

Naive nested-loop matching degrades to O(N * M) on repetitive inputs (like DNA or crafted regex/HTTP payloads), creating CPU DoS vulnerabilities; linear-time automata keep WAFs, log scanners, and search engines predictable at gigabytes per second.

  • Knuth-Morris-Pratt (KMP) precomputes an LPS (Longest Proper Prefix which is also Suffix) array in O(M) time so the text pointer never moves backward, guaranteeing O(N + M) worst-case.
  • Boyer-Moore compares right-to-left and uses bad-character + good-suffix heuristics to skip up to M characters per mismatch, achieving sublinear O(N / M) average time on large alphabets.
  • Rabin-Karp computes a polynomial rolling hash in O(1) per slide, making it ideal for multi-pattern equal-length matching and 2D matrix/plagiarism fingerprinting.
  • Aho-Corasick builds a Trie augmented with KMP-style failure links and dictionary-suffix links, scanning text in O(N + Sum(M_i) + Z) regardless of how many thousands of patterns exist.
  • Standard libraries already optimize exact search: CPython uses a Boyer-Moore-Horspool/Sunday hybrid (fastsearch), while JVM intrinsics vectorize String.indexOf with SIMD.

Good candidates

  • Single-pattern exact search with strict O(N + M) worst-case guarantees on adversarial or repetitive inputs (KMP / Z-algorithm).
  • High-throughput single-pattern search in large ASCII/UTF-8 logs or source files where skipping ahead by M characters cuts cache reads (Boyer-Moore / Boyer-Moore-Horspool).
  • Multi-pattern scanning against thousands of signatures—such as DLP, WAF rules, antivirus, or profanity filters—in one pass (Aho-Corasick).

Think twice

  • Full-text natural language search with stemming, fuzzy typos, or BM25 ranking—use an inverted index (Lucene/OpenSearch) or edit-distance/FST.
  • Complex regular expressions with backreferences—use RE2/DFA-based engines rather than raw exact-match algorithms.
  • One-off short strings (< 1 KB) where Python's in (Two-Way / fastsearch) or Java's String.indexOf already runs optimized native C/intrinsic SIMD code.
Deep Dive & Production Considerations
02 / Concrete walkthrough

Architectural mechanics & implementation

ScenarioAn API gateway inspects 50 MB/s of JSON payloads against 12,000 sensitive-keyword and SQLi signatures; running 12,000 separate regexes or contains() calls takes 180 ms per 1 MB payload.

The idea

Naive string matching throws away everything it learned when a mismatch occurs, backing up the text pointer and re-reading characters repeatedly. Modern string-matching algorithms eliminate redundant comparisons by precomputing structure in the pattern(s): KMP and Aho-Corasick reuse matched prefixes via failure links, Boyer-Moore jumps past impossible alignments from right to left, and Rabin-Karp summarizes windows into O(1)-updatable rolling hashes.

Concrete walkthrough

Tracing KMP on text T = "ABABDABACDABABCABAB" and pattern P = "ABABCABAB":

  1. Build LPS table for P: [0, 0, 1, 2, 0, 1, 2, 3, 4] (e.g., at index 8 'B', prefix "ABAB" matches suffix "ABAB", length 4).
  2. Scan T with pointer i (never decrements) and P with j:
    • i=0..3 matches "ABAB" (j=4).
    • At i=4, T[4]='D' != P[4]='C'. Instead of resetting i to 1, KMP sets j = lps[3] = 2, keeping i=4.
    • T[4]='D' != P[2]='A', so j = lps[1] = 0; still mismatch, so i advances to 5.
  3. Match: At i=10..18, j reaches 9 == len(P), reporting match at i - j = 10, then sets j = lps[8] = 4 to continue searching for overlapping matches.

Aho-Corasick generalizes KMP to thousands of patterns by combining a prefix trie with BFS-built failure links and output chains.

Z-algorithm and Rabin-Karp mechanics

The Z-algorithm builds an array Z[i] storing the length of the longest substring starting at i that matches a prefix of S, using a [L, R] Z-box to reuse prior comparisons in O(N). Running it on P + '$' + T finds all occurrences where Z[i] == len(P) without explicit state transitions. Rabin-Karp instead maps a window of length M to H = sum(c_k * B^(M-1-k)) mod Q and slides in O(1) via H_next = ((H - T[i]*B^(M-1)) * B + T[i+M]) mod Q.

Failure modes

Two pitfalls dominate production deployments: DFS failure-link bugs in custom Aho-Corasick implementations (which leave deep failure pointers dangling) and UTF-8 multi-byte boundary splits when running byte-level automata over character-indexed rules—always normalize encoding (UTF-8 bytes vs. Unicode code points) before compiling patterns.

Built-in runtimes vs. custom code

In Java, String.indexOf uses HotSpot SIMD intrinsics (UseVectorizedMismatchIntrinsic), outperforming hand-rolled pure-Java KMP on non-adversarial text; reach for org.ahocorasick or a custom KMP only for multi-pattern sets or streaming byte buffers. In Python, str.find / in executes C-level fastsearch; use pyahocorasick (C extension) when matching hundreds or thousands of patterns.

Practical checklist

  • Use native String.indexOf (Java) or in / str.find (Python) for single-pattern in-memory checks.
  • Use Aho-Corasick whenever matching > 10–20 literal patterns simultaneously.
  • Build Aho-Corasick failure links strictly via BFS and follow dictionary-suffix links for overlapping hits.
  • Use KMP for O(M)-memory streaming across network/file chunk boundaries.
  • Use double-hashing (mod 1e9+7 and mod 1e9+9) in Rabin-Karp when collisions could cause O(N*M) slowdowns.
03 / Engineering trade-offs

Weighing architectural decisions

Worst-case guarantee (KMP) vs. average speed (Boyer-Moore)

Advantage: KMP never backtracks and holds a strict O(N + M) ceiling even on pathological `AAAA...AB` inputs.

Drawback: KMP inspects every character sequentially, whereas Boyer-Moore skips large chunks and runs 3x–5x faster on typical English or log text.

Aho-Corasick memory vs. multi-pattern throughput

Advantage: Scans 10,000+ patterns simultaneously in one O(N + Z) pass.

Drawback: Dense transition tables (`states * alphabet_size`) consume significant RAM unless compressed with sparse maps or Double-Array Tries.

Rabin-Karp rolling hash collisions vs. simplicity

Advantage: Extends naturally to 2D grids and variable-size rolling fingerprints (rsync/chunking).

Drawback: Hash collisions require an O(M) character-by-character verification, degrading worst-case to O(N * M) without double hashing.

04 / Failure modes & resilience

Explain where it breaks · Known failure modes

Adversarial O(N*M) backtracking DoS

Naive matching or unverified rolling-hash collisions on crafted inputs like `"a" * 100000` against `"a" * 5000 + "b"` spike CPU to 100%.

What helps: Use KMP, Two-Way, or Aho-Corasick for untrusted inputs, or double-mod rolling hashes with strict step budgets.

Aho-Corasick trie memory explosion

Allocating a 256-entry `int[256]` array per Trie node for 500k UTF-8 pattern characters consumes gigabytes of heap.

What helps: Use byte-level transitions with sparse sorted arrays, hash maps, or a Double-Array Trie (DAT) representation.

Missing overlapping matches via failure links

Walking only `isEndOfWord` on the current Aho-Corasick node misses shorter suffixes (e.g., matching `"she"` misses `"he"`).

What helps: Precompute dictionary-suffix (output) links during BFS failure-link construction and traverse them on every match.

Integer overflow in Rabin-Karp rolling hash

Multiplying base powers without modular reduction at every step overflows 64-bit integers and breaks hash equality.

What helps: Apply `% MOD` (using a large prime like `1_000_000_007` or `2^61 - 1`) after every add/subtract/multiply step.

05 / Practical checklist

Avoid these mistakes

  • Re-implementing KMP or Boyer-Moore in Python/Java loops for simple single-string checks when built-in C/SIMD `in` or `indexOf` is 10x faster.
  • Building Aho-Corasick failure links with DFS instead of BFS (failure links depend on shorter-depth ancestors already being resolved).
  • Confusing `LPS` (longest proper prefix-suffix) construction in KMP by failing to fall back `j = lps[j - 1]` inside a `while` loop.
  • Forgetting to verify exact character equality after a Rabin-Karp hash match.
  • Splitting streaming buffers naively at fixed 64 KB boundaries without carrying state or overlap, missing patterns that straddle chunk edges.
