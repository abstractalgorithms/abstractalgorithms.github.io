Kruskal Minimum
Spanning Tree.

Kruskal's algorithm builds a Minimum Spanning Tree (MST) by sorting all edges by weight and greedily adding the lightest edge that does not create a cycle, tracked in near-O(1) via Union-Find.

THE BIG IDEA / Key takeaway · CONCEPT GUIDE

Sort edges in O(E log E) and merge components with Disjoint Set Union (path compression + union by rank)—ideal for sparse graphs, pre-sorted edges, and clustering.

Explanation anchor
01 / The idea

Foundational mechanics & core principles

Minimum Spanning Trees minimize total connection cost across networks—fiber-optic backbones, PCB trace routing, VPC peering topologies, and single-linkage hierarchical clustering. Kruskal's edge-centric approach shines when graphs are sparse (E ≈ V) or when edges arrive as a stream/list rather than an adjacency matrix, and its core primitive (Union-Find) powers dynamic connectivity checks across compilers and distributed systems.

  • Greedy Cut Property: the lightest edge crossing any cut (partition of vertices) is guaranteed to belong to some MST, which proves Kruskal's global sorting order is optimal.
  • Time complexity is O(E log E) dominated by sorting the edges; the Union-Find phase takes O(E · α(V)) where α(V) ≤ 4 for any graph fitting in the observable universe (V ≤ 10⁸⁰).
  • Disjoint Set Union (DSU) requires both path compression (flattening parent pointers during find) and union by rank/size to guarantee inverse-Ackermann amortized time.
  • Early termination optimization: an MST on V vertices always has exactly V - 1 edges; stop iterating the sorted edge list immediately once V - 1 edges are accepted.
  • Integer-weight speedup: if edge weights are small integers (e.g., 0..10⁶), replacing comparison sort with Radix Sort or Counting Sort drops total runtime to O(E + V · α(V)).

Good candidates

  • Sparse graphs where E is close to V (e.g., road networks, planar grids, or k-NN graphs with E ≤ 5V), where O(E log E) beats Prim's heap overhead.
  • Edge-list inputs or streaming/external-sort workloads where edges can be sorted on disk without loading the full adjacency list into RAM.
  • Single-linkage clustering or bottleneck-path problems where stopping Kruskal early at K connected components yields K-clusters that maximize minimum inter-cluster distance.

Think twice

  • Dense graphs where E ≈ V² (e.g., all-pairs Euclidean distances on 10,000 points = 50M edges)—Prim's O(V²) without a heap avoids sorting 50M edges.
  • Directed graphs (Minimum Spanning Arborescence)—greedy cycle-free edge selection fails on directed graphs; use Edmonds' / Chu-Liu algorithm instead.
  • Steiner Tree or degree-constrained spanning trees (e.g., max 3 cables per router), which are NP-hard and cannot be solved greedily by Kruskal.

02 / Concrete walkthrough

Architectural mechanics & implementation

ScenarioA telecom planner needs to connect 1,200 cell towers using 3,100 candidate trench routes with varying per-kilometer excavation costs.

The idea

Kruskal's algorithm treats an undirected weighted graph G=(V,E)G = (V, E)G=(V,E) as a forest of VVV isolated single-vertex trees and merges them into one Minimum Spanning Tree by processing edges strictly from lightest to heaviest. At each step, if the candidate edge (u,v)(u, v)(u,v) connects two different trees (find(u) != find(v)), adding it cannot form a cycle and—by the Cut Property—is safe for an MST. Once V−1V - 1V−1 edges are accepted, all vertices belong to a single tree of minimum total weight.

Concrete walkthrough

Take 5 vertices {0, 1, 2, 3, 4} and 7 weighted edges sorted ascending:

  1. (0, 1, w=1): find(0) != find(1) → Accept (total = 1, edges = 1).
  2. (2, 3, w=2): find(2) != find(3) → Accept (total = 3, edges = 2).
  3. (1, 2, w=3): find(1) != find(2) → Accept, merges {0,1} and {2,3} (total = 6, edges = 3).
  4. (0, 3, w=4): find(0) == find(3) (both root at 0) → Reject (would form cycle 0-1-2-3-0).
  5. (3, 4, w=5): find(3) != find(4) → Accept (total = 11, edges = 4).
  6. Early Exit: edges == V - 1 == 4, so remaining edges (0, 4, w=7) and (1, 4, w=8) are never inspected.

Kruskal's pipeline: global edge sorting feeds an O(α(V)) Disjoint Set Union cycle filter until V - 1 edges are accepted.

Disjoint Set Union Mechanics

DSU maintains two flat integer arrays of length VVV: parent[i] = i and size[i] = 1 (or rank[i] = 0). During find(x), path compression rewrites every visited node's parent directly to the root (or uses iterative path halving parent[x] = parent[parent[x]] to avoid recursion). During union(a, b), union by size/rank always attaches the smaller tree under the larger tree's root. Together, Tarjan proved MMM operations take O(M⋅α(V))O(M \cdot \alpha(V))O(M⋅α(V)) time, where α(V)≤4\alpha(V) \le 4α(V)≤4 for all practical inputs.

Failure modes

  1. Silent Disconnected Forest: Returning a partial tree when edges_added < V - 1 without flagging connectivity failure.
  2. 64-bit Sum Overflow: Summing 10510^5105 edge weights of 10910^9109 overflows 32-bit integers.
  3. Uncompressed DSU: Omitting either path compression or union by rank degrades find() to O(V)O(V)O(V) on skewed trees.
  4. Non-Deterministic Tie-Breaking: Equal-weight edges produce different valid MSTs depending on sort stability; if deterministic output is required, break ties by (weight, min(u,v), max(u,v)).

Variants: Maximum Spanning Tree & Second-Best MST

  • Maximum Spanning Tree: Sort edges descending (-weight) and run identical Kruskal + DSU logic (used for widest bottleneck bandwidth routing).
  • Kruskal's Reconstruction Tree: Instead of merging u and v directly, create a new internal node w_node as parent of both roots; LCA queries on this binary tree answer the maximum edge weight on any path in O(log⁡V)O(\log V)O(logV).
  • K-Clustering: Stop Kruskal when components == K (i.e., after V - K merges) to maximize the minimum spacing between KKK clusters.

Practical checklist

  • Verify the graph is undirected; use Edmonds' algorithm for directed graphs.
  • Use flat primitive arrays (int[] / long[]) for parent and size instead of object wrappers.
  • Accumulate total MST weight in int64 (long).
  • Break loop immediately when edges_added == V - 1.
  • Check edges_added == V - 1 after the loop to catch disconnected graphs (handling V == 0 or V == 1 cleanly).
03 / Engineering trade-offs

Weighing architectural decisions

Kruskal vs. Prim (Binary Heap)

Advantage: Kruskal operates on a flat edge array with sequential cache-friendly sorting and simple DSU arrays, outperforming Prim on sparse graphs (E < 4V).

Drawback: Prim avoids sorting all E edges upfront and wins on dense graphs (E ≈ V²) or when an adjacency matrix is already in memory.

Comparison Sort vs. Radix/Counting Sort

Advantage: Comparison sort (Quicksort/Timsort) handles arbitrary 64-bit floats, negative weights, and custom comparators cleanly.

Drawback: Sorting floats costs O(E log E), whereas 32-bit integer or quantized weights can use 8-bit/16-bit Radix Sort for near-linear O(E) scaling.

Recursive vs. Iterative Path Compression in DSU

Advantage: Recursive `find(x)` is 3 lines of code and easy to verify.

Drawback: On pathological trees before compression or constrained stacks, recursion risks stack overflow; iterative path halving (`parent[x] = parent[parent[x]]`) uses O(1) stack space.

04 / Failure modes & resilience

Explain where it breaks · Known failure modes

Disconnected Graph Returning a Forest Instead of an MST

If the input graph has multiple connected components, Kruskal terminates after exhausting all edges with fewer than V - 1 edges and silently produces a spanning forest.

What helps: Assert `edges_added == V - 1` at the end of the loop (for V > 0) and raise or return an explicit disconnected-graph error if fewer edges were added.

Integer Overflow on Total MST Weight

Individual edge weights fit in 32-bit signed integers (up to 2.1×10⁹), but summing V - 1 edges overflows `int32` silently.

What helps: Accumulate `total_weight` in a 64-bit integer (`int64` / `long` in Java, arbitrary-precision `int` in Python).

Missing Path Compression or Rank Heuristic in DSU

Implementing naive Union-Find without union by rank or path compression allows skewed chains of depth O(V), degrading total runtime to O(E · V).

What helps: Always pair `parent[x] = find(parent[x])` (or iterative path halving) with `size[]` or `rank[]` comparison during `union(u, v)`.

Floating-Point Tie Instability

Using NaN or imprecise float comparisons in custom sort comparators violates strict weak ordering and causes undefined sort behavior or crashes.

What helps: Validate finite weights upfront or scale decimal costs to fixed-point integers (e.g., cents or micrometers) before sorting.

05 / Practical checklist

Avoid these mistakes

  • Assuming Kruskal works on directed graphs to find a minimum-cost directed spanning tree (arborescence).
  • Forgetting to check `edges_added == V - 1` to detect disconnected graphs or continuing to scan remaining edges after `V - 1` edges are already chosen.
  • Using `int32` for the accumulated MST weight when edge weights are up to 10⁹ and V = 10⁵.
  • Representing DSU with a hash map of objects instead of flat integer arrays (`parent[]`, `rank[]`), adding 5–10x GC and pointer-chasing overhead.
  • Failing to handle self-loops (`u == v`) or parallel edges cleanly—DSU naturally ignores them via `find(u) == find(v)`, but custom code that skips DSU checks breaks.
