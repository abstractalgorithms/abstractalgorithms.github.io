Stack & Queue Data Structures
& Monotonic Stack Pattern.

Stacks (LIFO) and Queues (FIFO) are linear abstract data types providing O(1) push/pop or enqueue/dequeue operations to control execution order, backtracking, and asynchronous buffering.

THE BIG IDEA / Key takeaway · CONCEPT GUIDE

Use a dynamic array/ArrayDeque for both stacks and queues in Java and Python (avoiding legacy synchronized Stack or O(N) list.pop(0)), and switch to bounded ring buffers or monotonic deques when memory predictability or sliding-window O(1) extrema are required.

Explanation anchor
01 / The idea

Foundational mechanics & core principles

Stacks power every call stack, expression parser, and DFS traversal, while queues form the backbone of BFS, rate-limiting buffers, and producer-consumer pipelines across OS kernels and distributed brokers.

  • Both stack push/pop and queue enqueue/dequeue run in amortized O(1) time and O(N) space when backed by a circular array or doubly-linked list.
  • In Java, prefer ArrayDeque over java.util.Stack (which extends Vector and synchronizes every call) and over LinkedList (which allocates a node per element and hurts CPU cache locality).
  • In Python, use collections.deque (a doubly-linked list of 64-element blocks) for O(1) append/popleft; list.pop(0) is O(N) due to element shifting.
  • Bounded queues (e.g., ArrayBlockingQueue or Disruptor ring buffers) enforce backpressure so slow consumers do not trigger OutOfMemoryError.
  • Monotonic stacks and deques maintain sorted invariants by popping dominated elements on insertion, turning O(N*K) nested loops into O(N) single-pass algorithms.

Good candidates

  • LIFO backtracking, undo/redo histories, bracket/AST parsing, monotonic stack problems (next greater element), and iterative DFS.
  • FIFO task scheduling, BFS shortest-path in unweighted graphs, level-order tree traversal, and decoupling bursty producers from steady consumers.
  • Sliding-window maximum/minimum or bounded-latency ring buffers using a double-ended queue (Deque).

Think twice

  • Random-access lookups by index or key—use a contiguous array or hash map instead of scanning a stack or queue.
  • Priority-ordered processing where highest-urgency items must jump ahead of older ones—use a binary heap / PriorityQueue.
  • Durable multi-consumer event replay across restarts—in-memory queues lose state on crash; use Kafka, RabbitMQ, or Redis Streams.
Deep Dive & Production Considerations
02 / Concrete walkthrough

Architectural mechanics & implementation

ScenarioA Java ingestion service receives 120,000 metrics/sec and previously used an unbounded LinkedBlockingQueue, causing 4 GB heap growth and 1.2s GC stop-the-world pauses during downstream DB slowdowns.

The idea

Stacks (Last-In, First-Out) and Queues (First-In, First-Out) restrict where elements enter and leave a sequence so that insertion and removal stay O(1) without shifting or searching. A stack models nested state and reversal; a queue models fair ordering and temporal decoupling between producers and consumers.

Concrete walkthrough

Consider a circular-array queue (like ArrayDeque with capacity 8, head = 0, tail = 0, mask = capacity - 1):

  1. Enqueue (offer(A), offer(B), offer(C)): Write at buf[tail] and advance tail = (tail + 1) & mask -> tail moves to 3.
  2. Dequeue (poll()): Read buf[head] (A), null out the slot to avoid GC retention, and advance head = (head + 1) & mask -> head moves to 1.
  3. Wrap-around: When tail reaches index 7 and head is at 2, the next offer wraps tail = (7 + 1) & 7 = 0 without copying any elements.
  4. Resize: Only when tail == head (buffer full) does the structure allocate a 2x array and copy [head..end] followed by [0..tail], yielding amortized O(1) per operation.

Power-of-two circular buffers turn modulo arithmetic into bitwise AND (& mask), delivering cache-friendly O(1) FIFO operations with strict memory bounds.

Monotonic stacks and deques

A monotonic stack maintains elements in strictly increasing or decreasing order by popping violating elements before pushing the new one. Each element is pushed once and popped at most once, guaranteeing O(N) total time across the entire array—ideal for next-greater-element, daily temperatures, and largest-rectangle-in-histogram problems. Extending this to a deque (ArrayDeque / collections.deque) lets you also evict expired indices from the front for O(N) sliding-window extrema.

Failure modes

In production, the most common queue failure is unbounded memory growth when Executors.newFixedThreadPool pairs an unbounded LinkedBlockingQueue with slow downstream I/O. In algorithms, off-by-one window eviction in monotonic deques and reference leaks (forgetting to null out popped array slots in custom ring buffers) cause subtle bugs and GC memory leaks.

Cache locality and concurrency

Modern CPUs prefetch sequential cache lines (64 bytes). An ArrayDeque stores references contiguously, whereas LinkedList scatters 32-byte node objects across the heap, causing pointer-chasing cache misses. For multi-producer, multi-consumer workloads, prefer ArrayBlockingQueue for strict bounds or ConcurrentLinkedDeque / LMAX Disruptor when lock contention on a single monitor limits throughput.

Practical checklist

  • Default to ArrayDeque (Java) and collections.deque (Python) for both stacks and queues.
  • Always bound production work queues and define a RejectedExecutionHandler or HTTP 429 policy.
  • Use iterative stacks (ArrayDeque) instead of recursion when tree/graph depth can exceed 1,000 nodes.
  • Store array indices (not raw values) in monotonic stacks/deques so distance and window expiry are trivial.
  • Null out cleared slots in custom array-backed stacks/queues to prevent loitering object references.
03 / Engineering trade-offs

Weighing architectural decisions

Circular array (ArrayDeque) vs. Linked list

Advantage: Contiguous array slots fit in L1/L2 CPU cache lines and avoid per-element heap allocation and GC pressure.

Drawback: Unbounded array-backed structures require occasional O(N) resizing spikes unless capacity is pre-sized or bounded.

Bounded vs. Unbounded queues

Advantage: Bounded queues guarantee O(1) memory ceiling and propagate backpressure upstream before the process OOMs.

Drawback: Requires an explicit overflow policy (block producer, drop oldest, drop newest, or reject with 429/503).

Iterative explicit stack vs. Call-stack recursion

Advantage: Heap-allocated ArrayDeque/list stacks handle millions of nodes without risking StackOverflowError (typically 1 MB thread stack in JVM, 1,000 frames in CPython).

Drawback: Slightly more verbose state management when simulating post-order or multi-phase recursion frames.

04 / Failure modes & resilience

Explain where it breaks · Known failure modes

Unbounded queue OOM under consumer stall

Producers keep enqueuing into an unbounded queue while a downstream database stalls, exhausting heap memory and crashing the service.

What helps: Always use bounded capacity (e.g., ArrayBlockingQueue(capacity) or deque(maxlen=N)) with explicit rejection or circuit breaking.

O(N^2) hidden complexity from list.pop(0)

Using a Python list as a FIFO queue shifts all remaining elements on every pop(0), turning a 100k-item BFS into 5 billion memory moves.

What helps: Use collections.deque.popleft() or queue.Queue for O(1) head removal.

Thread-stack overflow on deep trees/graphs

Recursive DFS on a skewed 100,000-node linked graph exceeds the JVM/CPython call stack limit and crashes.

What helps: Convert recursion to an explicit heap-allocated stack (ArrayDeque in Java, list in Python).

Head-of-line blocking in a single FIFO queue

One slow 30-second export job at the front of a single-worker FIFO queue stalls thousands of 5 ms interactive requests behind it.

What helps: Partition queues by workload class (fast vs. bulk) or use fair/weighted scheduling across separate worker pools.

05 / Practical checklist

Avoid these mistakes

  • Using java.util.Stack in new Java code instead of Deque<T> stack = new ArrayDeque<>().
  • Using LinkedList as a queue in Java when ArrayDeque is faster and uses ~4x less memory per element.
  • Forgetting to check isEmpty() before peek()/pop(), causing NoSuchElementException or IndexError.
  • Using an unbounded LinkedBlockingQueue in ThreadPoolExecutor, which prevents maxPoolSize threads from ever spawning.
  • Mutating shared mutable objects after pushing them onto a queue without defensive copying or immutability.
