STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What is Observability-Driven Testing (ODT).

Observability-Driven Testing (ODT) turns OpenTelemetry traces, spans, and structured events into first-class test assertions.

By injecting W3C traceparent and baggage: test_run_id=... headers from test runners (Playwright, pytest, JUnit) into services and Kafka/SQS queues, each test run produces one unified distributed trace—allowing tools like Tracetest or Malabi to assert span('payment.charge').attributes['retry_count'] == 0 or db.query_count <= 5.

Trace-Based Assertions

End-to-End W3C traceparent Propagation Across Async Queues

Trace assertions catch hidden N+1 queries, dropped async events, and silent retries that HTTP 200 hides.

02
STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why black-box HTTP 200 assertions miss silent partial failures.

A black-box assert response.status_code == 200 passes even when a background Kafka event was dropped, a cache stampede occurred, or an N+1 SQL regression doubled p99 latency.

Two common pitfalls break ODT setups: Broken Async Context Propagation (a Kafka/SQS producer omits traceparent, orphaning child spans) and BatchSpanProcessor Flush Races (the test queries Tempo 100 ms after HTTP 200, before the default 5-second batch flush runs).

Shorten Test Flush Delay

Set OTEL_BSP_SCHEDULE_DELAY=500 in CI/test environments and poll the trace backend with backoff.

Isolate Synthetic Traffic

Tag synthetic tests with baggage: test_run_id=... so they never pollute production SLO error budgets.

STAGE 03 · WHERE IT IS USEDL5 · APPLIED DESIGN

Where ODT excels (and where Unit Tests win).

Use trace-based assertions for async distributed flows and canary gates; keep pure logic in fast unit tests.

Good Candidate: Async Pipelines & Canary RolloutsVerifies Kafka/SQS handoffs, Saga compensations, and Argo Rollouts / Flagger canary SLIs.Requires an ephemeral OTel collector + Tempo/Jaeger in CI.

04
STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

Asserting on Distributed Trace Spans in CI.

Configure head/tail sampling to retain 100% of traces carrying test_run_id, then assert on span existence, error status, and SQL query counts.

# Tracetest-style assertion against a distributed Order -> Kafka -> Billing trace
type: Test
spec:
  trigger:
    type: http
    httpRequest: { url: "http://api:8080/v1/orders", method: "POST" }
  specs:
    - selector: span[name="kafka.consume orders"]
      assertions:
        - attr:otel.status_code != "ERROR"
    - selector: span[db.system="postgresql"]
      assertions:
        - attr:tracetest.selected_spans.count <= 5  # Catch N+1 SQL regressions
