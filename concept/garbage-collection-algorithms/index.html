STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What are Garbage Collection Algorithms.

Garbage collectors automatically reclaim unreachable heap objects using two families of algorithms: Reference Counting (used in CPython/Swift, tracking incoming pointer counts per object) and Tracing (used in JVM, Go, V8, tracing reachability from GC Roots like stacks and globals).

Modern tracing collectors maintain the tri-color invariant (White = unvisited, Grey = discovered/unscanned, Black = scanned/live). When application threads mutate pointers concurrently with the marker, write barriers (SATB in G1GC, hybrid barrier in Go) ensure a Black object never points to a White object without re-greying it.

Tri-Color Marking

Tri-Color Reachability & Concurrent Write-Barrier Invariant

Write barriers preserve the tri-color invariant during concurrent mutator execution so live objects are never swept.

02
STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why Generational & Concurrent Collectors Exist.

Naive stop-the-world (STW) mark-sweep freezes all application threads for seconds on multi-gigabyte heaps. Meanwhile, the Weak Generational Hypothesis observes that >90% of objects die young: copying only live survivors out of Eden takes O(Live) time—not O(Heap)—and eliminates external fragmentation.

Why Reference Counting Alone Fails

Reference counting reclaims acyclic objects immediately, but cannot collect cycles (A <-> B) without a backup cycle tracer and incurs atomic cache-line contention on shared pointers.

Heap Headroom Governs CPU Overhead

Tracing collectors need 1.5x–3x live-set headroom; squeezing free heap near 0% triggers continuous GC thrashing and allocation stalls.

STAGE 03 · WHERE IT IS USEDL5 · APPLIED DESIGN

Choosing the Right Collector for Your Latency & Throughput SLA.

Collector choice trades raw CPU throughput against tail-latency pause guarantees and RAM overhead.

ChoiceWhat it buysWhat it costs
Generational Regional (G1GC / V8 Orinoco)Great balance of high throughput and bounded ~10–50 ms pauses for general web/API servers.Evacuation pauses can still spike to 200+ ms under humongous allocations or sudden promotion bursts.
Concurrent Compacting (Generational ZGC / Shenandoah)Sub-millisecond (`<1 ms`) p99.9 pauses even on 64 GB–1 TB+ heaps via colored pointers / load barriers.Uses 5–15% more CPU for barriers and requires generous heap headroom to avoid allocation stalls.
Avoid GC: Hard Real-Time (<50 µs Jitter)Rust ownership or C++ arena/region allocators guarantee zero safepoint or barrier jitter.Manual lifetime/ownership engineering instead of automatic heap reclamation.
04
STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

Production Tuning: ZGC, Go GOMEMLIMIT & Python gc.freeze().

In containers, always leave 25–30% RAM headroom outside the managed heap for off-heap buffers, Metaspace, and thread stacks. In Go 1.19+, set GOMEMLIMIT to ~80–85% of the pod memory limit so GC triggers before the Linux OOM killer strikes; in forked Python workers, call gc.freeze() after master imports to prevent Copy-on-Write page unsharing.

# JDK 21+ Generational ZGC inside a 4 GiB Kubernetes container
java \
  -XX:+UseZGC \
  -XX:+ZGenerational \
  -XX:MaxRAMPercentage=72.0 \
  -XX:MaxDirectMemorySize=512m \
  -Xlog:gc*:stdout:time,uptime,level,tags \
  -jar service.jar

# Go 1.19+ soft memory limit inside a 2 GiB Kubernetes pod
export GOGC=100
export GOMEMLIMIT=1700MiB

STAGE 05 · ALTERNATIVESL6 · SCALE & TRADE-OFFS

Alternatives: Throughput STW vs. Concurrent Compacting vs. Non-Moving.

Compare the three dominant production GC designs across pause time, fragmentation, and CPU cost.

ChoiceWhat it buysWhat it costs
Parallel / Throughput STW GCZero barrier overhead (~98%+ mutator CPU), ideal for offline batch jobs.Multi-second STW pauses make it unsuitable for interactive APIs.
Concurrent Compacting (ZGC / Shenandoah)Eliminates fragmentation and caps STW pauses at <1 ms.Load/store barrier instructions add ~5–10% CPU overhead.
Non-Moving Mark-Sweep (Go Runtime)Sub-millisecond STW phases with no object relocation barriers; size-segregated spans limit fragmentation.Cannot compact sparse pages back into contiguous bump-pointer regions.
06
STAGE 06 · PRODUCTION ARCHITECTUREL7 · STAFF / PRINCIPAL

Production Safeguard: Low-Pause GC + Fencing Tokens.

Even concurrent collectors can hit allocation stalls if mutators allocate faster than background threads reclaim. In distributed systems holding leases or locks, pair low-pause GC (ZGC) with storage-enforced fencing tokens so an unexpected safepoint or allocation stall never corrupts shared state.

Container Memory & Lease Safety

GOMEMLIMIT / ZGC Backpressure vs. OOMKill

Proactive memory limits (GOMEMLIMIT, MaxRAMPercentage=72%) trigger reclamation before the Linux cgroup OOM killer fires.
