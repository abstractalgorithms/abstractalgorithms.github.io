CDN Architecture & Geo-Distributed Edge Caching

Slash origin server latency using BGP Anycast routing, edge PoPs, cache-control directives, and stale-while-revalidate invalidation.

Orientation & Intuition

A Content Delivery Network (CDN) is a globally distributed network of Points of Presence (PoPs) that terminates client TCP/TLS connections physically close to users via BGP Anycast routing. By serving cached static assets and API responses from the network edge, CDNs reduce origin server load by 80-95% and drop round-trip times from hundreds of milliseconds to under 15ms.

Key takeaway Use BGP Anycast to terminate user TCP/TLS handshakes at the closest edge PoP; combine Cache-Control directives (s-maxage, stale-while-revalidate) with surrogate keys (Cache-Tags) to achieve instant origin offload without serving stale data.

Core Architecture & Trade-offs

The speed of light imposes an immutable physical limit on network packets: transcontinental round-trips (e.g. London to California) cost ~140ms per round trip. Requiring 3-way handshakes, TLS negotiation, and data fetches across oceans creates sluggish multi-second page loads. CDNs place cached data and TLS terminators within 10ms of 95% of global internet users.

Key Architecture Invariants

  • BGP Anycast Routing: Multiple edge PoPs advertise the exact same IP address via Border Gateway Protocol (BGP). Internet routers automatically steer user packets to the topologically closest PoP.
  • Cache-Control & Surrogate Directives: Differentiates browser caching from shared edge caching using max-age (browser) vs s-maxage (CDN edge), and stale-while-revalidate for background updates.
  • Surrogate Keys & Tag-Based Invalidation: Tags cached objects with domain identifiers (e.g. 'article-123', 'author-45'); origin servers issue a single purge request by tag to invalidate thousands of related edge objects in milliseconds.
  • Tiered Caching & Origin Shields: Edge PoPs query regional shield PoPs instead of directly hammering origin servers on cache misses, consolidating origin read requests.
  • Edge Compute & Dynamic Request Routing: Lightweight V8 isolates or WebAssembly runtimes execute authentication, header rewriting, and A/B test experiments directly at the edge.

When to Use

  • Static web assets (images, JavaScript, CSS, fonts, videos) with high read reusability.
  • High-traffic public API endpoints with moderate freshness tolerances (e.g. product catalogs, leaderboards).
  • Shielding origin data centers against Layer 3/4 and Layer 7 volumetric DDoS attacks.

When NOT to Use

  • Strictly personalized user-specific transactional data (e.g. shopping cart checkout, bank account balances) with zero cache reuse.
  • Internal microservice RPCs operating inside the same private cloud VPC.
  • Applications with strict data residency regulations that prohibit caching payload data across international borders without sovereignty guarantees.

Deep Dive & Production Considerations

1. Physical Latency & The BGP Anycast Architecture

The primary constraint in global networking is propagation delay: fiber optic cables transmit signals at approximately 200,000 km/s (2/3 the speed of light in a vacuum).

How Anycast Works

In standard Unicast, each IP address routes to exactly one server. In Anycast, multiple edge servers in London, Tokyo, Frankfurt, and New York advertise the identical IP address via BGP. The user's local ISP router automatically sends traffic to the nearest geographic node based on standard AS-path metrics.

2. HTTP Cache-Control Header Semantics

http 
HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8
Cache-Control: public, max-age=300, s-maxage=3600, stale-while-revalidate=86400
Surrogate-Key: product-catalog category-electronics
ETag: "33a64df551425fcc55e4d42a148795d9f25f89d4"
  • public: Allows both shared edge proxies (CDNs) and private user browsers to cache the response.
  • max-age=300: Browsers can cache the response for 5 minutes before verifying freshness.
  • s-maxage=3600: CDN shared edge caches can retain the object for 1 hour, ignoring the browser max-age.
  • stale-while-revalidate=86400: If the 1-hour window expires, the CDN serves the stale cached copy instantly to the user while asynchronously dispatching a single background request to origin to refresh the cache.

3. Surrogate Keys & Instant Tag-Based Purging

Instead of maintaining brittle URL lists for cache eviction, high-throughput architectures attach Surrogate-Keys:

  1. When generating a product page, the application adds: Surrogate-Key: product-994 category-audio brand-sony.
  2. The CDN indexes the cached item under all three tags.
  3. When the product price changes, the backend emits:
    bash 
    curl -X POST "https://api.fastly.com/service/$SVC_ID/purge/product-994" \
  -H "Fastly-Key: $API_TOKEN"
  4. The CDN immediately invalidates that single product across all 150+ global PoPs in < 150ms without touching unrelated items.
