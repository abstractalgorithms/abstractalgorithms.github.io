01
STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What is CDN Edge Caching.

A Content Delivery Network (CDN) is a globally distributed reverse-proxy tier that terminates TCP/QUIC and TLS at Points of Presence (PoPs) 5–20 ms from end users.

Using BGP Anycast, every PoP announces the same IP prefix so routers send each user to the topologically closest healthy PoP. Inside HTTP headers, max-age controls the browser cache while s-maxage controls the shared CDN cache—letting you cache aggressively at the edge (e.g., 24h) with instant surrogate-key purging while keeping browser TTLs short (60s).

Two-Tier Edge Shield

User (Anycast) -> Edge PoP -> Origin Shield -> Authenticated Origin

1.Origin Shielding: Funneling 200 global PoPs through 1 regional Shield PoP collapses global cache misses into 1 origin fetch.

2.Stale-While-Revalidate: Serves expired content in 0 ms while refreshing asynchronously in the background.

3.Authenticated Origin Pull: Origin ALB verifies the CDN's client mTLS cert to close direct-to-IP DDoS bypasses.

Anycast PoPs + Origin Shielding + mTLS Origin Pulls deliver 5-20 ms global reads while protecting origin capacity.

02
STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why we need Key Normalization & Collapse Controls (and cache-busting traps).

Misconfigured CDNs silently drop from 99% hit rate to 0% and DDoS your own origin:

  1. Query-String Cache Busting: Marketing links append unique ?fbclid=xyz or ?utm_source=ig parameters, creating millions of distinct cache keys for the exact same page.
  2. Cookie Poisoning: An analytics script sets a session cookie on the root domain, and default CDN rules bypass caching whenever a Cookie header is present.
  3. Vary-Header Explosion: Returning Vary: User-Agent fragments the cache across thousands of browser strings instead of normalizing to mobile/desktop.
Edge Request Flow

Anycast QUIC Handshake -> Key Normalization -> SWR Background Refresh

Key normalization preserves hit rates, while stale-while-revalidate hides revalidation latency from users.

Content-Hashed Immutable Assets

Serve app.9d2f.js with public, max-age=31536000, immutable—never purge it; just deploy a new filename hash.

Surrogate-Key Purging

Tag responses with Surrogate-Key: sku-42 cat-shoes so updating a product purges all affected catalog pages in <150 ms.

STAGE 03 · WHERE IT IS USEDL5 · APPLIED DESIGN

Where Edge Caching Policies apply by route type.

Separate immutable static bundles, semi-dynamic catalog pages, and private user endpoints with distinct Cache-Control policies.

ChoiceWhat it buysWhat it costs
Immutable Static Assets (`app.9d2f.js`)public, max-age=31536000, immutable: 99.9%+ hit rate, zero origin traffic, never needs purging.Requires build-pipeline content hashing in filenames.
Semi-Dynamic Catalog / CMS APIspublic, max-age=30, s-maxage=86400, stale-while-revalidate=300 + Surrogate-Key purge.Must strip tracking query params and irrelevant cookies from the edge cache key.
Private User Data (`/me`, `/checkout`)private, no-store guarantees shared CDN PoPs never cache PII across users.Still benefits from CDN TLS termination and HTTP/3 connection reuse to origin.
04
STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

How Cache Headers, Key Normalization, and Origin Pulls are configured.

Normalize cache keys at the edge (strip utm_*, fbclid, gclid), enable Request Collapsing + Origin Shield, and lock down the origin firewall to accept only CDN mTLS / IP ranges.

# Origin response headers for semi-dynamic catalog + Surrogate-Key purging
location /api/v1/catalog/ {
    add_header Cache-Control "public, max-age=30, s-maxage=86400, stale-while-revalidate=300";
    add_header Vary "Accept-Encoding"; # never Vary: * or raw User-Agent
    proxy_pass http://catalog_backend;
}

# Immutable fingerprinted static bundles
location /assets/ {
    add_header Cache-Control "public, max-age=31536000, immutable";
}

STAGE 05 · ALTERNATIVESL6 · SCALE & TRADE-OFFS

Alternatives: CDN Edge vs. Regional Reverse Proxy vs. App Redis.

Combine edge caching for network RTT reduction with Redis for personalized or fine-grained dynamic fragments.

ChoiceWhat it buysWhat it costs
Global Anycast CDN (Cloudflare, Fastly, CloudFront)5-20 ms RTT globally, HTTP/3 0-RTT, DDoS/WAF absorption before origin.Coarser invalidation than in-app Redis; requires careful header/cookie discipline.
Origin Redis / VarnishFine-grained per-user or per-object caching and complex assembly.Users still pay full cross-continental WAN RTT to reach the origin region.
Edge Compute (Workers + KV)Runs auth/A-B routing or HTML personalization at the PoP without hitting origin.Strict CPU/memory limits and eventual consistency for global KV stores.
06
STAGE 06 · PRODUCTION ARCHITECTUREL7 · STAFF / PRINCIPAL

Production example: Anycast CDN + Origin Shield + Surrogate-Key Purge Bus.

Global storefronts emit Surrogate-Key tags on catalog responses. When a merchant updates price or inventory in PostgreSQL, a CDC event calls the CDN Purge API by surrogate key in <150 ms while Origin Shield coalesces the resulting re-fetches.

Instant Edge Purge

Merchant DB Update -> CDC Purge Worker -> CDN Surrogate-Key Eviction

1.Targeted Invalidation: Purge sku-42 across all 200+ PoPs without flushing the entire site cache.

2.Shield Collapse: Origin Shield absorbs the post-purge spike into 1 origin query per region.

3.HTTP/3 + 0-RTT: QUIC eliminates TCP head-of-line blocking on lossy mobile networks.

Surrogate-key purging + Origin Shield gives near-real-time freshness with 95%+ origin offload.
