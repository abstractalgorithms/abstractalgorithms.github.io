STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What are BFS, DFS, and Dijkstra.

Graph algorithms fall into three core traversal patterns over an adjacency list (which takes ~8 MB for V=100k, deg=10 vs. ~10 GB for an O(V²) matrix):

  • BFS (O(V+E)): Expands level-by-level via a FIFO queue, guaranteeing minimum-hop shortest paths on unweighted graphs.
  • DFS (O(V+E)): Explores deep via recursion or an explicit stack; 3-color marking (White/Gray/Black) detects directed cycles and produces topological orderings.
  • Dijkstra (O((V+E) log V)): Greedily pops the lowest-cost frontier vertex from a min-heap for non-negative weighted graphs.
3-Color DFS

Directed Cycle Detection & Topological Sort State Machine

An edge pointing to a GRAY node proves a cycle exists in a directed graph; reverse exit order yields a valid topological sort.

STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why Picking the Wrong Traversal Breaks Scale or Correctness.

Using DFS for shortest paths misses optimal routes; using Dijkstra on negative edge weights locks in suboptimal distances; and running unidirectional BFS on a 50M-user social graph (b=120, depth=4) visits >200M edges, whereas Bidirectional BFS cuts visited nodes from ~1.7M to ~25k.

Stale Heap Entry Skip in Dijkstra

When using lazy deletion in a min-heap, always check if d > dist[u]: continue right after popping (d, u) so outdated entries don't re-relax neighbors.

Iterative DFS for Deep Chains

Deep dependency chains (V > 10,000) overflow the OS call stack in recursive DFS; use an explicit heap-allocated stack.

Matching Traversal to Problem Structure.

Select BFS, Bidirectional BFS, DFS, or Dijkstra based on edge weights and query shape.

ChoiceWhat it buysWhat it costs
BFS / Bidirectional BFS (Unweighted)Minimum-hop paths in social graphs and network topologies; bidirectional search shrinks `O(b^d)` to `O(2 * b^(d/2))`.Stores the full frontier queue in RAM (`O(b^d)`), unlike DFS's `O(d)` stack.
DFS / Kahn's Topological Sort (DAGs)Detects circular imports in 18,000-package Bazel/Cargo monorepos in `<40 ms` and schedules parallel builds.Cannot find shortest paths; recursive form risks stack overflow on deep chains.
Avoid Dijkstra: Negative Edge WeightsUse Bellman-Ford (`O(VE)`) or SPFA when rebates or `-ln(rate)` arbitrage edges are negative.Dijkstra's greedy finality assumption silently returns wrong answers on negative edges.

STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

Dijkstra with Stale-Pop Guard & 3-Color Cycle Detection.

Combine heapq with a dist table and stale-entry skip (if d > dist[u]: continue) for clean O((V+E) log V) Dijkstra.

import heapq

def dijkstra(adj: dict[int, list[tuple[int, int]]], src: int, n: int) -> list[float]:
    dist = [float("inf")] * n
    dist[src] = 0.0
    pq = [(0.0, src)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]:
            continue  # Skip stale heap entry
        for v, w in adj.get(u, ()):
            if w < 0:
                raise ValueError("Dijkstra requires non-negative weights")
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist

STAGE 05 · ALTERNATIVESL6 · SCALE & TRADE-OFFS

Alternatives: Dijkstra vs. A* Search vs. Bellman-Ford.

When domain geometry or negative weights enter the picture, specialize beyond plain Dijkstra.

ChoiceWhat it buysWhat it costs
Dijkstra (`O((V+E) log V)`)No domain heuristic required; computes shortest paths to all reachable nodes from `src`.Expands uniformly in all directions even when target coordinates are known.
A* Search (Admissible Heuristic)Guides expansion toward the target using Euclidean/Haversine lower-bound estimates, cutting visited nodes by 5x–20x.Requires a provably admissible (`h(u) <= true_dist(u, target)`) heuristic.
Bellman-Ford (`O(V · E)`)Handles negative edge weights and detects negative-weight cycles.Significantly slower than Dijkstra on large non-negative graphs.

Production Optimization: Bidirectional BFS Frontier Expansion.

When finding shortest paths between a known src and dst in high-degree social or microservice graphs, always expand the smaller frontier queue next—turning b^6 blowups into two tiny b^3 meets in the middle.

Search Space Reduction

Bidirectional BFS: Expand Smaller Frontier Until Intersection

Always expanding whichever frontier is smaller cuts visited nodes from O(b^d) to O(2 * b^(d/2)).
