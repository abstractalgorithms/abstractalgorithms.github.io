The idea & core mechanics.

Why does a 4,000-token RAG prompt answer in 150ms for the first word, yet take 8 seconds to finish streaming 400 words—and cost 4x more per output token? Because LLM inference runs two completely different workloads: all input tokens fly through GPU tensor cores in parallel (Prefill), whereas every output token must stream model weights and the KV cache from HBM memory one token at a time (Decode). See how production gateways budget prompts and prefix caches in Design an Enterprise RAG Gateway.

ChoiceWhat it buysWhat it costs

Think twiceEstimating token budgets by word count alone—code, JSON, and non-English text expand 2x–4x in token count.

Principle 1

Subword tokenization (BPE / SentencePiece): ~1 English token ≈ 4 chars (~0.75 words), whereas JSON punctuation, whitespace, and non-Latin scripts consume far more tokens per character.

Principle 2

Input tokens (Prompt): Processed in parallel in one Prefill pass—compute-bound (O(N²) attention), driving Time To First Token (TTFT).

Principle 3

Output tokens (Completion): Generated autoregressively one token at a time—HBM memory-bandwidth-bound, driving Time Per Output Token (TPOT) and total generation time.

Principle 4

Context window = Input tokens + Output tokens: both must fit inside max_context_len, and both allocate KV-cache memory for the duration of the request.

RAG Prompt Budget & Cost Asymmetry.

A RAG assistant sends 6,000 input tokens (system prompt + 8 retrieved chunks) and generates 400 output tokens.

Lesson: Prefill processes all 6,000 input tokens in ~120ms (TTFT). Decode takes 400 sequential steps (~20ms/token = 8 seconds total). At $2.50/1M input and $10/1M output, the 400 output tokens cost ~$0.004 while the 6,000 input tokens cost ~$0.015—and caching the 2,000-token system prefix cuts input cost and TTFT further.

Reference implementation (Python — Context Window & Output Reserve Budgeter)

# Deterministic context-window budgeter preventing output truncation (Python)
def fit_rag_chunks(system_tokens: int, query_tokens: int, chunks: list[tuple[str, int]],
                   max_context: int = 8192, reserve_output: int = 1024) -> list[str]:
    budget = max_context - reserve_output - system_tokens - query_tokens
    selected = []
    for text, tok_len in chunks:
        if tok_len <= budget:
            selected.append(text)
            budget -= tok_len
    return selected

Failure modes & mitigations.

How Input & Output Tokens breaks under concurrency, partial network partitions, or overload—and how production systems recover.

Silent Output Truncation

Input + output exceeds context window or hits max_tokens, cutting off JSON mid-object. Mitigation: Reserve max_tokens upfront from the context budget and trim retrieved chunks/history before calling the model.

Prompt Cache Busting

Placing a dynamic timestamp or user ID at the start of the system prompt invalidates KV prefix caching on every request. Mitigation: Put all static instructions and tool schemas first; append dynamic user/RAG context at the end.
