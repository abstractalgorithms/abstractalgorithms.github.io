What is an API Gateway.

Why this matters: The mechanism: understand how an API Gateway works from first principles.

Think of What is an API Gateway as the intuition layer for API Gateway & Layer 7 Protocols: The mechanism: understand how an API Gateway works from first principles.

An API gateway is a reverse proxy operating at OSI Layer 7 (Application Layer). Unlike a Layer 4 load balancer that forwards raw TCP/UDP packets by IP and port, an L7 gateway parses HTTP headers, paths, cookies, gRPC metadata, and WebSocket upgrade handshakes—terminating TLS 1.3 once at the edge, validating JWTs against a cached JWKS, enforcing token-bucket rate limits, and transcoding REST/JSON to internal gRPC/Protobuf.

Edge Filter Chain

Layer 7 API Gateway Request & Protocol Routing Pipeline

1.TLS & ALPN Termination: Terminates external TLS 1.3 once at the edge and reuses long-lived HTTP/2 pools upstream.

2.Local Auth & Rate Limit: Verifies JWT signatures against cached JWKS and checks token buckets before forwarding.

3.Protocol Transcoding: Translates browser REST/JSON into internal binary gRPC frames using .proto descriptors.

An L7 gateway terminates edge protocols once and routes stateless RPCs and stateful sockets to isolated upstream pools.

STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why we need L7 Gateways (and why L4 proxies break gRPC).

Why this matters: The problem: see what breaks without L7 Gateways under real concurrency or scale.

Think of Why we need L7 Gateways (and why L4 proxies break gRPC) as the intuition layer for API Gateway & Layer 7 Protocols: The problem: see what breaks without L7 Gateways under real concurrency or scale.

Layer 4 load balancers break HTTP/2 and gRPC: because gRPC multiplexes thousands of RPCs over one long-lived TCP connection, an L4 proxy pins all RPCs from a client onto a single backend pod. Gateways also prevent WebSocket reconnect storms, buffer bloat on large uploads, and timeout mismatches between REST (5s) and WebSocket routes (60s+ idle).

L7 Stream Balancing

HTTP/2 gRPC Transcoding & Per-RPC Upstream Balancing

Terminating HTTP/2 at the L7 gateway lets it balance individual gRPC streams across all backend pods.

Engineering Decision Framework
Problem
How to implement API Gateway & Layer 7 Protocols without hitting unbounded tail latency, state divergence, or operational fragility.
Naive Solution
Use a single unpartitioned path with unbounded retries and synchronous global coordination.
Why It Fails
Global coordination serializes throughput under load, while unbounded retries amplify transient stalls into full outages.
Alternatives
Compare synchronous strict-consistency paths against bounded asynchronous replication, local caching, or partitioned ownership.
Engineering Decision
To bound blast radius during partial cluster failures, centralize cross-cutting edge concerns in a single L7 proxy, but keep business logic out of it so the gateway never becomes a monolithic bottleneck.
Trade-Offs
Gains predictable p99 latency and fault isolation in exchange for explicit bounding, observability, and slightly higher implementation complexity.

Use an API gateway at the north-south ingress boundary for cross-cutting concerns; split UI aggregation into a BFF and high-volume /ws sockets into a dedicated pool.

ChoiceWhat it buysWhat it costs
North-South Edge Ingress (REST + gRPC)Centralizes TLS, WAF, JWKS auth, rate limiting, and observability (X-Request-ID).Adds 1–3 ms proxy hop; misconfigured plugins affect all routes globally.
Dedicated /ws WebSocket Pool (>50k sockets)Isolates memory-heavy persistent sockets from latency-sensitive REST/gRPC workers.Requires gradual connection draining (5–10 min) + jittered client reconnects on deploy.
Avoid: Domain Business Logic in Gateway PluginsMove fan-out joins and DB lookups into a separate Backend-for-Frontend (BFF) service.Heavy Lua/Wasm orchestration turns the gateway into an unmaintainable monolith.

Compare connection models, payload formats, and load-balancing requirements across L7 protocols.

ChoiceWhat it buysWhat it costs
REST (HTTP/1.1 & HTTP/2 + JSON)Native browser support, human-readable, cacheable via ETag/Cache-Control.Verbose JSON parsing and larger payloads at high RPS.
gRPC (HTTP/2 + Protobuf)5–10x smaller binary payloads, strict .proto contracts, bidirectional streaming.Requires L7 stream balancing and grpc-web/JSON transcoding for browsers.
