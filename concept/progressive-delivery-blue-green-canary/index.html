01
STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What is Progressive Delivery.

Progressive delivery separates deploying a binary from exposing a feature to 100% of users using three complementary mechanisms: Blue-Green (two identical environments with an instant load-balancer cutover), Canary (incremental traffic shifting 1% -> 10% -> 50% -> 100% gated by automated P99 latency and 5xx SLO checks over 5–15 minute bake windows), and Feature Toggles (runtime flags decoupling trunk merges from user cohort activation).

Canary Rollout Gate

Automated SLO-Gated Canary Progression & Rollback

Automated metric gates halt and revert bad releases before more than a tiny fraction of users are affected.

02
STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why we need Progressive Delivery (Bounding Blast Radius).

Big-bang weekend deploys turn minor regressions—like a memory leak or subtle N+1 query—into company-wide outages requiring frantic hotfixes. By shifting only 1% of traffic to the canary or flipping a feature flag off in <1 second, teams contain blast radius automatically and decouple marketing launches from code pushes.

Expand-Contract DB Compatibility Is Mandatory

During Blue-Green or Canary rollouts, old (v1) and new (v2) replicas share the same database concurrently—never drop or rename columns until v1 pods are 100% drained.

Flag Hygiene Prevents Combinatorial Tech Debt

Assign a 30-day TTL to release toggles and delete stale flags once 100% rolled out.

03
STAGE 03 · WHERE IT IS USEDL5 · APPLIED DESIGN

Where Blue-Green, Canary, and Feature Toggles fit.

Match the rollout mechanism to your compute budget, stateful constraints, and observability maturity.

ChoiceWhat it buysWhat it costs
Good Candidate: Canary (High-Traffic Microservices)Minimal extra compute (1–10% surge) and tiny blast radius gated by real Prometheus P99/5xx metrics.Requires mature observability, statistical baseline comparison, and automated rollback triggers.
Good Candidate: Blue-Green (Monoliths / Stateful Cutovers)Instant atomic LB/DNS flip-back with zero mixed-version replicas serving traffic simultaneously.Requires 2x compute capacity during cutover and careful DB backward compatibility.
Avoid: Breaking Schema Drops During Active RolloutsAlways run Expand -> Backfill -> Switch -> Contract across separate deploys.Dropping a column while v1 pods are still live crashes 100% of v1 traffic.
04
STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

How Argo Rollouts Canary Gates are configured.

Use a progressive delivery controller (Argo Rollouts or Flagger) with explicit traffic steps, bake pauses, and an AnalysisTemplate querying Prometheus for error rate and p99 latency against the baseline.

# Argo Rollouts Canary spec with automated SLO analysis
apiVersion: argoproj.io/v1alpha1
kind: Rollout
spec:
  strategy:
    canary:
      steps:
        - setWeight: 5
        - pause: { duration: 10m }
        - analysis:
            templates: [{ templateName: slo-5xx-p99-gate }]
        - setWeight: 25
        - pause: { duration: 10m }
        - setWeight: 100

STAGE 05 · ALTERNATIVESL6 · SCALE & TRADE-OFFS

Alternatives: Blue-Green vs. Canary vs. Rolling Update.

Each deployment strategy trades compute overhead against rollback speed and mixed-version exposure.

ChoiceWhat it buysWhat it costs
Blue-Green DeploymentInstant atomic rollback; clean version separation (never mixes v1 and v2 traffic).Requires 2x peak compute capacity during cutover windows.
SLO-Gated CanaryMinimal extra capacity and automated <1–5% blast radius containment.v1 and v2 run concurrently, requiring backward-compatible APIs and schemas.
Standard Kubernetes Rolling UpdateBuilt-in with zero extra controllers or service mesh.Lacks automated Prometheus SLO rollback gates—readiness probes alone miss business-logic 500s.
06
STAGE 06 · PRODUCTION ARCHITECTUREL7 · STAFF / PRINCIPAL

Production example: Envoy Weighted Canary + Prometheus Gate.

Argo Rollouts shifts 5% of Envoy ingress traffic to the v2 canary pods, waits 10 minutes, and runs an AnalysisRun comparing canary vs. baseline p99 latency and 5xx rate. When canary 5xx spikes above threshold, Argo automatically resets weight to 0% in seconds.

Canary Evaluation Flow

Argo Rollouts + Envoy + Prometheus Auto-Rollback

Unbiased canary evaluation catches regressions at 5% traffic and restores 100% v1 without human intervention.
