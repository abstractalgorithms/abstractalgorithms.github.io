Reinforcement Learning
Basics.

Reinforcement learning (RL) trains an agent to make sequential decisions by interacting with an environment and maximizing cumulative discounted reward rather than learning from static labeled examples.

THE BIG IDEA / Key takeaway · CONCEPT GUIDE

Formulate a problem as a Markov Decision Process (MDP) with clear states, actions, and shaped rewards—and only reach for RL when delayed feedback or sequential trade-offs defeat supervised learning or heuristics.

Explanation anchor
01 / The idea

Foundational mechanics & core principles

Many real-world optimization problems—from adaptive bitrate streaming and data-center cooling to LLM alignment via RLHF—cannot be solved by single-step predictions because every action changes future states. RL provides a principled mathematical framework for balancing immediate payoff against long-term outcomes under uncertainty.

  • Every RL problem is modeled as a Markov Decision Process (MDP) defined by states (S), actions (A), transition dynamics P(s'|s,a), reward R(s,a), and discount factor gamma (typically 0.95–0.995).
  • Agents must balance exploration (trying unfamiliar actions to discover higher rewards) and exploitation (selecting the best-known action), commonly via epsilon-greedy schedules or entropy regularization.
  • Value-based methods (Q-learning, DQN) estimate expected return Q(s,a) and derive a policy via argmax, whereas policy-gradient methods (PPO, SAC) directly optimize a parameterized policy pi(a|s).
  • Temporal-difference (TD) learning updates value estimates from bootstrapped next-state predictions, trading slight bias for dramatically lower variance than full Monte Carlo rollouts.
  • Reward design is the primary engineering lever: poorly specified rewards cause reward hacking, where the agent maximizes the metric while violating the designer's intent.

Good candidates

  • Decisions are sequential and each action alters future states and available options (e.g., robotics control, traffic routing, inventory replenishment).
  • A fast, faithful simulator or safe offline environment exists where an agent can run thousands to millions of trial episodes without catastrophic cost.
  • Optimal behavior is hard to label per step, but a scalar outcome metric (throughput, energy saved, win/loss, human preference score) is measurable.

Think twice

  • Each decision is independent and labeled ground truth is available—standard supervised learning (XGBoost, neural classifiers) converges faster and is far more stable.
  • Exploring suboptimal actions in production carries unacceptable safety, financial, or compliance risk and no high-fidelity simulator exists.
  • Simple domain heuristics, PID controllers, or convex optimization (LP/MILP) already achieve near-optimal performance with deterministic guarantees.

02 / Concrete walkthrough

Architectural mechanics & implementation

ScenarioA video player must choose chunk bitrates (300 kbps to 6 Mbps) every 2 seconds over fluctuating cellular links without knowing future bandwidth.

The idea

Reinforcement learning models decision-making as a closed feedback loop between an agent and an environment, formalized as a Markov Decision Process (MDP) tuple (S, A, P, R, gamma). At discrete step t, the agent observes state s_t, selects action a_t according to policy pi(a|s), receives scalar reward r_t, and transitions to s_{t+1}.

The agent's objective is to maximize expected discounted return G_t = sum_{k=0}^{inf} gamma^k * r_{t+k}, where gamma in [0, 1) controls how strongly future rewards are weighted relative to immediate ones. Unlike supervised learning, there is no oracle providing the right label y_t at each step; the agent must solve the temporal credit assignment problem—figuring out which earlier actions caused a reward observed many steps later.

Concrete walkthrough

Consider tuning a 200-step Proximal Policy Optimization (PPO) loop in Gymnasium (CartPole-v1 or a custom autoscaler simulator) using PyTorch:

  1. Vectorized rollout: Run 8 parallel environment workers for T = 128 steps each, collecting a batch of 1,024 transitions (s_t, a_t, r_t, done_t, log_prob_t, V(s_t)).
  2. Advantage estimation (GAE): Compute Generalized Advantage Estimation A_t with gamma = 0.99 and lambda = 0.95. An advantage A_t > 0 means action a_t outperformed the critic's baseline V(s_t).
  3. Clipped policy update: Over 4 epochs of mini-batch size 256, compute the probability ratio r_t(theta) = pi_theta(a_t|s_t) / pi_old(a_t|s_t) and optimize L_CLIP = min(r_t * A_t, clip(r_t, 0.8, 1.2) * A_t).
  4. Value & entropy loss: Jointly minimize (V_theta(s_t) - G_t)^2 and add -0.01 * H(pi_theta) to prevent premature deterministic collapse.
  5. Evaluation gate: Every 10 updates, run 20 deterministic eval episodes (argmax or mean action) on held-out seeds and promote the checkpoint only if mean return improves.

Closed-loop actor-critic cycle: transitions flow from the environment into a rollout buffer, where the critic computes advantages to safely update the policy.

Core algorithm families and when each fits

RL algorithms split into three practical families:

  • Value-based (DQN, Rainbow): Learn Q(s, a) using Bellman backups r + gamma * max_{a'} Q_target(s', a'). Best for discrete action spaces (e.g., 5–50 choices) where an experience replay buffer maximizes sample efficiency.
  • On-policy Actor-Critic (PPO, A2C): Maintain both a policy pi(a|s) and a value baseline V(s). Work seamlessly for discrete or continuous actions, tolerate noisy rewards well, and are the standard choice for RLHF and fast simulators.
  • Off-policy Actor-Critic (SAC, TD3): Combine replay buffers with continuous policy networks and twin Q-critics. Soft Actor-Critic (SAC) maximizes reward plus policy entropy, making it ideal for continuous robotics and control where simulator steps are expensive.

Failure modes and diagnostics

When an RL run flatlines or diverges, inspect four telemetry curves before changing architecture:

  • Explained variance of V(s) < 0: The critic is worse than predicting the mean return; check reward scaling, gamma, or value-loss weight.
  • Policy entropy drops to zero early: The agent locked onto a suboptimal deterministic action before exploring; increase entropy coefficient or use SAC.
  • KL divergence spikes (> 0.05 per update): Policy steps are too aggressive; lower learning rate (e.g., 3e-4 -> 1e-4) or tighten PPO clip range.
  • High training return, poor eval return: The agent memorized deterministic simulator quirks; add domain randomization and evaluate across unseen seeds.

Bridging simulation to production

Production RL systems almost never allow an unconstrained neural policy to act directly on live infrastructure. Instead, teams wrap the policy in a safety shield (a deterministic rule layer that rejects or clamps out-of-bounds actions), run the policy in shadow mode logging counterfactual actions against the incumbent heuristic, and gate rollouts with off-policy evaluation (OPE) estimators such as Doubly Robust or Importance Sampling before enabling a 1–5% canary slice.

Practical checklist

  • Confirm sequentiality: Verify that current actions genuinely alter future states; otherwise use contextual bandits or supervised learning.
  • Build a baseline first: Benchmark a random policy and a simple domain heuristic to establish floor and target metrics.
  • Normalize inputs and clip rewards: Apply running mean/std normalization to observations and scale rewards to roughly [-10, 10].
  • Separate train and eval seeds: Report mean and 10th-percentile return across at least 10 held-out evaluation seeds.
  • Add deterministic safety bounds: Enforce hard physical, latency, or budget guardrails outside the learned policy before production.
03 / Engineering trade-offs

Weighing architectural decisions

On-policy (PPO) vs. Off-policy (DQN / SAC)

Advantage: On-policy algorithms like PPO are stable, easy to tune, and parallelize cleanly across vectorized environments.

Drawback: On-policy updates discard trajectories after each gradient step, requiring 10x–100x more environment samples than replay-buffer off-policy methods.

Dense shaped rewards vs. Sparse terminal rewards

Advantage: Dense intermediate rewards accelerate credit assignment in long-horizon tasks where terminal success is rare.

Drawback: Hand-crafted shaping often introduces unintended local optima where agents farm intermediate bonuses instead of finishing the task.

Sim-to-real training vs. Live online learning

Advantage: Simulators enable millions of fast, risk-free episodes and domain randomization before touching hardware.

Drawback: Unmodeled dynamics (sim-to-real gap) can cause policies to fail abruptly when deployed to physical or production environments.

04 / Failure modes & resilience

Explain where it breaks · Known failure modes

Reward Hacking / Specification Gaming

The agent discovers an exploit that yields high numerical reward without achieving the intended real-world goal (e.g., spinning in place to collect proximity bonuses).

What helps: Use potential-based reward shaping, add terminal task-completion gates, and audit top-reward trajectories visually and statistically.

Q-Value Overestimation & Divergence

Combining function approximation, bootstrapping, and off-policy updates (the 'deadly triad') causes Q-estimates to spiral to infinity.

What helps: Use target networks, Double DQN / clipped double-Q (TD3/SAC), gradient norm clipping, and reward scaling.

Policy Collapse / Catastrophic Forgetting

An overly large policy gradient step destroys previously learned behavior, collapsing episode return mid-training.

What helps: Constrain step size with PPO's clipped surrogate objective (clip=0.2) or KL-divergence penalties, and checkpoint best evaluation weights.

Distribution Shift in Offline / Production Rollouts

State distributions encountered in production diverge from training logs, causing erratic out-of-distribution actions.

What helps: Apply conservative offline RL penalties (CQL), ensemble uncertainty wrappers, and deterministic safety shields that clamp unsafe actions.

05 / Practical checklist

Avoid these mistakes

  • Deploying RL on a problem with no sequential state dependency where contextual bandits or supervised learning would converge in minutes.
  • Training without normalizing observations and rewards, leading to exploding gradients when sensor scales span orders of magnitude.
  • Evaluating only on training seeds instead of held-out environment configurations, masking severe overfitting to deterministic dynamics.
  • Setting gamma too low (e.g., 0.5) for long-horizon tasks, making the agent myopic, or too high (0.9999) without sufficient episode length.
  • Skipping a simple baseline (random policy, greedy heuristic, or PID controller) before investing weeks in neural RL pipelines.
