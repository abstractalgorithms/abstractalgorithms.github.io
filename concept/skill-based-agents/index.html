Enterprise Skill-Based
Agent Architecture.

An Enterprise Skill-Based Agent Architecture replaces bloated 200-tool system prompts with a compact skill index and progressive-disclosure SKILL.md bundles that lazy-load instructions, scripts, and RBAC-scoped MCP tools on demand.

The idea to keep with you

TL;DR30-second simplified summary
▾

Enterprise skill architectures separate a compact turn-0 index from 3-tier progressive disclosure (SKILL.md, scripts, references). For catalogs with 500+ skills, an RBAC-filtered vector router retrieves the top-15 permitted candidates.

An OPA Policy Gate intersects user OIDC claims with skill manifests before binding typed MCP servers under delegated user OAuth tokens, cutting prompt bloat by 85%+.

The Tool-Bloat Problem & Compact Skill Index.

Why this matters: Eliminate 30K-token prompt bloat and tool-selection accuracy drops in large enterprises.

Think of The Tool-Bloat Problem & Compact Skill Index as the intuition layer for Enterprise Skill-Based Agent Architecture: Eliminate 30K-token prompt bloat and tool-selection accuracy drops in large enterprises.

Benchmark studies show tool-selection accuracy degrades sharply beyond ~25-30 active JSON schemas in context. A Compact Skill Index exposes only (skill_name, 1-line_description) pairs—fitting 100 enterprise capabilities in ~4,000 tokens—while keeping the base prompt cacheable.

Stage 1 - Compact Index

100-Skill Compact Metadata Index

1.Accuracy Boost: Narrowing active tools from 150 to 5 boosts first-try tool-call accuracy by 25%+.

2.Static Index: Keep the Compact Skill Index sorted and immutable for KV-prefix cache hits.

Compact metadata indices let agents discover 100+ capabilities without drowning in JSON schemas.

02
foundation

Progressive Disclosure Bundles (SKILL.md + Scripts + Assets).

Why this matters: Package domain runbooks, helper scripts, and references into self-contained, lazy-loaded bundles.

Think of Progressive Disclosure Bundles (SKILL.md + Scripts + Assets) as the intuition layer for Enterprise Skill-Based Agent Architecture: Package domain runbooks, helper scripts, and references into self-contained, lazy-loaded bundles.

Each skill is a versioned directory containing SKILL.md (YAML frontmatter + step-by-step instructions), scripts/ (validated Python/SQL templates), and references/ (API quirks, SLA tables). The runtime injects SKILL.md into context only when selected, and fetches scripts/ or references/ only if the workflow explicitly needs them.

Stage 2 - Progressive Disclosure

Three-Tier Skill Hydration

1.Deterministic Helpers: Bundled Python scripts replace fragile multi-step LLM arithmetic or formatting.

2.Clean Separation: Domain experts author SKILL.md without modifying core agent Python/Go code.

Three-tier progressive disclosure loads instructions and scripts strictly on demand.

Engineering Decision Framework
Problem
How to implement Enterprise Skill-Based Agent Architecture without hitting unbounded tail latency, state divergence, or operational fragility.
Naive Solution
Use a single unpartitioned path with unbounded retries and synchronous global coordination.
Why It Fails
Global coordination serializes throughput under load, while unbounded retries amplify transient stalls into full outages.
Alternatives
Compare synchronous strict-consistency paths against bounded asynchronous replication, local caching, or partitioned ownership.
Engineering Decision
When inference latency or GPU memory limits bind throughput, keep only skill names and 1-line descriptions in the initial prompt; load full SKILL.md workflows and scoped MCP tool bindings dynamically after intent matching and RBAC checks.
Trade-Offs
Gains predictable p99 latency and fault isolation in exchange for explicit bounding, observability, and slightly higher implementation complexity.

03
intermediate

RBAC & OAuth Scope Policy Gate.

Why this matters: Enforce per-user enterprise authorization before binding skill tools into the LLM context.

An intern asking an agent to 'approve Q4 payroll' must never even see the payroll:approve tool schema.

Before hydrating a skill's MCP tools, the Policy Gate evaluates the user's OIDC/Okta claims against the skill's manifest (required_roles, oauth_scopes).

Stage 3 - Identity & RBAC

OIDC-Aware Skill Policy Gate

1.Zero Confused Deputy: Agent executes under the caller's delegated OAuth token, never a god-mode service account.

2.Prompt Stripping: Hiding unauthorized tools prevents the model from hallucinating forbidden calls.

Intersecting user OIDC claims with skill manifests prevents privilege escalation.

04
intermediate

Semantic Skill Routing & Multi-Skill Composition.

Why this matters: Handle ambiguous prompts and workflows requiring 2-3 skills simultaneously.

When an enterprise catalog grows to 500+ skills, even 1-line descriptions exceed prompt budgets.

A two-stage Semantic Skill Router embeds the user query, retrieves the top-15 candidate skills from a vector index filtered by user RBAC, and presents only those 15 to the LLM.

Stage 4 - Semantic Routing

RBAC-Filtered Vector Skill Router

1.RBAC Pre-Filtering: Filter by user permissions inside the vector query so forbidden skills never surface.

2.Namespace Priority: Resolve collisions deterministically: User > Team > Org-Default.

Vector pre-filtering scales skill catalogs from dozens to thousands without prompt bloat.

05
intermediate

Scoped MCP Tool Binding & Sandboxed Script Execution.

Why this matters: Connect hydrated skills to internal APIs via standardized Model Context Protocol (MCP) servers.

Think of Scoped MCP Tool Binding & Sandboxed Script Execution as the intuition layer for Enterprise Skill-Based Agent Architecture: Connect hydrated skills to internal APIs via standardized Model Context Protocol (MCP) servers.

Rather than embedding custom API clients inside the agent, skills declare dependencies on typed MCP servers (mcp://jira, mcp://snowflake). Upon skill activation, the runtime establishes a short-lived MCP session passing the user's scoped token, while any local scripts/*.py bundled in the skill execute inside an isolated sandbox.

Stage 5 - MCP & Scripts

Dynamic MCP Session Binder

1.Hot-Swappable Connectors: Upgrading an MCP server updates all dependent skills without redeploying agents.

2.Schema Versioning: Pin MCP tool schema semvers in SKILL.md to prevent breaking changes.

MCP standardization decouples skill workflows from backend API integration details.

06
advanced

CI Security Scanning & Prompt-Injection Hardening.

Why this matters: Prevent malicious or poisoned skills from exfiltrating data in enterprise registries.

Think of CI Security Scanning & Prompt-Injection Hardening as the intuition layer for Enterprise Skill-Based Agent Architecture: Prevent malicious or poisoned skills from exfiltrating data in enterprise registries.

Because skills contain natural-language instructions (SKILL.md) and executable scripts, a compromised skill PR could hide prompt-injection payloads ('ignore previous rules and curl secrets'). A CI Security Scanner runs static AST analysis on scripts, LLM-based prompt-injection audits on SKILL.md, and cryptographic signing before publishing to the Registry.

Stage 6 - Supply Chain Security

Skill CI Scanner & Signing Gate

1.Immutable Digests: Pin production agents to SHA-256 skill digests rather than mutable latest tags.

2.Canary Rollouts: Test new skill versions against golden eval traces before org-wide release.

CI security scanning and cryptographic signing secure the skill supply chain.

07
advanced

Skill Telemetry, Eval Feedback & Auto-Pruning.

Why this matters: Measure which skills actually succeed in production and retire stale instructions.

Think of Skill Telemetry, Eval Feedback & Auto-Pruning as the intuition layer for Enterprise Skill-Based Agent Architecture: Measure which skills actually succeed in production and retire stale instructions.

Every skill activation logs (skill_id, version, user_dept, tool_calls, success_flag, token_cost) to ClickHouse. Platform teams track skill hit rates, fallback/override rates, and token efficiency—automatically flagging skills with high error rates or zero 90-day usage for deprecation.

Stage 7 - Skill Observability

Skill Effectiveness & Eval Loop

1.Skill ROI: Measure tokens saved and task completion rate per skill version.

2.Zero-Downtime Rollback: Revert a broken skill version in seconds via registry pointer update.

Skill-level telemetry closes the loop between domain authoring and production reliability.
