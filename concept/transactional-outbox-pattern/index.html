Transactional Outbox Pattern

Atomically persist domain changes and outbound events in one database transaction, then relay asynchronously to the message bus.

✓ When to Use

  • ✓Microservices emitting integration events
  • ✓Need DB + broker alignment
  • ✓CDC-friendly pipelines

✕ When NOT to Use

  • ✕Fire-and-forget analytics with no consistency requirement

Why It Matters

Core Architecture & Rules

  • →Same transaction for row + outbox insert
  • →Relay polls or tails CDC
  • →Consumers must be idempotent

Failure Modes & Mitigations

  • ⚖Stuck relay:Outbox grows unbounded.

    Mitigation: Lag alerts and dead-letter for poison payloads.

Example Usages

Order placed event

Scenario: Insert order row and outbox record together.

Outcome: Relay publishes after commit; retries safe with idempotent consumers.
