STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What is Consensus Replication (Raft & Multi-Paxos).

Why this matters: The mechanism: understand how Consensus Replication (Raft & Multi-Paxos) works from first principles.

Consensus protocols (Paxos, Raft, ZAB) let a cluster of unreliable machines agree on an ordered sequence of state transitions—and never lose a committed write—even when nodes crash or networks partition.

They combine monotonic term/ballot numbers (fencing stale leaders) with intersecting majority quorums (⌊N/2⌋+1\lfloor N/2 \rfloor + 1⌊N/2⌋+1): 3 nodes tolerate 1 failure; 5 nodes tolerate 2. Raft decomposes consensus into Leader Election (RequestVote with log-freshness check), Log Replication (AppendEntries with prevLogIndex/prevLogTerm), and Safety.

Raft Majority Quorum

3-Node Raft Cluster: Leader AppendEntries + Quorum Commit (term=4)

1.Odd Cluster Sizing: A 4-node cluster has quorum 3 (tolerates 1 failure)—identical fault tolerance to 3 nodes at higher cost.

2.Log-Freshness Election: A candidate can only win RequestVote if its log is at least as up-to-date as a majority.

3.1-RTT Commit: Once 2 of 3 nodes fsync index 108, the leader commits and applies it to the state machine.

Intersecting majorities guarantee any newly elected leader already holds every committed log entry.

STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why we need Consensus (and how stale leaders & shared disks break it).

Why this matters: The problem: see what breaks without Consensus under real concurrency or scale.

Naive primary-replica async replication loses committed writes on failover (RPO > 0) and risks split-brain if the old primary stays reachable.

Even in Raft/Paxos clusters, three operational hazards cause outages:

  1. Stale Leader Reads: Serving reads from a leader without ReadIndex or valid hardware leases lets an isolated ex-leader return stale data.
  2. WAL Disk Starvation: Sharing Raft WAL disks with app logs or container pulls spikes fsync past electionTimeout, triggering cascading elections.
  3. Membership Change Split-Brain: Adding 2 nodes at once without single-node steps or Joint Consensus can create two disjoint majorities.
Linearizable ReadIndex

How Raft Leader Lease / ReadIndex Prevents Stale Ex-Leader Reads

ReadIndex confirms leadership with a heartbeat quorum before serving local state, avoiding a disk log write on reads.

Engineering Decision Framework
Problem
How to implement Consistency & Consensus Replication (Raft / Paxos) without hitting unbounded tail latency, state divergence, or operational fragility.
Naive Solution
Use a single unpartitioned path with unbounded retries and synchronous global coordination.
Why It Fails
Global coordination serializes throughput under load, while unbounded retries amplify transient stalls into full outages.
Alternatives
Compare synchronous strict-consistency paths against bounded asynchronous replication, local caching, or partitioned ownership.
Engineering Decision
If replicas diverge under asymmetric network delays, use Raft/Paxos quorums when you need linearizable state (locks, metadata, ledgers), and remember that even-numbered clusters add cost without improving fault tolerance.
Trade-Offs
Gains predictable p99 latency and fault isolation in exchange for explicit bounding, observability, and slightly higher implementation complexity.

How Raft AppendEntries, WAL fsync, and Snapshots are managed

# Core Raft AppendEntries log-consistency & commit invariant (Python)
class RaftNode:
    def __init__(self):
        self.current_term = 0
        self.log: list[tuple[int, bytes]] = [] # (term, command)
        self.commit_index = -1

    def handle_append_entries(self, term: int, prev_idx: int, prev_term: int,
                              entries: list[tuple[int, bytes]], leader_commit: int) -> tuple[int, bool]:
        if term < self.current_term:
            return self.current_term, False # fence stale leader
        self.current_term = term
        if prev_idx >= 0:
            if prev_idx >= len(self.log) or self.log[prev_idx][0] != prev_term:
                return self.current_term, False # log divergence -> leader decrements nextIndex
        # Truncate conflicting suffix & append new entries (fsync before returning True!)
        self.log = self.log[:prev_idx + 1] + entries
        if leader_commit > self.commit_index:
            self.commit_index = min(leader_commit, len(self.log) - 1)
        return self.current_term, True
