Segment Trees for
Range Queries.

A Segment Tree partitions an array of size N into a binary tree of contiguous intervals, supporting both arbitrary monoid range queries (sum, min, max, gcd) and point/range updates in O(log N) time using 4N space and lazy propagation.

What is a Segment Tree.

Why this matters: The mechanism: understand how a Segment Tree works from first principles.

A Segment Tree is a binary tree built over an array A[0…N−1]A[0 \dots N-1]A[0…N−1] where each node stores the aggregate of a contiguous interval [l,r][l, r][l,r]. The root covers [0,N−1][0, N-1][0,N−1], splitting at mid=⌊(l+r)/2⌋\text{mid} = \lfloor (l+r)/2 \rfloormid=⌊(l+r)/2⌋ into [l,mid][l, \text{mid}][l,mid] and [mid+1,r][\text{mid}+1, r][mid+1,r].

Any arbitrary query range [L,R][L, R][L,R] decomposes into at most $2 \log_2 N$ canonical tree nodes, guaranteeing O(log⁡N)O(\log N)O(logN) query and update bounds for any associative monoid (sum, min, max, gcd, affine transforms).

Canonical Range Split

Segment Tree Interval Partitioning & Lazy Propagation (N=6)

1.1. 4N Allocation: 1-indexed recursive trees need 4*N slots so non-power-of-2 N never overflows.

2.2. Lazy Push-Down: Deferred range updates sit in lazy[node] and push to children only when traversed.

3.3. Monoid Identity: Out-of-range branches return the exact identity: 0 for sum/gcd, +inf for min, -inf for max.

Decomposing [L, R] into O(log N) canonical intervals enables fast dynamic range updates and queries.

STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

How Recursive Lazy Propagation is implemented cleanly.

Why this matters: Operational control: configure bounds, failure handling, and safe production defaults.

Think of How Recursive Lazy Propagation is implemented cleanly as the intuition layer for Segment Trees for Range Queries: Operational control: configure bounds, failure handling, and safe production defaults.

Build bottom-up in O(N)O(N)O(N) (not NNN point updates), update tree[node] immediately when setting lazy[node], and invoke push_down on every partial-overlap descent in both update and query.

class LazySegTree:
    def __init__(self, arr: list[int]):
        self.n = len(arr)
        self.tree = [0] * (4 * self.n)
        self.lazy = [0] * (4 * self.n)
        self._build(arr, 1, 0, self.n - 1)

    def _build(self, arr, node: int, l: int, r: int) -> None:
        if l == r:
            self.tree[node] = arr[l]
            return
        mid = (l + r) // 2
        self._build(arr, 2 * node, l, mid)
        self._build(arr, 2 * node + 1, mid + 1, r)
        self.tree[node] = self.tree[2 * node] + self.tree[2 * node + 1]

    def _push(self, node: int, l: int, r: int) -> None:
        if self.lazy[node] != 0 and l != r:
            mid = (l + r) // 2
            val = self.lazy[node]
            self.tree[2 * node] += val * (mid - l + 1)
            self.lazy[2 * node] += val
            self.tree[2 * node + 1] += val * (r - mid)
            self.lazy[2 * node + 1] += val
            self.lazy[node] = 0

    def range_add(self, ql: int, qr: int, val: int, node=1, l=0, r=None) -> None:
        if r is None: r = self.n - 1
        if qr < l or r < ql: return
        if ql <= l and r <= qr:
            self.tree[node] += val * (r - l + 1)
            self.lazy[node] += val
            return
        self._push(node, l, r)
        mid = (l + r) // 2
        self.range_add(ql, qr, val, 2 * node, l, mid)
        self.range_add(ql, qr, val, 2 * node + 1, mid + 1, r)
        self.tree[node] = self.tree[2 * node] + self.tree[2 * node + 1]
