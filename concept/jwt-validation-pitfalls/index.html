STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What Makes JWT Headers Dangerous When Trusted Blindly.

Why this matters: The mechanism: understand how What Makes JWT Headers Dangerous When Trusted Blindly works from first principles.

A signed JWT (JWS) has three Base64URL segments: header.payload.signature. Crucially, the header is unauthenticated until the signature is verified—yet it carries alg (algorithm), kid (key ID), and optional jku (JWKS URL).

Naive verifiers that obey those header hints fall victim to three classic exploits: alg: none (stripping the signature), Key Confusion (CVE-2015-9235) (forging an HS256 token signed with the server's public RSA key), and jku SSRF (pointing the verifier to an attacker-hosted JWKS).

Key Confusion Attack

How RS256-to-HS256 Forgery Works — And How Allowlists Block It

Always hardcode the expected algorithm list server-side—never read `alg` from the untrusted JWT header.

Before · Long-Lived Bearer + Implicit Trust

import jwt
from jwt import PyJWKClient

# Pinned IdP JWKS endpoint (never read jku/x5u from token) with built-in caching
JWKS_CLIENT = PyJWKClient("https://auth.example.com/.well-known/jwks.json", cache_keys=True, lifespan=600)

def verify_access_token(token: str) -> dict:
    signing_key = JWKS_CLIENT.get_signing_key_from_jwt(token)
    return jwt.decode(
        token,
        signing_key.key,
        algorithms=["ES256", "RS256"],  # Strict server-side allowlist; blocks alg=none & HS256
        audience="https://api.example.com/billing",
        issuer="https://auth.example.com/",
        options={"require": ["exp", "iss", "aud", "sub"]},
        leeway=30,
    )

Gateway Auth Flow

API Gateway (Pinned JWKS Cache) -> Rate-Limited IdP -> Internal mTLS

1.No Header Trust: Gateway ignores jku/x5u and rejects any alg outside [ES256, RS256].

2.kid DoS Shield: Unknown kid triggers at most 1 JWKS refresh per 60s, blocking cache-busting floods.

3.Strict Scoping: aud claim binds each token to its intended target service.

Centralizing RFC 8725 validation at the gateway with a rate-limited JWKS cache eliminates per-service auth bugs.
