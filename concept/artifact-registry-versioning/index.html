STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What is Artifact Registry Versioning.

Why this matters: The mechanism: understand how Artifact Registry Versioning works from first principles.

An artifact registry is a content-addressable storage system. Every container image, Helm chart, or Wasm module you push is decomposed into compressed layer blobs and a JSON manifest whose SHA-256 hash—the digest (sha256:9f86...)—uniquely identifies that exact byte sequence.

Tags (v1.4.2, latest) are merely mutable pointers to a digest. Reliable delivery pipelines separate human naming (immutable <semver>-<git_sha> tags) from machine deployment (image@sha256:...), and store SBOMs (SPDX/CycloneDX) and Cosign .sig attestations alongside the image via the OCI Distribution Spec.

Content-Addressable OCI Graph

Tag Pointer -> OCI Image Index -> Manifest Digest -> Layer Blobs

1.Tag vs. Digest: Tags are mutable aliases unless locked; the manifest sha256 digest cryptographically hashes every layer.

2.Multi-Arch Index: An OCI Image Index maps linux/amd64 and linux/arm64 manifests under one top-level digest.

3.Supply-Chain Referrers: Trivy SBOMs and Cosign signatures attach directly to the digest without mutating image layers.

Content-addressable digests guarantee that staging, prod, and rollbacks execute the exact same verified bytes.

STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why we need Immutable Versioning (and why :latest fails).

Why this matters: The problem: see what breaks without Immutable Versioning under real concurrency or scale.

Mutable tags like :latest, :prod, or :v1 break reproducibility and rollback safety:

  1. Silent Re-Tagging Corruption: Two concurrent CI runs on the same branch overwrite each other's tag, leaving different Kubernetes nodes running different code under the same tag.
  2. Base-Image Drift: FROM node:20-alpine pulls different OS packages on Monday vs. Friday unless pinned to @sha256:....
  3. Broken Rollbacks After GC: A naive 30-day retention rule deletes the previous release digest, turning an emergency rollback into ImagePullBackOff.
Build-Once Promote-Many

Immutable Build -> Scan & Sign -> Digest-Pinned Prod Deploy

Build once into staging, attach attestations to the digest, and promote the exact digest to production.

Engineering Decision Framework
Problem
How to implement Artifact Registry Versioning without hitting unbounded tail latency, state divergence, or operational fragility.
Naive Solution
Use a single unpartitioned path with unbounded retries and synchronous global coordination.
Why It Fails
Global coordination serializes throughput under load, while unbounded retries amplify transient stalls into full outages.
Alternatives
Compare synchronous strict-consistency paths against bounded asynchronous replication, local caching, or partitioned ownership.
Engineering Decision
To keep the architecture evolvable without sacrificing reliability, tag for humans, deploy by immutable digest: mutable tags like :latest or :v1 can be overwritten silently, whereas image@sha256:... guarantees bit-for-bit reproducibility.
Trade-Offs
Gains predictable p99 latency and fault isolation in exchange for explicit bounding, observability, and slightly higher implementation complexity.

STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

How Lifecycle Policies, Retention Tiers, and Digest Pinning are managed.

Why this matters: Operational control: configure bounds, failure handling, and safe production defaults.

Control registry bloat without breaking rollbacks:

  1. Two-Tier Retention: Purge ephemeral pr-* / dev-* tags after 7–14 days, but retain v* releases for 180–365 days (and protect any digest currently running in a cluster).
  2. Pin Base Images: Always write FROM gcr.io/distroless/static@sha256:... in Dockerfiles.
  3. Admission Verification: Enforce Kyverno or OPA Gatekeeper policies rejecting pods without @sha256: digests or valid Cosign signatures.

STAGE 06 · PRODUCTION ARCHITECTUREL7 · STAFF / PRINCIPAL

Production example: Multi-Region OCI Registry + Admission Controller.

Why this matters: Production architecture: see how the components compose end to end under real load.

Think of Production example: Multi-Region OCI Registry + Admission Controller as the intuition layer for Artifact Registry Versioning: Production architecture: see how the components compose end to end under real load.

Enterprise platforms replicate signed OCI artifacts across regions (e.g., GAR/ECR replication) and gate Kubernetes admission with Kyverno / Sigstore Policy Controller, which verifies the Cosign signature and SBOM attestation against the exact @sha256: digest before scheduling any Pod.

Signed Promotion Pipeline

CI Buildx -> Regional OCI Registry -> Kyverno Admission -> Kubelet

1.Admission Gate: Kyverno blocks unsigned images or mutable :latest tags at Kubernetes API admission time.

2.Registry Pull-Through: Regional registry mirrors cache upstream base images, eliminating DockerHub rate limits.

3.Cluster-Aware GC: Garbage collection checks active pod digests across clusters before expiring old releases.

Immutable digests + admission signature checks close the loop from source commit to running container.
