What is Low-Level System Design (LLD).

Why this matters: The mechanism: understand how Low-Level System Design (LLD) works from first principles.

While High-Level Design (HLD) governs distributed services over networks, Low-Level Design (LLD) governs the internal architecture of a service or library: entities (identity + lifecycle), value objects (immutable, equality by value), and stateless domain services.

Clean LLD models lifecycles as explicit Finite State Machines (FSMs) and isolates volatile rules behind Strategy, State, Observer, and Command interfaces.

Why boolean flags and check-then-act races break services.

Why this matters: The problem: see what breaks without Why boolean flags and check-then-act races break services under real concurrency or scale.

Poor LLD produces god classes, brittle if-else trees, and concurrency bugs at 100k+ lines of code.

Two failure modes recur constantly: boolean flag explosion (isActive, isPaused, isDeleted allowing illegal states) and check-then-act race conditions where two threads both see spot.isFree() == true and issue duplicate tickets.

Lifecycle & Failure Recovery

Explicit Transition Table + Striped Locking

public enum SeatStatus { AVAILABLE, HELD, BOOKED }

public final class Seat {
    private SeatStatus status = SeatStatus.AVAILABLE;
    private Instant holdExpiresAt = Instant.EPOCH;
    private final ReentrantLock lock = new ReentrantLock();

    public boolean tryHold(Instant now, Duration ttl) {
        lock.lock();
        try {
            if (status == SeatStatus.BOOKED) return false;
            if (status == SeatStatus.HELD && now.isBefore(holdExpiresAt)) return false;
            status = SeatStatus.HELD;
            holdExpiresAt = now.plus(ttl);
            return true;
        } finally {
            lock.unlock();
        }
    }
}
