The idea to keep with you

Bitmask DP encodes a subset of n <= 20 elements as an integer 0 .. 2^n - 1, turning exponential factorial permutations (n!) into polynomial-in-subset DP (O(n^2 2^n) or O(n 2^n)).

STAGE 01 · WHAT IT ISL4 · FUNDAMENTALS

What is Bitmask Dynamic Programming.

When a problem's optimal substructure depends only on which subset SSS of nnn items has been used (and optionally the last item), all permutations of SSS collapse into a single DP state. Bitmask DP encodes S⊆{0,…,n−1}S \subseteq \{0,\dots,n-1\}S⊆{0,…,n−1} as an nnn-bit integer mask where bit iii is 1 iff item i∈Si \in Si∈S.

Setting one unvisited bit (mask | (1 << j)) strictly increases the integer value of mask, giving a built-in topological DAG order over 0 .. (1 << n) - 1 and reducing n!n!n! permutations to O(n2n)O(n 2^n)O(n2n) or O(n22n)O(n^2 2^n)O(n22n).

Bitmask DAG Transitions

Held-Karp TSP State Compression (0001 -> 0011 -> 0111 -> 1111)

Because setting a bit strictly increases mask, iterating mask from 0 to (1<<n)-1 processes states in valid topological order.

STAGE 02 · WHY WE NEED ITL4 · FUNDAMENTALS

Why we need Bitmask Compression (and complexity/memory traps).

At n=18n = 18n=18, $18! \approx 6.4 \times 10^{15}$ is impossible, whereas 182⋅218≈8.5×10718^2 \cdot 2^{18} \approx 8.5 \times 10^7182⋅218≈8.5×107 runs in under a second.

Watch three classic pitfalls:

  1. Accidental O(4n)O(4^n)O(4n) Submask Loop: Iterating 0..2^n-1 inside 0..2^n-1 takes $1.07 \times 10^9$ ops at n=15n=15n=15, whereas sub = (sub - 1) & mask takes O(3n)≈1.4×107O(3^n) \approx 1.4 \times 10^7O(3n)≈1.4×107.
  2. Redundant Dimension in Assignment: When assigning item i to worker k, you only need dp[mask] (not dp[i][mask]) because popcount(mask) uniquely determines i!
  3. OOM on 2D long Tables: long[1 << 20][20] uses 160 MB.
Feasibility Ceilings

Choosing Bitmask DP Pattern by Input Bound n

1.Popcount Trick: In bipartite matching/assignment, k = mask.bit_count() gives the current worker index for free.

2.SOS DP Optimization: Sum over Subsets DP computes F[mask] = sum(A[sub]) in O(n 2^n) instead of O(3^n).

3.Reachability Guard: Check dp[FULL][u] < INF before returning in case the graph has no Hamiltonian path.

Check n against 2^n vs 3^n before writing the transition loop.

Sum Over Subsets (SOS) DP

Compute F[mask] = sum(A[sub] for sub subset of mask) in O(n 2^n) by adding one bit dimension i at a time.

Symmetric Start Optimization

In a closed TSP tour, fix start node = 0 so you don't multiply work by n starting nodes.

Where Bitmask DP is used.

Use bitmask DP whenever n≤20n \le 20n≤20 and you need exact optimal solutions for routing, matching, or partitioning.

STAGE 04 · HOW IT IS MANAGEDL5 · APPLIED DESIGN

How Held-Karp TSP & SOS DP are implemented.

Use iterative bottom-up loops over mask (avoiding Python recursion overhead) and int.bit_count() for assignment.

# 1. Held-Karp TSP starting at node 0: O(n^2 * 2^n)
def tsp_held_karp(dist: list[list[int]]) -> int:
    n = len(dist)
    INF = 10**15
    dp = [[INF] * n for _ in range(1 << n)]
    dp[1][0] = 0
    for mask in range(1, 1 << n):
        if not (mask & 1): continue
        for u in range(n):
            if dp[mask][u] == INF: continue
            for v in range(1, n):
                if not (mask & (1 << v)):
                    nxt = mask | (1 << v)
                    dp[nxt][v] = min(dp[nxt][v], dp[mask][u] + dist[u][v])
    full = (1 << n) - 1
    return min(dp[full][u] + dist[u][0] for u in range(1, n))

# 2. Sum over Subsets (SOS) DP: O(n * 2^n)
def sos_dp(A: list[int], n: int) -> list[int]:
    F = A[:]
    for i in range(n):
        for mask in range(1 << n):
            if mask & (1 << i):
                F[mask] += F[mask ^ (1 << i)]
    return F

STAGE 06 · PRODUCTION ARCHITECTUREL7 · STAFF / PRINCIPAL

Production example: SQL Join-Order Optimizer (System R / Selinger DP).

Relational database query planners (PostgreSQL geqo_threshold, DuckDB) use bitmask DP (Selinger / DPccp) to pick the optimal join tree across nnn tables! Each mask represents a subset of joined relations, and sub = (sub - 1) & mask enumerates candidate left/right subplans.

Database Query Planner

Selinger Bitmask Join-Order DP (Subsets of Relations)

1.Relation Bitmask: Up to ~12–16 joined tables are encoded directly as bitmasks in C++.

2.Connected Subgraphs: DPccp skips disconnected cross-product submasks to stay fast on star/chain schemas.

3.Heuristic Fallback: Above geqo_threshold (12 tables in Postgres), planner switches to genetic/greedy search.

Production SQL optimizers use bitmask DP to find exact optimal join trees before falling back to heuristics for huge queries.
