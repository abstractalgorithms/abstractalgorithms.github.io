Programming.

THE BIG IDEA / Key takeaway · CONCEPT GUIDE

Whenever a problem tracks which items from a small set ($n \le 20$) have been visited or assigned, pack the subset into an integer bitmask and transition by setting one bit at a time.

Explanation anchor
01 / The idea

Foundational mechanics & core principles

Brute-force permutation search over n=20n = 20n=20 items evaluates 20!≈2.4×101820! \approx 2.4 \times 10^{18}20!≈2.4×1018 states—impossible even on a cluster. Bitmask DP collapses all permutations that share the same visited set and last element into a single state, shrinking 2.4×10182.4 \times 10^{18}2.4×1018 down to 20×220≈2.1×10720 \times 2^{20} \approx 2.1 \times 10^720×220≈2.1×107 states, which solves in under 100 ms in C++/Java.

  • State compression: bit iii of mask is 1 iff element iii is included, mapping any subset S⊆{0,…,n−1}S \subseteq \{0,\dots,n-1\}S⊆{0,…,n−1} to an array index [0 .. (1 << n) - 1].
  • Held-Karp TSP recurrence: dp[mask | (1 << nxt)][nxt] = min(dp[mask | (1 << nxt)][nxt], dp[mask][cur] + dist[cur][nxt]).
  • Canonical assignment optimization: when assigning item iii to worker kkk, you only need dp[mask] (not dp[i][mask]) because popcount(mask) uniquely determines iii!
  • Iterative topological order: mask strictly increases whenever you set a new bit (mask | (1 << j) > mask), so a flat for mask in range(1 << n) loop is always a valid DP order.
  • Submask-transition complexity: iterating sub = (sub - 1) & rem across all mask values takes ∑k=0n(nk)2n−k=3n\sum_{k=0}^{n} \binom{n}{k} 2^{n-k} = 3^n∑k=0n​(kn​)2n−k=3n total operations—feasible up to n≤15n \le 15n≤15.

Good candidates

  • Traveling Salesperson Problem (TSP) and shortest Hamiltonian path/cycle over n≤20n \le 20n≤20 nodes (Held-Karp algorithm).
  • Exact bipartite matching, task assignment, or partitioning into kkk equal-sum subsets when n≤20n \le 20n≤20.
  • Sum over Subsets (SOS) DP and broken-profile / grid-tiling DP where each column state is a bitmask of height H≤12H \le 12H≤12.

Think twice

  • Inputs with n>22n > 22n>22—225≈3.3×1072^{25} \approx 3.3 \times 10^7225≈3.3×107 states already exceeds typical memory/time budgets unless using meet-in-the-middle.
  • Problems where order does not matter beyond item counts (use standard knapsack or frequency DP instead).
  • Large-scale routing (n>50n > 50n>50) where heuristics, ILP/MIP solvers, or Christofides approximation are required.
Deep Dive & Production Considerations
02 / Concrete walkthrough

Architectural mechanics & implementation

ScenarioA courier dispatcher computes the exact minimum-time route across 16 drop-off stops from a depot using asymmetric traffic travel times.

The idea

When a problem's state depends on which subset of nnn items has been used, any permutation of those items that ends at the same item (or has no order dependency) is equivalent. Bitmask DP represents that subset as an nnn-bit integer mask where bit iii is 1 if item iii is in the subset. Setting a single bit (mask | (1 << j)) strictly increases the integer value, which guarantees a natural DAG over [0 .. 2^n - 1] and collapses O(n!)O(n!)O(n!) search into O(n2n)O(n 2^n)O(n2n) or O(n22n)O(n^2 2^n)O(n22n).

Concrete walkthrough

Solve shortest Hamiltonian path (visiting all 4 nodes 0, 1, 2, 3 starting at 0):

  1. Init: dp[1 << 0][0] = 0 (mask = 0001), all other dp[mask][u] = INF.
  2. Mask 0001 ({0}): From u = 0, try unvisited v in {1, 2, 3}. Set dp[0011][1] = dist[0][1], dp[0101][2] = dist[0][2], dp[1001][3] = dist[0][3].
  3. Mask 0011 ({0, 1}): From u = 1, transition to unvisited v = 2 -> dp[0111][2] = min(..., dp[0011][1] + dist[1][2]) and v = 3 -> dp[1011][3].
  4. Final: After all masks up to 1111 ((1 << 4) - 1) finish, the answer is min(dp[1111][u] for u in range(4)).

Bitmask DP advances strictly from smaller to larger integer masks, guaranteeing every subproblem is solved before its supersets.

Feasibility bounds by n

Before committing to bitmask DP, check nnn against the transition complexity:

  • n≤20n \le 20n≤20 with O(n2n)O(n 2^n)O(n2n) (e.g., assignment): 20×106≈2×10720 \times 10^6 \approx 2 \times 10^720×106≈2×107 ops — fast in C++/Java.
  • n≤18n \le 18n≤18 with O(n22n)O(n^2 2^n)O(n22n) (e.g., TSP): 324×262,144≈8.5×107324 \times 262,144 \approx 8.5 \times 10^7324×262,144≈8.5×107 ops — near the 1-second limit.
  • n≤15n \le 15n≤15 with O(3n)O(3^n)O(3n) (submask DP): 315≈1.4×1073^{15} \approx 1.4 \times 10^7315≈1.4×107 ops — safe; n=17n = 17n=17 (1.3×1081.3 \times 10^81.3×108) is borderline.
  • n∈[21,40]n \in [21, 40]n∈[21,40]: Switch to Meet-in-the-Middle (O(2n/2)O(2^{n/2})O(2n/2)) or branch-and-bound.

Failure modes

  • OOM from 2D long table: long[1 << 20][20] uses 160 MB; swap dimensions or pack values into int when possible.
  • Accidental O(4n)O(4^n)O(4n) submask loop: Iterating 0..2^n-1 inside 0..2^n-1 instead of sub = (sub - 1) & mask turns 1.4×1071.4 \times 10^71.4×107 into 1.07×1091.07 \times 10^91.07×109 ops at n=15n = 15n=15.
  • Ignoring disconnected graphs: Returning dp[FULL][u] without checking < INF when no Hamiltonian path exists.

Sum over Subsets (SOS) DP

When you need F[mask] = sum(A[sub] for sub subset of mask) for all 2n2^n2n masks, naive submask iteration takes O(3n)O(3^n)O(3n). SOS DP reduces this to O(n2n)O(n 2^n)O(n2n) by adding one bit dimension at a time:

for i in range(n): for mask in range(1 << n): if mask & (1 << i): F[mask] += F[mask ^ (1 << i)]

This exact loop computes subset sums over 2202^{20}220 masks in ~20 million additions.

Practical checklist

  • Verify nnn fits the complexity budget (n≤20n \le 20n≤20 for O(n2n)O(n 2^n)O(n2n), n≤15n \le 15n≤15 for O(3n)O(3^n)O(3n)).
  • Check whether popcount(mask) eliminates an explicit index dimension.
  • Guard unreachable states (if dp[mask] == INF: continue) before inner transitions.
  • Use sub = (sub - 1) & mask for O(3n)O(3^n)O(3n) submask enumeration, never brute-force O(4n)O(4^n)O(4n).
  • Precompute FULL_MASK = (1 << n) - 1 and use 1L << i in Java / 1ULL << i in C++.
03 / Engineering trade-offs

Weighing architectural decisions

Bottom-Up Tabulation vs. Top-Down Memoization

Advantage: Bottom-up loops over `mask = 0 .. (1<<n)-1` avoid recursion overhead and are cache-friendly.

Drawback: Top-down DFS with memoization skips unreachable masks (e.g., when graph edges are sparse or constraints prune branches).

Dropped Dimension via `popcount(mask)` vs. Explicit Index

Advantage: Eliminates an entire $O(n)$ memory dimension (e.g., shrinking 20 MB to 1 MB) when elements are processed in fixed order.

Drawback: Only applies when the number of set bits uniquely identifies the current step (assignment), not when order among chosen items matters (TSP).

Submask DP ($O(3^n)$) vs. SOS DP ($O(n 2^n)$)

Advantage: Submask iteration handles arbitrary non-associative subset merges directly.

Drawback: At $n = 18$, $3^{18} \approx 3.87 \times 10^8$ ops times out, whereas SOS DP ($18 \cdot 2^{18} \approx 4.7 \times 10^6$) finishes in milliseconds.

04 / Failure modes & resilience

Explain where it breaks · Known failure modes

Memory Explosion on 2D State Table

Allocating `dp[1 << 20][20]` as 64-bit integers consumes $20 \times 2^{20} \times 8 = 160$ MB, triggering OOM in tight 64–128 MB sandboxes.

What helps: Use 32-bit `int` when values fit, drop redundant dimensions via `popcount(mask)`, or store `dp[last][mask]` for better cache locality.

Wrong `3^n` vs `4^n` Bound Estimation

Looping over all `mask` and all `sub` independently costs $O(4^n)$, timing out at $n = 14$ ($2.6 \times 10^8$), whereas enumerating submasks of the complement costs $O(3^n)$.

What helps: Always iterate `sub = (sub - 1) & mask` (or `& (~mask & FULL)`) instead of checking `if (sub & mask) == sub` over $2^n$.

Python Per-State Overhead Timeout

Even when $n \cdot 2^n \approx 10^7$ is small enough for C++/Java, pure Python nested loops over $10^7$ states take >5 seconds.

What helps: Precompute bit-transitions outside inner loops, prune unreachable masks, or use `lru_cache` / iterative arrays in C++/Java for $n \ge 17$.

Missing Base Case / Unreachable Mask Guard

Transitioning from `dp[mask]` initialized to `INF` without checking `if dp[mask] == INF: continue` wastes time and risks arithmetic overflow.

What helps: Skip unreachable states early and check `mask & (1 << i)` before transitioning.

05 / Practical checklist

Avoid these mistakes

  • Writing `1 << n` in Python/Java without checking if $n$ actually fits within the $2^n$ time/memory budget ($n \le 20$ for $O(n 2^n)$, $n \le 15$ for $O(3^n)$).
  • Storing `dp[mask][last]` when `dp[mask]` alone suffices (such as worker-job assignment where `worker = popcount(mask)`).
  • Forgetting to check `if (mask & (1 << nxt)) != 0: continue` when extending a path, allowing vertices to be revisited.
  • Using `sub = (sub - 1) & mask` without handling `sub == 0` if the empty submask is a valid base or transition.
  • Checking `if (sub & mask) == sub` inside a $0 \dots 2^n-1$ inner loop, accidentally turning $O(3^n)$ into $O(4^n)$.
