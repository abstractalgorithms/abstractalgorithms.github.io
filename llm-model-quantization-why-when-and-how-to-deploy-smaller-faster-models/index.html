LLM Model Quantization: Why, When, and How to Deploy Smaller, Faster Models

Stage 1 — Bits, Scales, and Zero-Points: Quantization in Plain Language

  • At a high level, quantization maps floating-point values to a smaller set of discrete numbers.
  • Instead of storing weights as 16-bit or 32-bit floats, you store them as 8-bit or 4-bit values plus metadata (such as scale factors) to approximately reconstruct original values during compute.
  • Common quantization families Common precision targets 📊 Precision vs Size Trade-off This diagram maps the four common numeric precision formats — FP32, FP16, INT8, and INT4 — as a linear chain from largest to smallest.
  • Moving from FP32 to FP16 halves memory; moving to INT8 halves it again; reaching INT4 achieves roughly an 8× reduction relative to FP32.

Stage 2 — From FP16 Checkpoint to Production Artifact: The Quantization Process

  • A reliable quantization workflow is a pipeline, not a one-click conversion.
  • Example: "<1.5% drop on eval score, p95 latency -20%, memory -50%." 2.
  • Weights only, or weights + activations.
  • PTQ INT8 for low risk, or 4-bit (GPTQ/AWQ/NF4 paths) when memory pressure is high.

Stage 3 — Deep Dive: What Changes Inside the Model

  • The internals: weights, activations, and kernels Quantization changes both representation and execution path: - Representation: tensors are stored as lower-bit integers (or low-precision floats) plus scale metadata.
    • Arithmetic path: kernels may run integer matrix multiplies and rescale outputs.
    • Memory traffic: fewer bytes move from VRAM/DRAM, often the real bottleneck for decoder inference.
  • For LLMs, this matters because generation is frequently memory-bandwidth-bound rather than pure compute-bound.

Stage 4 — Edge Cases That Break Naive Quantization

  • Quantization fails most often when teams skip workload realism.
  • One practical pattern is selective precision: keep the most sensitive modules in higher precision and quantize the rest.

Stage 6 — Real-World Applications: Quantization Patterns

  • Case study 1: API-hosted assistant - Input: mixed user prompts, medium context, strict latency target.
    • Process: start with INT8 PTQ for all linear layers, keep output head in FP16.
    • Output: lower p95 latency and lower GPU memory, with minimal answer-quality drift.
  • Case study 2: edge or on-prem deployment - Input: constrained hardware, low concurrency, strict memory limits.

End-to-end outcome

After working through the stages, you should be able to explain:

    • Start with INT8 PTQ unless you have a strong reason to jump directly to 4-bit.
    • Calibration quality matters as much as quantization algorithm choice.
