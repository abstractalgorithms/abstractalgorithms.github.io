STAGE 02 · IMPACTL5 · APPLIED DESIGN

What happens without watermarks, ACID upserts, and compaction.

Why this matters: The problem: see what breaks without What happens without watermarks, ACID upserts, and compaction under real concurrency or scale.

Streaming directly into raw Parquet on S3/GCS causes three cascading data failures:

  1. Duplicate Silver Rows: Micro-batch retries after an executor crash append duplicate records unless upserts are idempotent.
  2. Small-File Explosion: Writing 30-second micro-batches across 200 partitions creates ~17M tiny files/month, crushing S3 LIST and query planning.
  3. Unbounded State OOM: Deduplicating event_id without withWatermark() grows RocksDB/JVM state indefinitely until executors OOM.
Medallion ACID Streaming

Kafka -> Bronze (Append) -> Silver (Watermark + Iceberg MERGE) -> Gold

1.Bronze Layer: Raw immutable append with Kafka offset metadata for replay.

2.Watermark Dedup: Bounds state store memory by dropping late keys past the 10-min window.

3.Iceberg MVCC: Atomic snapshot commits in foreachBatch guarantee exactly-once Silver.

4.Async Compaction: Rewrites small micro-batch files into 512 MB Parquet targets.

Iceberg MVCC snapshots + Spark checkpoints provide exactly-once upserts while async compaction keeps S3 read latency fast.

STAGE 03 · NAIVE SOLUTIONL5 · APPLIED DESIGN

Naive solution (and why raw Parquet append breaks).

Why this matters: The problem: see what breaks without Naive solution under real concurrency or scale.

A naive pipeline runs df.writeStream.format('parquet').start('s3://silver/'):

  • No Upserts or GDPR Deletes: Parquet files are immutable; CDC updates and row-level deletes require rewriting entire partitions manually.
  • At-Least-Once Duplicates: Task retries leave partial/duplicate files visible to readers.
  • Schema Breakage: Adding a new JSON field crashes downstream BI queries.

STAGE 04 · ENTERPRISE SOLUTIONL6 · SCALE & TRADE-OFFS

Enterprise solution: Spark Structured Streaming + Apache Iceberg + AQE.

Why this matters: Operational control: configure bounds, failure handling, and safe production defaults.

Enterprise Lakehouses pair Spark Structured Streaming with Apache Iceberg (or Delta Lake):

  • Bronze: Append raw Kafka payloads with kafka_offset and ingest_ts every 30 s.
  • Silver: Apply withWatermark('event_ts', '10 minutes') + dropDuplicates(['event_id']), then execute MERGE INTO inside foreachBatch using checkpointLocation for exactly-once commits.
  • Maintenance & Governance: Run periodic rewrite_data_files (bin-pack to 512 MB), expire_snapshots, and Iceberg time-travel / GDPR row-level DELETE.
Exactly-Once Micro-Batch

30s Micro-Batch Commit & Compaction Flow

Readers see atomic Iceberg snapshots only after MERGE commits, preventing dirty reads or duplicate rows.

query = (silver_df.writeStream
    .foreachBatch(upsert_to_iceberg_silver)
    .option('checkpointLocation', 's3://checkpoints/silver_orders')
    .trigger(processingTime='30 seconds')
    .start())

Where Real-Time Medallion Lakehouses are used.

The Bronze/Silver/Gold Lakehouse pattern unifies streaming and batch analytics:

  • ML Feature Stores: Serving < 2 min fresh user-session aggregates for real-time fraud and ranking models.
  • E-Commerce Order & Inventory BI: Merging Debezium CDC streams into queryable Iceberg tables with time-travel audits.
  • GDPR / CCPA Compliance: Executing row-level deletes across petabyte object storage without full-table rewrites.
