Kubernetes Pod Disruption Budgets
& Safe Node Drains.

A misconfigured PodDisruptionBudget (such as minAvailable: 100% or minAvailable == replicas) sets disruptionsAllowed=0, causing kubectl drain and Karpenter/GKE/EKS node upgrades to hang indefinitely with HTTP 429 eviction blocks.

01 / UnderstandFailure & constraints

Clarify what is failing.

Each PDB resulted in desiredHealthy >= currentHealthy, setting disruptionsAllowed=0 and causing the Kubernetes Eviction API to return HTTP 429 TooManyRequests.

Design objective

Run kubectl get pdb -A to inspect ALLOWED DISRUPTIONS column.

Requirements

  • Ensure voluntary disruptions (node drains, Karpenter consolidation, EKS upgrades) always have disruptionsAllowed >= 1 for multi-replica services.
  • Prevent broken PDB configurations (`minAvailable >= replicas` or `maxUnavailable: 0`) from being admitted to the cluster.
  • Handle singleton stateful workloads (`replicas: 1`) safely during planned upgrades without hanging drains for hours.
  • Alert on `disruptionsAllowed == 0` long before a scheduled node upgrade begins.

Constraints

  • Cluster runs 180 nodes across 3 AZs with EKS managed node groups and Karpenter.
  • Multi-AZ stateless services must maintain at least N-1 replicas during voluntary drains.
  • Zero unapproved force-deletes (`--force --grace-period=0`) on stateful production pods.
Known failure modes

Assuming PDBs protect against OOMKills or EC2 hardware failures (they only govern voluntary Eviction API calls).

Graceful SIGTERM + Reschedule

  1. 01Admission Validation: Kyverno rejects PDBs with maxUnavailable: 0, minAvailable: 100%, or singleton minAvailable: 1.
  2. 02Voluntary Drain Request: EKS upgrade controller or Karpenter requests graceful pod eviction before cordoning node.
  3. 03Budget Verification: API server verifies currentHealthy > desiredHealthy (maxUnavailable: 1 allows 1 eviction).
  4. 04Graceful Replacement: Replacement pod starts on a new 1.29 node while old pod drains connections gracefully.
  5. 05Continuous Audit: Prometheus alerts if disruptionsAllowed==0 for >15m so issues are fixed before upgrades.
Using maxUnavailable: 1 with unhealthyPodEvictionPolicy: AlwaysAllow and Kyverno admission checks prevents HTTP 429 drain deadlocks.

The invariants

  • Update auth-service and billing-worker PDBs to maxUnavailable: 1.
  • Add unhealthyPodEvictionPolicy: AlwaysAllow (K8s 1.27+).
  • Deploy Kyverno ClusterPolicy in Enforce mode.
03 / Trace the lifecycleKey decisions

Follow the execution path.

Use maxUnavailable for stateless/HPA workloads so scaling down never deadlocks drains; use minAvailable only for fixed-size quorum sets (e.g., minAvailable: 2 on 3-node etcd), and omit PDBs on singletons.

Step 1

Use maxUnavailable: 1 (or 25%) for all Deployments with HPA.

Step 2

Use minAvailable: 2 for 3-node quorum StatefulSets.

Step 3

Scale singletons to replicas: 2 or remove their PDB.

YAML · Lifecycle trace
# 3-node quorum StatefulSet (e.g., Zookeeper/etcd): allows 1 node down at a time
spec:
  minAvailable: 2
  selector:
    matchLabels:
      app: zookeeper
Key trade-off

Omitting PDB on a singleton allows brief 10-30s restart during upgrades instead of blocking the entire node upgrade for 6 hours.

04 / ImplementConfiguration & code

Build the safeguards.

By default (IfHealthyBudget), a CrashLooping pod reduces currentHealthy below desiredHealthy, causing K8s to block eviction of even the broken pod itself. AlwaysAllow lets broken pods be evicted.

1. Reference implementation

YAML · Solution
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata:
  name: billing-worker-pdb
spec:
  maxUnavailable: 1
  unhealthyPodEvictionPolicy: AlwaysAllow
  selector:
    matchLabels:
      app: billing-worker
---
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: block-deadlocking-pdb
spec:
  validationFailureAction: Enforce
  rules:
    - name: disallow-zero-disruptions
      match:
        any:
          - resources:
              kinds: ["PodDisruptionBudget"]
      validate:
        message: "PDB must not set maxUnavailable=0 or minAvailable=100%."
        deny:
          conditions:
            any:
              - key: "{{ request.object.spec.maxUnavailable || '' }}"
                operator: Equals
                value: 0
              - key: "{{ request.object.spec.minAvailable || '' }}"
                operator: Equals
                value: "100%"

2. Harden for scale

By default (IfHealthyBudget), a CrashLooping pod reduces currentHealthy below desiredHealthy, causing K8s to block eviction of even the broken pod itself. AlwaysAllow lets broken pods be evicted.

YAML · Scale hardening
spec:
  maxUnavailable: 1
  unhealthyPodEvictionPolicy: AlwaysAllow

3. Operational controls

Step 1

Verify cluster version >= 1.27.

Step 2

Set unhealthyPodEvictionPolicy: AlwaysAllow on PDBs.

Step 3

Confirm drain evicts unhealthy pods without violating healthy pod budgets.

Implementation note

maxUnavailable: 1 guarantees safe node-by-node upgrades across any HPA replica count >= 2.

Prove the fix works.

Alert on kube_poddisruptionbudget_status_pod_disruptions_allowed == 0 sustained for >15 minutes via kube-state-metrics.

YAML · Verification
- alert: KubernetesPdbZeroDisruptionsAllowed
  expr: kube_poddisruptionbudget_status_pod_disruptions_allowed == 0
  for: 15m
  labels:
    severity: warning
  annotations:
    summary: "PDB {{ $labels.namespace }}/{{ $labels.poddisruptionbudget }} blocks node drains"

Acceptance criteria

Target: no scenario-correlated errors in the tested workload, no duplicate committed writes, and no routine forced termination. Document traffic patterns, duration, and fault injections. A clean run is evidence—not an unconditional guarantee.

Theory & Tips and Tricks

Practical heuristics & interview traps
