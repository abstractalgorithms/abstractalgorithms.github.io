Distributed & Application Caching
Caching keeps a reusable copy of data so an application can avoid repeating a database query, calculation, or network call. It can make responses faster and reduce database load. The trade-off: the copy may be out of date.
Database Sharding & Range Partitioning
Horizontally partitioning a dataset across independent database nodes by a shard key—using either contiguous key ranges or consistent hashing—to scale write throughput and storage beyond a single primary's CPU, IOPS, and memory ceiling.
Consistent Hashing & Virtual Nodes
Consistent hashing assigns data keys to servers in a way that limits how many keys move when servers are added or removed. This helps avoid widespread cache misses and sudden load on databases.
Rate Limiting Algorithms, Token Buckets & Redis Lua
Rate limiting enforces caps on request or resource consumption per caller, tenant, or endpoint over time to protect downstream capacity, ensure fair multi-tenant sharing, and blunt abuse.

STAGE 02 · IMPACTL5 · APPLIED DESIGN

What happens with hash collisions and synchronous analytics.

Why this matters: The problem: see what breaks without What happens with hash collisions and synchronous analytics under real concurrency or scale.

Two design mistakes cripple URL shorteners under viral traffic:

  1. Synchronous Click DB Updates: Incrementing UPDATE urls SET clicks = clicks + 1 on every redirect turns a 116k QPS read workload into 116k QPS of row-locked DB writes.
  2. MD5 Truncation Collisions: Truncating an MD5/SHA256 hash to 7 chars forces a DB SELECT + retry loop on every write and leaks predictability.
100:1 Read-Optimized Path

Redirect API -> Redis Cache (Hit) / Sharded KV (Miss) + Async Kafka

Redirect API checks Redis first, falls back to Sharded KV only on cache miss, and emits click events asynchronously to Kafka so redirects never block on DB writes.

STAGE 03 · NAIVE SOLUTIONL5 · APPLIED DESIGN

Naive solution (and why auto-increment IDs or MD5 truncation fail).

Why this matters: The problem: see what breaks without Naive solution under real concurrency or scale.

A naive implementation uses a single Postgres SERIAL column encoded to Base62 or truncates md5(long_url)[:7]:

  • Single DB Bottleneck: One auto-increment sequence cannot scale writes multi-region and exposes sequential enumeration.
  • Hash Retry Loops: Truncated hashes collide under the birthday paradox, requiring DB round-trips to verify uniqueness.
04
STAGE 04 · ENTERPRISE SOLUTIONL6 · SCALE & TRADE-OFFS

Enterprise solution: Range-Allocated Base62 Keys + Redis Redirects + Kafka Analytics.

Why this matters: Operational control: configure bounds, failure handling, and safe production defaults.

Production URL shorteners decouple key generation, redirects, and analytics:

  • Collision-Free Key Generation: Each API server leases a non-overlapping numeric range (e.g., 1,000,000 IDs from ZooKeeper/etcd) or uses a distributed Snowflake/Feistel-scrambled counter encoded in Base62 ([a-zA-Z0-9]), guaranteeing zero collisions with zero DB checks.
  • Custom Aliases & Expiry: Store (short_alias, long_url, expires_at) in a sharded KV/DB partitioned by hash(short_alias).
  • Low-Latency Redirects: Lookup short_alias in Redis (< 2 ms), return 302 Found (or 301 when analytics aren't needed), and emit click telemetry asynchronously to Kafka.
Write & Redirect Flows

Range-Based Base62 Minting vs. Cached 302 Redirect

Local counter ranges eliminate write-path collision checks, while Redis + async Kafka keep redirect latency < 10 ms.

ALPHABET = "0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ"
BASE = len(ALPHABET)

def encode_base62(num: int, min_len: int = 7) -> str:
    if num == 0:
        return ALPHABET[0] * min_len
    chars = []
    while num > 0:
        num, rem = divmod(num, BASE)
        chars.append(ALPHABET[rem])
    encoded = "".join(reversed(chars))
    return encoded.rjust(min_len, ALPHABET[0])

class RangeShortener:
    def __init__(self, start_id: int, end_id: int):
        self.curr = start_id
        self.end = end_id

    def next_alias(self) -> str:
        if self.curr >= self.end:
            raise RuntimeError("Lease next range from coordinator")
        alias = encode_base62(self.curr)
        self.curr += 1
        return alias

STAGE 05 · SYSTEM DESIGN APPLICATIONSL7 · STAFF / PRINCIPAL

Where URL Shortener Patterns apply in System Design.

Why this matters: Scope boundary: identify where this pattern fits best and where simpler or async alternatives win.

The range-allocated Base62 + read-cache pattern powers many high-read indirection systems:

  • Link Shorteners & QR Code Platforms (Bitly): Global edge caching with asynchronous clickstream aggregation.
  • Pastebins & Shareable Permalinks: Generating unguessable, collision-free short keys without DB round-trips.
  • Affiliate & Ad Tracking Redirectors: Sub-10 ms 302 redirects paired with Kafka click attribution.
