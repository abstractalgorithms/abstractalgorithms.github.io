STAGE 03 · NAIVE SOLUTIONL5 · APPLIED DESIGN

Why capturing `this` in Cleaner or skipping cleanable.clean() still leaks.

Why this matters: The problem: see what breaks without Why capturing this in Cleaner or skipping cleanable.clean under real concurrency or scale.

Two subtle bugs break naive Cleaner migrations:

  • Capturing this in the cleanup lambda: CLEANER.register(this, () -> freeNative(this.handle)) holds a strong reference to this, so the object never becomes phantom-reachable and leaks forever.
  • Calling freeNative() directly in close(): Without cleanable.clean(), the Cleaner still fires later and triggers a C++ double-free segfault.

STAGE 04 · ENTERPRISE SOLUTIONL6 · SCALE & TRADE-OFFS

Enterprise solution: AutoCloseable + Static Non-Capturing Cleaner State.

Why this matters: Operational control: configure bounds, failure handling, and safe production defaults.

Replace finalize() (deprecated for removal) with deterministic AutoCloseable + an idempotent Cleaner safety net:

  • Deterministic try-with-resources: Callers release native buffers immediately via close() with zero GC delay.
  • static final class NativeState implements Runnable: Holds only the raw long handle and an AtomicBoolean freed—never a reference to the enclosing NativeImageBuffer.
  • Single-Shot cleanable.clean(): close() delegates to cleanable.clean(), which invokes NativeState.run() at most once and deregisters the Cleanable so double-free is impossible.
Idempotent Native Cleanup

Deterministic close() vs. Phantom-Reachable Cleaner Safety Net

AtomicBoolean + cleanable.clean() guarantee idempotent single-free across explicit close() and GC Cleaner.

public final class NativeImageBuffer implements AutoCloseable {
    private static final Cleaner CLEANER = Cleaner.create();

    private static final class NativeState implements Runnable {
        private final long handle;
        private final AtomicBoolean freed = new AtomicBoolean(false);
        NativeState(long handle) { this.handle = handle; }
        @Override public void run() {
            if (freed.compareAndSet(false, true)) {
                freeNative(handle);
            }
        }
    }

    private final NativeState state;
    private final Cleaner.Cleanable cleanable;

    public NativeImageBuffer(long handle) {
        this.state = new NativeState(handle);
        this.cleanable = CLEANER.register(this, this.state);
    }

    @Override public void close() {
        cleanable.clean(); // Idempotent: invokes NativeState.run() once
    }
}

STAGE 05 · SYSTEM DESIGN APPLICATIONSL7 · STAFF / PRINCIPAL

Where deterministic off-heap lifecycle management is critical.

Why this matters: Scope boundary: identify where this pattern fits best and where simpler or async alternatives win.

Eliminating finalize() is mandatory in high-throughput JVM media, ML, and networking services:

  • JNI Image/Video & Tensor Buffers: Prevents native RSS leaks in OpenCV, FFmpeg, and ONNX/PyTorch wrappers.
  • Netty / Direct ByteBuffer Pools: Pairs explicit release() reference counting with leak detection.
  • Java 22+ Foreign Function & Memory (Arena): Replaces JNI + Cleaner with deterministic confined/shared Arena scopes.
