Resolving Linux Conntrack
Table Exhaustion.

Short-lived TCP/UDP connections fill Linux nf_conntrack_max (default 65,536), causing the kernel to silently drop new SYN and DNS packets (nf_conntrack: table full, dropping packet).

01 / UnderstandFailure & constraints

Clarify what is failing.

Conntrack exhaustion is a fixed table-capacity limit (`nf_conntrack_max`, default 65,536), not a CPU bottleneck. Closed flows linger for `120s` in `TIME_WAIT`, filling the table.

Design objective

Check `sysctl net.netfilter.nf_conntrack_count net.netfilter.nf_conntrack_max`.

Requirements

  • Eliminate `nf_conntrack` packet drops (`insert_failed == 0`) up to `200,000 req/s` burst.
  • Keep conntrack hash-table lookup overhead low (`average chain length <= 4`) so gateway CPU stays under 50%.
  • Eliminate connection churn between Envoy/Nginx and upstream backends.
  • Add Prometheus alerting on `nf_conntrack` utilization (`> 75%`) and drop counters.

Constraints

  • Gateway nodes use `iptables` NAT rules for VIP/Kubernetes Service routing in the current topology.
  • Memory overhead for `nf_conntrack` must stay under `512 MiB` per 64 GiB node.
  • Cannot drop stateful firewalling on external ingress interfaces.
Known failure modes

Running `conntrack -L` on a 1M-entry table in production can briefly stall packet processing.

Long-lived TCP pools

  1. 01Fast Hash Lookup: With 262,144 hash buckets, average chain length stays <= 4 even at 700k active/TW entries.
  2. 0230s TIME_WAIT Expiry: Closed client flows expire in 30s instead of 120s, freeing 4x more table capacity.
  3. 03Eliminate Backend Churn: Envoy/Nginx reuses persistent upstream connections, avoiding 100k+ new backend conntrack entries/sec.
  4. 04Raw Table Exemption: Loopback and non-NATted internal telemetry bypass nf_conntrack via iptables -t raw.
  5. 05Saturation Alerting: Page when nf_conntrack_entries / nf_conntrack_entries_limit > 0.75 or drop > 0.
Combining `1M` conntrack sizing (`buckets = max / 4`), `30s` `TIME_WAIT` expiry, and upstream keep-alive pooling eliminates packet drops.

The invariants

  • Apply sysctl parameters in /etc/sysctl.d/99-conntrack.conf.
  • Set hashsize=262144 in /sys/module/nf_conntrack/parameters/hashsize.
  • Enable keepalive 512 and HTTP/1.1 persistent connections in Nginx.
03 / Trace the lifecycleKey decisions

Follow the execution path.

Use `NOTRACK` when traffic does not require NAT (`MASQUERADE`/`DNAT`) or stateful firewalling—such as loopback, internal BGP/direct-routed VIPs, or high-QPS UDP telemetry.

Step 1

Verify whether the interface/port performs SNAT/DNAT (if yes, NOTRACK will break it).

Step 2

Add -t raw -A PREROUTING -i lo -j NOTRACK and -t raw -A OUTPUT -o lo -j NOTRACK.

Step 3

Ensure ACCEPT rule for UNTRACKED state exists in filter table.

YAML · Lifecycle trace
# Example sysctl.d/99-conntrack.conf paired with raw NOTRACK
net.netfilter.nf_conntrack_max: 1048576
net.netfilter.nf_conntrack_tcp_timeout_time_wait: 30
net.netfilter.nf_conntrack_tcp_timeout_established: 3600
net.netfilter.nf_conntrack_udp_timeout: 15
Key trade-off

NOTRACK eliminates all conntrack RAM and spinlock overhead, but disables RELATED,ESTABLISHED stateful firewalling for that traffic.

04 / ImplementConfiguration & code

Build the safeguards.

A `SYN` flood fills `nf_conntrack` with `SYN_RECV` entries if not mitigated. Enable `tcp_syncookies=1`, shorten `nf_conntrack_tcp_timeout_syn_recv=15`, and drop floods in `XDP`/edge WAF before Netfilter.

1. Reference implementation

NGINX · Solution
upstream api_backend {
    server 10.20.1.10:8080;
    server 10.20.1.11:8080;
    keepalive 512;
    keepalive_requests 10000;
    keepalive_timeout 60s;

server {

2. Harden for scale

A `SYN` flood fills `nf_conntrack` with `SYN_RECV` entries if not mitigated. Enable `tcp_syncookies=1`, shorten `nf_conntrack_tcp_timeout_syn_recv=15`, and drop floods in `XDP`/edge WAF before Netfilter.

PYTHON · Scale hardening
def detect_syn_flood(syn_recv_count: int, conntrack_max: int) -> bool:
    # Alert if half-open SYN_RECV entries exceed 20% of conntrack capacity
    return (syn_recv_count / conntrack_max) > 0.20

3. Operational controls

Step 1

Enable `net.ipv4.tcp_syncookies = 1` and `net.netfilter.nf_conntrack_tcp_timeout_syn_recv = 15`.

Step 2

Deploy `XDP` (`eBPF` at NIC driver level) or upstream AWS Shield / Cloudflare to drop spoofed SYNs before `sk_buff` reaches Netfilter.

Step 3

Monitor `SYN_RECV` count in `conntrack`.

Implementation note

Persistent keep-alive pools hold open file descriptors (`nofile` ulimit must be raised) but cut TCP handshakes by >95%.

05 / Verify & observeEvidence & acceptance

Prove the fix works.

Move L4 load balancing to `eBPF`/`XDP` (e.g., Cilium or Katran) with Direct Server Return (DSR) and `BPF_MAP_TYPE_LRU_HASH` per-CPU conntrack maps.

  • ↗
    Replace `iptables` NAT with `eBPF` `tc`/`XDP` forwarding.
  • ↗
    Use DSR so return traffic flows directly from backend to client, halving gateway PPS.
  • ↗
    Replace global `nf_conntrack` locks with lockless per-CPU eBPF LRU hash maps.
PYTHON · Verification
def estimate_dsr_savings(ingress_pps: int, egress_pps: int) -> dict[str, int]:
    # DSR bypasses gateway on return path (typically 4x-10x larger than ingress)
    return {"without_dsr_pps": ingress_pps + egress_pps, "with_dsr_pps": ingress_pps}

Acceptance criteria

Target: no scenario-correlated errors in the tested workload, no duplicate committed writes, and no routine forced termination. Document traffic patterns, duration, and fault injections. A clean run is evidence—not an unconditional guarantee.

Review questions

Failure scenario 1

Relying solely on `nf_conntrack_max` during a volumetric SYN flood still exhausts kernel memory.

Failure scenario 2

Asymmetric routing firewalls dropping DSR return packets if stateful security groups sit in the return path.

Alternatives considered

  • Scale horizontally behind AWS NLB / GCP Maglev with IP preservation.
