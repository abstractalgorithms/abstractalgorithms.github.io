Capacity Math: 50M Namespaces, 100B Facts & 250K Recall QPS.

Why this matters: Derive DRAM, Int8 HNSW NVMe, Knowledge Graph, and H100 extraction sizing.

At 250,000 recall QPS and 15 ms target service window, Little's Law requires L = 3,750 in-flight RPCs (9,000 at 36 ms burst).

Tier 1 Redis holds 50M active sessions x 2.4 KB (~240-343 GB DRAM with RF=2). Tier 2 Int8 quantized 1536-dim vectors (1,920 bytes/vector including HNSW links) span 120 Qdrant shards on NVMe.

Stage 1 • Capacity Sizing

3-Tier Memory & 160-H100 Extraction Sizing

1.4x Vector Savings: Int8 quantization shrinks 1536-dim vectors from 6,144 B to 1,536 B.

2.3,750 In-Flight RPCs: Little's Law (250K QPS x 0.015s) sizes gateway concurrency.

Int8 quantization and 3-tier sizing bound DRAM, NVMe, and GPU footprints for 250K QPS.

Single-Stage Filterable HNSW vs Per-Tenant Collections.

Why this matters: Select bitset-masked shared HNSW over 50M separate collections.

Creating 50M separate HNSW collections exhausts OS file descriptors and per-index graph RAM overhead.

Conversely, post-filtering a global index collapses recall for small tenants.

Stage 3 • Multi-Tenant Vector Index

Single-Stage Bitset-Filtered HNSW

1.>95% Recall: Single-pass bitset masking avoids post-filter empty sets.

2.Zero FD Bloat: 120 shared shards replace 50M separate HNSW indexes.

Bitset-filtered shared HNSW shards preserve >95% recall across 50M namespaces without FD bloat.

Kafka Partitioning & 8B SLM Conflict Resolution Pipeline.

Why this matters: Guarantee per-namespace ordering during asynchronous fact extraction.

To prevent race conditions when two turns from the same user arrive back-to-back, Kafka partitions ingestion topics by {tenant_id}:{namespace_id}.

Consumer groups batch turns to 160 H100 GPUs running an 8B SLM that outputs ADD, UPDATE, DELETE, or NOOP ops.

Namespace-Keyed Kafka -> 160x H100 SLM

2.<=2.0s Convergence: Async GPU batching keeps extraction throughput at 50K QPS.

Namespace-keyed Kafka partitions preserve causal ordering across async 8B SLM mutations.

3-Way Scatter-Gather Fusion & Lazy Ebbinghaus Scoring.

Why this matters: Combine Redis, Qdrant, and Neo4j outputs within a 25ms p99 recall budget.

The Recall Gateway dispatches parallel RPCs to Tier 1 (4ms cap), Tier 2 (15ms cap), and Tier 3 (18ms cap).

Results are deduplicated by fact_id, fused via Reciprocal Rank Fusion (RRF), and re-scored using lazy Ebbinghaus decay R(t) = exp(-ddt/(SI)).

Stage 5 • Hybrid Fusion

Per-Tier Deadlines -> RRF -> Ebbinghaus Boost

1.Strict Tier Caps: One slow tier never stalls the entire 25ms recall SLA.

2.Hybrid Grounding: Balances semantic similarity with recency and graph structure.

Hard per-tier deadlines and RRF + Ebbinghaus scoring deliver ranked context within 25 ms.

Hedged Reads & Graceful Tier-3 Circuit Breaking.

Why this matters: Eliminate 2.97% tail amplification across 3-way parallel scatter-gather.

At 250K QPS, 3-way scatter-gather amplifies independent 1% tail stalls into a 2.97% system tail rate.

Firing an 8.5 ms hedged read to a replica cuts tail probability to ~0.12%.

Stage 6 • Tail & Degraded Mode

8.5ms Hedging + Tier-3 Fallback

1.0.12% Tail Rate: 8.5ms hedging reduces 3-way tail stalls by 24x.

2.Zero Hard Outages: Graph stalls degrade cleanly to vector + working memory.

8.5 ms hedged reads and Tier 3 circuit breakers protect the 25 ms p99 SLA under partial failure.
