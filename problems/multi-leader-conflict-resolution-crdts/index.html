01 / UnderstandFailure & constraints

Clarify what is failing.

At real time t=1000 ms, EU writes with skewed clock t_eu=1180 ms. US reads it at t=1080 ms and writes a dependent update stamped t_us=1090 ms. LWW sees 1180 > 1090 and discards US's newer causal write.

Design objective

Trace the causal chain `EU_write -> US_read -> US_write`.

Requirements

  • Eliminate silent data loss for concurrent writes to shopping carts (set/map mutations) and counters across all 3 regions.
  • Establish causal ordering across regions without relying on synchronized physical wall clocks (tolerating up to 500 ms NTP skew).
  • Preserve local-region write latency <= 15 ms p99 (no synchronous cross-region 2PC on every write).
  • Surface true unresolvable scalar conflicts via sibling versions or deterministic domain merge callbacks.

Constraints

  • Cross-region RTTs: US-EU 75 ms, US-AP 180 ms, EU-AP 150 ms.
  • Must continue accepting local writes during a cross-region WAN partition.
  • Application code must be in Java or Python.
Known failure modes

Zero error logs are emitted when LWW drops a write, making data loss invisible until customer complaints.

03 / Trace the lifecycleKey decisions

Follow the execution path.

Routing EU and AP writes to US-East adds 75–180 ms RTT per write and breaks write availability during WAN partitions. CRDTs preserve 15 ms local writes and zero-loss convergence.

Step 1

Compare local write latency (<15 ms) vs cross-region RTT (75–180 ms).

Step 2

Reserve single-leader/home-region routing strictly for hard-invariant operations like payment capture.

PYTHON · Lifecycle trace
class PNCounter:
    def __init__(self):
        self.p, self.n = {}, {}
    def inc(self, region: str, val: int = 1):
        self.p[region] = self.p.get(region, 0) + val
    def value(self) -> int:
        return sum(self.p.values()) - sum(self.n.values())
    def merge(self, other: 'PNCounter'):
        for r, v in other.p.items(): self.p[r] = max(self.p.get(r, 0), v)
        for r, v in other.n.items(): self.n[r] = max(self.n.get(r, 0), v)
Key trade-off

CRDTs cannot enforce a global non-negative cap (value >= 0) without cross-region reservation.

04 / ImplementConfiguration & code

Build the safeguards.

Enforce a `max_clock_offset_ms = 500` guard on `HLC.receive()`: if `msg_pt - wall > 500`, reject/quarantine replication from that node and alert on NTP drift.

1. Reference implementation

PYTHON · Solution
import time

class HLC:
    def __init__(self):
        self.pt = 0
        self.l = 0

    def local_event(self) -> tuple[int, int]:
        wall = int(time.time() * 1000)
        if wall > self.pt:
            self.pt, self.l = wall, 0
        else:
            self.l += 1
        return (self.pt, self.l)

    def receive(self, msg_pt: int, msg_l: int) -> tuple[int, int]:
        wall = int(time.time() * 1000)
        prev_pt = self.pt
        self.pt = max(prev_pt, msg_pt, wall)
        if self.pt == prev_pt == msg_pt:
            self.l = max(self.l, msg_l) + 1
        elif self.pt == prev_pt:
            self.l += 1
        elif self.pt == msg_pt:
            self.l = msg_l + 1
        else:
            self.l = 0
        return (self.pt, self.l)

2. Harden for scale

Enforce a `max_clock_offset_ms = 500` guard on `HLC.receive()`: if `msg_pt - wall > 500`, reject/quarantine replication from that node and alert on NTP drift.

PYTHON · Scale hardening
MAX_SKEW_MS = 500
if msg_pt - wall > MAX_SKEW_MS:
    raise ValueError(f'Clock skew {msg_pt - wall}ms exceeds {MAX_SKEW_MS}ms; quarantining node')

3. Operational controls

Step 1

Compare `msg_pt - wall` against `500 ms` threshold.

Step 2

Log/quarantine skewed messages and fence the drifting node until NTP resyncs.

Implementation note

If a rogue node's physical clock jumps +1 hour into the future, HLC `pt` latches to +1 hour until bounded by max-drift rejection.

Review questions

Failure scenario 1

Stepping an OS clock backward without HLC breaks monotonic timestamps; always use `chrony` slew mode.

Failure scenario 2

GC'ing tombstones before a partitioned region syncs causes deleted cart items to resurrect.

Alternatives considered

  • Reset/archive cart state on checkout completion.
