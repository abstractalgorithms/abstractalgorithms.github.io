01 / UnderstandFailure & constraints

Clarify what is failing.

A single shared key has only 1 TTL; jitter only spreads expirations across different keys, not concurrent readers of the same key.

Design objective

Compute misses in a 50ms window at 50k req/s: 2,500 simultaneous misses.

Requirements

  • Cap database recomputation for any expired hot key to at most 1-2 queries per refresh cycle across 200 API pods.
  • Keep API p99 latency under 15 ms even during cache refresh.
  • Ensure data staleness never exceeds 65 seconds.
  • Protect PostgreSQL even if Redis restarts or is cold-started.

Constraints

  • 200 stateless API pods (no sticky sessions).
  • DB query takes 180 ms under normal load and must never exceed 5 concurrent identical queries.
  • Redis cluster is already deployed; avoid adding new stateful infrastructure if possible.
Known failure modes

504 Gateway Timeouts cascading to retry storms from mobile/web clients.

L1 caching + singleflight + Redis SWR/XFetch cuts Redis load 500x and caps PostgreSQL refreshes to 1 query per minute.

The invariants

  • Store {value, delta_s, soft_expiry} in Redis with 300s hard TTL.
  • Evaluate now - delta_s * beta * math.log(random.random()) >= soft_expiry.
  • If triggered, acquire SET lock NX PX 2000 and refresh asynchronously while returning value.

04 / ImplementConfiguration & code

Build the safeguards.

Per-pod singleflight collapses 50,000 req/s to at most 200 concurrent Redis lock attempts, and `SET NX` + 50ms backoff collapses those 200 to 1 PostgreSQL query.

1. Reference implementation

PYTHON · Solution
import math, random, time, json

def get_with_xfetch(redis_client, key: str, fetch_fn, soft_ttl=60, hard_ttl=300, beta=1.0):
    raw = redis_client.get(key)
    now = time.time()
    if raw:
        entry = json.loads(raw)
        should_refresh = (now - entry['delta'] * beta * math.log(random.random())) >= entry['soft_exp']
        if should_refresh and redis_client.set(f'lock:{key}', '1', nx=True, px=2000):
            t0 = time.time()
            val = fetch_fn()
            delta = time.time() - t0
            redis_client.set(key, json.dumps({'val': val, 'delta': delta, 'soft_exp': time.time() + soft_ttl}), ex=hard_ttl)
        return entry['val']
    # Cold cache fallback: acquire lease or wait
    for _ in range(10):
        if redis_client.set(f'lock:{key}', '1', nx=True, px=2000):
            t0 = time.time()
            val = fetch_fn()
            redis_client.set(key, json.dumps({'val': val, 'delta': time.time()-t0, 'soft_exp': time.time() + soft_ttl}), ex=hard_ttl)
            return val
        time.sleep(0.05 + random.uniform(0, 0.02))
        raw = redis_client.get(key)
        if raw:
            return json.loads(raw)['val']
    return fetch_fn()

2. Harden for scale

Per-pod singleflight collapses 50,000 req/s to at most 200 concurrent Redis lock attempts, and `SET NX` + 50ms backoff collapses those 200 to 1 PostgreSQL query.

PYTHON · Scale hardening
import threading

db_bulkhead = threading.BoundedSemaphore(5)

def safe_query_db(fn):
    if not db_bulkhead.acquire(timeout=0.2):
        raise RuntimeError('DB bulkhead full - fail fast 503')
    try:
        return fn()
    finally:
        db_bulkhead.release()

3. Operational controls

Step 1

200 pods each collapse ~250 local threads via singleflight -> 200 Redis `SET NX` calls.

Step 2

1 pod wins the lock and runs 1 DB query (180ms); 199 pods wait 50ms and read the populated key.

Step 3

Enforce a DB-side bulkhead (`Semaphore(5)`) as a last-resort circuit breaker.

Implementation note

Inline refresh on the 1 winning request adds 180ms to 1 out of 3,000,000 requests; offloading to a background thread keeps even that request < 5ms.

05 / Verify & observeEvidence & acceptance

Prove the fix works.

Publish an invalidation event over Redis Pub/Sub to evict the 2s L1 cache across all 200 pods and overwrite (not delete) the Redis key with the cancelled state.

  • ↗
    Broadcast `PUBLISH cache:invalidate deal:global:active` so all 200 pods evict L1 immediately.

def update_deal_and_broadcast(redis_client, new_payload: dict):
    redis_client.set('deal:global:active', json.dumps(new_payload), ex=300)
    redis_client.publish('cache:invalidate', 'deal:global:active')

Acceptance criteria

Target: no scenario-correlated errors in the tested workload, no duplicate committed writes, and no routine forced termination. Document traffic patterns, duration, and fault injections. A clean run is evidence—not an unconditional guarantee.

Review questions

Failure scenario 1

If the DB query takes > 2s (exceeding lock PX 2000), a second pod can acquire the lock; set PX to 5x p99 DB time.

Failure scenario 2

Redis Pub/Sub is fire-and-forget; keep the 2s L1 TTL as a safety net for missed Pub/Sub messages.

Alternatives considered

  • Accepting the 2-second L1 + 60s soft TTL lag.
