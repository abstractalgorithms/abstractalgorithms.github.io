Given an integer array nums (1 <= nums.length <= 100,000, -10,000 <= nums[i] <= 10,000) and 1 <= k <= U (where U is unique elements), we must return the k most frequent elements in strictly better than O(N log N) time. Because no element can appear more than N times, frequency is bounded to [1..N]—allowing linear-time bucket selection.

02
STAGE 02 · IMPACTL5 · APPLIED DESIGN

Complexity gap: O(N log N) sort vs. O(N log k) heap vs. O(N) buckets.

Why this matters: The problem: see what breaks without Complexity gap: O under real concurrency or scale.

Choosing the wrong selection strategy degrades throughput as N and k grow:

  1. Full Sort (O(U log U)): Violates the < O(N log N) constraint when U ≈ N (100,000 unique values).
  2. Min-Heap of Size k (O(N + U log k)): Still pays O(U log k) comparisons when k is large (k ≈ N/2), and still requires the O(U) frequency map.

STAGE 03 · NAIVE SOLUTIONL5 · APPLIED DESIGN

Common pitfalls: value-indexed buckets, shared fill([]), and boundary ties.

Why this matters: Scope boundary: identify where this pattern fits best and where simpler or async alternatives win.

Three common bugs break naive implementations:

  • Indexing buckets by nums[i]: Fails on negative integers (-10,000 <= nums[i]).
  • new Array(N + 1).fill([]): Shares the exact same array reference across all N + 1 slots!
  • Pushing an entire bucket without checking result.length === k: Can return more than k elements.

04
STAGE 04 · ENTERPRISE SOLUTIONL6 · SCALE & TRADE-OFFS

Optimal O(N) solution: Frequency Hash Map + Bounded Bucket Array.

Why this matters: Operational control: configure bounds, failure handling, and safe production defaults.

Execute three linear passes (O(N) expected time, O(N) auxiliary space) without mutating nums:

  1. Count (O(N)): Build Map<number, number> mapping each distinct integer to its frequency.
  2. Group by Frequency (O(U)): Allocate buckets of length nums.length + 1 (undefined slots, lazily initialized) and push num into buckets[count].
  3. Collect Top-K (O(N)): Scan freq from N down to 1, pushing elements one by one and returning immediately once result.length === k.
O(N) Bucket Selection

Hash Map -> Lazy Frequency Buckets -> Early-Return Scan

1.Bounded Range [1..N]: Sum of all frequencies equals N, so no count can exceed N.

2.Negative-Safe: Frequency is always >= 1, so negative input values map cleanly into buckets.

3.Early Return: Stop as soon as result.length === k without sorting the output.

Bucket selection achieves O(N) expected time and O(N) space while handling negatives and arbitrary output order.

export function topKFrequent(nums: number[], k: number): number[] {
  const frequency = new Map<number, number>();
  for (const num of nums) {
    frequency.set(num, (frequency.get(num) ?? 0) + 1);
  }

  const buckets: Array<number[] | undefined> = new Array(nums.length + 1);
  for (const [num, count] of frequency) {
    (buckets[count] ??= []).push(num);
  }

  const result: number[] = [];
  for (let freq = buckets.length - 1; freq >= 1 && result.length < k; freq--) {
    const bucket = buckets[freq];
    if (!bucket) continue;
    for (const num of bucket) {
      result.push(num);
      if (result.length === k) return result;
    }
  }
  return result;
}
