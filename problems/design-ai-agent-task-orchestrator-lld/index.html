STAGE 01 · WHY IT MATTERSL4 · FUNDAMENTALS

Why AI agent orchestrators need clean LLD boundaries.

Autonomous AI agents execute multi-step plans that mix LLM reasoning, parallel tool calls, human-in-the-loop pauses, and cyclic retries. Without clean object-oriented separation between domain state, tool execution, token accounting, and streaming UI observers, concurrent tool calls race on shared state or blow past token budgets.

02
STAGE 02 · IMPACTL5 · APPLIED DESIGN

Runaway token loops, race conditions, and coupled LLM clients.

Ad-hoc while True agent loops fail in three ways:

  1. Runaway Cost Loops: Cyclic tool retries without a shared TokenBudget guard burn millions of tokens on stuck tasks.
  2. Parallel Tool Races: Concurrent tool calls mutating shared TaskRun history corrupt step ordering.
  3. Tight Coupling: Hardcoding OpenAI/Gemini SDK calls inside step logic prevents unit testing or swapping retry policies.

03
STAGE 03 · NAIVE SOLUTIONL5 · APPLIED DESIGN

Naive `while` loops and unguarded shared dictionaries.

A single monolithic run_agent() function with a plain dict for state and if/elif tool dispatch cannot safely execute independent tools in parallel, lacks pluggable backoff strategies, and forces callers to poll instead of streaming StepEvents.

04
STAGE 04 · ENTERPRISE SOLUTIONL6 · SCALE & TRADE-OFFS

Enterprise solution: State Machine + Registry + Atomic TokenBudget + Observer.

Structure the orchestrator around four SOLID components:

  • TaskRun State Machine: Enforces valid transitions (PENDING, RUNNING, WAITING_HUMAN, COMPLETED, FAILED) and stores immutable StepRecords.
  • TokenBudget (Thread-Safe): Uses a threading.Lock / atomic consume(tokens) check before every LLM or tool step, raising BudgetExceededError cleanly.
  • ToolRegistry & RetryStrategy: Decouples tool schemas/handlers from LLMClient (Dependency Inversion) and injects exponential backoff per tool.
  • StepObserver Bus: Emits non-blocking StepEvents (TOOL_STARTED, TOKEN_USED, STATE_CHANGED) for SSE/WebSocket streaming.
Parallel Tool Execution

Budget Check -> Concurrent Tool Pool -> Observer Stream

Atomic budget reservation and isolated tool executors let independent tool calls run concurrently without state races.

from concurrent.futures import ThreadPoolExecutor
from dataclasses import dataclass, field
from enum import Enum
import threading

class RunState(Enum):
    PENDING = "PENDING"
    RUNNING = "RUNNING"
    WAITING_HUMAN = "WAITING_HUMAN"
    COMPLETED = "COMPLETED"
    FAILED = "FAILED"

class TokenBudget:
    def __init__(self, max_tokens: int):
        self._remaining = max_tokens
        self._lock = threading.Lock()

    def consume(self, tokens: int) -> bool:
        with self._lock:
            if tokens > self._remaining:
                return False
            self._remaining -= tokens
            return True

class AgentOrchestrator:
    def __init__(self, llm_client, registry, retry_strategy, observers):
        self.llm = llm_client
        self.registry = registry
        self.retry = retry_strategy
        self.observers = observers
        self.pool = ThreadPoolExecutor(max_workers=8)

STAGE 05 · SYSTEM DESIGN APPLICATIONSL7 · STAFF / PRINCIPAL

Where agent task orchestrator patterns are used.

These LLD primitives form the core of modern agentic runtimes:

  • LangGraph & Temporal AI Workflows: Persist TaskRun state transitions at each step so WAITING_HUMAN checkpoints survive process restarts.
  • Enterprise MCP Tool Servers: Use ToolRegistry and TokenBudget guards to expose domain APIs safely to multi-step agents.
