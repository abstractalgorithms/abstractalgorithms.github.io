Fixing Ephemeral Port Exhaustion
with Connection Pooling.

Creating a new HttpClient per request opened and closed 1,200 TCP connections/sec, filling all 28,232 Linux ephemeral ports with TIME_WAIT sockets and causing EADDRNOTAVAIL.

01 / UnderstandFailure & constraints

Clarify what is failing.

Linux holds closed client sockets in `TIME_WAIT` for 60s (`2*MSL`), capping new connections to a single `dst_ip:dst_port` at `28,232 / 60 = 470.5/sec`.

Design objective

Check `sysctl net.ipv4.ip_local_port_range` (default `32768 60999` = 28,232).

Requirements

  • Eliminate `EADDRNOTAVAIL` errors at 1,500+ RPS per pod (and scale cleanly to 5,000 RPS).
  • Reduce `TIME_WAIT` socket count per pod from ~28,200 to < 200.
  • Keep p99 downstream call latency under 10ms without TCP handshake overhead on every request.
  • Avoid unsafe kernel hacks that break NAT/Kubernetes `kube-proxy` traffic.

Constraints

  • Linux default ephemeral port range `ip_local_port_range` is `32768 60999` (28,232 ports).
  • TCP `TIME_WAIT` duration is hardcoded to `2 * MSL` = 60 seconds in Linux.
  • Downstream pricing service sits behind a single Kubernetes `ClusterIP` (`10.96.45.12:8080`).
Known failure modes

Assuming `EADDRNOTAVAIL` is a downstream server issue when it is 100% client-side.

HTTP/1.1 Keep-Alive / h2

  1. 01Pool Checkout: Worker borrows one of 128 pre-established keep-alive sockets instead of calling socket()+connect().
  2. 02Zero-Handshake RPC: Request flows over existing TCP socket to 10.96.45.12:8080 with 0ms handshake overhead.
  3. 03Backend Delivery: Kube-proxy routes packet to healthy pricing pod; response returns on same socket.
  4. 04Socket Reuse: Socket is returned to pool (not closed), avoiding FIN and 60s TIME_WAIT state.
  5. 05Controlled Rotation: Only ~2 sockets/sec rotate for load rebalancing, keeping TIME_WAIT under 128 sockets.
Properly sizing a singleton keep-alive pool cuts socket churn from 1,500/sec to ~2/sec, eliminating ephemeral port exhaustion.

The invariants

  • Move requests.Session() outside the request handler to module scope.
  • Set HTTPAdapter(pool_maxsize=128) to override the tiny default of 10.
  • Add net.ipv4.tcp_tw_reuse=1 and ip_local_port_range="1024 65535" as defense-in-depth.
03 / Trace the lifecycleKey decisions

Follow the execution path.

`tcp_tw_recycle` broke NATed clients by rejecting out-of-order PAWS timestamps and was removed in Linux 4.12; `tcp_tw_reuse=1` safely allows *outbound* clients to reuse `TIME_WAIT` sockets after 1s.

Step 1

Verify kernel version (uname -r >= 4.12).

Step 2

Use tcp_tw_reuse=1 (or 2 for loopback-only) strictly for outbound client connections.

YAML · Lifecycle trace
sysctls:
  - name: net.ipv4.tcp_tw_reuse
    value: "1"
Key trade-off

tcp_tw_reuse requires net.ipv4.tcp_timestamps=1 (enabled by default on Linux).

04 / ImplementConfiguration & code

Build the safeguards.

Kubernetes `ClusterIP` load-balances at TCP `SYN` time; use L7 load balancing (Envoy/Linkerd/Istio or headless Service + client-side `round_robin`) so requests distribute evenly.

1. Reference implementation

JAVA · Solution
PoolingHttpClientConnectionManager cm = new PoolingHttpClientConnectionManager();
cm.setMaxTotal(256);
cm.setDefaultMaxPerRoute(128);

2. Harden for scale

Kubernetes `ClusterIP` load-balances at TCP `SYN` time; use L7 load balancing (Envoy/Linkerd/Istio or headless Service + client-side `round_robin`) so requests distribute evenly.

YAML · Scale hardening
apiVersion: v1
kind: Service

  name: pricing-headless

  clusterIP: None

3. Operational controls

Step 1

Replace `ClusterIP` L4 routing with an Envoy sidecar or headless Service (`clusterIP: None`).

Step 2

Set `max_requests_per_connection` or 60s `maxLifeTime` so sockets periodically rebalance.

Implementation note

`pool_maxsize=128` uses ~128 file descriptors (< 1 MB kernel RAM) and eliminates 99.9% of `TIME_WAIT`.

05 / Verify & observeEvidence & acceptance

Prove the fix works.

Alert on `node_sockstat_TCP_tw > 5000` and HTTP client pool `leased / max` utilization plus `pending_acquires`.

  • ↗
    Scrape `node_exporter` `sockstat` metrics per node.
  • ↗
    Expose Micrometer `httpcomponents.httpclient.pool.route.max` and `leased`.
YAML · Verification
- alert: HighTimeWaitSockets
  expr: node_sockstat_TCP_tw > 5000
  for: 3m
  labels:
    severity: warning

Acceptance criteria

Target: no scenario-correlated errors in the tested workload, no duplicate committed writes, and no routine forced termination. Document traffic patterns, duration, and fault injections. A clean run is evidence—not an unconditional guarantee.

Review questions

Failure scenario 1

Infinite keep-alive over `ClusterIP` leaves newly added pods at 0% CPU during scale-out.

Failure scenario 2

Watching only pod CPU/memory misses port exhaustion completely.

Alternatives considered

  • eBPF `tcp_set_state` tracing (Cilium/Pixie) for per-pod `TIME_WAIT` attribution.

Theory & Tips and Tricks

Practical heuristics & interview traps

  • 01Interview anchor: Reuse a singleton HTTP connection pool (keep-alive) to cut connection churn by 1,000x; never rely on tcp_tw_recycle (removed in Linux 4.12 and broken behind NAT).
  • 02Trade-off tip: tcp_tw_reuse requires net.ipv4.tcp_timestamps=1 (enabled by default on Linux).
  • 03Watch out for: Infinite keep-alive over ClusterIP leaves newly added pods at 0% CPU during scale-out.
