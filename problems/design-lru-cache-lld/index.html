01
STAGE 01 · WHY IT MATTERSL4 · FUNDAMENTALS

Why O(1) LRU is the foundation of in-memory caching.

Whether in an OS page cache, database buffer pool, or API cache, bounded memory forces eviction when capacity is exceeded. To sustain high throughput, both get(key) and put(key, value)—including promoting a hit to Most Recently Used (MRU) and evicting the Least Recently Used (LRU)—must complete in O(1) time.

02
STAGE 02 · IMPACTL5 · APPLIED DESIGN

O(N) eviction stalls and null-pointer bugs without sentinel nodes.

Two implementation flaws break naive LRU caches:

  1. O(N) Linear Scan on Eviction: Tracking timestamps in a hash map without a linked list forces an O(N) scan to find the oldest key on every put().
  2. Head/Tail Edge-Case Bugs: Managing raw head/tail pointers without dummy sentinel nodes leads to null-pointer dereferences when capacity == 1 or when removing the last node.
O(1) Data Structure

HashMap Lookup + Sentinel Doubly Linked List (MRU <-> LRU)

Sentinel head/tail nodes eliminate null checks while the hash map gives O(1) node access.

03
STAGE 03 · NAIVE SOLUTIONL5 · APPLIED DESIGN

Naive array/list shifting and `O(log N)` min-heaps.

Using a Python list (remove + append) is O(N) per get(), while a min-heap keyed by access timestamp degrades to O(log N) and leaves stale heap entries. Only HashMap + DoublyLinkedList achieves true O(1).

04
STAGE 04 · ENTERPRISE SOLUTIONL6 · SCALE & TRADE-OFFS

Enterprise solution: Sentinel Doubly Linked List + Per-Instance Lock.

Implement clean O(1) primitives with zero special cases:

  • Sentinel head & tail: Every real node always has a non-null prev and next, making _remove(node) and _add_front(node) 4-line pointer swaps.
  • Update vs. Insert Order: In put(key, value), if key exists, update node.val and promote to MRU without evicting; only evict tail.prev when inserting a new key at len(map) > capacity.
  • Thread Safety: Guard get/put with a threading.Lock (or stripe across N shards for multi-core scale).
O(1) Operations

get(k) Promotion vs. put(k, v) Capacity Eviction

Both get() and put() execute a constant number of pointer and hash-map operations.

import threading

class _Node:
    __slots__ = ("key", "val", "prev", "next")
    def __init__(self, key: int = 0, val: int = 0):
        self.key, self.val = key, val
        self.prev = self.next = None

class LRUCache:
    def __init__(self, capacity: int):
        self.cap = capacity
        self.map: dict[int, _Node] = {}
        self.head, self.tail = _Node(), _Node()
        self.head.next, self.tail.prev = self.tail, self.head
        self.lock = threading.Lock()

    def _remove(self, node: _Node) -> None:
        node.prev.next, node.next.prev = node.next, node.prev

    def _add_front(self, node: _Node) -> None:
        node.next, node.prev = self.head.next, self.head
        self.head.next.prev = self.head.next = node

    def get(self, key: int) -> int:
        with self.lock:
            node = self.map.get(key)
            if not node:
                return -1
            self._remove(node)
            self._add_front(node)
            return node.val

    def put(self, key: int, value: int) -> None:
        with self.lock:
            if key in self.map:
                node = self.map[key]
                node.val = value
                self._remove(node)
                self._add_front(node)
                return
            if len(self.map) >= self.cap:
                lru = self.tail.prev
                self._remove(lru)
                del self.map[lru.key]
            node = _Node(key, value)
            self.map[key] = node
            self._add_front(node)

STAGE 05 · SYSTEM DESIGN APPLICATIONSL7 · STAFF / PRINCIPAL

Where LRU caches are used in systems.

LRU (and its striped/W-TinyLFU variants) underpins caching across every layer:

  • Language & OS Primitives: Python @functools.lru_cache, Redis allkeys-lru eviction, and Linux page-cache active/inactive lists.
  • Multi-Core API Servers: Sharded LRU (64-128 segments) or SIEVE/Caffeine caches scale single-lock LRU to 1M+ ops/sec.
