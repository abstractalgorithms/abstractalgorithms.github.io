01 / UnderstandFailure & constraints

Clarify what is failing.

Standard attention writes/reads O(N^2) matrices S and P to HBM, exhausting 80 GB VRAM and bottlenecking on HBM bandwidth.

Design objective

Compute S and P memory: B * H * N * N * 2 bytes.

Requirements

  • Compute exact attention without approximations (no sparse/linear attention) in O(N) auxiliary HBM memory.
  • Keep all intermediate S_ij and P_ij tiles strictly inside GPU SRAM (shared memory) using block sizes B_r and B_c.
  • Maintain numerical stability across tiles using online softmax rescaling (running max m_i and running denominator l_i).
  • Support backward-pass gradient computation without storing the N x N matrix P in HBM.

Constraints

  • Sequence length N up to 65,536; head dimension d = 128; FP16/BF16 inputs with FP32 accumulator.
  • On-chip SRAM budget per Streaming Multiprocessor (SM) is ~192 KB (A100) to ~228 KB (H100).
  • Reference implementation must be written in Python (PyTorch/NumPy) demonstrating exact tiled online softmax.
Known failure modes

CUDA OutOfMemoryError during long-context prefill or training.

Update m_i, l_i & Rescale O_i

  1. 01Load Query Tile: Outer loop assigns Q_i [B_r x d] to an SM and keeps it resident in SRAM.
  2. 02Stream KV Tiles: Inner loop streams K_j, V_j [B_c x d] blocks up to causal diagonal.
  3. 03Fused MatMul: Compute local attention logits in SRAM without writing S_ij to HBM.
  4. 04Online Rescale: Update running max/sum-exp in FP32 and rescale prior O_i accumulator.
  5. 05Flush Final Output: Normalize O_i once after K/V loop finishes and write O_i and L_i to HBM.
All N x N intermediate attention scores stay inside on-chip SRAM; only final outputs O_i and log-sum-exp L_i are written to HBM.

The invariants

  • Partition Q into B_r-row tiles and K, V into B_c-row tiles.
  • Initialize FP32 O_i, l_i, and m_i = -inf for each Q_i tile.
  • Stream K_j, V_j; compute S_ij, update m_new and l_i, rescale O_i by exp(m_i - m_new), and add P_tilde @ V_j.
  • Normalize O_i /= l_i once after the inner loop and store L_i = m_i + log(l_i).
03 / Trace the lifecycleKey decisions

Follow the execution path.

Putting Q in the outer loop gives each thread block exclusive ownership of O_i, eliminating cross-block atomic writes to HBM.

Step 1

In FA-1 (K/V outer), different thread blocks updated the same O_i rows, forcing HBM atomic/sync overhead.

Step 2

In FA-2 (Q outer), each SM owns O_i in registers/SRAM and writes it to HBM exactly once.

PYTHON · Lifecycle trace
def max_kv_tile_size(sram_bytes: int, d: int, B_r: int = 128) -> int:
    # Q_i (FP16) + O_i (FP32) + K_j,V_j (FP16) + S_ij (FP32)
    fixed = B_r * d * 2 + B_r * d * 4
    per_kv_row = (2 * d * 2) + (B_r * 4)
    return max(16, (sram_bytes - fixed) // per_kv_row)
Key trade-off

Q-outer loop parallelizes across (batch heads N / B_r), maximizing SM occupancy during prefill/training.

04 / ImplementConfiguration & code

Build the safeguards.

Ring Attention distributes Q, K, V chunks across GPUs in a ring topology and merges partial (O_i, l_i, m_i) blocks via online softmax.

1. Reference implementation

PYTHON · Solution
import numpy as np

def flash_attention_v2_forward(
    Q: np.ndarray, K: np.ndarray, V: np.ndarray,
    B_r: int = 64, B_c: int = 64, causal: bool = True
) -> tuple[np.ndarray, np.ndarray]:
    N, d = Q.shape
    scale = 1.0 / np.sqrt(d)
    O = np.zeros((N, d), dtype=np.float32)
    L = np.zeros(N, dtype=np.float32)

    for i_start in range(0, N, B_r):
        i_end = min(i_start + B_r, N)
        Q_i = Q[i_start:i_end].astype(np.float32)
        rows = i_end - i_start
        O_i = np.zeros((rows, d), dtype=np.float32)
        l_i = np.zeros(rows, dtype=np.float32)
        m_i = np.full(rows, -np.inf, dtype=np.float32)

        j_limit = i_end if causal else N
        for j_start in range(0, j_limit, B_c):
            j_end = min(j_start + B_c, N)
            K_j = K[j_start:j_end].astype(np.float32)
            V_j = V[j_start:j_end].astype(np.float32)
            S_ij = (Q_i @ K_j.T) * scale

            if causal and j_end > i_start:
                q_idx = np.arange(i_start, i_end)[:, None]
                k_idx = np.arange(j_start, j_end)[None, :]
                S_ij = np.where(k_idx > q_idx, -np.inf, S_ij)

            m_ij = np.max(S_ij, axis=1)
            m_new = np.maximum(m_i, m_ij)
            alpha = np.exp(m_i - m_new)
            P_tilde = np.exp(S_ij - m_new[:, None])

            l_i = alpha * l_i + np.sum(P_tilde, axis=1)
            O_i = alpha[:, None] * O_i + (P_tilde @ V_j)
            m_i = m_new

        O[i_start:i_end] = O_i / l_i[:, None]
        L[i_start:i_end] = m_i + np.log(l_i)
    return O, L

2. Harden for scale

Ring Attention distributes Q, K, V chunks across GPUs in a ring topology and merges partial (O_i, l_i, m_i) blocks via online softmax.

PYTHON · Scale hardening
def merge_ring_attention(O_acc: np.ndarray, L_acc: np.ndarray, O_new: np.ndarray, L_new: np.ndarray) -> tuple[np.ndarray, np.ndarray]:
    L_max = np.maximum(L_acc, L_new)
    w_acc = np.exp(L_acc - L_max)
    w_new = np.exp(L_new - L_max)
    denom = w_acc + w_new
    O_merged = (O_acc * w_acc[:, None] + O_new * w_new[:, None]) / denom[:, None]
    L_merged = L_max + np.log(denom)
    return O_merged, L_merged

3. Operational controls

Step 1

Shard sequence N across P GPUs (each holds N/P tokens of Q, K, V).

Step 2

Compute local FlashAttention while asynchronously P2P-passing K, V blocks around the ring.

Step 3

Merge incoming block (O_block, L_block) into local (O_acc, L_acc) using log-sum-exp rescaling.

Implementation note

Deferring division by l_i to the end of the K/V loop (FlashAttention-2) removes B_r * d divisions per inner step.

PYTHON · Verification
def resolve_kv_physical_block(block_table: np.ndarray, seq_id: int, token_pos: int, block_size: int = 16) -> tuple[int, int]:
    logical_block = token_pos // block_size
    offset = token_pos % block_size
    return int(block_table[seq_id, logical_block]), offset

Acceptance criteria

Target: no scenario-correlated errors in the tested workload, no duplicate committed writes, and no routine forced termination. Document traffic patterns, duration, and fault injections. A clean run is evidence—not an unconditional guarantee.

Review questions

Failure scenario 1

Load imbalance under causal masking if blocks are assigned contiguously; mitigated by Zig-Zag / Striped Ring Attention.

Failure scenario 2

Small block sizes (< 8 tokens) reduce coalesced HBM memory reads.

Alternatives considered

  • Contiguous pre-allocated max_seq_len KV buffers for static batch sizes.
