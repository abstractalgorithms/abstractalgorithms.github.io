The idea to keep with you

Standard Transformer self-attention computes S = QK^T / sqrt(d), P = softmax(S), and O = PV. At sequence length N = 32,768 with 32 attention heads in FP16, materializing S and P in GPU HBM requires 32 * 32,768^2 * 2 bytes = 68.7 GB per layer—exceeding an 80 GB NVIDIA H100/A100 GPU and saturating HBM memory bandwidth. Design and implement an exact, IO-aware tiled attention algorithm in Python/PyTorch (reference kernel logic) that reduces HBM memory from O(N^2) to O(N) while remaining mathematically identical to standard attention.

Why standard O(N^2) attention hits the GPU HBM memory wall.

Standard attention computes S=QKT/dS = QK^T / \sqrt{d}S=QKT/d​, P=softmax(S)P = \text{softmax}(S)P=softmax(S), and O=PVO = PVO=PV. At sequence length N=32,768N = 32,768N=32,768 with $32$ heads in FP16, materializing SSS and PPP in off-chip GPU HBM consumes $32 \times 32,768^2 \times 2\text{ bytes} = 68.7\text{ GB}$ per layer—exceeding an 80 GB H100/A100 and wasting ~10× slower HBM bandwidth (1.5–3.35 TB/s vs. ~19 TB/s on-chip SRAM).

02
STAGE 02 · IMPACTL5 · APPLIED DESIGN

What happens when S and P are materialized in HBM.

Unfused attention kernels suffer two fatal bottlenecks at long context (32k–64k):

  1. O(N^2) HBM OOM: Storing SSS and PPP for activations causes immediate CUDA Out-of-Memory during training/prefill.
  2. Memory-Bandwidth Bound: Launching separate matmul, mask, softmax, and dropout kernels reads/writes N2N^2N2 matrices to HBM repeatedly while Tensor Cores sit idle.
GPU Memory Hierarchy

HBM (80GB, 3 TB/s) <-> On-Chip SRAM (228KB, 19 TB/s) Tiled Fusion

1.Zero N x N in HBM: S_ij and P_ij tiles live strictly in 192–228 KB SM SRAM and are discarded.

2.Online Softmax: Rescales running max m_i and sum l_i across K/V blocks with exact equivalence.

3.O(N) Backward: Saves only O(N) log-sum-exp stats (m, l) to recompute P_ij in SRAM on backward.

4.3x-7x Speedup: Fusing matmul + softmax + PV in SRAM converts bandwidth-bound ops to compute-bound.

Keeping S_ij and P_ij tiles inside fast SM SRAM reduces HBM memory from O(N^2) to O(N) with zero mathematical approximation.

STAGE 03 · NAIVE SOLUTIONL5 · APPLIED DESIGN

Naive solution (and why sparse/linear approximations or standard fusion fail).

Two naive workarounds compromise either accuracy or memory:

  • Sparse / Linear Attention: Approximates softmax, degrading long-context retrieval accuracy.
  • Row-wise Softmax Without Tiling: Still requires holding full NNN-length rows in SRAM, which overflows the 192–228 KB SM SRAM budget at N=65,536N = 65,536N=65,536.

STAGE 04 · ENTERPRISE SOLUTIONL6 · SCALE & TRADE-OFFS

Enterprise solution: Tiled Online Softmax + SRAM Kernel Fusion + Recomputation.

FlashAttention achieves exact attention in O(N) HBM memory:

  • Outer/Inner Tiling: Partition QQQ into blocks of size BrB_rBr​ and K,VK, VK,V into blocks of size BcB_cBc​ sized to fit in 192 KB SRAM (d = 128).
  • Online Softmax Rescaling: For each Kj,VjK_j, V_jKj​,Vj​ tile, compute Sij=QiKjT/dS_{ij} = Q_i K_j^T / \sqrt{d}Sij​=Qi​KjT​/d​ in SRAM, update minew=max⁡(mi,rowmax(Sij))m_i^{\text{new}} = \max(m_i, \text{rowmax}(S_{ij}))minew​=max(mi​,rowmax(Sij​)), rescale prior accumulator OiO_iOi​ and lil_ili​ by emi−minewe^{m_i - m_i^{\text{new}}}emi​−minew​, and accumulate P~ijVj\tilde{P}_{ij} V_jP~ij​Vj​ in FP32.
  • Backward Recomputation: Store only (mi,li)(m_i, l_i)(mi​,li​) (O(N)) in HBM; during backward pass, recompute Sij,PijS_{ij}, P_{ij}Sij​,Pij​ on-the-fly in SRAM.
Tiled Online Softmax Loop

Streaming K_j, V_j Tiles Through SRAM Without Materializing N x N

Each Q_i block accumulates exact softmax-weighted V across all K_j, V_j tiles using only O(Br * Bc) SRAM.

import numpy as np

def flash_attention_exact(Q: np.ndarray, K: np.ndarray, V: np.ndarray, Br: int = 64, Bc: int = 64) -> np.ndarray:
    """Exact IO-aware tiled attention with online softmax rescaling (single head)."""
    N, d = Q.shape
    scale = 1.0 / np.sqrt(d)
    O = np.zeros((N, d), dtype=np.float32)
    l = np.zeros((N, 1), dtype=np.float32)
    m = np.full((N, 1), -np.inf, dtype=np.float32)

    for i in range(0, N, Br):
        Qi = Q[i:i+Br].astype(np.float32)
        Oi = np.zeros((Qi.shape[0], d), dtype=np.float32)
        li = np.zeros((Qi.shape[0], 1), dtype=np.float32)
        mi = np.full((Qi.shape[0], 1), -np.inf, dtype=np.float32)

        for j in range(0, N, Bc):
            Kj = K[j:j+Bc].astype(np.float32)
            Vj = V[j:j+Bc].astype(np.float32)
            Sij = (Qi @ Kj.T) * scale
            m_tile = np.max(Sij, axis=1, keepdims=True)
            m_new = np.maximum(mi, m_tile)
            P_tilde = np.exp(Sij - m_new)
            alpha = np.exp(mi - m_new)
            li = alpha * li + np.sum(P_tilde, axis=1, keepdims=True)
            Oi = alpha * Oi + P_tilde @ Vj
            mi = m_new

        O[i:i+Br] = Oi / li
        l[i:i+Br], m[i:i+Br] = li, mi
    return O

STAGE 05 · SYSTEM DESIGN APPLICATIONSL7 · STAFF / PRINCIPAL

Where IO-Aware Tiled Attention applies in ML Systems.

FlashAttention is the core kernel behind modern long-context LLM training and inference:

  • Long-Context LLM Training (32k–1M tokens): Enables training without hitting 80 GB HBM OOMs.
  • High-Throughput LLM Serving (vLLM / TensorRT-LLM): Paired with PagedAttention for fast prefill and decode.
  • Multimodal & Video Transformers: Scaling exact attention to high-resolution image/video token sequences.
