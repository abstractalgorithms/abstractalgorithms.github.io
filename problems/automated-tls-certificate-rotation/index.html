01 / UnderstandFailure & constraints

Clarify what is failing.

TLS termination occurs at the CDN edge before HTTP routing, and internal monitors bypassed the CDN or disabled certificate verification.

Design objective

Inspect CDN edge certificate `notAfter` via `openssl s_client -connect api.globalshop.com:443 -servername api.globalshop.com`.

Requirements

  • Eliminate manual certificate rotation via automated ACME/CDN-managed renewal at 30 days before expiry.
  • Monitor the actual public CDN edge endpoints from multiple global vantage points (never bypass TLS verification).
  • Alert on *both* certificate days-remaining (`<= 21d`, `<= 7d`) and renewal-job failures.
  • Support fast (< 5 min) failover to a secondary CA (e.g., Let's Encrypt -> Google Trust Services / ZeroSSL) if primary ACME fails.

Constraints

  • Must cover 45 wildcard and SAN domains across 120 global CDN PoPs.
  • Zero-downtime certificate swap without dropping active TLS 1.3 sessions.
  • Strict compliance: `insecureSkipVerify` is forbidden in all production probes.
Known failure modes

Monitoring only the leaf cert and missing an expired intermediate CA cert (`probe_ssl_earliest_cert_expiry` checks the earliest in the chain).

Global Public Edge Probes

  1. 01DNS-01 Challenge: At 30 days before expiry, ACME controller writes _acme-challenge TXT record via scoped IAM role.
  2. 02Atomic Edge Deployment: Signed cert + chain is uploaded to CDN control plane; PoPs hot-swap without dropping active TLS sessions.
  3. 03Secondary ACME Issuer: If Let's Encrypt fails 3x, automation switches to ZeroSSL/Google Trust Services ClusterIssuer.
  4. 04Edge Chain Verification: External probes verify full cert chain and expiry against public DNS every 60s.
  5. 05Escalating Pager: Prometheus fires P2 at 21d remaining (9 days after missed renewal) and P1 at 7d.
Renewing at 30 days remaining and probing the public CDN edge with strict chain verification eliminates silent expirations.

The invariants

  • Configure renewBefore: 720h (30 days) on 90-day certs.
  • Alert on certmanager_certificate_ready_status == 0 so broken DNS-01 IAM roles are caught on day 1.
  • Probe all 45 public domains via blackbox_exporter.
03 / Trace the lifecycleKey decisions

Follow the execution path.

Prefer CDN-managed certs for single-CDN simplicity; use your own ACME + API push when running multi-CDN or strict custom key custody.

Step 1

Check if your architecture uses multi-CDN DNS steering (e.g., Cloudflare + Fastly).

Step 2

Verify whether compliance requires HSM/customer-owned private keys.

  duration: 2160h # 90d

Key trade-off

CDN-managed certs remove operational burden but don't synchronize private keys across two different CDN vendors.

04 / ImplementConfiguration & code

Build the safeguards.

Use wildcard SAN consolidation to stay under rate limits and maintain a pre-configured secondary ACME CA (ZeroSSL / Google Trust Services).

1. Reference implementation

YAML · Solution
- alert: CertManagerRenewalFailing
  expr: certmanager_certificate_ready_status == 0
  for: 15m
  labels:
    severity: warning

2. Harden for scale

kind: ClusterIssuer

3. Operational controls

Step 1

Consolidate subdomains into wildcard certs (`*.globalshop.com`) to reduce cert count.

Step 2

Configure a secondary `ClusterIssuer` with ZeroSSL/GTS EAB credentials ready for 1-line failover.

Implementation note

A 30-day renewal buffer gives SREs 9 days to notice a warning before the 21-day alert even fires.

Acceptance criteria

Target: no scenario-correlated errors in the tested workload, no duplicate committed writes, and no routine forced termination. Document traffic patterns, duration, and fault injections. A clean run is evidence—not an unconditional guarantee.

06 / Discuss trade-offsBoundaries & alternatives

Know what each control buys.

Control / PatternBenefitTrade-off
Option 1CDN-managed certs remove operational burden but don't synchronize private keys across two different CDN vendors.—
Option 2Purchasing a 1-year commercial DigiCert backup cert stored in Vault for break-glass use.—

Review questions

Failure scenario 1

Misconfigured CAA DNS records (`0 issue "letsencrypt.org"`) blocking the backup CA from issuing.

Failure scenario 2

Rotating the CDN client cert without keeping the old CA in the origin truststore during propagation.

Alternatives considered

  • Cloudflare Authenticated Origin Pulls with 10-year origin certs + WAF IP allowlisting.
