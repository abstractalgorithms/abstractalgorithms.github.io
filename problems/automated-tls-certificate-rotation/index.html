01
STAGE 01 · WHY IT MATTERSL4 · FUNDAMENTALS

Why TLS expiry causes total silent outages.

Modern web architectures terminate public TLS at CDN PoPs (120+ edge locations) and route over separate connections to origin ALBs. When a 90-day certificate expires at the edge, browsers abort during the TLS handshake before any HTTP request reaches your servers—so internal VPC probes and origin metrics look 100% healthy while every customer is locked out.

02
STAGE 02 · IMPACTL5 · APPLIED DESIGN

Blind spots in origin-only monitoring and silent ACME failures.

Three gaps combined to cause a total outage across 45 SAN/wildcard domains:

  1. Origin-Only Probing: Internal monitors hit origin.internal or used insecureSkipVerify: true, never testing the public CDN edge chain.
  2. Silent DNS-01 IAM Drift: Revoking route53:ChangeResourceRecordSets broke ACME renewal 21 days earlier with no alert.
  3. No Backup CA: Single-CA reliance leaves no fast (< 5 min) recovery path during CA rate-limits or outages.
Edge vs. Origin Blind Spot

Expired Edge Cert vs. Green Internal Probes

Internal VPC probes bypass the CDN edge; only external strict-TLS probes catch edge cert expiry.

03
STAGE 03 · NAIVE SOLUTIONL5 · APPLIED DESIGN

Naive fixes (and why they still break).

Relying on calendar reminders, curl -k scripts, or a single ACME cron job fails in production:

  • Calendar / Manual Renewal: Breaks across 45 domains and human handoffs.
  • insecureSkipVerify: true: Masks expired leaf certs, missing intermediate CAs, and 526 Invalid SSL origin-to-CDN mTLS failures.
  • Expiry-Only Alerting: Alerting only at <= 7 days leaves too little time if a DNS-01 IAM bug or CA rate-limit blocks issuance.
04
STAGE 04 · ENTERPRISE SOLUTIONL6 · SCALE & TRADE-OFFS

Enterprise solution: 33% Renewal Buffer, Edge Blackbox Probes & Dual-CA.

Implement a closed-loop automated TLS pipeline:

  • Early ACME Renewal: Renew 90-day certs at 60 days (renewBefore: 720h), giving a 30-day runway before expiry.
  • Pipeline & Edge Observability: Alert immediately (P2) on certmanager_certificate_ready_status == 0 or failed renewal attempts, and run external blackbox_exporter probes (45 domains × 3 regions × 1/min = 2.25 handshakes/sec) with insecure_skip_verify: false checking both public edge and origin-facing TLS (<= 21d warn, <= 7d page).
  • Hot-Swappable Dual-CA: Pre-authorize both Let's Encrypt and Google Trust Services / ZeroSSL in DNS CAA records so failover completes in < 5 min without dropping TLS 1.3 sessions.
Zero-Touch TLS Lifecycle

90-Day Cert Renewal, Verification & Dual-CA Failover

Renewing at 60 days with dual-CA CAA records provides a 30-day safety buffer and <5-minute failover.

# Prometheus blackbox_exporter strict edge TLS module
modules:
  http_2xx_strict_tls:
    prober: http
    timeout: 5s
    http:
      tls_config:
        insecure_skip_verify: false
# Alert rules:
# 1) probe_ssl_earliest_cert_expiry - time() < 86400 * 21  -> P2 Warning
# 2) probe_ssl_earliest_cert_expiry - time() < 86400 * 7   -> P1 Page
# 3) certmanager_certificate_ready_status == 0             -> P2 Renewal Broken
05
STAGE 05 · SYSTEM DESIGN APPLICATIONSL7 · STAFF / PRINCIPAL

Where automated TLS lifecycles are used.

Automated short-lived certificate rotation underpins both public edge security and internal zero-trust meshes:

  • Multi-CDN & Edge Gateways: Cloudflare, Fastly, and AWS CloudFront automate 90-day ACME renewals with CT-log monitoring.
  • Kubernetes Service Meshes (SPIFFE/Istio): Rotate workload mTLS SVIDs every few hours automatically via cert-manager and Envoy SDS.
