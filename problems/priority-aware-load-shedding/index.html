The idea to keep with you

01
STAGE 01 · WHY IT MATTERSL4 · FUNDAMENTALS

Why priority-blind load shedding drops revenue-critical traffic.

When a mobile push notification spikes /v1/telemetry/events from 2,000 to 35,000 RPS against a 20,000 RPS fleet (20 pods, 200 threads/pod), every endpoint shares the same ingress and worker pools. Without criticality classification, a $500 /v1/checkout/confirm request competes 1:1 for threads with replaceable analytics pings.

02
STAGE 02 · IMPACTL5 · APPLIED DESIGN

How shared queues and global rate limits cause 42% checkout failure.

Under 15x telemetry overload, priority-blind defenses fail in two ways:

  1. Indiscriminate 503 Drops: Telemetry consumes ~90% of worker threads, dropping 42% of /v1/checkout/confirm (500 RPS) and /v1/auth/token (1,500 RPS).
  2. Large FIFO Queue Timeouts: Tomcat's default acceptCount=100 queues requests for seconds; by the time a checkout request reaches a thread, the client has already timed out.
Shared Pool Collapse vs. Tiered Shedding

35k RPS Telemetry Flood vs. Priority Admission

Shedding Tier-3 telemetry at the Envoy edge in <1 ms preserves 99.99% availability for Tier-0 checkout and auth.

03
STAGE 03 · NAIVE SOLUTIONL5 · APPLIED DESIGN

Why static global RPS caps and large FIFO queues break.

Static global rate limits either reject legitimate telemetry when the cluster has spare off-peak capacity, or still allow Tier-3 bursts to exhaust the shared cap before Tier-0 arrives. Similarly, raising Tomcat acceptCount or thread counts just adds queueing delay and context-switching overhead.

04
STAGE 04 · ENTERPRISE SOLUTIONL6 · SCALE & TRADE-OFFS

Enterprise solution: Criticality Tiers, AIMD Concurrency, and Bulkheads.

Combine edge classification, adaptive concurrency, and pool isolation:

  • 4 Criticality Tiers at Ingress: Tag routes at Envoy with X-Priority-Tier: CRITICAL_PLUS (Tier 0: /checkout, /auth), CRITICAL (Tier 1), SHEDDABLE_PLUS (Tier 2), and SHEDDABLE (Tier 3: /telemetry).
  • Adaptive Concurrency (AIMD / Gradient): Measure p95 RTT vs. baseline min_rtt rather than static RPS; when concurrency approaches saturation, shed Tier 3 first (429 + Retry-After), then Tier 2.
  • LIFO Short Queues + Thread Bulkheads: Reserve dedicated connection/thread pools for Tier 0 and process short burst queues LIFO so fresh requests succeed before deadlines expire.
Priority Admission Pipeline

Edge Classification, AIMD Limiter, and Tier-0 Bulkhead

1.Criticality Tagging: Assign Tier-0 to /checkout and /auth at the gateway; tag /telemetry as Tier-3 SHEDDABLE.

2.Adaptive Concurrency: Envoy gradient controller shrinks concurrency limit as p95 RTT rises above min_rtt.

3.Fast-Fail <1ms: Shed Tier-3 at the edge with HTTP 429 + Retry-After before touching backend threads or DB.

Priority-aware shedding uses 100% of spare capacity during normal traffic and drops only low-priority tiers under overload.

# Envoy Adaptive Concurrency + Route Header Tagging
http_filters:
  - name: envoy.filters.http.adaptive_concurrency
    typed_config:
      "@type": type.googleapis.com/envoy.extensions.filters.http.adaptive_concurrency.v3.AdaptiveConcurrency
      gradient_controller_config:
        sample_aggregate_percentile:
          value: 95
        concurrency_limit_params:
          max_concurrency_limit: 4000
        min_rtt_calc_params:
          interval: 60s
05
STAGE 05 · SYSTEM DESIGN APPLICATIONSL7 · STAFF / PRINCIPAL

Where priority-aware load shedding protects production SLAs.

Criticality-tiered admission control is a core pattern in high-scale gateways and storage engines:

  • API Gateways & BFFs: Protect login, checkout, and payment webhooks during bot or push-notification storms.
  • Multi-Tenant SaaS Backends: Shed background exports and analytics before interactive UI queries.
  • Distributed Queues & Microservices: Propagate priority headers so downstream databases also shed low-priority batch work.
