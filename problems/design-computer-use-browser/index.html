The idea to keep with you

If latency budgets leave no room for synchronous retries, pre-warm Firecracker memory snapshots with Chromium booted so tenant sessions attach in < 150 ms while keeping strict per-session KVM isolation.

TL;DR30-second simplified summary
▾

Booting a fresh Linux VM and Chromium binary cold takes 2–4 seconds, blowing the < 150 ms interactive allocation budget. Maintaining a Pre-Warmed Firecracker Snapshot Pool restores identical clean Chromium memory images in < 125 ms, binding each session via AF_VSOCK to a Temporal worker.

Each step compresses screenshots via perceptual-hash delta checks (skipping redundant VLM calls when the screen hasn't changed), streams live WebRTC/VNC frames so users can take over CAPTCHAs or logins, and routes all outbound browser traffic through an egress proxy blocking RFC-1918/metadata IPs.

def allocate_warm_sandbox(pool, tenant_id: str, session_id: str) -> dict:
    if not tenant_id or not session_id:
        raise ValueError('tenant_id and session_id are required')
    vm = pool.claim_warm_snapshot(timeout_ms=150)
    if vm is None:
        raise TimeoutError('Warm microVM pool exhausted; shed or queue session')
    vm.attach_egress_policy(tenant_id=tenant_id, block_rfc1918=True)
    return {'vm_id': vm.id, 'vsock_port': vm.vsock_port}
STAGE 03 · IMPLEMENTATION

Core Control-Plane Logic

1.Bounded Claim Timeout: Wait at most 150 ms for a warm snapshot before triggering cold-boot fallback and pool scaling.

2.Tenant Tagging: Bind tenant_id and session_id to the microVM TAP interface for egress auditing.

3.Clean Teardown: Register an automatic lease TTL so orphaned sessions reclaim RAM within 60s of disconnect.

Warm-snapshot claiming with a 150 ms timeout, tenant TAP tagging, and lease-based cleanup keeps allocation deterministic.
