Consistent Hashing & Virtual Nodes
Consistent hashing assigns data keys to servers in a way that limits how many keys move when servers are added or removed. This helps avoid widespread cache misses and sudden load on databases.
Database Sharding & Range Partitioning
Horizontally partitioning a dataset across independent database nodes by a shard key—using either contiguous key ranges or consistent hashing—to scale write throughput and storage beyond a single primary's CPU, IOPS, and memory ceiling.
Consistency & Consensus Replication (Raft / Paxos)
Fault-tolerant replication protocols (Raft, Multi-Paxos, Quorum) that keep distributed state consistent across node crashes and network partitions using majority quorums (2f+1) and monotonic term numbers.

STAGE 02 · IMPACTL5 · APPLIED DESIGN

Rebalancing storms, split quorums, and tombstone resurrection.

Why this matters: The problem: see what breaks without Rebalancing storms, split quorums, and tombstone resurrection under real concurrency or scale.

Naive distributed KV designs break under real cluster churn:

  1. Modulo Hashing (hash(key) % N): Adding 1 node reshuffles ~90% of keys across the cluster, saturating WAN/LAN bandwidth.
  2. Split Quorum Outages: Requiring strict W=2, R=2, N=3 during a 2-node partition stalls writes completely unless sloppy quorum + hinted handoff is supported.
  3. Celebrity Key Hotspots & Tombstones: Skewed keys overload one token range, and un-repaired deletes can resurrect during read-repair.

04
STAGE 04 · ENTERPRISE SOLUTIONL6 · SCALE & TRADE-OFFS

Enterprise solution: Consistent Hashing + Tunable Quorum + LSM Storage.

Why this matters: Operational control: configure bounds, failure handling, and safe production defaults.

Combine four orthogonal distributed primitives:

  • Consistent Hashing + Vnodes: Maps keys and nodes onto [0, 2^32-1] with 150-256 virtual nodes per physical server, keeping node-join movement at 1/N.
  • Tunable Quorum (R + W > N): Coordinators fan out to N=3 replicas; W=2, R=2 guarantees quorum overlap (strong reads), while W=1, R=1 favors latency. Sloppy quorum + hinted handoff absorbs transient outages.
  • Gossip + Merkle Trees: Decentralized Gossip detects node failures without a central SPOF; read-repair and Merkle-tree anti-entropy sync divergent replicas.
  • LSM-Tree Local Engine: WAL + 128 MB MemTable + SSTables convert 50k random writes/sec into sequential NVMe appends.
Tunable Quorum Path

Coordinator Quorum (R + W > N) & Hinted Handoff

Any R + W > N configuration guarantees at least one node in the read quorum holds the latest write.

export interface QuorumConfig {
  N: number; // Total replicas
  W: number; // Write quorum
  R: number; // Read quorum
}

export function evaluateQuorum({ N, W, R }: QuorumConfig) {
  const strong = R + W > N;
  return {
    isStronglyConsistent: strong,
    model: strong
      ? `Strong Consistency: R(${R}) + W(${W}) > N(${N}) guarantees quorum overlap.`
      : `Eventual Consistency: R(${R}) + W(${W}) <= N(${N}) prioritizes availability/latency.`
  };
}
