01 / UnderstandFailure & constraints

Clarify what is failing.

With a single monitor, `notify()` can wake a thread of the same role (e.g., a consumer wakes another sleeping consumer when the queue is empty), leaving all producers asleep forever.

Design objective

Trace: Queue is full; P1 and P2 sleep. C1 takes 1 item and calls `notify()`, waking P1. Before P1 runs, P3 steals the slot and fills it. C2 takes 1 item? No, C2 was also sleeping—if P1 calls `notify()` it might wake P2 instead of C2.

Requirements

  • Enforce strict capacity bound `N` (`put` blocks when full; `take` blocks when empty) to apply backpressure to producers.
  • Support multiple concurrent producers and consumers with strict FIFO ordering and zero missed signals or spurious-wakeup bugs.
  • Support timed `offer(item, timeout)` and `poll(timeout)` returning `false`/`null` cleanly on deadline expiration.
  • Support `InterruptedException` cleanly without corrupting queue state or leaking condition signals.

Constraints

  • Zero `Thread.sleep` polling / busy-waiting.
  • Fixed array-backed ring buffer (`O(1)` enqueue/dequeue, zero per-node GC allocation on steady-state).
  • Must handle 150,000 ops/sec across 24 concurrent threads.
Known failure modes

Thundering herd wakeups degrading CPU when 16 producers wake simultaneously for 1 free slot.

  1. 01Acquire lock & check while(full): Producer acquires lock; if count == N, awaits on `notFull` inside a `while` loop.
  2. 02Enqueue in O(1) and wrap index: Writes reference into pre-allocated array, increments `count`, wraps `putIdx`.
  3. 03Wake one waiting consumer: Signals `notEmpty` specifically, never waking another producer.
  4. 04Dequeue & null slot for GC: Consumer reads element, nulls `items[takeIdx]` to avoid memory retention, decrements `count`.
  5. 05Release backpressure: Signals `notFull` so a blocked producer can resume.
Separate `notFull` and `notEmpty` Condition queues eliminate missed signals while the ring buffer bounds memory to N slots.

The invariants

  • Validate capacity > 0 and reject null items.
  • Implement enqueue(T x) and dequeue() helpers that wrap indices and signal the opposite Condition.
  • Use awaitNanos(nanos) in a while loop for offer and poll.
03 / Trace the lifecycleKey decisions

Follow the execution path.

Split into `putLock` and `takeLock` with an `AtomicInteger count` (the `LinkedBlockingQueue` design), or use batch-drain (`drainTo`) so consumers acquire the lock once per 64 events.

Step 1

Two-lock splitting lets a producer enqueue while a consumer dequeues in parallel.

Step 2

Alternatively, drainTo(batch, 64) amortizes lock acquisition by 64x with zero extra node allocations.

PYTHON · Lifecycle trace
# Batch draining in Python consumer reduces lock acquisitions by 64x
def drain_batch(queue, max_items: int = 64) -> list:
    batch = [queue.get()]  # block for at least 1 item
    while len(batch) < max_items and not queue.empty():
        try:
            batch.append(queue.get_nowait())
        except Exception:
            break
    return batch
Key trade-off

Two-lock linked queues allocate a Node per item (more GC), whereas drainTo on a ring buffer keeps zero-GC allocation.

04 / ImplementConfiguration & code

Build the safeguards.

Blocking the 16 receiver threads applies natural TCP backpressure (TCP receive window shrinks to 0), slowing upstream senders instead of crashing the JVM—unless receivers share threads with health checks.

1. Reference implementation

JAVA · Solution
import java.util.Objects;
import java.util.concurrent.TimeUnit;
import java.util.concurrent.locks.Condition;
import java.util.concurrent.locks.ReentrantLock;

public class BoundedBlockingQueue<T> {
    private final Object[] items;
    private int putIndex, takeIndex, count;
    private final ReentrantLock lock = new ReentrantLock();
    private final Condition notEmpty = lock.newCondition();
    private final Condition notFull = lock.newCondition();

    public BoundedBlockingQueue(int capacity) {
        if (capacity <= 0) throw new IllegalArgumentException("capacity must be > 0");
        this.items = new Object[capacity];
    }

    public void put(T item) throws InterruptedException {
        Objects.requireNonNull(item);
        lock.lockInterruptibly();
        try {
            while (count == items.length) {
                notFull.await();
            }
            enqueue(item);
        } finally {
            lock.unlock();
        }
    }

    public T take() throws InterruptedException {
        lock.lockInterruptibly();
        try {
            while (count == 0) {
                notEmpty.await();
            }
            return dequeue();
        } finally {
            lock.unlock();
        }
    }

    public boolean offer(T item, long timeout, TimeUnit unit) throws InterruptedException {
        Objects.requireNonNull(item);
        long nanos = unit.toNanos(timeout);
        lock.lockInterruptibly();
        try {
            while (count == items.length) {
                if (nanos <= 0L) return false;
                nanos = notFull.awaitNanos(nanos);
            }
            enqueue(item);
            return true;
        } finally {
            lock.unlock();
        }
    }

    private void enqueue(T item) {
        items[putIndex] = item;
        if (++putIndex == items.length) putIndex = 0;
        count++;
        notEmpty.signal();
    }

    @SuppressWarnings("unchecked")
    private T dequeue() {
        T item = (T) items[takeIndex];
        items[takeIndex] = null; // prevent GC retention
        if (++takeIndex == items.length) takeIndex = 0;
        count--;
        notFull.signal();
        return item;
    }
}

// Fail-fast backpressure with 429 shedding
if (!queue.offer(event, 50, TimeUnit.MILLISECONDS)) {
    metrics.counter("telemetry.dropped.backpressure").increment();
    return Response.status(429).build();

3. Operational controls

Step 1

Keep health-check endpoints (`/healthz`) on a separate thread pool from the 16 blocked receiver threads so Kubernetes doesn't restart the pod.

Step 2

Alternatively, use `offer(item, 50ms)` and return `429 Too Many Requests` / drop-oldest if real-time shedding is preferred over TCP backpressure.

Implementation note

Non-fair `ReentrantLock` maximizes throughput at 150k ops/s; pass `true` if strict thread-wakeup fairness is required.

05 / Verify & observeEvidence & acceptance

Prove the fix works.

Python's GIL serializes bytecode execution across threads, making `queue.Queue(maxsize=N)` effective for I/O-bound workers but CPU-limited; for multi-core Python parallelism, use `multiprocessing.Queue` or `asyncio.Queue(maxsize=N)`.

  • ↗
    Explain that `queue.Queue` internally uses `threading.Lock` + `not_empty`/`not_full` `Condition`s (same pattern).
  • ↗
    For async event loops, use `asyncio.Queue(maxsize=N)` (`await q.put()`, `await q.get()`) so coroutines yield without blocking the event loop.

Acceptance criteria

Target: no scenario-correlated errors in the tested workload, no duplicate committed writes, and no routine forced termination. Document traffic patterns, duration, and fault injections. A clean run is evidence—not an unconditional guarantee.

Review questions

Failure scenario 1

Blocking Netty/Reactor event-loop threads with `put()` freezes all network I/O on that event loop.

Failure scenario 2

Calling `threading` `queue.Queue.get()` inside an `asyncio` coroutine freezes the entire event loop.

Alternatives considered

  • `multiprocessing.Queue` or `concurrent.futures.ProcessPoolExecutor` for CPU-heavy parsing.
