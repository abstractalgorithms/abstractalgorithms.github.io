The idea to keep with you

When traffic spikes expose hidden coupling, consistent-hash by hostname (not full URL) so each host's politeness timer and `robots.txt` cache live on one shard.

TL;DR30-second simplified summary
▾

Crawling 10B pages/month (~4,000 pages/sec) across a distributed fetcher fleet breaks down quickly if URLs are sharded by hash(url)—because 50 workers would hit example.com simultaneously.

Sharding the Mercator Frontier by hash(hostname) guarantees every domain's Back Queue, robots.txt cache (24h TTL), and politeness timer reside on a single owner shard. Fetchers use non-blocking async DNS resolvers (avoiding glibc getaddrinfo thread blocking) and stream parsed pages through a 64-bit SimHash (Hamming distance <= 3) near-duplicate detector before indexing.

Distributed Web Crawler & Mercator URL Frontier
The Mercator URL Frontier separates crawl priority (Front Queues) from per-host politeness (Back Queues) so high-priority domains are crawled fast without DDoSing any single origin server.
Consistent Hashing & Virtual Nodes
Consistent hashing assigns data keys to servers in a way that limits how many keys move when servers are added or removed. This helps avoid widespread cache misses and sudden load on databases.

Crawler Trap & Robots Guard.

Why this matters: Reject infinite URL traps and disallowed paths before enqueueing discovered links.

from urllib.parse import urlparse

def is_safe_to_enqueue(url: str, max_depth: int = 8, max_len: int = 512) -> bool:
    if not url or len(url) > max_len:
        return False
    parsed = urlparse(url)
    if parsed.scheme not in ('http', 'https') or not parsed.netloc:
        return False
    segments = [s for s in parsed.path.split('/') if s]
    if len(segments) > max_depth or len(set(segments)) < len(segments) - 2:
        return False  # Reject repeating path-loop traps (/a/b/a/b/a/b)
    return True
