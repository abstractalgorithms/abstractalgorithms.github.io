Active-Active Multi-Master
Split-Brain Recovery.

When a WAN partition separates two active-active relational primaries (us-east and eu-west) accepting concurrent writes to the same rows, naive Last-Write-Wins (LWW) wall-clock reconciliation silently overwrites valid transactions upon reconnection.

01 / UnderstandFailure & constraints

Clarify what is failing.

Wall clocks across regions drift by tens or hundreds of milliseconds under NTP, so a causally older write in a fast-clock region receives a higher timestamp and overwrites a newer write in a slower-clock region.

Design objective

Observe that NTP only guarantees ~10-250ms accuracy over WAN, not strict real-time ordering.

Requirements

  • Detect 100% of concurrent conflicting writes across partitioned regions without relying on synchronized NTP wall clocks.
  • Preserve additive/counter mutations (e.g., balance debits/credits, usage quotas) without lost-update overwrites.
  • Quarantine and surface true semantic conflicts (e.g., concurrent status transitions) for deterministic resolution rather than silent overwrite.
  • Support automated region-affinity routing during normal operation to minimize cross-region write conflicts (< 0.1%).

Constraints

  • Cross-region WAN RTT is 85ms; local writes must commit in < 15ms p99 (cannot do synchronous 2PC across the Atlantic on every write).
  • Clock skew between `us-east-1` and `eu-west-1` can reach 250ms under NTP degradation.
  • Schema and application logic must be expressible in PostgreSQL SQL and Java/Python.
Known failure modes

Silent data loss of upgrades, payments, and revocations.

  2. 02Detect Concurrent Modification: Applier sees target row's current hlc (108) != incoming base_hlc (100), proving a concurrent split-brain write.
  3. 03Commutative Ledger Merge: For balance/quota tables, append-only delta rows merge commutatively with zero lost updates.
  4. 04Quarantine Semantic Conflicts: For non-commutative state (e.g. plan tier), both versions are logged to replication_conflicts instead of silent overwrite.
  5. 05Loop-Free Convergence: Resolved state propagates once without triggering an infinite replication ping-pong.
Comparing `incoming.base_hlc` against `current_row.hlc` detects 100% of concurrent writes, routing deltas to CRDT merge and state conflicts to quarantine.

The invariants

  • Implement HLC.now() and HLC.update(remote_hlc) to preserve happens-before ordering.
  • Send (base_hlc, new_hlc, payload) in every replication event.
  • Execute conditional UPDATE ... WHERE id = %s AND hlc_ts = %s; if rowcount == 0, insert into replication_conflicts.
03 / Trace the lifecycleKey decisions

Follow the execution path.

Replace mutable `balance` updates with an append-only `balance_ledger` table keyed by `(origin_region, tx_id)` so all regional deltas merge commutatively.

Step 1

Store every credit/debit as an immutable INSERT with delta_cents.

Step 2

Replicate INSERTs bi-directionally with ON CONFLICT (origin_region, tx_id) DO NOTHING.

Step 3

Compute current balance via a periodic materialized rollup + recent deltas.

SQL · Lifecycle trace
CREATE TABLE balance_ledger (
    origin_region SMALLINT NOT NULL,
    tx_id         UUID NOT NULL,
    account_id    BIGINT NOT NULL,
    delta_cents   BIGINT NOT NULL,
    hlc_ts        BIGINT NOT NULL,
    PRIMARY KEY (origin_region, tx_id)
);
-- Concurrent US (-500) and EU (+1000) both survive merge:
-- SUM(delta_cents) converges identically in both regions.
Key trade-off

Eliminates lost-update conflicts completely, though overdrafts during a partition require async reconciliation or credit limits.

04 / ImplementConfiguration & code

Build the safeguards.

Tag every replicated transaction with `origin_region` (or PostgreSQL replication origin session state) and configure the CDC publisher to stream only locally originated changes.

1. Reference implementation

PYTHON · Solution
import time

class HybridLogicalClock:
    def __init__(self):
        self.pt = int(time.time() * 1000)
        self.lc = 0

    def now(self) -> int:
        phys = int(time.time() * 1000)
        if phys > self.pt:
            self.pt, self.lc = phys, 0
        else:
            self.lc += 1
        return (self.pt << 16) | (self.lc & 0xFFFF)

    def receive(self, remote_hlc: int) -> int:
        r_pt, r_lc = remote_hlc >> 16, remote_hlc & 0xFFFF
        phys = int(time.time() * 1000)
        if phys > self.pt and phys > r_pt:
            self.pt, self.lc = phys, 0
        elif self.pt == r_pt:
            self.lc = max(self.lc, r_lc) + 1
        elif r_pt > self.pt:
            self.pt, self.lc = r_pt, r_lc + 1
        else:
            self.lc += 1
        return (self.pt << 16) | (self.lc & 0xFFFF)

2. Harden for scale

Tag every replicated transaction with `origin_region` (or PostgreSQL replication origin session state) and configure the CDC publisher to stream only locally originated changes.

SQL · Scale hardening
-- PostgreSQL applier marks incoming changes with remote origin
SELECT pg_replication_origin_session_setup('origin_eu_west');
-- Only local writes (origin = NULL) are published back to EU-West

3. Operational controls

Step 1

Set `pg_replication_origin_session_setup('eu_origin')` in the applier connection.

Step 2

Configure logical replication / Debezium to ignore transactions with a non-local `origin_id`.

Step 3

Run the deterministic conflict resolver in exactly one designated tie-breaker region (e.g., `us-east-1`).

Implementation note

Requires adding `hlc_ts` and `origin_region` columns to replicated tables and tracking `base_hlc` in CDC events.

05 / Verify & observeEvidence & acceptance

Prove the fix works.

Abandon async multi-master when strict global uniqueness or zero-overdraft invariants cannot tolerate 85ms partitions, and instead use single-writer per shard/tenant or global Raft (CockroachDB/Spanner).

  • ↗
    Measure true cross-region conflict rate and business cost of post-partition overdrafts.
  • ↗
    If strict serializability is mandatory, shard by `tenant_id` with a single authoritative Raft leaseholder per shard.
  • ↗
    Keep read replicas local for `< 5ms` reads while routing writes to the tenant's leaseholder.

Acceptance criteria

Target: no scenario-correlated errors in the tested workload, no duplicate committed writes, and no routine forced termination. Document traffic patterns, duration, and fault injections. A clean run is evidence—not an unconditional guarantee.

Review questions

Failure scenario 1

Forgetting to set the replication origin in an admin/backfill script triggers a feedback storm across the WAN.

Failure scenario 2

Misconfigured GeoDNS routing a tenant's traffic to the wrong region adds 85ms latency per hop.

Alternatives considered

  • Multi-region CockroachDB with `REGIONAL BY ROW` locality.
