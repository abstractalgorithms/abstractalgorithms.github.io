Sliding Window Maximum with
a Monotonic Deque.

Naive O(N*k) scans or O(N log k) max-heaps with lazy deletion cause GC pressure and p99 latency spikes on 500k events/sec streams; a monotonic decreasing deque computes exact sliding-window maxima in strict O(N) time and O(k) space.

01 / CONTRACT & SCOPE3 MIN

Define the problem & constraints.

A lazy-deletion heap never pops expired smaller items until they reach the root, growing to O(N); storing indices lets the deque detect window expiry in O(1).

SAY THIS

Store indices in a monotonic decreasing deque, evicting expired front indices and smaller back indices so every element is pushed and popped at most once.

Requirements

  • Compute the exact maximum over a sliding window of size `k` in `O(1)` amortized time per event (`O(N)` total).
  • Bound memory strictly to `<= O(k)` active elements with zero stale-node accumulation.
  • Support both count-based windows (`k` samples) and time-based windows (`W` milliseconds).
  • Handle duplicate maximum values correctly without prematurely evicting the active max.

Constraints

  • Stream rate is 500,000 events/sec (2 microseconds average budget per event).
  • Window size k can be up to 100,000.
  • Implementation must be in Python or Java.

02 / ALGORITHMIC APPROACH5 MIN

Core pattern & invariants.

Use `collections.deque` storing `(index_or_ts, value)` with `popleft()` for window expiry and `pop()` for monotonic dominance.

Step 1Evict expired front elements (`while` loop for time-based, `if` for count-based).
↓
Step 2Pop back elements `<= val` to preserve strict decreasing order.
↓
Step 3Append `(key, val)` and return `dq[0][1]`.

The invariants

  • `<=` minimizes memory on flat plateaus; use `<` only if you specifically need the *oldest* index of a tied maximum.

PYTHON / sliding-window-maximum-monotonic-deque.py
from collections import deque

class SlidingWindowMax:
    def __init__(self, window_size: int) -> None:
        self.k = window_size
        self.dq: deque[tuple[int, float]] = deque()
        self.idx = 0

    def push_count(self, val: float) -> float:
        if self.dq and self.dq[0][0] <= self.idx - self.k:
            self.dq.popleft()
        while self.dq and self.dq[-1][1] <= val:
            self.dq.pop()
        self.dq.append((self.idx, val))
        self.idx += 1
        return self.dq[0][1]

    def push_time(self, ts_ms: int, val: float) -> float:
        cutoff = ts_ms - self.k
        while self.dq and self.dq[0][0] <= cutoff:
            self.dq.popleft()
        while self.dq and self.dq[-1][1] <= val:
            self.dq.pop()
        self.dq.append((ts_ms, val))
        return self.dq[0][1]
04 / EDGE CASES & LIMITS4 MIN

Complexity & boundary traps.

Pre-aggregate incoming events into fixed-width time buckets (e.g., 10 ms tumbling buckets) and run the monotonic deque over those 500 buckets instead of raw events.

Unbounded raw-event deque OOMing during DDoS or retry storms.

05 / TRADE-OFFS & FOLLOW-UPS5 MIN

Alternatives & extensions.

Using `<=` evicts older equal maxima immediately because the newer identical value will stay in the window longer—keeping deque size smaller.

Run one local monotonic deque per partition, emit each partition's `(bucket_ts, local_max)` to an aggregator, and take `max` across the 16 partition maxima.
