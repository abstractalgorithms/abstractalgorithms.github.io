STAGE 02 · IMPACTL5 · APPLIED DESIGN

FIFO thrashing, starvation, and global-lock bottlenecks.

Why this matters: The problem: see what breaks without FIFO thrashing, starvation, and global-lock bottlenecks under real concurrency or scale.

Naive elevator controllers fail under peak lobby rush:

  1. FIFO Yo-Yo Thrashing: Serving requests strictly in arrival order (5 -> 48 -> 7 -> 42) wastes travel time and starves intermediate floors.
  2. Infinite Direction Starvation: Continuously inserting new UP requests above can starve DOWN passengers unless the car commits to its current sweep.
  3. Global Lock Contention: Locking all 6 cars behind one mutex blocks cabin button presses while another car's door opens.

Naive Solution
Use a single unpartitioned path with unbounded retries and synchronous global coordination.
Why It Fails
Global coordination serializes throughput under load, while unbounded retries amplify transient stalls into full outages.
Alternatives
Compare synchronous strict-consistency paths against bounded asynchronous replication, local caching, or partitioned ownership.
Engineering Decision
If latency budgets leave no room for synchronous retries, separate external hall calls from internal car requests, schedule each car's stops with two directional heaps (min-heap UP, max-heap DOWN) under a per-elevator lock, and inject DispatchStrategy.
Trade-Offs
Gains predictable p99 latency and fault isolation in exchange for explicit bounding, observability, and slightly higher implementation complexity.

STAGE 04 · ENTERPRISE SOLUTIONL6 · SCALE & TRADE-OFFS

Enterprise solution: Dual Directional Heaps + Strategy Pattern.

Why this matters: Operational control: configure bounds, failure handling, and safe production defaults.

Structure the system around three clean abstractions:

  • ElevatorCar (Per-Car Lock + Dual Heaps): Maintains upStops (min-heap) and downStops (max-heap) + currentWeightKg / maxCapacityKg guarded by its own ReentrantLock (LOOK algorithm reverses only when the active directional heap empties).
  • DispatchStrategy Interface: selectElevator(cars, HallRequest) scores eligible (!= MAINTENANCE, below capacity) cars—swappable between NearestDirectionalStrategy and LoadBalancedStrategy.
  • ElevatorController: Routes external HallRequest(floor, dir) through DispatchStrategy and delegates internal CabinRequest(floor) directly to the car.
Request Dispatch Flow

HallRequest -> DispatchStrategy -> Per-Car LOOK Heaps

Pluggable DispatchStrategy picks the best eligible car while per-car locks isolate concurrent stop insertions.

import heapq, threading
from enum import Enum

class Direction(Enum):
    UP = 1; DOWN = -1; IDLE = 0; MAINTENANCE = 99

class ElevatorCar:
    def __init__(self, car_id: int, max_load: int = 800):
        self.car_id, self.floor, self.dir = car_id, 1, Direction.IDLE
        self.max_load, self.load = max_load, 0
        self.up_heap: list[int] = []    # min-heap
        self.down_heap: list[int] = []  # max-heap (store -floor)
        self._seen: set[int] = set()
        self._lock = threading.Lock()

    def add_stop(self, target: int) -> None:
        with self._lock:
            if self.dir == Direction.MAINTENANCE or target in self._seen:
                return
            self._seen.add(target)
            if target >= self.floor:
                heapq.heappush(self.up_heap, target)
            else:
                heapq.heappush(self.down_heap, -target)
