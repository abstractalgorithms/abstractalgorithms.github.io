Synchronous Scoring & Async Feedback Topology.

Think of Synchronous Scoring & Async Feedback Topology as the intuition layer for Design a Real-Time Financial Fraud Detection System (<30ms SLA): Separate the <30ms decision path from durable Kafka state and analyst feedback.

The Payment Gateway calls the Fraud Decision Service via gRPC while simultaneously publishing the event to Kafka. Flink maintains RocksDB velocity state, Triton scores the transaction, and every decision + analyst override loops back to update blacklists and training lakes.

Sync gRPC Scoring & Async Kafka Feedback

1.Dual-Path Consistency: Synchronous RPC updates local state while Kafka provides durable replay.

2.Immutable Audit: Every decision logs exact feature values and rule IDs for regulatory compliance.

Concurrent enrichment and Triton inference deliver <30ms decisions while Kafka persists durable state.

Engineering Decision Framework
Problem
How to implement Design a Real-Time Financial Fraud Detection System (<30ms SLA) without hitting unbounded tail latency, state divergence, or operational fragility.
Naive Solution
Use a single unpartitioned path with unbounded retries and synchronous global coordination.
Why It Fails
Global coordination serializes throughput under load, while unbounded retries amplify transient stalls into full outages.
Alternatives
Compare synchronous strict-consistency paths against bounded asynchronous replication, local caching, or partitioned ownership.
Engineering Decision
When durability and read throughput pull in opposite directions, execute Flink velocity updates, bounded Neo4j/TigerGraph 2-hop queries, and Triton XGBoost+GNN inference in parallel with strict per-hop timeouts.
Trade-Offs
Gains predictable p99 latency and fault isolation in exchange for explicit bounding, observability, and slightly higher implementation complexity.

Idempotent Velocity Updates Under Retries.

Why this matters: Prevent network retries from double-counting transaction velocity.

Think of Idempotent Velocity Updates Under Retries as the intuition layer for Design a Real-Time Financial Fraud Detection System (<30ms SLA): Prevent network retries from double-counting transaction velocity.

If a Payment Gateway retries a timed-out fraud check, naive velocity counters increment twice, falsely triggering a burst block. Keying updates by a 5-minute idempotency cache of tx_id in RocksDB guarantees each authorization is counted exactly once.

Exactly-Once State

tx_id Deduplicated RocksDB Velocity

1.Retry Safety: Deduplicating by tx_id prevents false-positive burst blocks during network blips.

2.5-Min TTL: Short TTLs bound the deduplication index size in RocksDB.

tx_id deduplication inside RocksDB ensures network retries never inflate velocity counters.

Graph Partitioning & Asynchronous Edge Writes.

Why this matters: Keep graph writes from blocking 2-hop read queries at 50K TPS.

Think of Graph Partitioning & Asynchronous Edge Writes as the intuition layer for Design a Real-Time Financial Fraud Detection System (<30ms SLA): Keep graph writes from blocking 2-hop read queries at 50K TPS.

Writing new Card->Device edges synchronously during checkout creates lock contention. We serve 2-hop reads from a read-optimized TigerGraph/Neo4j cluster and stream new edges asynchronously via Kafka with a 500ms micro-batch writer.

Graph Scaling

Read-Optimized Graph Pool + Async Edge Writer

1.500ms Freshness: Async micro-batches balance write throughput with sub-second ring updates.

2.90-Day Pruning: Aging out old device links keeps the hot graph compact in RAM.

Decoupling synchronous 2-hop reads from micro-batched Kafka edge writes eliminates lock contention.

Triton Ensemble Serving (XGBoost + GNN).

Why this matters: Run tabular GBDT and Graph Neural Network models together in <8ms.

Think of Triton Ensemble Serving (XGBoost + GNN) as the intuition layer for Design a Real-Time Financial Fraud Detection System (<30ms SLA): Run tabular GBDT and Graph Neural Network models together in <8ms.

NVIDIA Triton hosts both the FIL (Forest Inference Library) GPU-accelerated XGBoost model and a quantized PyTorch GNN encoder in a single DAG pipeline, eliminating inter-service serialization overhead and hitting <8ms p99.

Unified Inference

Triton FIL XGBoost + GNN Ensemble DAG

1.Zero-Copy DAG: Triton BLS/Ensemble passes tensors in GPU memory without network hops.

2.FIL Speedup: GPU Forest Inference scores 1,000-tree XGBoost ensembles in ~2ms.

Co-hosting XGBoost FIL and GNN models inside Triton eliminates cross-service hops.

Hot-Reloadable DSL Rules & Dynamic Blacklists.

Think of Hot-Reloadable DSL Rules & Dynamic Blacklists as the intuition layer for Design a Real-Time Financial Fraud Detection System (<30ms SLA): Block active attack signatures across 50K TPS in under 15 seconds.

Fraud analysts need to block a compromised BIN or ASN immediately. A Git/UI-backed Rule Compiler pushes signed bytecode rules and Bloom-filtered entity blacklists via etcd/Kafka to all Decision Engine pods, taking effect in <15 seconds without restarts.

Rapid Response

Signed DSL Rule Hot-Reload Pipeline

Dry-run simulation and signed bytecode pushes enable safe sub-15-second rule deployments.
