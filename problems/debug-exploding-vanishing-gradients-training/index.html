01
STAGE 01 · WHY IT MATTERSL4 · FUNDAMENTALS

Why 24-layer Transformers diverge to NaN in FP16.

Mixed-precision training cuts activation memory in half, letting 24-layer Transformers fit on multi-GPU clusters. However, IEEE FP16 only has a 5-bit exponent (max representable value 65,504, min normal 6.1e-5)—so any unscaled attention logit or gradient spike overflows to Inf/NaN and corrupts all weights on the next optimizer step.

02
STAGE 02 · IMPACTL5 · APPLIED DESIGN

Post-LN gradient spikes and wasted GPU cluster hours.

At step 1,200, three numerical failures compound:

  1. Post-LN Residual Amplification: Applying LayerNorm after residual addition causes gradient norms near the output layer to blow up without warmup.
  2. FP16 Overflow & Underflow: Large gradients overflow 65,504 -> NaN, while small gradients underflow to 0 (vanishing updates).
  3. Wasted Compute: Multi-GPU runs crash mid-epoch, burning cluster budget.
Training Step Instability

FP16 Post-LN Overflow vs. Pre-LN + GradScaler + Clipping

Pre-LN bounds residual variance while unscale + norm clipping + dynamic GradScaler prevents NaN weight updates.

03
STAGE 03 · NAIVE SOLUTIONL5 · APPLIED DESIGN

Naive fixes (dropping to FP32 or slashing learning rate).

Switching back to full FP32 doubles activation/gradient memory and breaks the cluster's fixed memory budget. Meanwhile, slashing the learning rate 10x without Pre-LN or clipping stalls convergence and underfits.

04
STAGE 04 · ENTERPRISE SOLUTIONL6 · SCALE & TRADE-OFFS

Enterprise solution: Pre-LN + Warmup + Norm Clipping + BF16/GradScaler.

Stabilize the 24-layer Transformer within the same memory footprint:

  • Pre-LayerNorm (x + Attn(LN(x))): Keeps an unscaled identity residual path from input to output, bounding gradient variance.
  • BF16 or Dynamic GradScaler: Prefer BF16 (same 8-bit exponent as FP32, max 3.4e38, no loss scaling needed); if hardware requires FP16, wrap backward in torch.cuda.amp.GradScaler().
  • Unscale -> Clip (1.0) -> Step: Always call scaler.unscale_(optimizer) before clip_grad_norm_(params, 1.0) so clipping operates on true gradient magnitudes, plus linear LR warmup (1-5% of steps) into cosine decay.
Stabilized Training Loop

Pre-LN Residual + Mixed-Precision Guardrails

Pre-LN, dynamic loss scaling, gradient norm clipping, and LR warmup eliminate NaN spikes without losing speed.

scaler = torch.amp.GradScaler("cuda", enabled=use_fp16)
for step, batch in enumerate(loader):
    optimizer.zero_grad(set_to_none=True)
    with torch.amp.autocast("cuda", dtype=torch.bfloat16 if use_bf16 else torch.float16):
        loss = model(batch)
    scaler.scale(loss).backward()
    scaler.unscale_(optimizer)  # Must unscale BEFORE clipping!
    torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
    scaler.step(optimizer)      # Skips step automatically if Inf/NaN
    scaler.update()
    scheduler.step()
05
STAGE 05 · SYSTEM DESIGN APPLICATIONSL7 · STAFF / PRINCIPAL

Where gradient stability safeguards are used.

Every large-scale LLM and vision foundation-model training stack uses these exact primitives:

  • LLM Pre-Training (LLaMA / GPT / Megatron-LM): Combines Pre-RMSNorm, BF16 mixed precision, 1.0 global norm clipping, and QK-Norm to train 70B+ models.
  • Distributed FSDP / DeepSpeed: Aggregates global L2 gradient norms across all GPUs before clipping and stepping.
