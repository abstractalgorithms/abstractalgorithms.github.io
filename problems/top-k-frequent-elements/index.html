Top K Frequent Elements

Given an integer array nums and an integer k, return the k most frequent elements. The algorithm's time complexity must be better than O(N log N), where N is the array's size.

Scope, Requirements & Constraints

First pass: frequency map takes O(N) time and O(U) space where U is unique elements. Full sort on frequencies is O(U log U). Min-heap of size k is O(N log k). Bucket sort where index represents frequency is O(N) linear time.

Core Functional Requirements

  • ✓Return the k most frequent elements in any order.
  • ✓Time complexity must be strictly better than O(N log N).
  • ✓Handle negative numbers and arrays with all identical elements.
  • ✓k is always valid (1 <= k <= number of unique elements).

Scale & Latency Constraints

  • —1 <= nums.length <= 10^5
  • —-10^4 <= nums[i] <= 10^4
  • —k is in the range [1, the number of unique elements in the array].
  • —It is guaranteed that the answer is unique.

Reference Architecture & System Blueprint

Bucket Sort approach delivers optimal O(N) time complexity.

Hardened Implementation Steps

  1. 1Count occurrences of each number using a HashMap: freqMap[num] = count.
  2. 2Create an array of buckets of size N+1, where bucket[i] holds numbers that appear i times.
  3. 3Populate buckets: iterate through freqMap and append num to bucket[freqMap[num]].
  4. 4Iterate from bucket[N] down to bucket[0], collecting numbers into result array until result.length === k.

Key Decisions & Trade-Off Analysis

Architectural Decisions & Trade-Offs

  • ⚖Streaming input: In a live telemetry stream (e.g., top trending search queries), N is infinite. Bucket sort requires an end boundary. A Min-Heap or Count-Min Sketch operates continuously on unbounded streams.
  • ⚖Memory locality: Bucket sort creates an array of lists, causing memory fragmentation if U is sparse.

Scale Bottlenecks & Operational Hazards

Operational Hazards & Mitigations

  • ⚠Single machine memory exhaustion: 10 billion queries cannot fit in RAM for a full HashMap count.
  • ⚠Distributed MapReduce / Spark: Map step computes local counts per partition; Shuffle partitions by query hash; Reduce aggregates global counts; final stage runs Top-K heap per reducer.
  • ⚠Probabilistic streaming (Heavy Hitters): Use Count-Min Sketch + Min-Heap (Space-Saving algorithm) on each edge node, then merge sketches at the aggregator with bounded error guarantees.

Changed Constraints & System Extension

Follow-up: What if k = 10,000 and queries arrive with timestamps, and we need the Top K queries within the last 15-minute sliding window?

Extension Implementation Steps

  1. 1Divide 15-minute window into 15 one-minute buckets.
  2. 2Compute Top-K sketch per minute bucket.
  3. 3On window shift, drop the oldest bucket and sum counts from the remaining 14 buckets plus active bucket.
  4. 4Query time: merge 15 bucket sketches and extract top K.

Follow-Up Trade-Offs

  • ⚖Bucket granularity: 1-minute buckets give maximum 1-minute lag on eviction at low overhead. 1-second buckets increase precision at 60x memory cost.
