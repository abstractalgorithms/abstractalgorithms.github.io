01 / UNDERSTAND3 MIN

Clarify what counts.

We need the most frequent values, not the largest values. A full sort is unnecessary because only k winners matter.

SAY THIS

I’ll count occurrences first. Since every frequency is between 1 and N, I can group values by frequency and scan downward without comparison sorting.

METHOD CONTRACT
topKFrequent(nums: number[], k: number): number[]

Requirements

  • Return exactly k distinct elements with the highest frequencies.
  • Return elements in any order; no sorting of the output is required.
  • Support negative integers and repeated values.
  • Do not mutate the input array.

Constraints

  • 1 ≤ nums.length ≤ 100,000
  • −10,000 ≤ nums[i] ≤ 10,000
  • 1 ≤ k ≤ U, where U is the number of unique elements.
  • The answer set is guaranteed to be unique.

The unique-answer guarantee means there is no unresolved tie across the kth-place boundary. Ties inside the selected set are fine; output order is arbitrary.

02 / CHOOSE AN APPROACH3 MIN

Turn counts into indices.

A frequency map answers how often each value appears. An array of N + 1 buckets reverses that relationship: bucket[f] contains the values that appear f times.

Frequency mapvalue → occurrence count
↓
Bucket arraycount → list of values
↓
Top-k resultscan N → 1; stop at k

The invariants

  • After counting, the sum of all frequencies equals N.
  • Every distinct value appears in exactly one frequency bucket.
  • Before visiting bucket f, all buckets with greater frequencies have been processed.
  • The result contains only distinct values and never exceeds k entries.

Bucket traversal and pointer-free array operations are linear. The overall O(N) bound assumes average constant-time hash map access; it is not a language-level worst-case guarantee for Map.

04 / IMPLEMENT5 MIN

Three passes. One early return.

Create each populated bucket separately. Append values one at a time so we return exactly k entries without large spread operations or a final slice.

  1. Count occurrences.

    Build Map<number, number> in a single pass over nums.

  2. Group by frequency.

    Allocate N + 1 bucket slots and create lists only for frequencies that occur.

  3. Collect from highest to lowest.

    Visit each bucket in descending frequency order. Return as soon as result.length equals k.

TYPESCRIPT / topKFrequent.ts
export function topKFrequent(nums: number[], k: number): number[] {
  const frequency = new Map<number, number>();

  for (const num of nums) {
    frequency.set(num, (frequency.get(num) ?? 0) + 1);
  }

  const buckets: Array<number[] | undefined> =
    new Array(nums.length + 1);

  for (const [num, count] of frequency) {
    (buckets[count] ??= []).push(num);
  }

  const result: number[] = [];

  for (let count = nums.length; count >= 1; count--) {
    const bucket = buckets[count];
    if (!bucket) continue;

    for (const num of bucket) {
      result.push(num);
      if (result.length === k) return result;
    }
  }

  return result;
}

The final return satisfies TypeScript’s control-flow requirements. With valid k, the function returns from inside the bucket traversal.

05 / VERIFY & ANALYZE4 MIN

Explain why it works.

Descending bucket traversal visits values in nonincreasing frequency order. Therefore, the first k collected values form the required top-k set.

Descending selectionO(N + k)O(k) output
OverallO(N) expectedO(N) auxiliary

06 / DISCUSS TRADE-OFFS2 MIN

Know the alternatives.

Bucket selection is a strong fit for this finite-array problem. Compare alternatives using N for total elements and U for unique values—not interchangeable symbols.

ApproachTimeSpaceTrade-off
Sort unique valuesO(N + U log U) expectedO(U), plus sort workspaceSimple, but can reach O(N log N) when U scales with N.
Size-k min-heapO(N + U log(k + 1)) expectedO(U + k)Compact selection structure, but not uniformly better than O(N log N) when k and U scale with N.
Quickselect on countsO(N + U) expected; O(N + U²) worst caseO(U)Avoids N bucket slots but introduces partition logic and pivot-dependent worst cases.
Frequency bucketsO(N) expectedO(N)Direct selection using the frequency bound; may allocate more slots than needed when U is small.
What if memory is tighter?

Quickselect uses O(U) auxiliary storage for counts and unique values. A size-k heap also requires the O(U) exact count map, even though its selection structure is only O(k).

What if input arrives as a stream?

Clarify whether counts are over all history or a finite window, and whether approximate results are allowed. A size-k heap alone does not provide bounded-memory exact counting for unbounded unique keys. Streaming heavy-hitter methods are a different problem.

What if the answer is not guaranteed to be unique?

Clarify whether any valid top-k set is acceptable or whether a secondary rule, such as smaller value first, is required. The original problem needs no extra tie-breaking rule.

THE 30-SECOND SUMMARY

Frequency cannot exceed the input length. Use that bounded range as bucket indices to select the top k in O(N) expected time and O(N) auxiliary space.
