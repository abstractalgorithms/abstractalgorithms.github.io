Handling Asymmetric Network
Partitions & Split-Brain.

In a 3-node consensus or cluster-membership ring, a one-way or non-transitive link failure between Node A and Node C leaves B able to reach both while A and C cannot reach each other, triggering election storms, dual-leader windows, or split-brain membership eviction.

01 / UnderstandFailure & constraints

Clarify what is failing.

In standard Raft, any follower that misses heartbeats increments its term and broadcasts RequestVote; a peer receiving a higher term must update its term and force the current leader to step down, even if the leader is still connected to a majority.

Design objective

Trace heartbeats from Leader A: B receives them (timer resets), C does not (A<->C dropped).

Requirements

  • Eliminate election livelock and term-inflation storms when A<->C is severed while A<->B and B<->C remain healthy.
  • Guarantee linearizable lease/lock reads and writes with zero dual-leader stale writes during partial partitions.
  • Maintain cluster availability for the connected majority quorum (B + current leader) within <= 1,500ms of link degradation.
  • Prevent an isolated or partitioned former leader from committing stale mutations to downstream PostgreSQL/KV storage.

Constraints

  • Control-plane heartbeat interval is 100ms with a 500ms election timeout; cross-AZ RTT is 0.8ms.
  • All nodes run in 3 availability zones with no shared L2 broadcast domain; BGP/ACL drops can be asymmetric or non-transitive.
  • Downstream storage engines do not natively participate in the Raft consensus group and require explicit fencing.
Known failure modes

100% control-plane unavailability due to continuous term bumps every 500ms.

Enforces monotonic fencing_token

  1. 01Quorum Maintained: Leader A sends AppendEntries every 100ms to B, maintaining a 2/3 majority (A+B) and resetting B's election timer.
  2. 02Non-Disruptive Pre-Vote: C misses A's heartbeats and sends PreVote(6) to B without incrementing its own term.
  3. 03Bridge Rejects Disruption: B received A's heartbeat within election_timeout, so B denies C's PreVote; Term 5 stays intact.
  4. 04Fenced Storage Write: Leader A attaches its (term, log_index) fencing token to downstream lock mutations.
  5. 05Fencing Guard: Any delayed RPC from a deposed leader with token < 5:1042 is rejected by PostgreSQL.
Pre-Vote prevents C from triggering term inflation via bridge node B, while CheckQuorum and fencing tokens protect downstream storage.

The invariants

  • Add last_leader_heartbeat_ms tracking on every follower.
  • Require PreVote to pass before incrementing current_term.
  • Run check_quorum() on the leader every 100ms.
  • Attach (term << 32) | log_index as fencing_token on all downstream DB writes.
03 / Trace the lifecycleKey decisions

Follow the execution path.

ReadIndex guarantees linearizability without hardware clock assumptions at the cost of 1 quorum RTT, whereas Leader Leases serve reads locally in <0.5ms but require bounded clock drift.

Step 1

Evaluate ReadIndex: Leader records commitIndex, sends heartbeat round to confirm quorum, waits until appliedIndex >= commitIndex, and serves read.

Step 2

Evaluate Leader Lease: Leader tracks lease_end = start + election_timeout / max_clock_drift_factor based on majority ACKs.

Step 3

Select ReadIndex for multi-cloud or untrusted NTP environments; select Leader Lease only when PTP/chrony bounds drift < 10ms.

PYTHON · Lifecycle trace
def linearizable_read_index(leader, read_fn):
    read_idx = leader.commit_index
    # Confirm we are still leader via 1 quorum heartbeat round (0.8ms)
    if not leader.confirm_quorum_heartbeat():
        raise NotLeaderError("Lost quorum during ReadIndex check")
    leader.wait_until_applied(read_idx)
    return read_fn()
Key trade-off

ReadIndex adds ~0.8ms p99 latency per read batch but is immune to NTP/VM pause clock skew.

04 / ImplementConfiguration & code

Build the safeguards.

If B pauses for 600ms while A<->C is severed, A loses quorum and steps down via CheckQuorum; once B resumes, B and C can elect a new leader, and fencing tokens block any late RPC from A.

1. Reference implementation

PYTHON · Solution
import time

def handle_pre_vote(node, next_term, last_log_idx, last_log_term):
    now_ms = time.monotonic() * 1000
    # Reject if we recently heard from a valid leader (prevents C disrupting A via B)
    if (now_ms - node.last_leader_heartbeat_ms) < node.min_election_timeout_ms:
        return {"term": node.current_term, "vote_granted": False}
    if next_term <= node.current_term:
        return {"term": node.current_term, "vote_granted": False}
    if not node.is_log_up_to_date(last_log_idx, last_log_term):
        return {"term": node.current_term, "vote_granted": False}
    return {"term": node.current_term, "vote_granted": True}

def check_quorum(leader):
    now_ms = time.monotonic() * 1000
    active_peers = 1 + sum(
        1 for ts in leader.peer_last_ack_ms.values()
        if (now_ms - ts) < leader.election_timeout_ms
    )
    if active_peers < (leader.cluster_size // 2) + 1:
        leader.step_down_to_follower()

    fencing_token = :new_token,
    updated_at = NOW()
WHERE lock_key = :lock_key
  AND fencing_token < :new_token;

3. Operational controls

Step 1

A's `check_quorum()` detects only 1 active node (itself) after 500ms and steps down.

Step 2

B resumes and either grants PreVote to C or starts its own PreVote, electing a new leader in term T+1.

Step 3

Storage rejects any in-flight RPC from A carrying term T < T+1.

Implementation note

Adds 1 RTT to legitimate failovers (~0.8ms intra-region) in exchange for complete immunity to asymmetric term storms.

05 / Verify & observeEvidence & acceptance

Prove the fix works.

Emit an N x N pairwise reachability matrix from every node's heartbeat/SWIM probes to Prometheus and alert whenever `connected_peers < N-1` even while quorum is healthy.

  • ↗
    Export `raft_peer_link_up{src, dst}` (0 or 1) every 1s.
  • ↗
    Alert on `sum(raft_peer_link_up) < N*(N-1)` for > 15s (catches A<->C cut immediately).
  • ↗
    Correlate with `PreVoteDenied` counters to pinpoint which pair is partitioned.
YAML · Verification
# Prometheus alert rule for asymmetric mesh degradation
groups:
  - name: raft_mesh_health
    rules:
      - alert: AsymmetricNetworkPartitionDetected
        expr: raft_peer_link_up == 0 and on(cluster) raft_has_quorum == 1
        for: 15s
        labels:
          severity: page
        annotations:
          summary: "Non-transitive link failure between {{ $labels.src }} and {{ $labels.dst }}"

Acceptance criteria

Target: no scenario-correlated errors in the tested workload, no duplicate committed writes, and no routine forced termination. Document traffic patterns, duration, and fault injections. A clean run is evidence—not an unconditional guarantee.

Theory & Tips and Tricks

Practical heuristics & interview traps

  • 01Interview anchor: Never rely on direct pairwise reachability for cluster health or leadership; combine Raft Pre-Vote + CheckQuorum (or SWIM indirect probing) with monotonic fencing tokens at the storage layer.
  • 02Trade-off tip: ReadIndex adds ~0.8ms p99 latency per read batch but is immune to NTP/VM pause clock skew.
  • 03Watch out for: If fencing_token comparison is omitted in storage, A's delayed write overwrites C's newer lock.
