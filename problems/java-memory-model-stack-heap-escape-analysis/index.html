01 / UnderstandFailure & constraints

Clarify what is failing.

Stack frames store primitive locals and 4-byte compressed object references; heap objects carry a 12-byte header, fields, and 8-byte alignment padding.

Design objective

List stack frame components: Local Variable Array, Operand Stack, Frame Data (return address, constant pool ref).

Requirements

  • Explain the exact contents of a JVM thread stack frame (Local Variable Array, Operand Stack, Frame Data) vs. Heap object layout (12B Compressed OOP header + fields + 8B alignment).
  • Identify why C2 Escape Analysis classifies objects as NoEscape, ArgEscape, or GlobalEscape.
  • Diagnose why adding a 45-bytecode method or polymorphic call broke Scalar Replacement (referencing -XX:MaxInlineSize=35 and -XX:FreqInlineSize=325).
  • Refactor the hot path in Java to eliminate heap allocation and verify via JVM flags / JMH GC profiler.

Constraints

  • Must target HotSpot JVM (JDK 17/21) with default 1 MB thread stacks (-Xss1m) and G1GC.
  • Hot path must sustain 2M ops/sec with < 50 MB/sec allocation rate.
  • All code examples must be valid Java.
Known failure modes

Heaps >= 32 GB disable Compressed OOPs, expanding headers to 16B and references to 8B.

  1. 01Tier-4 C2 Compilation: HotSpot compiles hot bytecode and attempts to inline callees within MaxInlineSize/FreqInlineSize.
  2. 02Scalar Replacement: Object never leaves inlined scope; header is dropped and fields move to registers/stack.
  3. 03Fallback to Heap TLAB: Non-inlined call, megamorphic dispatch, or return/store forces real TLAB allocation.
  4. 04Store Reference on Stack: Local Variable Array stores only the 32-bit compressed pointer to the Eden object.
  5. 05Minor GC Pause: High TLAB churn triggers young-gen evacuation pauses impacting p99 latency.
Scalar Replacement eliminates heap allocation only when C2 can inline the entire object lifecycle and prove NoEscape.

The invariants

  • Replace Optional<Route> with direct null check or primitive routeId (-1 if missing).
  • Guard logger calls with isDebugEnabled() so temporary objects never become ArgEscape.
  • Keep calculateFee() small (< 35 bytecodes) and final so C2 always inlines it.
03 / Trace the lifecycleKey decisions

Follow the execution path.

Prefer Scalar Replacement for small short-lived tuples, ThreadLocal pooling only for large reusable buffers (byte[]), and off-heap MemorySegment for multi-GB caches.

Step 1

Use Scalar Replacement for < 64-byte value objects inside inlinable hot paths.

Step 2

Use ThreadLocal scratch byte[] / ByteBuffer for serialization buffers that cannot be scalar-replaced.

JAVA · Lifecycle trace
private static final ThreadLocal<byte[]> SCRATCH_BUF =

Key trade-off

Scalar Replacement requires zero cleanup and zero ThreadLocal hash lookups.

04 / ImplementConfiguration & code

Build the safeguards.

When a variable merges a newly allocated object with an existing/escaped object at a control-flow Phi node, C2 cannot eliminate the allocation.

1. Reference implementation

JAVA · Solution
public final class FastPaymentRouter {
    private static final int NO_ROUTE = -1;

    public long routeAndPrice(long amountMinor, int regionCode, RouteTable table, boolean debug) {
        // Scalar-replaceable local value if inlined; or even better, direct primitive math
        FeeBreakdown breakdown = computeFee(amountMinor, regionCode);
        int routeId = table.lookupFast(regionCode, breakdown.tier);
        if (routeId == NO_ROUTE) {
            return -1L;
        }
        if (debug) {
            logRoute(routeId, breakdown.total);
        }
        return breakdown.total;
    }

    // < 35 bytecodes, final: guaranteed C2 inline -> FeeBreakdown is NoEscape -> Scalar Replaced (0B)
    private FeeBreakdown computeFee(long amountMinor, int regionCode) {
        long fee = (amountMinor * (regionCode == 1 ? 15L : 25L)) / 10_000L;
        int tier = amountMinor > 100_000L ? 2 : 1;
        return new FeeBreakdown(amountMinor + fee, tier);
    }

    private static final class FeeBreakdown {
        final long total;
        final int tier;
        FeeBreakdown(long total, int tier) { this.total = total; this.tier = tier; }
    }

    private void logRoute(int routeId, long total) { /* cold path */ }
}

2. Harden for scale

When a variable merges a newly allocated object with an existing/escaped object at a control-flow Phi node, C2 cannot eliminate the allocation.

JAVA · Scale hardening
// BAD: Phi node merges new Money (NoEscape) with static ZERO (GlobalEscape) -> forces heap allocation!
// Money m = valid ? new Money(amt, 1) : Money.ZERO;

// GOOD: Compute primitive first; single allocation site or pure primitive path
long finalAmt = valid ? amt : 0L;
Money m = new Money(finalAmt, 1);

3. Operational controls

Step 1

Avoid `Money m = flag ? new Money(a) : ZERO;` where `ZERO` is a static constant.

Step 2

Construct `new Money(...)` unconditionally or compute primitives before constructing.

Implementation note

Returning a small immutable `FeeBreakdown` works with 0B allocation *only* because `computeFee` is private/small and inlined.

05 / Verify & observeEvidence & acceptance

Prove the fix works.

If Escape Analysis proves an object is NoEscape (visible to only one thread), C2 removes all synchronized monitor acquire/release instructions on it.

  • ↗
    Verify `-XX:+EliminateLocks` (enabled by default in HotSpot C2).
  • ↗
    Recognize that `StringBuffer` inside a local method has its lock elided, though `StringBuilder` is still preferred.
JAVA · Verification
public String formatLocal(int id) {
    // StringBuffer is synchronized, but C2 proves sb is NoEscape and elides all locks
    StringBuffer sb = new StringBuffer(32);
    sb.append("id=").append(id);
    return sb.toString();
}

Acceptance criteria

Target: no scenario-correlated errors in the tested workload, no duplicate committed writes, and no routine forced termination. Document traffic patterns, duration, and fault injections. A clean run is evidence—not an unconditional guarantee.

06 / Discuss trade-offsBoundaries & alternatives

Know what each control buys.

Control / PatternBenefitTrade-off
Option 1Scalar Replacement requires zero cleanup and zero ThreadLocal hash lookups.—
Option 2Arrays (`new byte[4096]`) are rarely scalar-replaced if indexed dynamically, making pooling worthwhile for large buffers.—
Option 3Use GraalVM JIT compiler, which supports Partial Escape Analysis (allocating only on the escaping branch).—

Review questions

Failure scenario 1

HotSpot C2's all-or-nothing Escape Analysis allocates on *all* paths if *any* branch escapes.

Failure scenario 2

Returning `sb` or passing it to a non-inlined logger re-enables full monitor locking.

Alternatives considered

  • Always use unsynchronized `StringBuilder` or `ArrayList` for local state instead of relying on JIT lock elision.

Theory & Tips and Tricks

Practical heuristics & interview traps
