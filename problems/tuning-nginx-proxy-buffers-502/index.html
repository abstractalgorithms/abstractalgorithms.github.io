01 / UnderstandFailure & constraints

Clarify what is failing.

Nginx's `proxy_buffer_size` (4 KB default on x86_64) must hold the entire upstream response header; a 9.4 KB `Set-Cookie` overflows it, causing Nginx to abort and emit `502`.

Design objective

Inspect `/var/log/nginx/error.log` for `upstream sent too big header`.

Requirements

  • Eliminate `502 Bad Gateway` and `400 Cookie Too Large` errors immediately.
  • Keep Nginx proxy buffer RAM bounded under 4 GB at 10,000 concurrent connections.
  • Prevent future RBAC claim growth from breaking reverse-proxy or CDN header limits.
  • Maintain sub-2 ms session validation latency on the SSO/API gateway.

Constraints

  • Nginx runs on x86_64 Linux with a 4 KB OS page size (`getconf PAGESIZE` = 4096).
  • External CDN/WAF in front of Nginx enforces a hard 16 KB total request header limit.
  • Existing logged-in users already hold bloated cookies and must be migrated smoothly.
Known failure modes

Wasting time restarting healthy upstream pods when the proxy buffer is the bottleneck.

Separate concerns. Map the flow.

Set `proxy_buffer_size 16k` and `large_client_header_buffers 4 16k` in Nginx, and store full RBAC claims in Redis behind a 64-byte opaque session ID.

The invariants

  • Update nginx.conf with 16k/32k buffer directives and validate with nginx -t.
  • Modify SSO login handler to write claims to Redis and issue an opaque sid cookie.
03 / Trace the lifecycleKey decisions

Follow the execution path.

Browsers enforce a 4,096-byte per-cookie limit and CDNs enforce 16 KB total header limits; only opaque server-side tokens prevent future RBAC growth from breaking clients.

Step 1

Replace Set-Cookie: jwt=<9.4KB> with Set-Cookie: sid=<64B>.

Step 2

Expire the old jwt cookie (Max-Age=0) on next user visit.

PYTHON · Lifecycle trace
sid = secrets.token_urlsafe(32)
await redis.set(f"sess:{sid}", json.dumps(claims), ex=28800)
response.set_cookie("sid", sid, httponly=True, secure=True, samesite="lax")
response.delete_cookie("legacy_jwt")
Key trade-off

Adds 1 Redis lookup (< 1 ms) in exchange for < 128B cookies and instant session revocation.

04 / ImplementConfiguration & code

Build the safeguards.

Once the 128 KB `proxy_buffers` fill, Nginx spills the excess body to disk (`proxy_temp_path`), increasing disk I/O unless `proxy_max_temp_file_size` is tuned.

1. Reference implementation

NGINX · Solution
server {
    large_client_header_buffers 4 16k;
    location / {
        proxy_pass http://sso_backend;
        proxy_buffering on;
        proxy_buffer_size 16k;
        proxy_buffers 8 16k;
        proxy_busy_buffers_size 32k;
    }
}

2. Harden for scale

Once the 128 KB `proxy_buffers` fill, Nginx spills the excess body to disk (`proxy_temp_path`), increasing disk I/O unless `proxy_max_temp_file_size` is tuned.

NGINX · Scale hardening
proxy_max_temp_file_size 64m;
proxy_temp_file_write_size 32k;

3. Operational controls

Step 1

Monitor `nginx_http_upstream_temp_files` or disk I/O.

Step 2

Cap `proxy_max_temp_file_size 64m;` (or `0` to stream directly to fast clients).

Implementation note

Max 144 KB/connection keeps 10,000 connections under 1.44 GB RAM.

05 / Verify & observeEvidence & acceptance

Prove the fix works.

Add an integration test asserting total `Set-Cookie` and response header size stays < 2,048 bytes on login and token refresh endpoints.

PYTHON · Verification
def test_login_cookie_size_budget(client, max_roles_user):
    resp = client.post("/oauth/token", json=max_roles_user)
    cookie_bytes = sum(len(v) for k, v in resp.headers.items() if k.lower() == "set-cookie")
    assert cookie_bytes < 2048, f"Cookie bloat detected: {cookie_bytes} bytes"

Acceptance criteria

Target: no scenario-correlated errors in the tested workload, no duplicate committed writes, and no routine forced termination. Document traffic patterns, duration, and fault injections. A clean run is evidence—not an unconditional guarantee.

Review questions

Failure scenario 1

Setting `proxy_max_temp_file_size 0` forces upstream app workers to stay blocked until slow mobile clients finish downloading.

Failure scenario 2

Testing only with a default admin user that has 1 role instead of a 100-role user.

Alternatives considered

  • Alert in production if `http_response_header_bytes_p99 > 4096`.
