Debugging Kubernetes
CrashLoopBackOff.

Referencing an absent or renamed Secret/ConfigMap in a Pod spec causes kubelet to block startup with CreateContainerConfigError—or CrashLoopBackOff if marked optional—halting rollouts and starving live replicas.

01 / UnderstandFailure & constraints

Clarify what is failing.

CreateContainerConfigError occurs when kubelet cannot mount a non-optional Secret/ConfigMap before starting the container; CrashLoopBackOff occurs when optional: true allows the container to start and crash inside app init. maxUnavailable: 50% allowed K8s to kill 6 healthy pods.

Design objective

Run kubectl get pods and kubectl describe pod to distinguish kubelet config errors from app exit code 1.

Requirements

  • Guarantee zero capacity loss of healthy running pods when a referenced Secret or ConfigMap is missing or malformed.
  • Eliminate silent `optional: true` runtime crashes by failing fast in CI/CD or pre-rollout admission gates.
  • Ensure config/secret updates trigger deterministic, auditable rollouts without stale-pod drift.
  • Automate secret sync readiness verification before Kubernetes Deployment rollout begins.

Constraints

  • Secrets are synced from AWS Secrets Manager via ExternalSecrets Operator (ESO).
  • Cluster runs Kubernetes 1.29 with Helm/ArgoCD GitOps.
  • Zero-downtime rollout SLA: minimum 12 healthy pods must remain available during deploys.
Known failure modes

Pods stuck in CrashLoopBackOff wait up to 5 minutes between retries even after the Secret is fixed.

  1. 01Pre-Rollout Secret Sync: ArgoCD applies ExternalSecret and ConfigMap in SyncWave -1 before touching Deployment.
  2. 02Health Gate Verification: If IAM typo blocks AWS sync, Wave -1 stays Degraded and Deployment v2 never starts.
  3. 03Surge-First Pod Creation: Deployment creates 3 v2 surge pods with optional: false and checksum annotations.
  4. 04Readiness-Gated Cutover: Existing 12 v1 pods remain 100% intact until v2 surge pods pass readinessProbe.
  5. 05Fast Rollback on Failure: If v2 stalls in CrashLoopBackOff, ArgoCD/Argo Rollouts aborts within 180s with 0 capacity loss.
Ordering Secret creation via SyncWaves and enforcing maxUnavailable: 0 ensures missing configs never evict healthy production pods.

The invariants

  • Annotate ExternalSecret with sync-wave: '-1'.
  • Set strategy.rollingUpdate.maxUnavailable: 0 and maxSurge: 25%.
  • Set optional: false on both secretRef and configMapRef.
03 / Trace the lifecycleKey decisions

Follow the execution path.

Mounted volume files support live secret rotation without pod restarts, whereas envFrom environment variables are frozen at process boot and can leak in crash dumps.

Step 1

Compare rotation: Kubelet updates mounted Secret files within ~60s; env vars never update without restart.

Step 2

Compare security: env vars can appear in /proc/pid/environ or debug dumps.

Step 3

Use volumeMounts for DB credentials/API keys and envFrom only for static non-sensitive flags.

YAML · Lifecycle trace
volumeMounts:
  - name: db-creds
    mountPath: /etc/secrets/db
    readOnly: true
Key trade-off

Mounted files require the application to watch or reload the file on SIGHUP/mtime change.

04 / ImplementConfiguration & code

Build the safeguards.

Deleting the stalled pods (or rolling back the Deployment revision) resets kubelet's exponential backoff timer immediately instead of waiting up to 5 minutes.

1. Reference implementation

YAML · Solution
apiVersion: apps/v1
kind: Deployment
metadata:
  name: checkout-service
  annotations:
    argocd.argoproj.io/sync-wave: "0"
spec:
  replicas: 12
  progressDeadlineSeconds: 180
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxUnavailable: 0
      maxSurge: 25%
  template:
    metadata:
      annotations:
        checksum/config: "{{ include (print $.Template.BasePath \"/configmap.yaml\") . | sha256sum }}"
    spec:
      containers:
        - name: checkout
          image: checkout:v2.4.0
          envFrom:
            - secretRef:
                name: checkout-db-creds-v2
                optional: false
            - configMapRef:
                name: checkout-flags-v2
                optional: false

3. Operational controls

Step 1

Verify ExternalSecret is Ready=True.

Step 2

Run kubectl rollout undo deployment/checkout-service (if bad release) or delete CrashLoopBackOff pods.

Step 3

Confirm all 12 pods reach Running 1/1 Ready.

Implementation note

Requires 25% surge capacity (+3 pods) in the node pool during deployments.

05 / Verify & observeEvidence & acceptance

Prove the fix works.

Render Helm templates in CI and run a cross-reference validator ensuring every secretRef/configMapRef/volume in Deployments matches a Secret, ExternalSecret, or ConfigMap in the same release.

  • ↗
    Run helm template . > rendered.yaml in CI.
  • ↗
    Run kubeconform for schema validation.
  • ↗
    Run a Python/OPA check verifying all referenced ConfigMap/Secret names exist in rendered manifests.
PYTHON · Verification
import yaml
# CI check: verify every envFrom.configMapRef.name exists in rendered ConfigMaps
def validate_refs(docs):
    cms = {d["metadata"]["name"] for d in docs if d and d.get("kind") == "ConfigMap"}
    for d in docs:
        if d and d.get("kind") == "Deployment":
            for c in d["spec"]["template"]["spec"]["containers"]:
                for ef in c.get("envFrom", []):
                    ref = ef.get("configMapRef", {}).get("name")
                    assert not ref or ref in cms, f"Missing ConfigMap: {ref}"

Acceptance criteria

Target: no scenario-correlated errors in the tested workload, no duplicate committed writes, and no routine forced termination. Document traffic patterns, duration, and fault injections. A clean run is evidence—not an unconditional guarantee.

Failure scenario 1

Theory & Tips and Tricks

Practical heuristics & interview traps

  • 01Interview anchor: Decouple immutable config/secrets via versioned names, enforce pre-deploy schema/reference validation in CI/CD, and use non-optional envFrom/volumes with safe RollingUpdate maxUnavailable=0 so broken configs never take down healthy pods.
  • 02Trade-off tip: Mounted files require the application to watch or reload the file on SIGHUP/mtime change.
  • 03Watch out for: Deleting pods before the Secret is actually synced just restarts the CrashLoopBackOff timer.
