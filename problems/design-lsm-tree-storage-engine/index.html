The core tensionLeveled vs. Size-Tiered Compaction — Pro: Leveled compaction keeps non-overlapping key ranges per level (L1+), bounding space amplification to ~1.1x and point-lookup fan-out to 1 SSTable per level. — Con: Leveled compaction rewrites data ~10x per level transition, increasing SSD wear and write amplification to 10x-30x compared to 2x-5x for size-tiered.

R

Define the boundaries.

Requirements · 4 minutes
SAY THIS: “Before proposing a topology for Design a Write-Optimized LSM-Tree Storage Engine, I’ll clarify the core functional requirements, burst characteristics, data volume, and availability SLOs to define rigid system boundaries.”
A B+Tree performs random 16 KB page reads and dirty-page flushes on random keys, exhausting 80,000 NVMe random IOPS. An LSM-tree batches writes in a sequential WAL and RAM SkipList, flushing 64 MB sorted runs sequentially.

What the system does

  • Support Put(key, value), Get(key), Delete(key), and ordered RangeScan(startKey, endKey) with crash durability.
  • Sustain 250,000 random writes/sec (250 MB/s) without triggering random 4 KB in-place page updates on disk.
  • Bound p99 point-lookup latency to <= 8 ms even across 10 TB of stored data and 90% negative lookups.
  • Reclaim space from overwritten keys and delete tombstones via background compaction without stalling foreground writers.

What to agree on

  • RAM budget is capped at 16 GB (max 256 MB for active/immutable MemTables; remainder for block cache and Bloom filters).
  • Storage is NVMe SSD (3.5 GB/s sequential write, 80,000 random read IOPS, 120 us 4 KB read latency).
  • Crash recovery from WAL must complete in under 10 seconds after an unclean process kill.

S

Keep state shared and partitioned.

Storage · 3 minutes
SAY THIS: “I’ll separate low-latency ephemeral cache state from authoritative durable storage, ensuring strict consistency where needed and partitioning for scale.”

Cache / Ephemeral state

state:{partitionKey}:activeWindow

  • In-memory key-value cache (Redis Cluster / Memcached).
  • TTL expiration matching window validity bounds.
  • Hash tags to co-locate keys for atomic Lua scripts or transactions.

Durable / Authoritative store

  • Distributed NoSQL / relational database (DynamoDB, PostgreSQL).
  • Durable write-ahead log with replica failover.
  • Cache-aside pattern: read misses warm cache from durable store.
  • Asynchronous CDC / event streaming to telemetry sinks.

Local-only node state is not a shared cluster quota: N nodes could admit roughly N × the configured limits. Ensure state co-location and transactional boundaries align with partition keys.

D

Make state mutations atomic.

Detailed design · 7 minutes
SAY THIS: “For the critical execution path, we enforce idempotency and concurrency controls using atomic primitives, avoiding lock contention and split-brain states.”
  1. Append to WAL with CRC32C and insert into ConcurrentSkipListMap.
  2. Swap active MemTable to immutable queue at 64 MB and flush asynchronously.
  3. On Get(key), probe MemTable -> Immutable MemTables -> L0 (all files, Bloom-filtered) -> L1..Ln (binary search file range, Bloom-filtered, binary search sparse index).

JAVA · REFERENCE IMPLEMENTATION
public byte[] get(byte[] userKey) {
    // 1. Check active & immutable MemTables
    byte[] val = findInMemTable(activeMemTable, userKey);
    if (val != null) return val == TOMBSTONE ? null : val;
    for (MemTable imm : immutableMemTables) {
        val = findInMemTable(imm, userKey);
        if (val != null) return val == TOMBSTONE ? null : val;
    }
    // 2. Check all overlapping L0 SSTables newest-first
    Version v = currentVersion.acquire();
    try {
        for (SSTableMeta sst : v.level0FilesNewestFirst()) {
            if (!sst.bloomFilter.mightContain(userKey)) continue;
            byte[] res = sst.searchDataBlock(userKey, blockCache);
            if (res != null) return res == TOMBSTONE ? null : res;
        }
        // 3. Check L1..Ln (at most 1 SSTable per level)
        for (int lvl = 1; lvl < v.numLevels(); lvl++) {
            SSTableMeta sst = v.binarySearchLevel(lvl, userKey);
            if (sst == null || !sst.bloomFilter.mightContain(userKey)) continue;
            byte[] res = sst.searchDataBlock(userKey, blockCache);
            if (res != null) return res == TOMBSTONE ? null : res;
        }
        return null;
    } finally {
        v.release();
    }
}

Avoid client-side read-modify-write loops without concurrency control. Use atomic scripts, row-level locks, or conditional mutations at the storage tier to guarantee linearizability.

E

Stress-test the design.

Evaluation · 6 minutes
SAY THIS: “The biggest operational risks involve node failover, partition skew, network isolation, and cascading downstream backpressure. Here is how we mitigate each.”
Architectural Trade-Off

Leveled compaction saves ~9 TB of SSD capacity vs Size-Tiered, at the cost of 3x higher compaction write volume.

Operational Hazard

Dropping tombstones before the bottommost level (L6) resurrects deleted keys from deeper SSTables.

D

Close with the trade-offs.

Discussion · 5 minutes
SAY THIS: “In closing, we optimized for sub-millisecond p99 latency and high availability under partition. We trade strict distributed linearizability for predictable throughput and operational simplicity.”

If the interviewer asks…

  • “Need stronger consistency?” Introduce synchronous consensus or linearizable leases; accept higher tail latency.
  • “Need lower cross-region latency?” Route reads to local replicas with asynchronous replication; accept bounded staleness.

Keep the conclusion focused

  • What guarantees are strictly enforced at runtime?
  • What happens during network partitions or node failures?
  • Which CAP trade-off was intentionally chosen and why?

Theory & Tips and Tricks

Practical heuristics & interview traps

  • 01Interview anchor: LSM-trees trade read amplification and background compaction CPU/I/O for 10x-50x higher random write throughput than B+Trees on SSDs and HDDs.
  • 02Trade-off tip: Leveled compaction saves ~9 TB of SSD capacity vs Size-Tiered, at the cost of 3x higher compaction write volume.
  • 03Watch out for: Dropping tombstones before the bottommost level (L6) resurrects deleted keys from deeper SSTables.
