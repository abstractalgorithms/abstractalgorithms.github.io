01 / UnderstandFailure & constraints

Clarify what is failing.

Envoy closes the client connection at 30s, but OrderService (45s) and InventoryService (60s x 3 retries) have no knowledge of the edge deadline and keep executing zombie work.

Design objective

Map each hop's configured timeout and retry count from edge to database.

Requirements

  • Propagate remaining request deadline across HTTP and gRPC boundaries using standard headers (grpc-timeout, x-envoy-upstream-rq-timeout-ms, or W3C deadline context).
  • Clamp every downstream RPC and SQL statement timeout to min(remaining_budget - hop_overhead_ms, local_max_timeout).
  • Enforce a bounded retry budget (max 10% retry amplification) and skip retries when remaining budget is below 2x p99 hop latency.
  • Cancel in-flight thread execution and JDBC/gRPC queries immediately upon context cancellation or deadline expiry.

Constraints

  • Peak checkout traffic is 4,500 RPS across 4 microservice hops with an end-to-end SLA of 3,000 ms p99 (30s hard edge cap).
  • Services run on Java 21 (Spring Boot + gRPC) behind Envoy sidecars with skewed system clocks (up to 150ms NTP drift across nodes).
  • Zero-downtime rollout required; legacy callers that omit deadline headers must fall back to a safe default edge budget.
Known failure modes

name: Connection Pool Starvation; description: HikariCP pools fill with abandoned queries, causing even healthy fast endpoints to fail.; mitigation: Propagate deadlines down to JDBC and abort queries when the caller disconnects.

The invariants

  • Parse incoming deadline duration into a monotonic System.nanoTime() deadline.
  • Subtract 50ms hop overhead before making downstream gRPC/HTTP calls.
  • Bind remaining ms to MySQL MAX_EXECUTION_TIME and skip retries if budget < 2 * p99.

04 / ImplementConfiguration & code

Build the safeguards.

Application-layer thread interruption does not automatically kill an in-flight MySQL query; you must bind the deadline to the SQL driver and DB engine.

1. Reference implementation

JAVA · Solution
public final class DeadlineContext {
  private final long deadlineNanos;

  public DeadlineContext(long budgetMs) {
    this.deadlineNanos = System.nanoTime() + TimeUnit.MILLISECONDS.toNanos(budgetMs);
  }

  public long remainingMs() {
    return Math.max(0L, TimeUnit.NANOSECONDS.toMillis(deadlineNanos - System.nanoTime()));
  }

  public <T extends AbstractStub<T>> T attachToGrpcStub(T stub, long hopBufferMs) {
    long budget = remainingMs() - hopBufferMs;
    if (budget <= 0) {
      throw Status.DEADLINE_EXCEEDED.withDescription("Budget exhausted").asRuntimeException();
    }
    return stub.withDeadlineAfter(budget, TimeUnit.MILLISECONDS);
  }
}

3. Operational controls

Step 1

Set JDBC Statement.setQueryTimeout() from the remaining deadline.

Step 2

Inject MySQL /*+ MAX_EXECUTION_TIME(ms) */ hint for sub-second precision.

Step 3

Listen to gRPC Context.current().addListener() to call Statement.cancel() immediately on client disconnect.

Implementation note

factor: 50ms Hop Safety Buffer; pro: Ensures downstream errors serialize cleanly back to the caller before the caller's timer fires.; con: Reduces usable leaf budget by 50ms per hop (150ms across 3 hops).
