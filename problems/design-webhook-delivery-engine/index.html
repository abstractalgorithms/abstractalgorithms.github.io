The idea to keep with you

To keep the architecture evolvable without sacrificing reliability, never share one unbounded worker queue across all webhook tenants—one slow or dead customer endpoint will fill every worker thread and stall healthy tenants unless isolated by per-endpoint circuit breakers and bulkheads.

TL;DR30-second simplified summary
▾

Core Mechanics: Outbound webhooks hit untrusted, unpredictable third-party servers. Sharing one queue causes head-of-line blocking when one customer endpoint stalls at 30s timeouts, while unsanitized URLs invite Server-Side Request Forgery (SSRF).

Visual & Structural Flow: Depicts Domain Event -> Transaction Outbox -> Partitioned Kafka Queue (by tenant_id) -> Per-Tenant Bulkhead Worker Pool (HMAC-SHA256 Signer + Circuit Breaker per endpoint) -> SSRF Egress Guard (Block 169.254/10.x) -> Customer HTTPS Endpoint, with failures routed to Exponential Backoff + Jitter -> DLQ -> Replay.

Trade-Offs & Production: Partitioning by tenant_id preserves per-tenant ordering, while per-endpoint circuit breakers trip after consecutive 5xx/timeouts so dead endpoints move to slow retry queues without blocking healthy tenants.

Failure Modes & Application: Resolve DNS once at egress and validate the target IP is public (blocking 127.0.0.0/8, 10.0.0.0/8, 169.254.169.254) before connecting to stop DNS-rebinding SSRF attacks.

Transactional Outbox Pattern
The Transactional Outbox pattern eliminates dual-write split-brain by inserting domain events into an outbox table inside the exact same ACID database transaction as the business state change, then relaying them asynchronously to Kafka/RabbitMQ.
Bulkhead & Fault Isolation
The bulkhead pattern partitions shared compute, thread pools, connection pools, and memory into isolated compartments so a slow or failing downstream dependency exhausts only its own quota rather than sinking the entire service.
Dead Letter Queues
A secondary quarantine queue that captures messages a consumer repeatedly fails to process after a bounded number of retries, preventing poison pills from blocking healthy traffic.

Isolated Multi-Tenant Webhook Delivery & SSRF Guard

1.Replay-Safe HMAC: Sign t=<unix_ts>.<body> so receivers reject signatures older than 5m.

2.Circuit Breaker: Trips on dead endpoints so workers never stall on 10s timeouts.

3.DNS-Pinned SSRF: Validates resolved IP is public and connects to that IP directly.

Caption: Combining per-endpoint circuit breakers, DNS-pinned SSRF egress guards, and tiered retry topics keeps healthy tenants fast.

import hmac, hashlib, ipaddress, socket, time

def sign_webhook_payload(secret: str, payload: bytes, timestamp: int | None = None) -> tuple[str, int]:
    """Generate replay-resistant Stripe-style HMAC-SHA256 signature header."""
    ts = int(timestamp or time.time())
    signed = f"{ts}.".encode("utf-8") + payload
    sig = hmac.new(secret.encode("utf-8"), signed, hashlib.sha256).hexdigest()
    return f"t={ts},v1={sig}", ts

def resolve_safe_public_ip(hostname: str) -> str:
    """Resolve hostname once and reject private, loopback, or cloud metadata IPs."""
    ip_str = socket.gethostbyname(hostname)
    ip = ipaddress.ip_address(ip_str)
    if ip.is_private or ip.is_loopback or ip.is_link_local or ip.is_multicast or ip.is_reserved:
        raise ValueError(f"Blocked non-public webhook target IP: {ip_str}")
    return ip_str

Never sleep() inside Kafka consumer threads—publish failed deliveries to dedicated delay topics (retry_1m, retry_15m, retry_2h) with jitter, then park exhausted events in a DLQ for 14 days.
