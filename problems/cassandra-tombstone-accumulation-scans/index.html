01 / UnderstandFailure & constraints

Clarify what is failing.

Deleting the oldest rows writes tombstones at the start of the partition. Every `LIMIT 50` scan starts at the partition head and must read through 100,000+ tombstones before finding 50 live rows.

Design objective

Describe how `DELETE` appends a tombstone marker in memtables/SSTables rather than erasing in place.

Requirements

  • Eliminate `TombstoneOverwhelmingException` and keep p99 poll latency under 15ms.
  • Support 200M tasks/day (~2,315 inserts/sec avg, 10k/sec peak) with 24-hour retention.
  • Allow expired data to be reclaimed without expensive tombstone compaction I/O.
  • Ensure workers do not repeatedly scan already-processed rows.

Constraints

  • Cassandra/ScyllaDB cluster must remain the backing store for task state/history.
  • Default `tombstone_warn_threshold = 1000`, `tombstone_failure_threshold = 100000`.
  • Must avoid `DROP` / `TRUNCATE` races with live writes.
Known failure modes

Coordinator memory exhaustion and multi-second GC pauses.

  1. 01Brokered Dispatch: Kafka/RabbitMQ dispatches ready task_ids without scanning Cassandra partitions.
  2. 02Zero-Tombstone Point Read: Worker fetches task payload by exact (hour_bucket, shard_id, task_id) via Bloom filter.
  3. 03TTL-Only Lifecycle: Worker updates status with default TTL=86400s and UNSET_VALUE for nulls instead of DELETE.
  4. 04Whole-SSTable Expiration: After 24h + gc_grace_seconds (1h), the entire 1-hour SSTable contains only expired cells.
  5. 05O(1) Disk Reclamation: TWCS deletes the expired SSTable file directly without reading or rewriting tombstones.
Offloading FIFO queuing to a message broker and storing task state in TWCS time-bucketed partitions eliminates tombstone scans completely.

The invariants

  • Create the CQL table with TWCS and gc_grace_seconds = 3600.
  • Use UNSET_VALUE in cassandra-driver so omitted fields do not write cell tombstones.
03 / Trace the lifecycleKey decisions

Follow the execution path.

Binding `None` in `INSERT` writes an explicit cell tombstone for `error_msg`. Using `UNSET_VALUE` skips the column entirely on the wire, writing zero tombstones.

Step 1

Import UNSET_VALUE from cassandra.query.

Step 2

Replace None with UNSET_VALUE for all optional fields on INSERT.

PYTHON · Lifecycle trace
from cassandra.query import UNSET_VALUE

def insert_task(session, prep_stmt, queue_name: str, hour_bucket: str, shard_id: int, task_id, payload: bytes, error_msg: str | None = None):
    # Never bind None -> writes a cell tombstone! Use UNSET_VALUE.
    err_val = error_msg if error_msg is not None else UNSET_VALUE
    session.execute(prep_stmt, (queue_name, hour_bucket, shard_id, task_id, "PENDING", payload, err_val))
Key trade-off

Zero tombstones written on insert, though UNSET_VALUE cannot clear an existing non-null value on an UPDATE.

04 / ImplementConfiguration & code

Build the safeguards.

Inspect SSTable metadata via `sstablemetadata` to verify `Estimated droppable tombstones` and `Maximum timestamp` vs. `Minimum timestamp` do not span multiple 1-hour windows.

1. Reference implementation

SQL · Solution
CREATE TABLE scheduler.tasks_by_bucket (
    queue_name text,
    hour_bucket text, -- e.g., '2026-11-13T01'
    shard_id int,     -- 0..99
    task_id timeuuid,
    status text,
    payload blob,
    error_msg text,
    PRIMARY KEY ((queue_name, hour_bucket, shard_id), task_id)
) WITH default_time_to_live = 86400
   AND gc_grace_seconds = 3600
   AND compaction = {
     'class': 'TimeWindowCompactionStrategy',
     'compaction_window_unit': 'HOURS',
     'compaction_window_size': 1,
     'unchecked_tombstone_compaction': true
   };

2. Harden for scale

Inspect SSTable metadata via `sstablemetadata` to verify `Estimated droppable tombstones` and `Maximum timestamp` vs. `Minimum timestamp` do not span multiple 1-hour windows.

PYTHON · Scale hardening
# Helper to compute remaining TTL so late updates expire with the original bucket
import time

def remaining_bucket_ttl(bucket_epoch_s: int, base_ttl_s: int = 86400) -> int:
    elapsed = int(time.time()) - bucket_epoch_s
    return max(60, base_ttl_s - elapsed)

3. Operational controls

Step 1

Check `sstablemetadata` for overlapping min/max timestamps (indicates mixed TTLs or repairs mixing windows).

Step 2

Verify `gc_grace_seconds` (3600) + `TTL` (86400) has elapsed for the oldest SSTables.

Implementation note

TWCS drops whole 1-hour SSTables cleanly after 25 hours with near-zero compaction I/O.

Acceptance criteria

Target: no scenario-correlated errors in the tested workload, no duplicate committed writes, and no routine forced termination. Document traffic patterns, duration, and fault injections. A clean run is evidence—not an unconditional guarantee.

Review questions

Failure scenario 1

Running `nodetool repair` on TWCS without subrange/incremental awareness can merge old and new windows.

Failure scenario 2

Clock skew between producers creating `TimeUUID`s out of order causes missed tasks if `task_id > checkpoint`.

Alternatives considered

  • Migrate fully to Kafka/RabbitMQ for work distribution.

Theory & Tips and Tricks

Practical heuristics & interview traps

  • 01Interview anchor: Never model a FIFO queue in an LSM-tree without time-bucketing; use TimeWindowCompactionStrategy (TWCS), partition by (bucket_id, time_slice), and align gc_grace_seconds so entire SSTables drop cleanly.
  • 02Trade-off tip: Zero tombstones written on insert, though UNSET_VALUE cannot clear an existing non-null value on an UPDATE.
  • 03Watch out for: Running nodetool repair on TWCS without subrange/incremental awareness can merge old and new windows.
