Fixing CoreDNS Query
Flooding from ndots:5.

Kubernetes defaults to ndots:5 with 3–4 search domains, causing every external lookup (like api.stripe.com, 2 dots) to fire 8–10 A/AAAA queries and flood CoreDNS + conntrack.

01 / UnderstandFailure & constraints

Clarify what is failing.

`api.stripe.com` has 2 dots (`< 5`), so `glibc` appends all 4 search suffixes first, sending 8 `A`/`AAAA` `NXDOMAIN` queries before the real one. Parallel `A`+`AAAA` UDP packets race in `nf_conntrack`, causing 5s retries.

Design objective

Inspect `/etc/resolv.conf` inside a running pod.

Requirements

  • Cut CoreDNS QPS by `>= 80%` without breaking internal short-name Kubernetes service resolution (e.g., `redis-master`).
  • Eliminate `5-second` UDP `conntrack` DNS timeouts across all 120 nodes.
  • Keep p99 DNS resolution latency under `2 ms` for cached external and internal domains.
  • Provide cluster-wide rollout without requiring manual code edits in every microservice.

Constraints

  • Pods use standard `glibc` (`Debian`/`Ubuntu`) and Alpine `musl` images.
  • IPv6 is disabled in the cluster VPC, yet `glibc` issues both `A` and `AAAA` queries in parallel.
  • External APIs must still resolve with fresh TTLs (respecting `30s–60s` upstream DNS TTLs).
Known failure modes

Using `api.stripe.com.` in HTTP `Host` headers can cause `400 Bad Request` on strict CDNs.

Separate concerns. Map the flow.

Mutate application pods to `ndots:2` + `single-request-reopen` via Kyverno, and run `NodeLocal DNSCache` with `force_tcp` upstream to CoreDNS.

External FQDNs

  1. 01Skip Search Suffixes: With ndots:2, 2-dot external domains resolve immediately without 4 NXDOMAIN search suffixes.
  2. 02Bypass Conntrack & NAT: NodeLocal listens on 169.254.20.10 with iptables NOTRACK, eliminating 5s UDP conntrack races.
  3. 03TCP Upstream to CoreDNS: Cache misses forward over persistent TCP to CoreDNS, avoiding UDP packet drops.
  4. 04Single Upstream Lookup: CoreDNS resolves and caches the external answer for 30s.
  5. 05Internal Names Preserved: Internal names like redis-master (0 dots) and auth.prod (1 dot) still append search suffixes.
Combining `ndots:2` with `NodeLocal DNSCache` (`NOTRACK` + `force_tcp`) cuts CoreDNS QPS by 97% and eliminates 5s UDP timeouts.

The invariants

  • Deploy node-local-dns DaemonSet on 169.254.20.10 and point kubelet --cluster-dns to it.
  • Apply Kyverno mutation policy setting ndots: 2.
  • Verify NXDOMAIN rate drops >80% in Prometheus.
03 / Trace the lifecycleKey decisions

Follow the execution path.

`ndots:2` still expands 0-dot (`redis`) and 1-dot (`auth.payments`) internal names via `.svc.cluster.local`, whereas `ndots:1` sends `auth.payments` to root DNS first. `force_tcp` avoids UDP `conntrack` drops between nodes and CoreDNS.

Step 1

Test dots < ndots: for ndots=2, 0 < 2 and 1 < 2 (search path used); 2 >= 2 (external root first).

Step 2

Use NOTRACK on 169.254.20.10 for pod-to-NodeLocal UDP.

Step 3

Use force_tcp from NodeLocal to CoreDNS so kube-proxy NAT never drops UDP.

PYTHON · Lifecycle trace
def resolves_internally_first(name: str, ndots: int = 2) -> bool:
    # Names with fewer than ndots try .svc.cluster.local suffixes first
    return name.count(".") < ndots
Key trade-off

TCP upstream adds a tiny connection-setup cost amortized over persistent connections, while eliminating UDP packet loss.

04 / ImplementConfiguration & code

Build the safeguards.

Enable `serve_stale` in CoreDNS/NodeLocal (`cache 30 { serve_stale 5m immediate }`) so transient upstream VPC DNS throttling serves slightly stale records instead of `SERVFAIL`.

1. Reference implementation

YAML · Solution
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: inject-ndots-2
spec:
  rules:
    - name: set-ndots-2
      match:
        any:
          - resources:
              kinds: [Pod]
              namespaces: ["!kube-system"]
      mutate:
        patchStrategicMerge:
          spec:
            dnsConfig:
              options:
                - name: ndots
                  value: "2"
                - name: single-request-reopen

2. Harden for scale

Enable `serve_stale` in CoreDNS/NodeLocal (`cache 30 { serve_stale 5m immediate }`) so transient upstream VPC DNS throttling serves slightly stale records instead of `SERVFAIL`.

YAML · Scale hardening
# Corefile cache block with serve_stale
.:53 {
    cache 30 {
        success 9984 30
        denial 9984 15
        serve_stale 5m immediate
    }
    forward . /etc/resolv.conf {
        max_concurrent 1000
    }
}

3. Operational controls

Step 1

Add `serve_stale 5m immediate` to CoreDNS `cache` plugin.

Step 2

Configure `max_concurrent` and `health` / `ready` timeouts.

Step 3

Increase VPC resolver / Route 53 Resolver inbound endpoint capacity if throttled.

Implementation note

Mutating `dnsConfig` applies cleanly to all new pods without requiring code changes across 50+ repos.

PYTHON · Verification
def check_dns_health(nxdomain_qps: float, total_qps: float, p99_ms: float) -> str:
    nx_ratio = nxdomain_qps / max(1.0, total_qps)
    if p99_ms > 50.0:
        return "CRITICAL_DNS_LATENCY"
    if nx_ratio > 0.40:
        return "WARN_NDOTS_AMPLIFICATION"
    return "HEALTHY"

Acceptance criteria

Target: no scenario-correlated errors in the tested workload, no duplicate committed writes, and no routine forced termination. Document traffic patterns, duration, and fault injections. A clean run is evidence—not an unconditional guarantee.

Review questions

Failure scenario 1

Setting `serve_stale` for too long (e.g., 24h) can pin traffic to a decommissioned IP after an outage.

Failure scenario 2

Averaging CoreDNS latency across all nodes hides single-node `conntrack` drops.

Alternatives considered

  • Use Hubble / eBPF DNS observability to attribute top `NXDOMAIN` callers by pod label.
