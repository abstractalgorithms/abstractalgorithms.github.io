The idea to keep with you

Your microservices cluster (120 nodes, `40,000 req/s` total outbound HTTP/gRPC calls to external APIs like `api.stripe.com`, `s3.us-east-1.amazonaws.com`, and internal services) experiences intermittent `5-second` DNS timeouts (`i/o timeout` / `UnknownHostException`). Inspecting CoreDNS (6 replicas) shows `280,000 QPS` of `NXDOMAIN` responses for `api.stripe.com.prod.svc.cluster.local`, `api.stripe.com.svc.cluster.local`, and `api.stripe.com.cluster.local`, saturating CoreDNS CPU and `nf_conntrack` UDP tables.

From patterns to decisions.

Full walkthrough · 5 stages
01
STAGE 01 · WHY IT MATTERSL4 · FUNDAMENTALS

Why ndots:5 floods CoreDNS across 120 Kubernetes nodes.

Kubernetes injects options ndots:5 into every pod's /etc/resolv.conf. Any hostname with fewer than 5 dots—including api.stripe.com (2 dots) or s3.us-east-1.amazonaws.com (4 dots)—is treated as a relative name first. glibc appends prod.svc.cluster.local, svc.cluster.local, and cluster.local for both A and AAAA records (6–8 queries per lookup), flooding CoreDNS with 280,000 QPS of NXDOMAIN responses and causing 5-second UDP nf_conntrack drops.

02
STAGE 02 · IMPACTL5 · APPLIED DESIGN

What happens during glibc A/AAAA parallel UDP conntrack races.

Two compounding bugs cause intermittent 5-second DNS timeouts:

  1. 8× NXDOMAIN Amplification: Every uncached external lookup generates 3 search-domain NXDOMAIN pairs before trying the root domain.
  2. Parallel A/AAAA Conntrack Race: glibc sends A and AAAA UDP packets from the same source port simultaneously; iptables NAT nf_conntrack races on creating the table entry, silently dropping one packet and forcing a 5-second resolv.conf retry.
ndots:5 Amplification vs. NodeLocal DNSCache

6x NXDOMAIN + Conntrack Drop (5s) vs. NodeLocal TCP (<2ms)

NodeLocal DNSCache bypasses nf_conntrack via NOTRACK and upgrades upstream queries to TCP, eliminating 5s UDP drops.

03
STAGE 03 · NAIVE SOLUTIONL5 · APPLIED DESIGN

Naive solution (and why scaling CoreDNS replicas alone fails).

Scaling CoreDNS from 6 to 30 replicas burns CPU on 280k QPS of NXDOMAINs without fixing the root cause: per-node nf_conntrack UDP packet drops between pods and kube-proxy iptables rules.

04
STAGE 04 · ENTERPRISE SOLUTIONL6 · SCALE & TRADE-OFFS

Enterprise solution: NodeLocal DNSCache + MutatingWebhook ndots:2 + single-request.

Production Kubernetes clusters fix both amplification and conntrack races cluster-wide:

  • NodeLocal DNSCache DaemonSet: Listens on link-local 169.254.20.10 per node with iptables NOTRACK (bypassing nf_conntrack completely), caches external TTLs (30–60 s) locally (< 1 ms), and forwards misses to CoreDNS over TCP.
  • Cluster-Wide ndots:2 + single-request-reopen: Inject ndots:2 and single-request-reopen via a Mutating Admission Webhook (or Kyverno policy) so api.stripe.com (2 dots) resolves from root immediately while short names (redis-master, 0 dots) still use cluster search domains.
  • Result: CoreDNS QPS drops by > 80%, 5 s timeouts vanish, and cached p99 stays < 2 ms.
Node-Local DNS Tier

Pod (ndots:2) -> NodeLocal DNSCache (NOTRACK) -> CoreDNS (TCP)

1.ndots:2 Policy: Eliminates 6x NXDOMAIN searches for external FQDNs without breaking short names.

2.NOTRACK Bypass: Skips Linux nf_conntrack for pod-to-NodeLocal DNS packets.

3.TCP Upstream: Upgrades NodeLocal -> CoreDNS to TCP, eliminating UDP packet drops.

4.single-request-reopen: Serializes glibc A/AAAA on separate sockets for musl/glibc safety.

NodeLocal DNSCache + ndots:2 cuts CoreDNS traffic by > 80% and eliminates conntrack-induced 5-second timeouts.

# Cluster-wide Kyverno / Webhook default injected into Pods (zero app code edits)
spec:
  dnsConfig:
    options:
      - name: ndots
        value: "2"
      - name: single-request-reopen
      - name: timeout
        value: "2"
      - name: attempts
        value: "2"
05
STAGE 05 · SYSTEM DESIGN APPLICATIONSL7 · STAFF / PRINCIPAL

Where NodeLocal DNS & ndots Tuning apply in Kubernetes.

DNS amplification and conntrack tuning are essential for high-QPS Kubernetes platforms:

  • Payment & Webhook Egress Clusters: Services calling Stripe, AWS S3, or Twilio at 40,000+ req/s.
  • Multi-Tenant Microservice Meshes: Keeping internal redis-master short-name resolution working while protecting CoreDNS.
  • Linux Conntrack Hardening: Preventing UDP table exhaustion on high-density 120-node clusters.
