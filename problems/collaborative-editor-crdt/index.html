The idea to keep with you

If latency budgets leave no room for synchronous retries, sequence CRDTs guarantee strong eventual consistency without a central serialization server, but require tombstone compaction and delta-state encoding so document memory does not grow unboundedly.

TL;DR30-second simplified summary
▾

Core Mechanics: Concurrent offline edits break naive index-based updates (insert(pos=5, 'x')). Sequence CRDTs (such as RGA or Yjs) assign each character a globally unique, causally ordered ID (lamport_ts, client_id) so concurrent inserts merge commutatively in any delivery order.

Visual & Structural Flow: Depicts Client A (Offline Edit) and Client B (Concurrent Edit) each maintaining a local RGA / Yjs Character Tree (a1@A, b1@B), exchanging deltas through a WebSocket Pub/Sub Gateway with Commutative Merge (Zero Locks) and persisting to a Compacted Snapshot Store + Op Log.

Trade-Offs & Production: CRDTs eliminate central OT transform-server bottlenecks and support peer-to-peer/offline merges, at the cost of tombstone metadata overhead—mitigated via run-length block encoding and background GC compaction.

Failure Modes & Application: Hash-route document rooms to stateful WebSocket/Redis-PubSub shards, enforce per-document max op-size limits, and compact op logs every N=1,000 edits.

CRDTs & Conflict-Free Replicated Data
CRDTs (Conflict-free Replicated Data Types) are replicated data structures whose concurrent updates commute or form a mathematical join-semilattice, guaranteeing every replica converges to the exact same state without coordination or consensus.
WebSocket Real-Time Scaling
WebSockets (RFC 6455) upgrade an HTTP connection into a persistent, full-duplex TCP frame stream; scaling to millions of concurrent connections shifts the bottleneck from request/sec to stateful memory, ephemeral ports, pub/sub fan-out, and reconnect storms.
Consistent Hashing & Virtual Nodes
Consistent hashing assigns data keys to servers in a way that limits how many keys move when servers are added or removed. This helps avoid widespread cache misses and sudden load on databases.

RGA/Yjs Delta Sync + Sticky WebSocket Shards + Op-Log Compaction.

Why this matters: The mechanism: route document rooms via consistent hashing and compact tombstones asynchronously.

Think of RGA/Yjs Delta Sync + Sticky WebSocket Shards + Op-Log Compaction as the intuition layer for Design a Real-Time Collaborative Document Editor (CRDTs & WebSockets): The mechanism: route document rooms via consistent hashing and compact tombstones asynchronously.

Consistent-hash doc_id to a WebSocket Room Shard (with Redis Pub/Sub cross-pod fanout for failover). Clients exchange state vectors ({clientId: maxClock}) on reconnect to fetch only missing binary deltas, while a background compactor merges the append-only op log into a single base snapshot and garbage-collects deleted tombstones once all active replicas acknowledge the epoch.

Sync & Persistence Path

CRDT Delta Sync & Snapshot Compaction Pipeline

1.State-Vector Sync: Reconnects exchange compact version vectors to stream only missing deltas.

2.Run-Length Blocks: Yjs merges contiguous typing by one author into 1 block, cutting RAM 10x.

3.Safe Compaction: Squashes op logs into a base snapshot periodically for fast cold loads.

Caption: Sticky document rooms broadcast tiny binary CRDT deltas in <80ms while background compaction bounds op-log and tombstone growth.

def compute_missing_deltas(local_clock: dict[str, int], remote_ops: list[dict]) -> list[dict]:
    """Filter operations unseen by a reconnecting client using its state vector."""
    missing = []
    for op in remote_ops:
        cid = op["client_id"]
        seq = op["seq"]
        if seq > local_clock.get(cid, 0):
            missing.append(op)
    return sorted(missing, key=lambda o: (o["lamport"], o["client_id"]))

Taming Tombstone Bloat & Ephemeral Cursor Presence.

Why this matters: Operational control: keep deleted characters and live cursors from bloating persistent state.

Think of Taming Tombstone Bloat & Ephemeral Cursor Presence as the intuition layer for Design a Real-Time Collaborative Document Editor (CRDTs & WebSockets): Operational control: keep deleted characters and live cursors from bloating persistent state.

Never persist live cursor/selection coordinates in the CRDT op log—broadcast awareness/presence as ephemeral volatile messages over WebSockets with a 30s TTL. For deleted text, compress consecutive deletions into run-length tombstone ranges and run periodic snapshot compaction.
