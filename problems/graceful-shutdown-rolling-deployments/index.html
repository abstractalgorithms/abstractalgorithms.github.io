The idea to keep with you

Every time a high-throughput API gateway / payment service (20,000 RPS across 40 Kubernetes pods behind an AWS ALB and Envoy ingress) runs a rolling deployment, clients observe a spike of 502 Bad Gateway errors and TCP RSTs for 15–30 seconds. Investigation shows pods immediately close Netty/Tomcat listener sockets upon receiving SIGTERM while kube-proxy and Envoy still route new and keep-alive requests to the terminating pod IP. Design a zero-downtime rolling deployment and graceful shutdown architecture.

Full walkthrough · 5 stages
01
STAGE 01 · WHY IT MATTERSL4 · FUNDAMENTALS

Why rolling deployments cause 15–30 second 502 spikes at 20k RPS.

When Kubernetes terminates a pod during a rolling update, two things happen asynchronously in parallel: kubelet sends SIGTERM to the container immediately, while the control plane propagates EndpointSlice / AWS ALB target deregistration to kube-proxy and Envoy over 2–10 seconds. If Spring Boot/Netty closes its listener socket immediately on SIGTERM, Envoy and ALB keep routing 20,000 RPS of new and keep-alive requests to a dead socket—spiking 502 Bad Gateway and TCP RSTs.

02
STAGE 02 · IMPACTL5 · APPLIED DESIGN

What happens during the EndpointSlice propagation race.

Immediate SIGTERM shutdown breaks both new and existing connections:

  1. Propagation Race: Envoy/ALB still holds the terminating pod IP as HEALTHY for 2–10 s after SIGTERM.
  2. Keep-Alive & HTTP/2 Pinning: Without an HTTP/2 GOAWAY frame or Connection: close on responses, proxies keep sending new requests down already-open TCP sockets.
  3. Premature Kill: In-flight 25-second requests get severed if terminationGracePeriodSeconds defaults to 30 s minus preStop.
Zero-Drop Termination Timeline

preStop Sleep (12s) -> SIGTERM Graceful Drain (25s) -> SIGKILL (45s)

The 12s preStop sleep absorbs EndpointSlice propagation lag while Spring Boot continues serving until Envoy drains.

03
STAGE 03 · NAIVE SOLUTIONL5 · APPLIED DESIGN

Naive solution (and why server.shutdown=graceful alone still drops 502s).

Enabling server.shutdown=graceful without a preStop hook still causes 502s: the moment SIGTERM arrives at t=0s, Tomcat/Netty stops accepting new connections—before Envoy and AWS ALB finish removing the pod IP (t=2..10s).

04
STAGE 04 · ENTERPRISE SOLUTIONL6 · SCALE & TRADE-OFFS

Enterprise solution: preStop Propagation Buffer + Graceful Drain + GOAWAY.

Zero-downtime rolling deployments coordinate three timers within terminationGracePeriodSeconds: 45:

  • 1. preStop Sleep (12 s): Blocks SIGTERM for 12 s while /readyz fails and EndpointSlice + AWS ALB deregister the pod; the server keeps accepting straggler requests routed during propagation.
  • 2. Graceful Shutdown (25 s timeout): At t=12 s, SIGTERM triggers Spring Boot server.shutdown=graceful (spring.lifecycle.timeout-per-shutdown-phase=25s), sending HTTP/2 GOAWAY frames and Connection: close on HTTP/1.1 responses while finishing active <= 25 s requests.
  • 3. Bounded Rollout Velocity: Set maxSurge: 25%, maxUnavailable: 0 so capacity never dips during the 45 s drain window.
Pod Shutdown Lifecycle

Serving -> Terminating (preStop 12s) -> Draining (25s) -> Exited

12s preStop + 25s drain fits safely inside terminationGracePeriodSeconds: 45 with zero dropped requests.

# Kubernetes PodSpec + Spring Boot 3 graceful shutdown config
# application.yaml:
#   server.shutdown: graceful
#   spring.lifecycle.timeout-per-shutdown-phase: 25s
spec:
  terminationGracePeriodSeconds: 45   # >= preStop (12s) + drain (25s) + buffer (8s)
  containers:
    - name: payment-api
      lifecycle:
        preStop:
          exec:
            command: ["sh", "-c", "sleep 12"]
05
STAGE 05 · SYSTEM DESIGN APPLICATIONSL7 · STAFF / PRINCIPAL

Where Graceful Shutdown applies in Production Kubernetes.

Coordinated preStop + graceful drain is mandatory for zero-downtime cloud deployments:

  • High-QPS API Gateways & Payment Services: Deploying 20+ times/day at 20k+ RPS with zero 502s.
  • gRPC & WebSocket Servers: Emitting HTTP/2 GOAWAY frames so long-lived streams migrate cleanly.
  • Spot / Preemptible Node Drains: Finishing in-flight jobs before PDB / autoscaler evictions.
