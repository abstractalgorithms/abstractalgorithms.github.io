The idea to keep with you

FD exhaustion, 429 storms, and frozen event-loop heartbeats.

An unthrottled asyncio scraper fails on three fronts:

  1. File Descriptor Exhaustion: 50,000 concurrent sockets exceed the container's 1024-4096 FD limit.
  2. 429 Banning: Bursting thousands of requests in 100 ms trips upstream rate limiters.
  3. Event-Loop Starvation: A 150 ms synchronous HTML/PDF parse blocks all 50 sockets and Kubernetes health probes.
Bounded Asyncio Pipeline

Queue -> Token Bucket (200/s) + Semaphore(50) -> Offloaded Parser

Bounding both socket concurrency (50) and request rate (200/s) while offloading CPU parsing keeps the event loop responsive.

Naive Solution
Use a single unpartitioned path with unbounded retries and synchronous global coordination.
Why It Fails
Global coordination serializes throughput under load, while unbounded retries amplify transient stalls into full outages.
Alternatives
Compare synchronous strict-consistency paths against bounded asynchronous replication, local caching, or partitioned ownership.
Engineering Decision
To keep the architecture evolvable without sacrificing reliability, pair an asyncio.Semaphore(50) + async Token Bucket (200 req/s) + bounded asyncio.Queue worker pool, and offload CPU-heavy parsing via asyncio.to_thread or ProcessPoolExecutor.
Trade-Offs
Gains predictable p99 latency and fault isolation in exchange for explicit bounding, observability, and slightly higher implementation complexity.

STAGE 04 · ENTERPRISE SOLUTIONL6 · SCALE & TRADE-OFFS

Enterprise solution: Worker Pool + Async Token Bucket + CPU Offload.

Why this matters: Operational control: configure bounds, failure handling, and safe production defaults.

Compose four clean primitives in Python 3.11+:

  • Bounded Queue & 50 Workers: A asyncio.Queue(maxsize=500) + 50 worker tasks (asyncio.TaskGroup) caps memory and in-flight sockets to <= 50 (matching aiohttp.TCPConnector(limit=50)).
  • Async Token Bucket (200 req/s): Serializes token refill via asyncio.Lock using time.monotonic() so average rate never exceeds 200 req/s.
  • CPU Offloading: Run await asyncio.to_thread(parse_html, body) (or loop.run_in_executor(process_pool, ...) for pure-Python CPU work) so heartbeats never stall.
  • Graceful Shutdown: On SIGTERM, cancel producer, drain queue or cancel TaskGroup cleanly, and close the ClientSession.
Concurrency & Rate Controls

Three-Layer Bounds: Socket Cap, Rate Bucket, and CPU Pool

Each layer enforces an independent bound: memory (500), rate (200/s), sockets (50), and event-loop latency (<5 ms).

import asyncio, time

class AsyncTokenBucket:
    def __init__(self, rate: float, capacity: float):
        self.rate, self.cap, self.tokens = rate, capacity, capacity
        self.updated = time.monotonic()
        self.lock = asyncio.Lock()

    async def acquire(self):
        while True:
            async with self.lock:
                now = time.monotonic()
                self.tokens = min(self.cap, self.tokens + (now - self.updated) * self.rate)
                self.updated = now
                if self.tokens >= 1.0:
                    self.tokens -= 1.0
                    return
                wait = (1.0 - self.tokens) / self.rate
            await asyncio.sleep(wait)

async def worker(queue: asyncio.Queue, sem: asyncio.Semaphore, bucket: AsyncTokenBucket, session):
    while True:
        url = await queue.get()
        try:
            await bucket.acquire()
            async with sem:
                async with session.get(url) as resp:
                    body = await resp.read()

        finally:
