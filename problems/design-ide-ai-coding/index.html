The idea to keep with you

To keep the architecture evolvable without sacrificing reliability, cancel stale in-flight HTTP/2 streams on every new keystroke so wasted GPU decode steps abort immediately rather than saturating the fleet.

TL;DR30-second simplified summary
▾

Without client-side debouncing (100–150 ms) and aggressive in-flight request cancellation, a fast typist fires 8 overlapping GPU inference requests per second—wasting 85% of GPU compute on discarded suggestions.

The IDE extension assembles a bounded context window (cursor prefix/suffix + Tree-sitter AST imports from open tabs), redacts high-entropy secrets (API keys/tokens) locally before network egress, and opens a cancellable HTTP/2 SSE stream. On the backend, a prefix-aware router hits FP8 7B/13B FIM pods using speculative decoding and RadixAttention KV caching.

Before you begin · Building blocksAlready know these? Jump to Stage 01 ↓
Fill-in-the-Middle (FIM) & Speculative IDE Code Completion
Fill-in-the-Middle (FIM) rearranges code around the cursor into <PRE> prefix <SUF> suffix <MID> so autoregressive models condition on both preceding and following code.
AI/LLM Prefix Caching & RadixAttention (Zero-Copy KV Sharing)
RadixAttention indexes cached GPU KV-cache blocks in a compressed prefix trie (Radix Tree) with LRU eviction, enabling zero-copy prefix sharing across concurrent and sequential LLM requests.
Context Compression for RAG
Techniques that prune, rerank, or summarize retrieved RAG chunks before LLM generation to slash token cost and TTFT while beating 'lost-in-the-middle' attention decay.
