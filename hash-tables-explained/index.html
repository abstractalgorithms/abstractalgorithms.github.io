🎯 System Scenario & Requirements

System Goal

A hash table gives you near-O(1) lookups, inserts, and deletes by using a hash function to map keys to array indices.

Actors & Components

  • Application or API tier
  • Core service under design
  • Operator or SRE observer

Functional Requirements

  • TLDR: A hash table gives you near-O(1) lookups, inserts, and deletes by using a hash function to map keys to array indices.
  • The tradeoff: collisions (when two keys hash to the same slot) must be handled, and a full hash table must be resized.
  • Python dict uses open addressing with compact arrays (since Python 3.6).

Constraints & Assumptions

  • Choose hash table when: You need fast key-value lookup and don't need ordering or range queries.
  • Choose BST when: You need sorted iteration or range queries (e.g., "find all keys between 10 and 50").
  • - O(1) average is not O(1) guaranteed.
  • Every hash table has a worst case.

This walkthrough focuses on Why Python Dicts Are Fast.

Before making a design choice, clarify:

  • Python dict uses open addressing with compact arrays (since Python 3.6).
  • Entries are stored in an incrementally-growing compact array indexed by insertion order, with a separate hash table of indices pointing into it.
  • This gives: - Fast iteration (compact memory, no pointer chasing).

Stage 2 — Hash Table Fundamentals

  • A hash table combines two simple ideas into a data structure with near-constant-time performance: 1.
  • An array provides O(1) access by index: array[42] is instant.
  • A hash function converts any key (string, integer, object) to an index: h("john") → 42 .
  • Together: given any key, compute its index in one step, then access the array slot directly.

Stage 4 — How a Hash Table Handles a Lookup

  • The lookup flow for key "alice" in a hash table with separate chaining: Three scenarios during lookup: 1.
  • Direct hit: array[index] contains exactly the target key → O(1).
  • Collision chain: array[index] has multiple entries → scan the short chain → O(k) where k = bucket length (typically 1–2 with good load factor).
  • Miss: The slot is empty → key not in table → O(1).

Stage 5 — Collisions: When Two Keys Land in the Same Slot

  • Given a finite array, two different keys will eventually map to the same slot.
  • Example: - hash('cat') = 2 → Stored at index 2.
    • hash('bird') = 2 → Collision at index 2!
  • Two collision resolution strategies: Separate Chaining Each slot holds a linked list of key-value pairs.

Stage 6 — Deep Dive: Load Factor and Rehashing

  • Load factor = (number of entries) / (array capacity).
  • As the table fills up (load factor → 1.0), collisions increase and performance degrades.
  • Standard practice: rehash when load factor exceeds 0.75 .
  • Create a new array 2× the size.
